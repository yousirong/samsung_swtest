## 1. 문제 요약
연구소 맵에
- `0` : 빈 칸
- `1` : 벽
- `2` : 불(또는 바이러스)

**빈 칸 3곳에 새로 벽을 설치**한 뒤, 불이 상하좌우로 퍼졌을 때 **남는 안전 영역(`0`의 개수)의 최댓값**을 구한다.

## 2. 필요한 이론
→ [G08 조합 선택 + BFS](../../theory/G08_조합선택BFS.md)

[바이러스 백신](2019상오후2_바이러스백신.md)과 **거의 같은 골격**이지만 방향이 반대다.

| | 바이러스 백신 | 방화벽 (이 문제) |
|---|---|---|
| 조합으로 고르는 것 | **확산 시작점** (병원) | **확산을 막을 벽** |
| BFS 시작점 | 고른 것 | 원래 있던 불(`2`) 전부 |
| 평가 | 걸린 **시간** (최소) | 남은 **빈 칸 수** (최대) |
| 고르는 개수 | M (가변) | **3 (고정)** |

> **★ "무엇을 조합으로 고를 것인가"** 가 두 문제를 가른다.
> 여기서는 벽을 고르고 불은 그대로 두므로, **BFS 시작점은 조합과 무관**하다.

`C(빈 칸 수, 3)` 이 탐색 공간. `N, M ≤ 8` 이면 빈 칸 최대 64개 → `C(64,3) ≈ 4만` × BFS `O(64)` → 여유.

## 3. 코드 흐름
```
main()
 └ input()                    N, M, MAP — 빈 칸을 emptyRoom[]에 수집, emptyCount
   maxAnswer = 0
   DFS(0, 0)
   printf(maxAnswer)

DFS(depth, start):
   if (depth == 3):           ★ 벽 3개 고정
      BFS()
      tmp = countEmpty()
      maxAnswer = max(maxAnswer, tmp)
      return
   for i in start..emptyCount-1:
      num_of_cases[depth] = i
      DFS(depth + 1, i + 1)   ★ 조합

BFS():
   copyMap(tmpMAP, MAP)       ★★ 매번 초기화
   고른 3곳에 벽 설치
   불(2)을 전부 큐에 삽입 → 확산
```

## 4. 핵심 코드

### 빈 칸 후보 수집
```c
struct RC { int r; int c; };
RC emptyRoom[MAX * MAX];
int emptyCount;

// input() 안에서
if (MAP[r][c] == 0)
{
    emptyRoom[emptyCount].r = r;
    emptyRoom[emptyCount++].c = c;
}
```
좌표가 아니라 **인덱스로 조합**을 고르게 된다. [바이러스 백신](2019상오후2_바이러스백신.md)의 `hospital[]` 과 같은 패턴.

### 조합 재귀 — 3개 고정
```c
void DFS(int depth, int start)
{
    // 벽 3개를 모두 골랐으면 실제로 BFS 시뮬레이션 수행
    if (depth == 3)
    {
        BFS();

        int tmp = countEmpty();
        if (maxAnswer < tmp) maxAnswer = tmp;

        return;
    }

    // 빈 칸 목록에서 하나씩 고르기
    for (int i = start; i < emptyCount; i++)
    {
        num_of_cases[depth] = i;

        // 다음 벽은 현재보다 뒤에서만 선택
        DFS(depth + 1, i + 1);      // ★ i + 1
    }
}
```

**`depth == 3`** 이 고정값인 것이 [바이러스 백신](2019상오후2_바이러스백신.md)(`depth == M`)과 다른 점.
문제가 "정확히 3개"라고 못 박았다.

### ★★ BFS — 벽 설치 후 다중 시작점 확산
```c
void BFS()
{
    // 원본 맵을 tmpMAP에 복사해서 시뮬레이션 시작
    copyMap(tmpMAP, MAP);          // ★★ 조합마다 필수

    // 1. 선택된 3곳에 벽 설치
    for (int i = 0; i < 3; i++)
    {
        int index = num_of_cases[i];
        tmpMAP[emptyRoom[index].r][emptyRoom[index].c] = WALL;
    }

    // 2. 현재 tmpMAP에서 모든 FIRE(2)를 큐에 넣는다. 즉, 멀티 소스 BFS 시작
    int rp, wp;
    rp = wp = 0;

    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            if (tmpMAP[r][c] == FIRE)
            {
                queue[wp].r = r;
                queue[wp++].c = c;
            }

    // 3. 확산 — 빈 칸(0)만 불로 바꾼다
    while (rp < wp) { ... if (tmpMAP[nr][nc] == 0) { 큐 삽입; tmpMAP[nr][nc] = FIRE; } ... }
}
```

**순서가 중요하다.**
1. **복사** — 원본 보존
2. **벽 설치** — 확산 전에 미리
3. **불 수집** — 벽 설치 **이후**에 (벽이 불을 덮을 일은 없지만 순서를 명확히)
4. **확산**

> **★ 여기서는 시간을 안 센다.** `tmpMAP[nr][nc] = FIRE` 로 그냥 불로 바꾼다.
> [바이러스 백신](2019상오후2_바이러스백신.md)은 시간이 답이라 `+1` 누적이 필요했지만, 이 문제는 **최종 상태만** 필요하다.
> **문제가 무엇을 묻느냐에 따라 BFS가 저장하는 값이 달라진다.**

### 안전 영역 세기
```c
int countEmpty()
{
    int sum = 0;

    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            sum += !tmpMAP[r][c];      // ★ tmpMAP == 0 이면 1을 더함
    return sum;
}
```

**`!tmpMAP[r][c]` 트릭**: `0` 이면 `1`, 아니면 `0`. `if` 없이 센다.
[회전하는 빙하](../G06/2020하오후2_회전하는빙하.md)의 `count += !MAP[nr][nc]` 와 같은 관용구.

### 검증이 필요 없는 이유
[바이러스 백신](2019상오후2_바이러스백신.md)은 "모두 퍼졌는가"를 검증해야 했다.
**이 문제는 검증이 없다.** 어떤 조합이든 유효하고, 단지 남는 빈 칸 수가 다를 뿐이다.

> **최댓값 문제 + 모든 후보가 유효** → 실패 규약(`INF`)이 필요 없다. `maxAnswer = 0` 으로 시작하면 충분.

## 5. 예제 손 추적

```
격자 (N=4, M=4)

  0  0  0  0
  0  2  0  0        2 = 불
  0  0  0  0
  0  0  0  1        1 = 원래 벽
```

빈 칸 14개 → `C(14, 3) = 364` 가지 조합.

### 조합 ①: 불을 완전히 가두기 — `(1,2) (2,1) (2,3)` 에 벽
```
설치 후:
  0  W  0  0
  W  2  W  0
  0  0  0  0
  0  0  0  1
```
불 `(2,2)` 에서 확산하려면
- 위 `(1,2)` = W → 막힘
- 왼쪽 `(2,1)` = W → 막힘
- 오른쪽 `(2,3)` = W → 막힘
- 아래 `(3,2)` = 0 → **퍼진다**

완전히 못 가둔다. 4방향 중 3개만 막았기 때문.

```
확산 후:
  0  W  0  0
  W  2  W  0
  F  F  F  F
  F  F  F  1

안전 영역 = 3 (첫 행의 0 세 칸)
```

### 조합 ②: 아래를 막기 — `(2,1) (2,3) (3,2)` 에 벽
```
  0  0  0  0
  W  2  W  0
  0  W  0  0
  0  0  0  1
```
불의 4방향: 위 `(1,2)` = 0 → **퍼진다**

```
확산 후 (위쪽으로 전부 퍼짐):
  F  F  F  F
  W  2  W  F
  0  W  0  F
  0  0  0  1

안전 영역 = 5
```

### 조합 ③: 완전 봉쇄 — `(1,2) (2,1) (2,3)` + 아래도? → 3개로는 4방향을 다 못 막는다
불 하나를 완전히 가두려면 **4방향 모두** 막아야 하는데 벽이 3개뿐이다.
따라서 이 배치에서는 **불을 가둘 수 없고**, 최대한 좁은 영역으로 몰아넣는 조합이 답이 된다.

> **불이 격자 가장자리에 있으면** 막아야 할 방향이 3개나 2개로 줄어 가둘 수 있다.
> 조합마다 결과가 크게 달라지는 이유.

### `copyMap` 을 빼면
```
조합 ① 실행 후 tmpMAP 이 불로 가득
조합 ② 시작 → 빈 칸이 거의 없음
→ countEmpty() 가 계속 작은 값
→ maxAnswer 가 갱신 안 되고 답이 작아진다
```

## 6. 함정 / 예상 함정
- **★★ 조합마다 `copyMap(tmpMAP, MAP)` 누락.** 이 그룹 공통 최다 실수.
- **★★ 벽을 설치하기 전에 불을 큐에 넣음.** 순서상 문제는 없지만(벽과 불은 겹치지 않음), **벽 설치 → 불 수집** 순서를 지키는 게 안전하다.
- **★ `DFS(depth+1, i)` 로 씀** → 같은 칸에 벽을 두 번 세운다. **`i + 1`**.
- **★ 불이 여러 개인데 각각 BFS를 돌림.** **전부 큐에 넣고 한 번**. [G05 토마토](../G05/38_BOJ_7576_토마토.md).
- **★ 확산 조건을 `!= WALL` 로.** **`== 0`(빈 칸)** 만 확산 대상이다. 이미 불인 칸을 다시 넣으면 무한 삽입.
- **★ 안전 영역에 원래 벽(`1`)을 포함.** `0` 인 칸만 센다.
- **`maxAnswer` 초기값.** 최댓값이므로 `0`. 안전 영역은 항상 0 이상이라 안전하다.
- **빈 칸이 3개 미만인 경우** — 문제가 3개 이상을 보장한다. 아니면 `DFS` 가 종료 조건에 도달 못 해 답이 0.
- **T-loop 마다 `emptyCount`, `maxAnswer` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **무엇을 조합으로 고르는지**([바이러스 백신](2019상오후2_바이러스백신.md)과 반대) 구분하는가
- [ ] 빈 칸 후보를 수집해 **인덱스로 조합**을 고르는가
- [ ] `DFS(depth+1, i+1)`, `depth == 3` 인가
- [ ] `BFS()` 첫 줄에 **`copyMap` 초기화**를 넣었는가
- [ ] 벽 설치 → 불 수집 → 확산 **순서**를 지켰는가
- [ ] 불을 **전부 큐에 넣고 while 한 번** 도는가
- [ ] 확산 조건이 **`== 0`** 인가
- [ ] 이 문제는 왜 **"모두 퍼졌는가" 검증이 필요 없는지** 설명할 수 있는가

## 8. 한 줄 요약
