## 1. 문제 요약
N×N 격자에 각 칸의 값(인구/계란 수)이 주어진다.

**인접한 두 칸의 차이가 `[L, R]` 범위 안**이면 국경을 열어 **하나의 연합**으로 묶는다.
연합이 만들어지면 그 연합의 모든 칸을 **`연합 총합 / 연합 칸 수`** 로 갱신한다 (정수 나눗셈).

이 과정을 **더 이상 어떤 이동도 일어나지 않을 때까지** 반복하며, **총 몇 번의 이동(일)** 이 발생하는지 구한다.

## 2. 필요한 이론
→ [G08 — 반복 확산형](../../theory/G08_조합선택BFS.md)

> ### ⚠️ **이 문제는 G08의 다른 세 문제와 성격이 다르다.**
> **조합을 고르지 않는다.** 완전탐색이 아예 없다.
>
> | | 다른 G08 문제 | 토스트 계란틀 |
> |---|---|---|
> | 후보 선택 | 조합 `C(n, M)` | **없음** |
> | BFS 횟수 | 조합마다 1번 | **하루마다 여러 번** (연합 개수만큼) |
> | 종료 | 조합 소진 | **변화가 없을 때까지** |
> | 답 | 최소/최대 | **반복 횟수** |
>
> **G08에 묶인 이유는 "플러드필로 덩어리를 찾는다"는 공통점 때문**이다.
> 실제로는 [G05 34번 단지번호붙이기](../G05/34_BOJ_2667_단지번호붙이기.md)를 **매일 반복**하는 문제에 가깝다.

**핵심 골격 두 가지**
```
① 플러드필 (G05 ①) : 격자 전체를 훑어 연합(덩어리)을 전부 찾는다
② 변화 없을 때까지  : while (변화 있음) { 하루 처리; answer++ }
```

## 3. 코드 흐름
```
main()
 └ input()                  N, L, R, MAP
   answer = 0
   while (1):
      result = simulate()   ★ 하루 처리, 이동이 있었는지 반환
      if (!result) break    ★ 변화 없으면 종료
      answer++
   printf(answer)

simulate():
   visit 전체 초기화          ★ 하루마다
   result = false
   for r, c 전체:
      if (visit) continue
      size = BFS(r, c)       ★ 연합 하나 찾고 평균 갱신까지
      if (size != 1) result = true
   return result

BFS(r, c):
   시작 칸 큐 삽입, sum = MAP[r][c]
   while: 인접 차이가 [L,R]이면 연합에 포함, sum 누적
   큐에 담긴 모든 칸을 sum/wp 로 갱신     ★ 큐를 재활용
   return wp
```

## 4. 핵심 코드

### ★★ BFS가 "찾기 + 갱신"을 한 번에
```c
int BFS(int r, int c)
{
    int rp, wp;
    rp = wp = 0;

    queue[wp].r = r;
    queue[wp++].c = c;
    visit[r][c] = true;

    // 연합 총합 초기값 = 시작 칸 값
    int sum = MAP[r][c];

    while (rp < wp)
    {
        RC out = queue[rp++];

        for (int i = 0; i < 4; i++)
        {
            int nr = out.r + dr[i];
            int nc = out.c + dc[i];

            if (nr < 1 || nc < 1 || nr > N || nc > N) continue;

            // 현재 칸과 인접 칸의 차이 계산
            int diff = abs(MAP[out.r][out.c] - MAP[nr][nc]);

            // 이미 방문했거나, 차이가 [L, R] 범위를 벗어나면 연합에 포함 불가
            if (visit[nr][nc] == true || (L <= diff && diff <= R) == false)
                continue;

            queue[wp].r = nr;
            queue[wp++].c = nc;
            visit[nr][nc] = true;
            sum += MAP[nr][nc];         // ★ 넣으면서 합도 누적
        }
    }

    // BFS가 끝난 뒤, queue[0 .. wp-1] 에는 이번 연합의 모든 칸이 들어 있음
    // 이 칸들을 모두 평균값으로 갱신
    for (int i = 0; i < wp; i++)
    {
        RC tmp = queue[i];
        MAP[tmp.r][tmp.c] = sum / wp;   // ★ 정수 나눗셈
    }

    return wp;                          // 연합 크기
}
```

**★ 큐를 두 번 쓰는 것이 이 구현의 묘미다.**
1. 탐색 중에는 **작업 큐**로
2. 탐색이 끝나면 `queue[0 .. wp-1]` 이 **연합 멤버 목록**이 된다

`rp` 는 전진했지만 `queue` 배열 자체는 그대로 남아 있으므로, **다시 `0` 부터 훑어 갱신**할 수 있다.
별도 목록 배열이 필요 없다 — [G02 큐의 "전진만 한다"](../../theory/G02_스택큐덱.md) 성질을 역이용한 것.

> **`return wp` 가 연합 크기**인 것도 [G05 34번](../G05/34_BOJ_2667_단지번호붙이기.md)과 같다.

### ★ 인접 판정 — 두 칸의 차이
```c
int diff = abs(MAP[out.r][out.c] - MAP[nr][nc]);

if (visit[nr][nc] == true || (L <= diff && diff <= R) == false) continue;
```

**`MAP[out]` 과 비교하지 `MAP[시작칸]` 과 비교하지 않는다.**
연합은 **연쇄적으로** 이어진다 — A와 B가 이어지고 B와 C가 이어지면 A·B·C가 한 연합이다. A와 C의 차이는 상관없다.

> [G05 40번 성곽](../G05/40_BOJ_2234_성곽.md)의 "두 칸을 함께 보는 이동 판정"과 같은 계열.

### 하루 = 플러드필 한 바퀴
```c
bool simulate()
{
    // 방문 배열 초기화
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= N; c++)
            visit[r][c] = false;        // ★★ 하루마다 초기화

    bool result = false;

    for (int r = 1; r <= N; r++)
    {
        for (int c = 1; c <= N; c++)
        {
            if (visit[r][c] == true) continue;

            int moveEggCount = BFS(r, c);

            // 연합 크기가 2 이상이면 실제 이동이 발생한 것
            if (moveEggCount != 1) result = true;
        }
    }

    return result;
}
```

**★ 크기 1인 연합도 BFS를 돈다.** 혼자인 칸은 평균이 자기 자신이라 값이 안 변하고, `result` 도 `true` 가 안 된다.
`if (size != 1)` 로 **실제 이동이 있었는지** 판정하는 것이 종료 조건의 근거.

### ★ "변화 없을 때까지" 루프
```c
int answer = 0;

while (1)
{
    bool result = simulate();

    if (result == false) break;     // ★ 이번 날에 이동이 없었다면 종료

    answer++;
}
```

**`answer++` 를 `break` 뒤가 아니라 앞에** 두면 마지막 헛돈 날까지 세어 답이 1 커진다.
`simulate()` 를 먼저 돌리고 → 변화 없으면 즉시 종료 → 있으면 카운트, 순서가 정확하다.

### ⚠️ 왜 `tmpMAP` 이 없는가
다른 G08 문제는 `copyMap` 이 필수였다. **여기는 `MAP` 을 직접 갱신한다.**

- **조합이 없으므로** 되돌릴 이유가 없다. 상태가 계속 앞으로만 간다
- 연합마다 갱신하지만 **`visit` 이 이미 처리한 칸을 막아** 같은 날 두 번 갱신되지 않는다

> **★ 다만 "동시성"은 자동으로 보장된다.** 한 연합을 갱신해도 그 칸들은 `visit` 처리되어 그날 다시 안 본다.
> 아직 방문 안 한 칸들은 **아직 갱신되지 않은 원래 값**이므로, 순서가 결과에 영향을 주지 않는다.
> [회전하는 빙하](../G06/2020하오후2_회전하는빙하.md)처럼 판정/반영을 분리할 필요가 없는 이유.

## 5. 예제 손 추적 — `N=2, L=20, R=50`

```
초기      50  30
          20  40
```

### 1일차
`visit` 초기화 후 `(1,1)` 부터.

**BFS(1,1)** — 시작 `50`
```
(1,1)=50 의 이웃:
  (1,2)=30 → diff = |50-30| = 20  ∈ [20,50] ✓ → 연합 포함, sum = 80
  (2,1)=20 → diff = |50-20| = 30  ∈ [20,50] ✓ → 연합 포함, sum = 100

(1,2)=30 의 이웃:
  (2,2)=40 → diff = |30-40| = 10  ∉ [20,50] ✗

(2,1)=20 의 이웃:
  (2,2)=40 → diff = |20-40| = 20  ∈ [20,50] ✓ → 연합 포함, sum = 140
```
**연합 = 네 칸 전부**, `sum = 140`, `wp = 4` → 평균 `140 / 4 = 35`

```
갱신 후    35  35
           35  35
```
`size = 4 ≠ 1` → `result = true` → `answer = 1`

> **연쇄 판정 확인**: `(1,2)=30` 과 `(2,2)=40` 은 차이 10이라 직접 안 이어진다.
> 하지만 `(2,1)=20` 을 통해 `(2,2)` 가 들어왔다. **연쇄가 작동한 사례.**

### 2일차
```
현재      35  35
          35  35
```
모든 인접 차이가 `0` → `∉ [20, 50]` → **어느 칸도 연합을 못 만든다.**

`(1,1)` BFS → 크기 1
`(1,2)` BFS → 크기 1
`(2,1)` BFS → 크기 1
`(2,2)` BFS → 크기 1

전부 `size == 1` → `result = false` → **break**

```
출력   1
```

### `answer++` 위치 확인
```
1일차: simulate() = true  → answer = 1
2일차: simulate() = false → break         ★ answer 증가 안 함
```
2일차에도 `answer++` 를 했다면 답이 `2` 가 되어 틀린다.

### 정수 나눗셈 주의
`sum = 140`, `wp = 4` → `35` (딱 나눠떨어짐)
`sum = 100`, `wp = 3` → `33` (버림) — 문제가 버림을 요구한다.

## 6. 함정 / 예상 함정
- **★★ `visit` 을 하루마다 초기화 안 함.** 둘째 날부터 아무 연합도 못 찾아 즉시 종료한다. **가장 흔한 실수.**
- **★★ `answer++` 위치.** 변화가 없는 마지막 날을 세면 답이 1 커진다. **`simulate()` → 변화 없으면 break → 있으면 `answer++`.**
- **★ 인접 판정을 시작 칸과 비교.** `MAP[out]`(현재 칸)과 비교해야 **연쇄**가 성립한다.
- **★ 크기 1 연합을 이동으로 셈.** `size != 1` 조건이 있어야 한다. 없으면 무한 루프.
- **★ 평균을 실수로 계산.** 문제가 **정수 나눗셈(버림)** 을 요구한다.
- **★ 큐 재활용을 모르고 별도 목록 배열을 만듦.** `queue[0..wp-1]` 이 그대로 멤버 목록이다.
- **BFS 도중에 평균을 갱신.** 탐색이 **끝난 뒤** 한 번에 갱신해야 한다. 도중에 바꾸면 `diff` 계산이 오염된다.
- **무한 루프 위험.** 평균을 취하면 값이 수렴하므로 반드시 끝난다. 하지만 종료 조건이 틀리면 무한 루프 — 반복 횟수 상한을 두고 디버깅하면 안전하다.
- **T-loop 마다 초기화** — 이 코드는 `T = 1` 고정.

## 7. 백지 재현 체크리스트
- [ ] 이 문제가 **조합 완전탐색이 아님**을 알고, 왜 G08에 묶였는지 설명할 수 있는가
- [ ] **`visit` 을 하루마다 초기화**하는가
