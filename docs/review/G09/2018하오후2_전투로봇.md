## 1. 문제 요약
N×N 격자에 전투로봇과 몬스터들이 있다.

**이동·전투 규칙**
- 로봇은 **자신의 레벨보다 작은** 몬스터만 제거할 수 있다
- **같은 레벨**의 몬스터가 있는 칸은 **지나갈 수만** 있고 제거는 못 한다
- **더 큰 레벨**의 몬스터가 있는 칸은 **지나갈 수 없다**

**로봇 초기 상태**: 시작 위치는 `9` 로 표시된 칸, 레벨 `2`, 제거 수(`attack`) `0`

**레벨업**: 자기 레벨과 같은 수만큼 몬스터를 제거하면 레벨 +1, `attack` 리셋

**선택 우선순위**: 가장 가까운 몬스터 → 가장 위쪽 → 가장 왼쪽

더 이상 제거할 수 없을 때까지의 **총 이동 시간**을 구한다.

## 2. 필요한 이론
→ [G09 최단거리 BFS 반복 시뮬](../../theory/G09_BFS반복시뮬.md)

[자율주행 전기차](2020상오후2_자율주행자동차.md)와 같은 골격이다.
```
while (제거 가능한 몬스터가 있는 동안):
    BFS로 모든 칸까지의 거리 계산
    우선순위에 맞는 몬스터 하나 선택
    제거 + 이동 + 레벨 갱신
    시간 누적
```

> ### ★★ 이 문제의 배울 점: **동점 처리를 훨씬 단순하게 하는 방법**
>
> [자율주행 전기차](2020상오후2_자율주행자동차.md)는 BFS 안에서 `(거리, r, c)` **3중 조건 비교**를 했다.
> **이 문제는 BFS를 끝까지 돌린 뒤 격자를 `(r, c)` 순서로 스캔**한다.
>
> ```c
> for (r = 1..N)          // 위에서 아래로
>     for (c = 1..N)      // 왼쪽에서 오른쪽으로
>         if (visit[r][c] < minTime) { 갱신 }    // ★ 조건 하나만
> ```
> **스캔 순서 자체가 "위쪽 우선 → 왼쪽 우선"을 만든다.**
> 같은 거리라면 먼저 스캔된 것(= 더 위, 더 왼쪽)이 이미 `minTime` 에 들어가 있고,
> 나중 것은 `<` 가 아니라 `==` 이라 갱신되지 않는다.
>
> **조건 3개가 1개로 줄어든다.** 실수가 훨씬 적다 — **이 방식을 기본으로 삼을 것.**

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()            N, MAP, 로봇 위치(9) 찾기, level=2, attack=0
      answer = 0
      while (1):
         time = simulate()
         if (time == 0) break
         answer += time
      printf(answer)

simulate():
   if (제거 가능한 몬스터 없음) return 0
   BFS()                            ★ 모든 칸 거리 계산
   격자 스캔 → 우선순위 몬스터 선택
   if (없음) return 0
   몬스터 제거, 로봇 이동, 레벨 갱신
   return minTime - 1
```

## 4. 핵심 코드

### 조기 종료 판정
```c
bool monsterExists()
{
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= N; c++)
            if (MAP[r][c] != 0 && MAP[r][c] < battleRobot.level)
                return true;
    return false;
}
```
**"제거 가능한" 몬스터**만 센다. 레벨이 크거나 같은 몬스터는 있어도 소용없다.
BFS를 돌리기 전에 확인해 **불필요한 탐색을 건너뛴다.**

### ★ BFS — 통과 가능 조건이 핵심
```c
void BFS()
{
    // 방문 배열 초기화                      ★★ 매 턴 필수
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= N; c++)
            visit[r][c] = 0;

    int rp, wp;
    rp = wp = 0;

    queue[wp].r = battleRobot.r;
    queue[wp++].c = battleRobot.c;
    visit[battleRobot.r][battleRobot.c] = 1;

    while (rp < wp)
    {
        RC out = queue[rp++];

        for (int i = 0; i < 4; i++)
        {
            int nr = out.r + dr[i];
            int nc = out.c + dc[i];

            if (nr < 1 || nc < 1 || nr > N || nc > N) continue;

            // ★ 로봇보다 큰 몬스터가 있는 칸은 못 지나감
            if (battleRobot.level < MAP[nr][nc]) continue;

            if (visit[nr][nc] != 0) continue;

            queue[wp].r = nr;
            queue[wp++].c = nc;
            visit[nr][nc] = visit[out.r][out.c] + 1;
        }
    }
}
```

**★ `<` 하나로 세 규칙이 다 처리된다.**
```
MAP[nr][nc] == 0            빈 칸       → level < 0 거짓 → 통과 ✓
MAP[nr][nc] < level         작은 몬스터  → 거짓 → 통과 ✓ (나중에 제거 대상)
MAP[nr][nc] == level        같은 레벨    → 거짓 → 통과 ✓ (지나만 감)
MAP[nr][nc] > level         큰 몬스터    → 참  → 막힘 ✗
```
**"제거 가능"과 "통과 가능"은 다른 조건**이다. BFS는 통과만 신경 쓰고, 제거 판정은 나중에 한다.

### ★★ 우선순위 선택 — 스캔 순서가 곧 우선순위
```c
int tmpR, tmpC;
int minTime = INF;

// r을 작은 순서(위쪽), c를 작은 순서(왼쪽)로 탐색하므로
// 같은 거리라면 자동으로 "가장 위, 가장 왼쪽" 우선순위가 적용됨
for (int r = 1; r <= N; r++)
{
    for (int c = 1; c <= N; c++)
    {
        // 빈칸이거나 도달 못한 칸이면 제외
        if (MAP[r][c] == 0 || visit[r][c] == 0) continue;

        // 같은 레벨 이상은 제거 불가
        if (battleRobot.level <= MAP[r][c]) continue;

        // 더 가까운 몬스터 발견 시 갱신
        if (visit[r][c] < minTime)          // ★ 조건 하나
        {
            minTime = visit[r][c];
            tmpR = r;  tmpC = c;
        }
    }
}
```

**세 가지 필터가 순서대로 걸린다.**
1. `MAP == 0` → 빈 칸 제외
2. `visit == 0` → **도달 불가 칸 제외** (큰 몬스터에 막혀 갇힌 영역)
3. `level <= MAP` → **제거 불가** 몬스터 제외 (같은 레벨은 지나만 감)

그리고 `<` (`<=` 아님) 비교가 **먼저 스캔된 것을 유지**해 우선순위를 만든다.

> **`<=` 로 쓰면 나중 것(더 아래, 더 오른쪽)이 채택되어 정반대 우선순위**가 된다. 한 글자가 답을 가른다.

### 실패 판정
```c
// BFS는 갔지만 실제로 제거 가능한 몬스터가 하나도 없는 경우
if (minTime == INF) return 0;
```
`monsterExists()` 가 `true` 였어도 **그 몬스터에 도달 못 할 수** 있다 (큰 몬스터가 길을 막음).
이 검사가 없으면 `tmpR`, `tmpC` 가 초기화 안 된 채 쓰인다.

### 레벨업
```c
MAP[tmpR][tmpC] = 0;                    // 몬스터 제거 → 빈칸
battleRobot.r = tmpR;
battleRobot.c = tmpC;                   // 로봇 이동

battleRobot.attack++;

if (battleRobot.attack == battleRobot.level)
{
    battleRobot.level++;
    battleRobot.attack = 0;             // ★ 리셋
}

return minTime - 1;                     // 시작 1 오프셋
```

**`attack` 리셋을 빼먹으면** 레벨이 한 번만 오르고 멈춘다.

## 5. 예제 손 추적 — 우선순위와 통과 규칙

```
격자 (로봇 레벨 2, 위치 (2,2))

  .  1  .  4
  .  🤖 .  .        1, 2, 3 = 몬스터 레벨
  2  .  1  .        4 = 로봇보다 큰 몬스터 (통과 불가)
  .  .  .  .
```

### BFS 통과 판정
```
(1,2)=1  : level(2) < 1 ? 거짓 → 통과 ✓
(3,1)=2  : level(2) < 2 ? 거짓 → 통과 ✓ (같은 레벨, 지나만 감)
(1,4)=4  : level(2) < 4 ? 참  → 막힘 ✗
```

### 거리 계산 결과 (`visit`, 시작 1)
```
  2  2  3  ✗          ← (1,4)는 도달 불가 (visit = 0)
  2  1  2  3
  3  2  3  4
  4  3  4  5
```

### 몬스터 선택 스캔
```
r=1, c=2: MAP=1, visit=2, level(2) > 1 ✓ 제거 가능
          visit(2) < INF → 채택!  minTime=2, (1,2)

r=3, c=1: MAP=2, visit=3, level(2) <= 2 → ✗ 제거 불가 (같은 레벨)

r=3, c=3: MAP=1, visit=3, 제거 가능
          visit(3) < 2 ? 거짓 → 갱신 안 함

r=1, c=4: MAP=4, visit=0 → ✗ 도달 불가
```
**선택: `(1,2)` 몬스터**, 이동 시간 `2 - 1 = 1`

### 동점 상황 확인
```
  .  1  .  .
  .  🤖 .  .
  .  1  .  .        위아래로 같은 거리(1)의 몬스터 두 마리
```
`visit[1][2] = 2`, `visit[3][2] = 2` — **동점**

```
스캔 순서: r=1 먼저
  r=1, c=2: visit(2) < INF → 채택, minTime=2, (1,2)
  r=3, c=2: visit(2) < 2 ? 거짓 → 갱신 안 함
```
**위쪽 `(1,2)` 선택** ✓ — 규칙("가장 위쪽")과 일치.
**`<` 를 `<=` 로 바꾸면** `(3,2)` 가 채택되어 틀린다.

### 레벨업 추적
```
level=2, attack=0
  몬스터 1마리 제거 → attack=1
  attack(1) == level(2)? 아니오

  몬스터 1마리 더 제거 → attack=2
  attack(2) == level(2)? 예 → level=3, attack=0   ★ 레벨업

level=3
  3마리 제거해야 level=4
```
레벨이 오를수록 **필요한 마릿수도 늘어난다.**

## 6. 함정 / 예상 함정
- **★★ 매 턴 `visit` 초기화 누락.** 두 번째 턴부터 BFS가 아무것도 못 찾는다.
- **★★ 우선순위 비교를 `<=` 로.** 정반대 우선순위가 된다. **`<` 여야 먼저 스캔된 것(위·왼쪽)이 유지된다.**
- **★★ "통과 가능"과 "제거 가능"을 같은 조건으로.** 통과는 `level >= MAP`, 제거는 `level > MAP`. **같은 레벨은 지나만 간다.**
- **★ `visit == 0`(도달 불가) 검사 누락.** 큰 몬스터에 막힌 몬스터를 선택하면 이동이 불가능하다.
- **★ `minTime == INF` 검사 누락.** `monsterExists()` 만으로는 부족하다 — 도달 가능성은 별개.
- **★ `attack` 리셋 누락.** 레벨이 한 번만 오른다.
- **★ 로봇 시작 칸(`9`)을 몬스터로 처리.** 입력 시 `MAP[r][c] = 0` 으로 바꾸고 로봇 위치만 기록해야 한다.
- **`minTime - 1` 오프셋.** 시작을 1로 뒀으므로.
- **T-loop 마다 `battleRobot`, `answer` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **BFS로 거리 계산 → 격자 스캔으로 선택** 2단 구조를 쓸 수 있는가
- [ ] **스캔 순서가 곧 우선순위**임을 이해하고 `<` 를 쓰는가
- [ ] BFS 통과 조건이 **`level < MAP` 이면 막힘**(같은 레벨은 통과)인가
- [ ] 제거 조건이 **`level > MAP`** 인가 (통과 조건과 다름)
- [ ] `visit == 0`(도달 불가) 필터를 넣었는가
- [ ] `minTime == INF` 실패 판정을 넣었는가
- [ ] 레벨업 시 **`attack` 리셋**을 하는가
- [ ] 매 턴 `visit` 초기화를 하는가
- [ ] [자율주행 전기차](2020상오후2_자율주행자동차.md)의 3중 조건 방식과 **이 방식의 차이**를 설명할 수 있는가
