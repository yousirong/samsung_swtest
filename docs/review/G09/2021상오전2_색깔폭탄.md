## 1. 문제 요약
N×N 격자에 폭탄이 있다. 값의 의미:

| 값 | 의미 |
|---|---|
| `-1` (`BLACK`) | 검은 폭탄 — 움직이지 않고 묶이지도 않음 (벽 역할) |
| `0` (`RED`) | 빨간 폭탄 — **어떤 색 묶음에도 들어갈 수 있는 만능** |
| `1` 이상 | 색깔 폭탄 (색 번호) |
| `-2` (`EMPTY`) | 빈 칸 |

**한 턴**
1. **가장 우선순위 높은 폭탄 묶음**을 찾는다 (크기 2 이상)
2. 그 묶음을 터뜨리고 **`묶음 크기²` 점수** 획득
3. **중력** — 폭탄이 아래로 떨어진다
4. **격자 반시계 90도 회전**
5. **중력** 한 번 더

더 이상 터뜨릴 묶음이 없을 때까지 반복하며 **총점**을 구한다.

**우선순위**: 크기 큰 것 → **빨간 폭탄 적은 것** → 행 큰 것(아래쪽) → 열 작은 것(왼쪽)

## 3. 코드 흐름
```
main()
 └ input()               N, M, MAP (테두리는 BLACK으로 초기화)
   printf(simulate())

simulate():
   score = 0
   while (1):
      모든 칸에서 BFS(r, c) → 묶음 정보 수집
      우선순위로 최선 묶음 선택
      if (없음) break
      score += 크기²
      deleteBomb(선택 묶음)      ★ BFS 한 번 더 (이번엔 지우기)
      bombDown()                 중력
      rotate()                   반시계 90도
      bombDown()                 중력
   return score
```

## 4. 핵심 코드

### 입력 — 테두리를 `BLACK` 으로
```c
void input()
{
    scanf("%d %d\n", &N, &M);

    // ★ 테두리 전체를 BLACK(-1)로 채운다
    for (int r = 0; r <= N + 1; r++)
        for (int c = 0; c <= N + 1; c++)
            MAP[r][c] = BLACK;

    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= N; c++)
            scanf("%d", &MAP[r][c]);
}
```

**`BLACK` 이 sentinel 역할**을 한다. BFS의 첫 조건이 `== BLACK` 이면 `continue` 이므로 **범위 체크가 통째로 사라진다.**
[G05 테두리 sentinel](../../theory/G05_그리드탐색심화.md)의 응용 — 마침 벽 역할을 하는 값이 이미 있어서 깔끔하다.

### ★★ BFS ① — 묶음 정보 수집 (지우지 않음)
```c
struct BOMB
{
    int total;   // 전체 폭탄 개수
    int red;     // 빨간 폭탄 개수
    int r;       // 행
    int c;       // 열
};

BOMB BFS(int r, int c)
{
    bool visit[MAX][MAX] = { 0 };      // ★ 지역 배열 — 매 호출 자동 초기화
    BOMB selectedBomb = { 0 };

    selectedBomb.total = 1;
    selectedBomb.r = r;
    selectedBomb.c = c;

    int bomb = MAP[r][c];              // ★ 이 묶음의 "기준 색"

    queue[wp].r = r;  queue[wp++].c = c;
    visit[r][c] = true;

    while (rp < wp)
    {
        RC out = queue[rp++];

        for (int i = 0; i < 4; i++)
        {
            int nr = out.r + dr[i];
            int nc = out.c + dc[i];

            if (MAP[nr][nc] == BLACK || visit[nr][nc] == true) continue;

            // ★★ 같은 색이거나 빨간 폭탄이면 묶음에 포함
            if (MAP[nr][nc] == bomb || MAP[nr][nc] == RED)
            {
                queue[wp].r = nr;  queue[wp++].c = nc;
                visit[nr][nc] = true;

                selectedBomb.total++;
                if (MAP[nr][nc] == RED) selectedBomb.red++;
            }
        }
    }

    return selectedBomb;
}
```

**★ 빨간 폭탄(`RED = 0`)이 만능이라는 것이 이 문제의 핵심 규칙**이다.
```c
if (MAP[nr][nc] == bomb || MAP[nr][nc] == RED)
```
기준 색과 같거나, **빨간색이면 무조건** 묶인다.

> ⚠️ **기준 색 `bomb` 은 시작 칸의 값으로 고정**된다. 빨간 폭탄을 타고 넘어가도 기준은 안 바뀐다.
> 그래서 `simulate()` 이 **빨간 폭탄에서는 BFS를 시작하지 않는다** — 기준 색이 `RED` 가 되어버리면 의미가 이상해지기 때문.

`visit` 이 **지역 배열 `{0}`** 이라 매 호출 자동 초기화된다. 격자 전체에서 BFS를 `N²` 번 호출하므로 이게 중요하다.

### ★ 우선순위 비교
```c
// a가 우선순위가 더 높으면 true
bool isPriority(BOMB a, BOMB b)
{
    if (a.total != b.total) return a.total > b.total;   // ① 큰 묶음
    if (a.red   != b.red)   return a.red   < b.red;     // ② 빨간 폭탄 적은 것
    if (a.r     != b.r)     return a.r     > b.r;       // ③ 아래쪽 (행 큰 것)
    return a.c < b.c;                                    // ④ 왼쪽 (열 작은 것)
}
```

**비교 방향이 항목마다 다르다.**
| 항목 | 방향 | 이유 |
|---|---|---|
| `total` | **크게** `>` | 큰 묶음이 점수가 높다 |
| `red` | **작게** `<` | 빨간 폭탄을 아껴야 나중에 유리 |
| `r` | **크게** `>` | "아래쪽" 우선 |
| `c` | **작게** `<` | "왼쪽" 우선 |

> **[전투로봇](2018하오후2_전투로봇.md)과 달리 스캔 순서로는 해결이 안 된다.** 항목마다 방향이 뒤섞여 있기 때문.
> **비교 함수를 따로 빼는 것**이 정답 — 조건이 4개나 되면 인라인으로 쓰다가 반드시 틀린다.

### 우선순위 초기값 — 방향에 맞춰 반대로
```c
BOMB selectedBomb = { 0 };
selectedBomb.red = selectedBomb.c = INF;    // 작은 것이 이기므로 크게 시작
selectedBomb.total = selectedBomb.r = -1;   // 큰 것이 이기므로 작게 시작
```

**네 필드를 각각 반대 방향으로 초기화**한다. 하나라도 틀리면 첫 후보가 채택되지 않거나 잘못 채택된다.
`selectedBomb.total == -1` 이 "아직 아무것도 못 찾음"의 판정으로도 쓰인다.

### 후보 스캔 — 어디서 BFS를 시작하는가
```c
for (int r = 1; r <= N; r++)
{
    for (int c = 1; c <= N; c++)
    {
        // ★ BLACK, RED, EMPTY 에서는 시작하지 않는다
        if (MAP[r][c] == BLACK || MAP[r][c] == RED || MAP[r][c] == EMPTY) continue;

        BOMB tmp = BFS(r, c);

        if (tmp.total == 1) continue;          // ★ 크기 1은 터뜨릴 수 없다

        if (isPriority(tmp, selectedBomb) == true)
            selectedBomb = tmp;
    }
}

if (selectedBomb.total == -1) break;           // 더 터뜨릴 게 없으면 종료
```

**시작점을 색깔 폭탄(`≥ 1`)으로 제한**하는 것이 중요하다.
- `RED` 에서 시작하면 기준 색이 `RED` 가 되어 규칙이 깨진다
- `BLACK`/`EMPTY` 는 묶음이 아니다

> ⚠️ **같은 묶음을 여러 번 BFS 한다.** 크기 5짜리 묶음이면 그 안의 색깔 폭탄 개수만큼 BFS가 돈다.
> 답은 같지만 낭비다. `visit` 을 바깥에 두면 줄일 수 있으나, **빨간 폭탄이 여러 묶음에 걸치므로** 단순히 공유하면 틀린다.
> **비효율을 감수하고 정확성을 택한 구현.**

### ★★ BFS ② — 실제로 지우기
```c
void deleteBomb(int r, int c)   // BFS
{
    ...
    bomb = MAP[r][c];
    MAP[r][c] = EMPTY;          // ★ 시작 칸부터 지운다
    ...
        if (MAP[nr][nc] == bomb || MAP[nr][nc] == RED)
        {
            큐 삽입; visit 표시;
            MAP[nr][nc] = EMPTY;    // ★ 지우면서 진행
        }
}
```

**`BFS()` 와 거의 같은 코드지만 세는 대신 지운다.**
합칠 수도 있지만(플래그 인자), **두 개로 나눈 편이 읽기 쉽다** — 탐색 단계에서 격자를 바꾸면 안 되기 때문.

> **★ 지우는 순서가 중요하다.** `MAP[nr][nc] = EMPTY` 를 **큐에 넣으면서** 한다.
> 나중에 몰아서 지우려면 멤버 목록이 필요한데, 이 구현은 즉시 지워서 그럴 필요가 없다.
> ([토스트 계란틀](../G08/2018하오전2_토스트계란틀.md)은 평균을 내야 해서 목록이 필요했다 — 목적에 따라 다르다.)

### 중력 — 아래로 몰기
```c
void bombDownColumn(int col)
{
    for (int r = N; r >= 1; r--)          // ★ 아래에서 위로 훑는다
    {
        if (MAP[r][col] == BLACK || MAP[r][col] == EMPTY) continue;

        int sr = r;
        while (1)
        {
            if (MAP[sr + 1][col] != EMPTY) break;   // 아래가 비어있지 않으면 정지

            // 한 칸 아래로 swap
            int tmp = MAP[sr][col];
            MAP[sr][col] = MAP[sr + 1][col];
            MAP[sr + 1][col] = tmp;

            sr++;
        }
    }
}

void bombDown()
{
    for (int col = 1; col <= N; col++)
        bombDownColumn(col);
}
```

**세 가지 포인트**
1. **아래에서 위로** 훑는다 (`r = N; r >= 1; r--`). 위에서부터 하면 아래 칸이 아직 안 정리돼 있다
2. **`BLACK` 은 안 움직인다** — 검은 폭탄은 고정
3. **열마다 독립** 처리 — [G07 2048](../G07/2016하2_2048게임.md)과 같은 구조

> ⚠️ **원본 코드에 중복 조건이 있다.**
> ```c
> if (MAP[sr + 1][col] != EMPTY) break;
> if (MAP[sr + 1][col] == EMPTY) { swap }    // ← 위에서 break 했으므로 항상 참
> ```
> 두 번째 `if` 는 **항상 참**이라 없어도 된다. 동작에는 문제없지만 **읽기 어렵게 만든다.**
> 재작성 시 두 번째 `if` 를 빼는 게 좋다.

**테두리가 `BLACK`** 이라 `MAP[N+1][col]` 이 `BLACK` 이고, `!= EMPTY` 라서 자동으로 바닥에서 멈춘다. sentinel의 이점.

### 반시계 90도 회전
```c
void rotate()   // 반시계 방향 회전
{
    int tmpMAP[MAX][MAX] = { 0 };
    copyMap(tmpMAP, MAP);

    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= N; c++)
            MAP[r][c] = tmpMAP[c][N - r + 1];
}
```
[G01 14번](../G01/14_BOJ_16935_배열돌리기3.md)의 반시계 공식 `temp[c][N+1-r]` 그대로.
정사각형이라 `N ↔ M` swap 이 필요 없다.

## 5. 예제 손 추적

### 빨간 폭탄의 만능 성질
```
격자 (기준: 시작 칸 (1,1) = 색 1)

  1  0  2          0 = RED (만능), -1 = BLACK
  2  1  0
```
`BFS(1,1)` — 기준 색 `bomb = 1`
```
(1,1)=1 시작, total=1
  (1,2)=0 = RED  → 포함 ✓  total=2, red=1
  (2,1)=2        → bomb(1)도 아니고 RED도 아님 → 제외

(1,2)=0 의 이웃:
  (1,3)=2        → 제외
  (2,2)=1 = bomb → 포함 ✓  total=3
```
**묶음 = `{(1,1), (1,2), (2,2)}`, `total=3`, `red=1`**

> `(1,2)` 의 빨간 폭탄이 **다리 역할**을 해서 떨어져 있는 두 개의 `1` 을 이어줬다.
> 이게 이 문제의 핵심 규칙이다.

### 우선순위 비교
```
후보 A: total=4, red=2, r=3, c=1
후보 B: total=4, red=1, r=2, c=5

isPriority(A, B):
  total 같음 (4 == 4)      → 다음
  red 다름  (2 != 1)       → return 2 < 1 = false

→ B가 우선   ★ 빨간 폭탄이 적은 쪽
```

```
후보 C: total=4, red=1, r=5, c=3
후보 B: total=4, red=1, r=2, c=5

isPriority(C, B):
  total 같음, red 같음     → 다음
  r 다름 (5 != 2)          → return 5 > 2 = true

→ C가 우선   ★ 아래쪽
```

### 한 턴 전체
```
① 묶음 선택 (total=3) → score += 9

② deleteBomb → 해당 칸들이 EMPTY

③ bombDown  → 위 폭탄이 아래로

④ rotate    → 격자 반시계 90도

⑤ bombDown  → 회전 후 다시 중력
```

> **★ 중력을 두 번 부르는 것**에 주의. 회전 전후 각각 필요하다.
> 회전하면 "아래" 방향이 바뀌므로 다시 떨어뜨려야 한다. 한 번만 부르면 공중에 뜬 폭탄이 남는다.

## 6. 함정 / 예상 함정
- **★★ 빨간 폭탄(`RED`)에서 BFS를 시작함.** 기준 색이 `RED` 가 되어 규칙이 깨진다. **색깔 폭탄(`≥1`)에서만 시작.**
- **★★ 우선순위 비교 방향을 섞음.** `total` 크게 / `red` **작게** / `r` 크게 / `c` 작게. **비교 함수로 빼서 관리.**
- **★★ 우선순위 초기값을 한 방향으로.** 네 필드를 **각각 반대로** 초기화해야 한다.
- **★★ 중력을 한 번만 호출.** 회전 **전후 두 번** 필요하다.
- **★ 중력을 위에서 아래로 훑음.** **아래에서 위로**(`r = N; r >= 1; r--`) 해야 한다.
- **★ 크기 1 묶음을 터뜨림.** `total == 1` 이면 `continue`.
- **★ `BLACK` 을 중력으로 움직임.** 검은 폭탄은 고정이다.
- **★ 회전 방향 착각.** 반시계다. `tmpMAP[c][N-r+1]`. 시계로 쓰면 전부 어긋난다.
- **`visit` 을 전역으로 두고 초기화 안 함.** `N²` 번 BFS를 도는데 지역 배열이 안전하다.
- **같은 묶음을 여러 번 BFS 하는 비효율** — 답은 맞지만 알아둘 것.
- **점수가 `크기²`** — 그냥 크기가 아니다.
- **`bombDownColumn` 의 중복 `if`** — 동작엔 무해하나 재작성 시 제거.

## 7. 백지 재현 체크리스트
- [ ] **빨간 폭탄이 만능**이고 **기준 색은 시작 칸 값으로 고정**임을 아는가
- [ ] BFS 시작점을 **색깔 폭탄(`≥1`)으로 제한**했는가
- [ ] 우선순위 4항목의 **방향**(크게/작게)을 정확히 쓰는가
- [ ] 우선순위 **초기값을 각각 반대 방향**으로 잡았는가
- [ ] **BFS 두 개**(세기 / 지우기)로 나눴는가
- [ ] 중력이 **아래에서 위로** 훑는가, `BLACK` 을 건너뛰는가
- [ ] **중력 → 회전 → 중력** 순서로 두 번 호출하는가
- [ ] 회전이 **반시계**(`tmpMAP[c][N-r+1]`)인가
- [ ] 점수가 **크기²** 인가
- [ ] 크기 1 묶음을 제외하는가

## 8. 한 줄 요약
"**빨간 폭탄이 다리 역할**을 하는 플러드필 + **4항목 우선순위 비교 함수** + **중력·회전·중력.** 새 이론은 하나도 없다."
