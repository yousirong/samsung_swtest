## 1. 문제 요약
N×N 격자에서 전기차가 **M명의 승객**을 목적지까지 데려다준다. 초기 배터리는 `C`.

**진행 규칙**
1. 아직 도착하지 않은 승객 중 **가장 가까운 승객**을 찾는다
2. **거리가 같으면 행 번호가 작은 승객, 그래도 같으면 열 번호가 작은 승객**
3. 승객 출발지까지 이동하면 그 거리만큼 배터리 소모
4. 목적지까지 이동하면 그 거리만큼 소모하지만, **도착 성공 시 이동 거리의 2배가 충전**
5. 모든 승객을 데려다주면 남은 배터리 출력
6. 배터리 부족하거나 도달 불가면 `-1`

## 2. 필요한 이론
→ [G09 최단거리 BFS 반복 시뮬](../../theory/G09_BFS반복시뮬.md)

**완전탐색이 없다.** 대신 **매 턴 BFS를 다시 돌린다.**

```
for 승객 M명:
    BFS ① 가장 가까운 승객 찾기      (차 위치에서)
    BFS ② 그 승객의 목적지까지 거리  (승객 출발지에서)
    배터리 갱신, 차 위치 갱신
```

**BFS를 두 번 쓰는 구조**가 이 문제의 골격이다. [G05 36번 미로 탐색](../G05/36_BOJ_2178_미로탐색.md)의 거리 누적을 **`2M` 번 반복**하는 셈.

> ### ★★ 이 그룹의 핵심 함정: 동점 처리
> "거리가 같으면 행이 작은 것, 그래도 같으면 열이 작은 것"
>
> **큐에서 먼저 나온 것을 채택하면 틀린다.** 큐 순서는 `dr/dc` 배열 순서에 의존하기 때문.
> 반드시 **`(거리, r, c)` 사전순 비교**를 명시적으로 해야 한다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()            N, M, C, MAP, car, people[]
      printf(simulate())

simulate():
   for i in 1..M:
      info = findPeople()                 ★ BFS ①
      if (승객 없음 or 배터리 부족) return -1
      C -= info.distance
      차를 승객 출발지로 이동
      dist = goToDestination(목적지)      ★ BFS ②
      if (도달 불가 or 배터리 부족) return -1
      C -= dist;  C += dist * 2           순소득 +dist
      차를 목적지로 이동, 승객 완료 표시
   return C
```

## 4. 핵심 코드

### ★★ BFS ① — 가장 가까운 승객 찾기
```c
INFO findPeople()
{
    // visit 초기화                          ★★ 매 턴 필수
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= N; c++)
            visit[r][c] = 0;

    // tmpMAP에 기본 MAP 복사
    for (int r = 0; r <= N + 1; r++)
        for (int c = 0; c <= N + 1; c++)
            tmpMAP[r][c] = MAP[r][c];

    // 아직 태우지 않은 승객들의 출발 위치를 tmpMAP에 승객 번호로 표시
    for (int i = 1; i <= M; i++)
    {
        if (people[i].check == true) continue;

        tmpMAP[people[i].sr][people[i].sc] = i;    // ★ 승객 번호를 격자에 박는다

        // 전기차가 이미 승객 출발지 위에 있는 경우 → 거리 0
        if (people[i].sr == car.r && people[i].sc == car.c)
        {
            INFO result = { i, 0 };
            return result;                          // ★ 조기 반환
        }
    }
    ...
}
```

**설계 포인트 두 가지**

**① 승객 위치를 `tmpMAP` 에 번호로 표시.**
BFS 중에 `tmpMAP[nr][nc] != 0` 이면 "승객 출발지이고 그 값이 승객 번호"가 된다.
승객 목록을 따로 순회하며 거리를 재는 것보다 **BFS 한 번으로 끝난다.**

**② 차가 이미 승객 위에 있는 경우 조기 반환.**
BFS는 **시작 칸 자신을 검사하지 않는다** (이웃만 본다). 그래서 거리 0인 경우를 놓친다.
이 예외 처리가 없으면 발밑의 승객을 못 태운다.

### ★★ 동점 처리 — 사전순 비교
```c
int minDistance = INF;
int minR = INF, minC = INF;
int peopleNumber = -1;

while (rp < wp)
{
    RC out = queue[rp++];

    for (int k = 0; k < 4; k++)
    {
        int nr = out.r + dr[k];
        int nc = out.c + dc[k];

        if (tmpMAP[nr][nc] == -1 || visit[nr][nc] != 0) continue;

        queue[wp].r = nr;
        queue[wp++].c = nc;
        visit[nr][nc] = visit[out.r][out.c] + 1;

        // tmpMAP[nr][nc] != 0 이면 승객 출발지
        if (tmpMAP[nr][nc] != 0)
        {
            // ★ 거리, 행, 열 기준으로 더 우선인 승객 선택
            if ((visit[nr][nc] < minDistance)
                || (visit[nr][nc] == minDistance && nr < minR)
                || (visit[nr][nc] == minDistance && nr == minR && nc < minC))
            {
                peopleNumber = tmpMAP[nr][nc];
                minDistance  = visit[nr][nc];
                minR = nr;  minC = nc;
            }
        }
    }
}

// visit은 시작점을 1로 저장했으므로 실제 거리는 -1
INFO result = { peopleNumber, minDistance - 1 };
```

**세 조건이 사전순 `(거리, r, c)` 비교를 구현한다.**
```
거리가 더 작다                              → 채택
거리가 같고 행이 더 작다                     → 채택
거리가 같고 행도 같고 열이 더 작다            → 채택
```

> **★ BFS를 끝까지 돌린다.** 승객을 찾자마자 멈추지 않는다.
> 같은 거리에 승객이 여러 명 있을 수 있으므로, **그 거리의 모든 승객을 봐야** 우선순위를 정할 수 있다.
>
> 대안: BFS를 끝까지 돌린 뒤 **격자 전체를 스캔**하며 `(visit, r, c)` 최소를 찾는 방법. 더 단순하고 실수가 적다.

### `-1` 반환 규약
```c
INFO result = { peopleNumber, minDistance - 1 };
```
승객을 못 찾으면 `peopleNumber = -1`, `minDistance = INF` 그대로다.
호출부에서 `peopleNumber == -1` 로 실패를 판정한다.

### BFS ② — 목적지까지
```c
int goToDestination(int er, int ec)
{
    // 도달 가능하면 최단거리, 도달 불가능하면 -1
    ...
}
```
평범한 격자 BFS. **`visit` 초기화를 또 해야 한다** — 같은 배열을 재사용하므로.

### 배터리 규칙
```c
C -= info.distance;        // 승객까지 이동
if (C < 0) return -1;

C -= dist;                 // 목적지까지 이동
if (C < 0) return -1;
C += dist * 2;             // 성공 시 2배 충전  →  순소득 +dist
```

**순서가 중요하다.** 소모를 먼저 하고 **음수 검사**를 한 뒤 충전한다.
충전을 먼저 하면 중간에 배터리가 바닥나는 케이스를 놓친다.

## 5. 예제 손 추적 — 동점 처리

```
격자 (차 = 🚗, 승객 출발지 = 숫자)

  .  .  1  .
  .  🚗 .  .
  .  .  2  .
  .  .  .  .
```
차는 `(2,2)`. 승객 1은 `(1,3)`, 승객 2는 `(3,3)`.

**거리 계산**
```
(2,2) → (1,3) : |1-2| + |3-2| = 2
(2,2) → (3,3) : |3-2| + |3-2| = 2
```
**동점이다.** 규칙 2에 따라 **행 번호가 작은** 승객 1(`r=1`)을 선택해야 한다.

### 사전순 비교가 어떻게 작동하는가
BFS가 거리 2인 칸들을 훑는 순서는 `dr/dc` 배열 순서에 달려 있다. 승객 2를 먼저 발견했다고 하자.

```
승객 2 발견: visit = 3 (시작 1 + 거리 2)
  minDistance = INF → 첫 조건 (3 < INF) 참 → 채택
  peopleNumber = 2, minR = 3, minC = 3

승객 1 발견: visit = 3, nr = 1, nc = 3
  조건 ①: 3 < 3        → 거짓
  조건 ②: 3 == 3 && 1 < 3  → 참 ✓ → 채택
  peopleNumber = 1, minR = 1, minC = 3
```

**최종 선택: 승객 1** ✓

> **먼저 발견한 것을 채택하는 방식이었다면** 승객 2가 선택되어 **틀린 답**이 나온다.
> 이 예제가 정확히 그 함정을 보여준다.

### 발밑 승객 케이스
```
  .  .  .  .
  .  🚗 .  .        차가 승객 3의 출발지 위에 있음
  .  .  .  .
```
BFS는 `(2,2)` 의 **이웃만** 검사하므로 `(2,2)` 자신은 절대 안 본다.
→ 조기 반환 `INFO result = { i, 0 }` 이 없으면 **이 승객을 영영 못 태운다.**

### 배터리 추적 — `C = 10`, 승객까지 2, 목적지까지 3
```
C -= 2   →  C = 8      (승객까지 이동)
C >= 0 ✓

C -= 3   →  C = 5      (목적지까지 이동)
C >= 0 ✓
C += 6   →  C = 11     (3 × 2 충전)
```
**순소득 `+3`** (이동 거리만큼 이득). 배터리가 늘어나는 구조라 M명을 다 태울 수 있는 경우가 많다.

**중간 바닥 케이스**: `C = 2`, 승객까지 2, 목적지까지 3
```
C -= 2   →  C = 0      ✓ (0은 허용)
C -= 3   →  C = -3     ✗  →  return -1
```
충전을 먼저 했다면 `0 + 6 - 3 = 3` 으로 통과해 **틀린 답**이 나온다.

## 6. 함정 / 예상 함정
- **★★ 동점을 큐 순서로 처리.** `(거리, r, c)` 사전순 비교를 명시해야 한다. **이 그룹 최다 실수.**
- **★★ 매 턴 `visit` 초기화 누락.** 두 번째 승객부터 BFS가 아무것도 못 찾는다. `findPeople()` 과 `goToDestination()` **양쪽 모두**.
- **★★ 차가 승객 위에 있는 경우(거리 0) 누락.** BFS는 시작 칸을 검사하지 않는다.
- **★ 배터리 검사 순서.** 소모 → 음수 검사 → 충전. 충전을 먼저 하면 중간 바닥을 놓친다.
- **★ 승객을 찾자마자 BFS 중단.** 같은 거리의 다른 승객을 못 본다. **끝까지 돌린다.**
- **★ `minDistance - 1` 오프셋.** 시작을 1로 뒀으므로.
- **도달 불가와 거리 0 혼동.** `goToDestination` 이 `-1` 을 반환하는지 `0` 을 반환하는지 규약을 명확히.
- **`tmpMAP` 에 승객 번호를 박을 때 `0` 번 승객이 없어야 한다.** 승객 번호를 **1부터** 시작해야 `!= 0` 판정이 성립한다.
- **T-loop 마다 `people[].check`, `car`, `C` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **BFS 두 번**(승객 찾기 / 목적지까지) 구조를 쓸 수 있는가
- [ ] **매 턴 `visit` 초기화**를 양쪽 BFS에 넣었는가
- [ ] 동점 처리를 **`(거리, r, c)` 사전순 비교**로 명시했는가
- [ ] **차가 승객 위에 있는 경우**를 조기 반환으로 처리했는가
- [ ] 승객 위치를 `tmpMAP` 에 **번호로 표시**하고 `!= 0` 으로 판정하는가 (번호는 1부터)
- [ ] 배터리를 **소모 → 검사 → 충전** 순서로 처리하는가
- [ ] BFS를 **끝까지** 돌리는가
- [ ] `minDistance - 1` 오프셋을 넣었는가

## 8. 한 줄 요약
"**매 턴 BFS 두 번.** 동점은 반드시 **`(거리, 행, 열)` 사전순**으로, 배터리는 **소모 → 검사 → 충전.**"
