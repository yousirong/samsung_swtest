## 1. 문제 요약
| 문제 | 내용 |
|---|---|
| **15649** N과 M(1) | `1 ~ N` 중 **서로 다른** M개를 골라 만든 수열 (순서 O) |
| **15654** N과 M(5) | `1~N` 대신 **입력값** 사용. 나머지 동일 |
| **15663** N과 M(9) | 입력에 **같은 값이 여러 번** 들어올 수 있음. 같은 수열은 한 번만 출력 ★ |

## 2. 필요한 이론
→ [G04 경우의 수 — 순열의 `visit`](../../theory/G04_경우의수.md)

| 축 | 값 |
|---|---|
| 순서 | **O** |
| 중복 | **X** |

순서를 구분하므로 `start` 를 쓸 수 없다(범위는 항상 `1..N`). 중복만 막아야 하는데, 그 도구가 **`visit` 배열**이다.

> **★★ 그리고 `visit` 은 반드시 되돌린다.**
> 이것이 [G03 DFS](../../theory/G03_DFS_BFS기초.md)와의 결정적 차이다.
> - **연결 요소 탐색(G03)**: 되돌리지 **않는다**. 한 번 방문하면 끝
> - **백트래킹(G04)**: 되돌린다. 다른 가지에서 그 숫자를 다시 써야 하므로
>
> 같은 `DFS` 라는 이름이지만 하는 일이 정반대다.

15663은 여기에 한 겹이 더 붙는다 → **`visit` 이 bool 에서 카운터로 승격**된다.

## 3. 코드 흐름
```
15649 / 15654
main() └ scanf(N, M) → (15654는 입력 + 정렬) → DFS(0)

DFS(depth):
   if (depth == M) { printCases(); return; }
   for i in 1..N:                    ★ start 없음, 항상 1부터
      if (visit[i]) continue;
      num_of_cases[depth] = i
      visit[i] = true
      DFS(depth + 1)
      visit[i] = false               ★★ 되돌림

15663
main() └ 값별 개수(possible[]) 집계 + 서로 다른 값만 number[]에 + 정렬 → DFS(0)
```

## 4. 핵심 코드

### 15649 — `visit` 되돌림
```c
bool visit[MAX];         // 숫자 i를 이미 사용했는지 표시

void DFS(int depth)
{
    if (depth == M) { printCases(); return; }

    for (int i = 1; i <= N; i++)
    {
        // 이미 사용한 숫자는 건너뜀
        if (visit[i] == true) continue;

        num_of_cases[depth] = i;
        visit[i] = true;             // 사용 처리

        DFS(depth + 1);

        visit[i] = false;            // ★★ 백트래킹: 사용 해제
    }
}
```

**`visit[i] = false` 를 빼면 어떻게 되는가**: 한 번 쓴 숫자가 영영 막힌다.
`N=4, M=2` 에서 `1 2` 를 만든 뒤 `1`, `2` 가 계속 막혀 있어 `1 3` 조차 못 만든다. **출력이 몇 줄 나오다 끝난다.**

### 15654 — 입력값 + 정렬
```c
// 단, 현재 자리에 i가 아니라 number[i]를 넣는다.
num_of_cases[depth] = number[i];
```
`visit[i]` 는 여전히 **인덱스 기준**이다(값 기준이 아님). 정렬은 사전순 출력을 위해 필요하다.

### ★ 15663 — `visit` 을 카운터로 승격
입력에 `9 7 9` 처럼 같은 값이 섞여 있고, **같은 수열을 두 번 출력하면 안 된다.**

문제는 `9` 가 두 개라는 것이다. `9 9` 는 출력해야 하지만, 첫 번째 `9` 와 두 번째 `9` 를 각각 쓴 `9 7` 두 가지는 하나로 합쳐야 한다.

**처방: 서로 다른 값만 남기고, 값마다 "몇 개까지 쓸 수 있는지"를 센다.**

```c
int possible[MAX];    // 이 값이 입력에 몇 개 있는가
int visit[MAX];       // ★ bool 이 아니라 int — 지금까지 몇 번 썼는가

// 입력 집계
scanf("%d", &value);
if (possible[value] == 0) { /* number[]에 새 값으로 추가 */ }
possible[value]++;

// DFS
for (int i = 1; i <= N; i++)
{
    // 이 값을 쓸 수 있는 만큼 다 썼으면 skip
    if (visit[i] == possible[number[i]]) continue;

    num_of_cases[depth] = number[i];
    visit[i]++;                       // ★ true 가 아니라 증가

    DFS(depth + 1);

    visit[i]--;                       // ★ false 가 아니라 감소
}
```

| | 15649/15654 | 15663 |
|---|---|---|
| `visit` 타입 | `bool` | **`int`** |
| 사용 처리 | `= true` | `++` |
| 해제 | `= false` | `--` |
| 스킵 조건 | `visit[i] == true` | `visit[i] == possible[값]` |

> **`bool` → 카운터 승격**이 이 문제의 전부다. `possible` 이 전부 1이면 15649와 완전히 같아진다.
> 기출에서 "같은 종류의 말이 여러 개"인 상황에 그대로 응용된다.

## 5. 예제 손 추적

### (가) 15649 — `N=4, M=2` (12가지)
```
depth 0, i=1 (visit[1]=T)
  depth 1: i=1 skip(사용중) → i=2 [1 2] → i=3 [1 3] → i=4 [1 4]
  복귀 → visit[1]=F                              ★ 여기서 되돌려야
depth 0, i=2 (visit[2]=T)
  depth 1: i=1 [2 1] → i=2 skip → i=3 [2 3] → i=4 [2 4]
...
```
```
1 2 | 1 3 | 1 4 | 2 1 | 2 3 | 2 4 | 3 1 | 3 2 | 3 4 | 4 1 | 4 2 | 4 3
```
**12가지 = `4P2 = 4 × 3`.**
- `1 1` 없음 → 중복 X (`visit` 이 막음)
- `1 2` 와 `2 1` 둘 다 있음 → 순서 O (`start` 를 안 씀)

### (나) 15663 — `N=4, M=2`, 입력 `9 7 9 1`
집계 결과: `possible[9]=2, possible[7]=1, possible[1]=1`
서로 다른 값 정렬: `number[] = {1, 7, 9}` (N이 4 → 3으로 줄지 않고 인덱스별 관리)

```
출력   1 7
       1 9
       7 1
       7 9
       9 1
       9 7
       9 9      ★ 9가 두 개이므로 가능
```
**7가지.**

여기서 두 가지를 확인한다.
- **`9 9` 가 나온다** — `possible[9] == 2` 라서 `visit` 카운터가 2까지 올라갈 수 있다
- **`1 1`, `7 7` 은 없다** — 각각 1개뿐이라 카운터가 1에서 막힌다
- **`9 7` 이 한 번만 나온다** — 서로 다른 값만 `number[]` 에 넣었으므로 첫 9/두 번째 9를 구분하지 않는다

> 실행으로 검증했다 (BOJ 15663 예제 출력과 일치).
> ```bash
> printf '4 2\n9 7 9 1\n' | python3 docs/split.py 30_BOJ_15649_15654_15663_순열.cpp 15663
> ```

## 6. 함정 / 예상 함정
- **★★ `visit[i] = false` 누락.** 출력이 몇 줄만 나오고 끝난다. **G04 최다 실수.**
- **★★ G03과 혼동해 되돌리지 않음.** 반대로 G03(연결 요소)에서 되돌리면 지수 시간. **문제 성격으로 구분**한다: "모든 경우를 만든다"면 되돌리고, "도달 가능한 곳을 센다"면 안 되돌린다.
- **★ 순열에 `start` 를 씀** → 조합이 되어 `2 1` 이 사라진다. 순열은 범위가 항상 `1..N`.
- **★ 15663에서 `visit` 을 `bool` 로 둠** → `9 9` 가 안 나온다. 카운터여야 한다.
- **15663에서 값 자체를 `visit` 인덱스로 씀.** 값이 10000까지 갈 수 있어 배열이 커진다. `number[]` 인덱스 기준으로 관리하는 게 이 코드의 방식.
- **정렬 누락** (15654, 15663) — 사전순 출력이 깨진다.
- **탐색 공간.** `N=8, M=8` 이면 `8! = 40320` — 통과. `12!` 은 4.8억이라 불가.
- 한 파일에 프로그램 3개 — 그대로 컴파일 불가.

## 7. 백지 재현 체크리스트
- [ ] 순열이 왜 `start` 를 못 쓰고 `visit` 을 쓰는지 설명할 수 있는가
- [ ] **`visit[i] = false` 되돌림**을 빠뜨리지 않는가
- [ ] G03의 `visit` 과 G04의 `visit` 차이를 말할 수 있는가
- [ ] 15663에서 `visit` 을 **카운터로 승격**하는 이유를 아는가
- [ ] `possible[]` 집계 + 서로 다른 값만 추리기를 구현할 수 있는가
- [ ] `9 7 9 1` 에서 왜 `9 9` 는 되고 `7 7` 은 안 되는지 아는가
- [ ] `4P2 = 12` 를 계산할 수 있는가

## 8. 한 줄 요약
"순서를 살리려면 범위는 `1..N` 그대로, 중복은 **`visit` 으로 막고 반드시 되돌린다.** 같은 값이 여러 개면 **카운터로 승격.**"
