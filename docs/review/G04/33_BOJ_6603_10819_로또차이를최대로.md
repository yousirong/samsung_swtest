## 1. 문제 요약
| 문제 | 내용 |
|---|---|
| **6603** 로또 | N개의 수 중 **6개를 고르는 모든 조합**을 사전순 출력. `N=0` 이면 종료 |
| **10819** 차이를 최대로 | N개의 수를 재배열해 `\|A[0]-A[1]\| + \|A[1]-A[2]\| + … + \|A[N-2]-A[N-1]\|` 를 **최대**로 |

## 2. 필요한 이론
→ [G04 경우의 수 — 완전탐색의 전형](../../theory/G04_경우의수.md)

**이 그룹의 마지막 문제이자, 기출로 가는 다리다.**

- **6603** 은 [31번 조합](31_BOJ_15650_15655_15664_조합.md)의 응용에 불과하다 (M이 6으로 고정, 다중 테스트케이스)
- **10819** 가 진짜다. 여기서 처음으로 **"모든 경우를 만든 뒤 각각을 평가해서 최댓값을 갱신"** 하는 구조가 나온다

```
DFS(depth):
   if (depth == N) {
       int tmp = calculate();                 ★ 이 경우를 평가
       if (maxAnswer < tmp) maxAnswer = tmp;  ★ 최댓값 갱신
       return;
   }
   ...
```

> **기출 [G07](../../theory/G07_완전탐색시뮬.md) 9문제 전체가 이 골격이다.**
> `calculate()` 자리에 시뮬레이션이 들어갈 뿐이다.
> 2048 게임, 2개의 사탕, 연산자 배치하기 — 전부 "수열을 만들고 → 돌려보고 → 최댓값".

## 4. 핵심 코드

### 6603 — 조합 그대로
```c
void DFS(int depth, int start)
{
    if (depth == 6) { printCases(); return; }    // ★ 6개 고정

    for (int i = start; i <= N; i++)
    {
        num_of_cases[depth] = number[i];
        DFS(depth + 1, i + 1);  // 다음 숫자는 현재보다 뒤에서만 고름
    }
}
```
[31번](31_BOJ_15650_15655_15664_조합.md)과 동일. **입력이 이미 오름차순으로 주어지므로 정렬이 불필요**하다.

```c
while (1)
{
    input();
    if (N == 0) break;   // 0 입력이면 종료
    DFS(0, 1);
    putchar('\n');       // 테스트케이스 구분용 빈 줄
}
```
**입력 개수를 모르는 다중 테스트케이스** 패턴. `while(1)` + 종료 조건 체크.

### 10819 — 순열 + 평가

**보조 함수 두 개**
```c
// stdlib.h의 abs를 직접 안 쓰고 구현
int abs(int x)
{
    return (x > 0) ? x : -x;
}

// |A[0]-A[1]| + |A[1]-A[2]| + ... 를 계산
int calculate()
{
    int sum = 0;
    for (int i = 0; i < N - 1; i++)
        sum += abs(num_of_cases[i] - num_of_cases[i + 1]);
    return sum;
}
```
> `abs` 를 직접 구현한 것은 [G02](../../theory/G02_스택큐덱.md)의 `strCompare` 와 같은 습관이다. `<stdlib.h>` 를 포함하면 충돌 위험이 있으니 이름을 피하는 편이 낫다.
> 루프가 `N - 1` 번인 것에 주의 — **인접 쌍의 개수**다.

**★ 만들고 → 평가하기**
```c
void DFS(int depth)
{
    // 순열이 완성된 경우
    if (depth == N)
    {
        int tmp = calculate();                  // 이 순열의 점수
        if (maxAnswer < tmp) maxAnswer = tmp;   // 최댓값 갱신
        return;
    }

    for (int i = 0; i < N; i++)
    {
        if (visit[i] == true) continue;

        num_of_cases[depth] = number[i];
        visit[i] = true;

        DFS(depth + 1);

        visit[i] = false;      // ★ 백트래킹
    }
}
```

**`depth == N`** 인 것에 주목. [30번](30_BOJ_15649_15654_15663_순열.md)은 `depth == M` (일부만 뽑음)이었는데, 여기는 **전체 순열**이라 `N` 이다. `N! ` 가지를 전부 만든다.

### 초기화
```c
maxAnswer = -1;
```
**최댓값 문제이므로 충분히 작은 값**으로 시작한다. 이 문제는 결과가 항상 0 이상이라 `-1` 로 충분하다. 최솟값 문제라면 `INF` 로 시작해야 한다 — **방향을 반대로 잡는 것이 흔한 실수**다.

## 5. 예제 손 추적

### 10819 — `N=6`, 입력 `20 1 15 8 4 10`

`6! = 720` 가지 순열을 전부 만들고 각각 `calculate()` 로 평가한다.

**최적 배치 하나**: `1 20 4 15 8 10`
```
|1 - 20|  = 19
|20 - 4|  = 16
|4 - 15|  = 11
|15 - 8|  =  7
|8 - 10|  =  2
─────────────
합계       = 55
```
아직 최댓값이 아니다. 실제 답은 **62**.

**최댓값을 내는 배치 하나**: `4 20 1 15 8 10`
```
|4 - 20|  = 16
|20 - 1|  = 19
|1 - 15|  = 14
|15 - 8|  =  7
|8 - 10|  =  2
─────────────
합계       = 58
```
이것도 아니다. **720가지를 전부 봐야 62가 나온다** — 그게 완전탐색의 요점이다. 사람이 최적 배치를 짐작하기 어려운 문제일수록 완전탐색의 가치가 크다.

```
출력   62
```

### 탐색 공간 확인
| N | `N!` | 판정 |
|---|---|---|
| 6 | 720 | 여유 |
| 8 | 40,320 | 문제 조건 상한 (`N ≤ 8`) — 여유 |
| 10 | 362만 | 아슬 |
| 12 | 4.8억 | ✗ |

**짜기 전에 이 표를 계산하는 습관**이 기출에서 완전탐색 가능 여부를 가른다.

## 6. 함정 / 예상 함정
- **★★ `maxAnswer` 초기화 방향.** 최댓값이면 작게(`-1`, `INT_MIN`), 최솟값이면 크게(`INF`). 반대로 잡으면 갱신이 한 번도 안 일어난다. **T-loop 이면 케이스마다 재초기화**도 필요하다.
- **★ `depth == N` vs `depth == M`.** 10819는 전체 순열이라 `N`. 습관적으로 `M` 을 쓰면 `M` 이 0이라 즉시 종료한다.
- **★ `visit` 되돌림 누락** — [30번](30_BOJ_15649_15654_15663_순열.md)과 동일. 답이 작게 나온다.
- **`calculate()` 루프 범위.** 인접 쌍은 `N - 1` 개다. `N` 번 돌면 `num_of_cases[N]` (범위 밖)을 읽는다.
- **`abs` 이름 충돌.** `<stdlib.h>` 를 포함하면 재정의 오류. 지금은 include 안 해서 괜찮지만 위험하다 — [G02 21번](../G02/21_BOJ_10866_덱.md)의 `strcmp` 와 같은 문제.
- **6603에서 `putchar('\n')` 누락.** 테스트케이스 사이 빈 줄이 채점 기준이다.
- **6603에서 정렬을 넣음.** 입력이 이미 오름차순이라 불필요하다. 넣어도 무해하지만 문제 조건을 읽는 습관이 중요.
- **탐색 공간 과소평가.** N이 조금만 커져도 `N!` 은 폭발한다. 완전탐색 전에 반드시 계산한다.

## 7. 백지 재현 체크리스트
- [ ] **"만들고 → 평가하고 → 갱신"** 골격을 쓸 수 있는가
- [ ] `maxAnswer` 초기화 방향을 문제(최대/최소)에 맞게 잡는가
- [ ] `depth == N` (전체 순열)과 `depth == M` (일부)를 구분하는가
- [ ] `visit` 되돌림을 넣었는가
- [ ] `calculate()` 의 루프가 `N - 1` 인 이유(인접 쌍)를 아는가
- [ ] `N!` 을 계산해 완전탐색 가능 여부를 판단하는가
- [ ] 6603의 `while(1)` + `N == 0` 종료 패턴을 아는가
- [ ] 이 골격에서 `calculate()` 를 시뮬레이션으로 바꾸면 기출이 된다는 것을 아는가
