> ### ⚠️ 분류 정정
> [G11 이론 카드](../../theory/G11_그리디DP.md)에 "DP / 선택 백트래킹"으로 적었지만,
> **이 소스는 DP를 쓰지 않는다.** 각 날짜를 **선택/미선택 2가지**로 전부 시도하는 `2^N` 완전탐색이다.
> `N ≤ 15` 이므로 `2^15 = 32768` — 충분히 통과한다.
>
> **DP 풀이도 가능하다** (§6 참고). 어느 쪽이든 맞지만 **코드가 무엇을 하는지는 정확히 알아야** 한다.

## 1. 문제 요약
`1일`부터 `N일`까지 매일 **그 날 시작할 수 있는 외주**가 하나씩 주어진다.

각 외주는
- **소요 기간** `time[i]`
- **완료 시 수익** `profit[i]`

를 갖는다. 어떤 날의 외주를 선택하면 **그 기간 동안 다른 외주를 할 수 없다.**

**N일 안에 끝낼 수 있는** 외주들만 골라 얻을 수 있는 **최대 수익**을 구한다.

## 2. 필요한 이론
→ [G11 그리디 · DP](../../theory/G11_그리디DP.md) + [G07 표준 골격](../../theory/G07_완전탐색시뮬.md)

**실제로는 [G07](../../theory/G07_완전탐색시뮬.md)의 "만들고 → 검증하고 → 평가" 골격**이다.

```
후보 : 각 날짜를 선택(1)/미선택(0)  →  2^N 가지 (중복순열, 선택지 2개)
검증 : 기간이 겹치지 않고 N일을 넘지 않는가?
평가 : 선택한 것들의 수익 합
```

> **[G04 28번 중복순열](../G04/28_BOJ_15651_15656_중복순열.md)에서 선택지가 `1..N` 이 아니라 `0/1` 인 형태**다.
> "부분집합 전체 탐색"의 전형 — **`2^N` 이 감당되면 가장 단순한 접근.**

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()             N, time[1..N], profit[1..N]
      maxAnswer = 0
      DFS(0)
      printf(maxAnswer)

DFS(depth):
   if (depth == N):
      if (check())                    ★ 유효한 조합인지 검증
      {
         tmp = getProfit()
         maxAnswer = max(maxAnswer, tmp)
      }
      return
   for i in 0..1:                     ★ 선택 안 함 / 선택
      num_of_cases[depth + 1] = i
      DFS(depth + 1)
```

## 4. 핵심 코드

### 선택/미선택 완전탐색
```c
int num_of_cases[MAX];   // i일 외주를 선택했는지 여부 (0 또는 1)

void DFS(int depth)
{
    if (depth == N)
    {
        if (check() == true)                    // ★ 검증 먼저
        {
            int tmp = getProfit();
            if (maxAnswer < tmp) maxAnswer = tmp;
        }
        return;
    }

    for (int i = 0; i < 2; i++)                 // ★ 선택지 2개
    {
        num_of_cases[depth + 1] = i;            // ★ 1-based 저장
        DFS(depth + 1);
    }
}
```

**`num_of_cases[depth + 1]`** 에 저장하는 것에 주의. 날짜가 `1..N` 이라 **1-based** 로 맞춘 것이다.
`depth` 는 `0..N-1` 이므로 `depth + 1` 이 `1..N`.

> **`visit` 도 `start` 도 없다.** 각 날짜가 독립된 0/1 선택이므로 순수 중복순열(선택지 2개)이다.
> 되돌릴 것도 없다 — 다음 반복에서 덮어쓴다.

### ★★ 검증 — 겹침과 범위를 한 번에
```c
bool check()
{
    bool visit[MAX] = { 0 };        // ★ 지역 배열, 매 호출 초기화

    for (int i = 1; i <= N; i++)
    {
        if (num_of_cases[i] == 0) continue;     // 선택 안 한 날

        for (int k = 0; k < time[i]; k++)
        {
            if (N < i + k) return false;        // ★ ① N일 초과
            if (visit[i + k] == true) return false;  // ★ ② 이미 점유

            visit[i + k] = true;                // 점유 표시
        }
    }

    return true;
}
```

**두 가지 실패 조건을 한 루프에서 잡는다.**

**① `N < i + k`** — 외주가 N일을 넘어간다.
`i` 일에 시작해 `time[i]` 일 걸리면 **`i + time[i] - 1` 일에 끝난다.**
루프 안에서 `i + k` 가 `N` 을 넘으면 즉시 실패.

**② `visit[i + k]`** — 다른 외주가 이미 그 날을 쓰고 있다.

> **★ `visit` 이 지역 배열 `{0}`** 이라 `2^N` 번 호출돼도 매번 깨끗하다.
> 전역으로 빼면 명시적 초기화가 필요하고, 빼먹으면 **첫 조합만 맞는다.**

### 수익 계산
```c
int getProfit()
{
    int sum = 0;

    for (int i = 1; i <= N; i++)
        sum += (num_of_cases[i] * profit[i]);   // ★ 0이면 0, 1이면 profit

    return sum;
}
```
**`0/1` 을 곱하는 트릭**으로 `if` 없이 합산한다. 선택 안 한 날은 `0 × profit = 0`.

### 검증 → 평가 순서
```c
if (check() == true)
{
    int tmp = getProfit();
    ...
}
```
**검증을 먼저** 한다. 유효하지 않은 조합의 수익을 계산하면 **불가능한 답이 최댓값이 된다.**

## 5. 예제 손 추적 — `N = 3`

```
1일: time=2, profit=10
2일: time=1, profit=20
3일: time=1, profit=30
```

`2^3 = 8` 가지 조합.

| 선택 `[1일,2일,3일]` | 검증 | 수익 |
|---|---|---|
| `[0,0,0]` | ✓ | 0 |
| `[0,0,1]` | 3일 시작, 3일 끝 ✓ | **30** |
| `[0,1,0]` | 2일 시작, 2일 끝 ✓ | 20 |
| `[0,1,1]` | 2일✓, 3일✓ 겹침 없음 ✓ | **50** ★ |
| `[1,0,0]` | 1일 시작, 2일 끝 ✓ | 10 |
| `[1,0,1]` | 1~2일, 3일 ✓ | **40** |
| `[1,1,0]` | 1일이 1~2일 점유, 2일이 2일 점유 → **겹침** ✗ | — |
| `[1,1,1]` | 겹침 ✗ | — |

```
최댓값 = 50   ([0,1,1])
```

### 검증 상세 — `[1,1,0]` 이 왜 실패하는가
```
i=1: num_of_cases[1]=1, time[1]=2
     k=0: i+k=1, N(3) >= 1 ✓, visit[1]=false → visit[1]=true
     k=1: i+k=2, N(3) >= 2 ✓, visit[2]=false → visit[2]=true

i=2: num_of_cases[2]=1, time[2]=1
     k=0: i+k=2, N(3) >= 2 ✓, visit[2]=true → ★ return false
```
**1일 외주가 2일까지 점유**했는데 2일 외주가 또 시작하려 해서 실패.

### N일 초과 — `time` 이 긴 경우
```
3일: time=5, profit=100  (N=3)

i=3: k=0: i+k=3, N(3) >= 3 ✓
     k=1: i+k=4, N(3) < 4  →  ★ return false
```
**3일에 5일짜리를 시작하면 7일에 끝나 N=3을 넘는다.**

### 탐색 공간
| N | `2^N` | 판정 |
|---|---|---|
| 10 | 1,024 | 여유 |
| 15 | 32,768 | 여유 (문제 상한) |
| 20 | 100만 | 아슬 |
| 30 | 10억 | ✗ |

`check()` 가 `O(N²)` 이라 총 `2^N × N²`. `N=15` 면 `32768 × 225 ≈ 700만` — 통과.

## 6. 함정 / 예상 함정
- **★★ 검증 없이 수익만 계산.** 겹치는 조합이 최댓값이 되어 답이 커진다.
- **★★ N일 초과 검사 누락.** `i + time[i] - 1 > N` 인 외주는 못 한다.
- **★ `visit` 을 전역으로 두고 초기화 안 함.** `2^N` 번 호출되므로 **지역 배열 `{0}`** 이 안전.
- **★ 인덱스 1-based/0-based 혼동.** 날짜가 `1..N` 이라 `num_of_cases[depth + 1]`.
- **★ `maxAnswer` 초기값.** 수익이 음수가 아니므로 `0` 이면 충분. 음수 수익이 있는 변형이면 `-INF`.
- **끝나는 날 계산.** `i` 일 시작 + `time[i]` 일 = **`i + time[i] - 1` 일에 끝난다.** `i + time[i]` 로 쓰면 하루 밀린다.
- **T-loop 마다 `maxAnswer` 초기화 누락.**

### DP 풀이 (참고)
`N` 이 크면 완전탐색이 안 된다. **뒤에서부터 채우는 DP** 로 `O(N)` 에 풀린다.
```c
// dp[i] = i일부터 시작할 때 얻을 수 있는 최대 수익
int dp[MAX] = { 0 };

for (int i = N; i >= 1; i--)
{
    if (i + time[i] - 1 > N)
        dp[i] = dp[i + 1];                            // 못 하면 건너뛴다
    else
        dp[i] = max(dp[i + 1],                        // 안 하는 경우
                    profit[i] + dp[i + time[i]]);     // 하는 경우
}
// 답 = dp[1]
```
**`dp[i+1]`(안 함) vs `profit[i] + dp[i + time[i]]`(함)** 중 큰 쪽.
**뒤에서부터 채워야** `dp[i + time[i]]` 가 이미 계산돼 있다.

> **A형에서는 `N ≤ 15` 라 완전탐색으로 충분**하지만, DP 형태를 알아두면 응용이 넓어진다.

## 7. 백지 재현 체크리스트
- [ ] 이 문제가 **`2^N` 부분집합 탐색**임을 알 수 있는가
- [ ] `DFS` 선택지가 **`0/1` 두 개**인가
- [ ] **검증(`check`)을 평가보다 먼저** 하는가
- [ ] 검증에서 **겹침**과 **N일 초과** 둘 다 잡는가
- [ ] 끝나는 날이 **`i + time[i] - 1`** 임을 아는가
- [ ] `visit` 을 지역 배열로 두어 호출마다 초기화되는가
- [ ] 인덱스가 **1-based** 로 일관되는가
- [ ] `2^N × N²` 를 계산해 완전탐색 가능을 확인했는가
- [ ] **DP 풀이**의 점화식을 쓸 수 있는가

## 8. 한 줄 요약
"각 날을 **선택/미선택 2^N** 으로 전부 시도. **검증(겹침 + N일 초과)을 먼저**, 그 다음 수익 합산."
