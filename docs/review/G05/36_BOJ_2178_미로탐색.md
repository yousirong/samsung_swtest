| 항목 | 내용 |

## 1. 문제 요약
N×M 미로에서 `1` 은 이동 가능, `0` 은 벽.
`(1,1)` 에서 `(N,M)` 까지 가는 **최소 칸 수**를 구한다. (시작·도착 칸 포함)

## 2. 필요한 이론
→ [G05 — ② 거리 누적](../../theory/G05_그리드탐색심화.md)

**"최단"이 나왔으므로 BFS 확정.** DFS로는 최단을 보장할 수 없다.

> **★ BFS가 최단인 이유**
> 큐는 **가까운 것부터** 꺼낸다. 어떤 칸에 **처음 도달한 순간**이 곧 그 칸까지의 최단 거리다.
> 그래서 `visit` 체크를 하는 순간 "이미 더 짧은 경로로 왔다"가 보장되고, 다시 볼 필요가 없다.

여기서 새로 나오는 기법 하나:

> **★ 거리를 별도 배열이 아니라 `MAP` 에 직접 누적한다.**
> `MAP[nr][nc] = MAP[out.r][out.c] + 1` — 부모 거리에 1을 더해 자식에 쓴다.
> 원래 `MAP` 값(`1`)이 시작값 역할을 하므로 **시작 칸이 자동으로 1**이 되고, "칸 수를 센다"는 문제 정의와 정확히 맞아떨어진다.

## 3. 코드 흐름
```
main()
 └ input()             N, M, 미로 (%1d)
   BFS(1, 1)           (1,1)에서 출발, 거리를 MAP에 누적
   printf(MAP[N][M])   도착 칸의 값이 곧 답
```

## 4. 핵심 코드

### 거리 누적 — 이 문제의 전부
```c
while (rp < wp)
{
    RC out = queue[rp++];

    for (int i = 0; i < 4; i++)
    {
        int nr = out.r + dr[i];
        int nc = out.c + dc[i];

        // 벽이거나 이미 방문했으면 건너뜀
        if (MAP[nr][nc] == 0 || visit[nr][nc] == true) continue;

        queue[wp].r = nr;
        queue[wp++].c = nc;
        visit[nr][nc] = true;

        MAP[nr][nc] = MAP[out.r][out.c] + 1;    // ★ 부모 거리 + 1
    }
}
```

**한 줄이 추가됐을 뿐** [34번](34_BOJ_2667_단지번호붙이기.md)의 BFS와 같다.

### `MAP` 을 거리 배열로 재활용하는 것의 묘미
```
입력 시 MAP:        BFS 후 MAP:
1 0 1 1 1 1         1 0 9 10 11 12
1 0 1 0 1 0         2 0 8  0 12  0
1 0 1 0 1 1         3 0 7  0 13 14
1 1 1 0 1 1         4 5 6  0 14 15
```
- 벽은 `0` 그대로 남는다 → **거리와 벽이 자연스럽게 구분**된다
- 시작 칸 `MAP[1][1]` 은 원래 값 `1` → 칸 수 세기의 시작값
- 도착 칸 `MAP[N][M]` 이 곧 답

> **`visit` 을 없애고 `MAP != 1` 로 방문 판정할 수도 있다.** 하지만 시작 칸이 이미 1이라 헷갈리므로, 이 코드처럼 `visit` 을 따로 두는 편이 안전하다.

### 조기 종료를 하지 않는다
이 코드는 도착점에 닿아도 BFS를 끝까지 돌린다. `(N,M)` 에 처음 도달한 시점이 최단이므로 거기서 `return` 해도 되지만, **끝까지 돌려도 값이 덮이지 않는다**(`visit` 이 막으므로). 안전한 선택이다.

## 5. 예제 손 추적 — BOJ 2178 예제

```
입력  4 6
      101111        # . # # # #
      101010        # . # . # .
      101011        # . # . # #
      111011        # # # . # #
```
(`#` = 1 = 길, `.` = 0 = 벽)

BFS가 `(1,1)` 에서 출발한다. `MAP[1][1] = 1`.

**층별 확산** (같은 거리끼리 묶어서)
| 거리 | 도달한 칸 |
|---|---|
| 1 | `(1,1)` |
| 2 | `(2,1)` |
| 3 | `(3,1)` |
| 4 | `(4,1)` |
| 5 | `(4,2)` |
| 6 | `(4,3)` |
| 7 | `(3,3)` |
| 8 | `(2,3)` |
| 9 | `(1,3)` |
| 10 | `(1,4)` |
| 11 | `(1,5)` |
| 12 | `(1,6)`, `(2,5)` |
| 13 | `(3,5)` |
| 14 | `(3,6)`, `(4,5)` |
| **15** | **`(4,6)`** ← 도착 |

**최종 `MAP` 상태**
```
 1  0  9 10 11 12
 2  0  8  0 12  0
 3  0  7  0 13 14
 4  5  6  0 14 15
```

```
출력  15
```

> 실행으로 검증했다.
> ```bash
> printf '4 6\n101111\n101010\n101011\n111011\n' | ./a.out
> ```

**경로를 되짚어 보면**: 왼쪽 세로줄을 따라 내려가 `(4,1)`→`(4,3)`, 3열을 타고 올라가 `(1,3)`, 1행을 따라 오른쪽으로, 다시 내려와 `(4,6)`. **미로가 지그재그로 강제**하는 구조다. 직선거리 `(4-1)+(6-1)+1 = 9` 보다 훨씬 길다.

**거리 12가 두 칸(`(1,6)`, `(2,5)`)에 동시에 나타나는 것**이 BFS의 층별 확산을 보여준다.

## 6. 함정 / 예상 함정
- **★★ DFS로 품.** 최단이 보장되지 않는다. "최소/최단"이 보이면 BFS.
- **★ 시작값을 0으로 둠.** 문제가 **칸 수**(시작·도착 포함)를 물으므로 시작이 1이다. 0에서 시작하면 답이 1 작다. `MAP` 을 재활용하면 원래 값 `1` 이 자동으로 이 역할을 한다 — 우연이 아니라 설계다.
- **★ `%1d` 누락** — `101111` 이 통째로 읽힌다.
- **★ 거리 갱신을 `visit` 체크 전에** 함. `if (...) continue;` 를 통과한 뒤에 갱신해야 한다. 앞에 두면 이미 최단으로 확정된 칸을 더 긴 거리로 덮어쓴다.
- **`visit` 을 꺼낼 때 찍음** → 중복 삽입 + 거리가 틀어진다. [G03](../../theory/G03_DFS_BFS기초.md)의 규칙.
- **도달 불가 처리.** 이 문제는 항상 도달 가능하다고 보장되지만, 아니라면 `MAP[N][M] == 1` (초기값 그대로)로 판정해야 한다. `0` 은 벽이므로 구분된다.
- **`N`(행)과 `M`(열) 혼동.** 입력이 `N M` 이고 미로는 `N` 줄. [35번](35_BOJ_4963_섬의개수.md)의 `W H` 와 순서가 반대라 헷갈리기 쉽다.

## 7. 백지 재현 체크리스트
- [ ] "최단"을 보고 **BFS를 확정**할 수 있는가, 그 이유를 설명할 수 있는가
- [ ] 거리 누적이 `MAP[nr][nc] = MAP[out.r][out.c] + 1` 인가
- [ ] 갱신을 **`continue` 체크 뒤에** 두었는가
- [ ] 시작값이 1인 이유(칸 수 세기)를 아는가
- [ ] `MAP` 재활용 시 벽(`0`)과 거리가 구분되는 이유를 아는가
- [ ] `%1d` 로 읽었는가
- [ ] 도달 불가를 어떻게 판정할지 말할 수 있는가

## 8. 한 줄 요약
"BFS는 **처음 도달이 곧 최단**. 거리는 `MAP` 에 **부모 + 1** 로 누적하면 배열 하나가 절약된다."
