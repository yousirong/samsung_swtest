# 39 — 나이트의 이동 (BOJ 7562)

| 항목 | 내용 |
|---|---|
| 유형 | G05 그리드 탐색 심화 — **② 거리 누적 (방향 배열만 교체)** |
| 소스 | [swtest/39_BOJ_7562_나이트의이동.cpp](../../../swtest/39_BOJ_7562_나이트의이동.cpp) |
| 링크 | https://www.acmicpc.net/problem/7562 |
| 구조 | T-loop (다중 테스트케이스) |

## 1. 문제 요약
`L × L` 체스판에서 나이트가 시작 칸에서 목표 칸까지 가는 **최소 이동 횟수**를 구한다.
나이트는 체스 규칙대로 **L자로 8방향** 움직인다.

## 2. 필요한 이론
→ [G05 — ② 거리 누적](../../theory/G05_그리드탐색심화.md)

**[36번 미로 탐색](36_BOJ_2178_미로탐색.md)과 완전히 같은 문제다.** 딱 하나가 다르다.

> **★ 이동 규칙이 바뀌어도 BFS는 그대로다. 바뀌는 것은 방향 배열뿐.**

| | 36번 미로 | 39번 나이트 |
|---|---|---|
| 이동 | 상하좌우 4칸 | L자 8칸 |
| 방향 배열 | `{-1,0,1,0}` / `{0,1,0,-1}` | `{-2,-1,1,2,2,1,-1,-2}` / `{1,2,2,1,-1,-2,-2,-1}` |
| 벽 | 있음 | **없음** (빈 판) |
| 그 외 | — | 동일 |

**이 문제의 학습 가치는 "방향 배열을 데이터로 분리해 둔 설계의 이점"을 체감하는 것**이다.
`dr/dc` 를 하드코딩했다면 BFS 본체를 다시 짜야 했겠지만, 배열로 빼 뒀기 때문에 **두 줄만 갈아끼우면** 끝난다.

## 3. 코드 흐름
```
main()
 └ scanf(T)
   for T번:
      input()                 L, 시작(sr,sc), 목표(er,ec) — MAP 초기화 포함
      printf(BFS(sr, sc))

BFS(r, c):
   시작 칸 큐에 삽입, MAP[r][c] = 1
   while (rp < wp):
      out = dequeue
      if (목표 도착) return MAP[out.r][out.c] - 1
      8방향: 범위 밖 skip, MAP != 0 이면 skip
             큐 삽입 + MAP[nr][nc] = MAP[out]+1
```

## 4. 핵심 코드

### ★ 나이트의 8방향
```c
int dr[] = { -2, -1,  1,  2,  2,  1, -1, -2 };
int dc[] = {  1,  2,  2,  1, -1, -2, -2, -1 };
```

**두 배열을 세로로 읽으면 시계 방향 한 바퀴**다.
```
       (-2,+1) (-2, ... )
   (-1,+2)          ← 12시 방향에서 시작해 시계로
       ·
   ( 1,+2)
       ...
```

| i | (dr, dc) | 방향 |
|---|---|---|
| 0 | `(-2, +1)` | 위위 → 오른쪽 |
| 1 | `(-1, +2)` | 위 → 오른오른 |
| 2 | `( 1, +2)` | 아래 → 오른오른 |
| 3 | `( 2, +1)` | 아래아래 → 오른쪽 |
| 4 | `( 2, -1)` | 아래아래 → 왼쪽 |
| 5 | `( 1, -2)` | 아래 → 왼왼 |
| 6 | `(-1, -2)` | 위 → 왼왼 |
| 7 | `(-2, -1)` | 위위 → 왼쪽 |

**검산법**: 모든 쌍이 `|dr| + |dc| == 3` 이고 `{|dr|, |dc|} == {1, 2}` 여야 한다.
8개가 서로 다르고 이 조건을 만족하면 정확하다.

### BFS — 36번과 동일, 상한만 8
```c
queue[wp].r = r;
queue[wp++].c = c;

// 시작 칸의 값을 1로 두고, 이후 이동할 때마다 +1 하면서 거리 정보를 저장
MAP[r][c] = 1;

while (rp < wp)
{
    RC out = queue[rp++];

    // 시작 칸을 1로 뒀으므로 실제 이동 횟수는 -1
    if (out.r == er && out.c == ec)
        return MAP[out.r][out.c] - 1;

    for (int i = 0; i < 8; i++)          // ★ 4가 아니라 8
    {
        int nr = out.r + dr[i];
        int nc = out.c + dc[i];

        // 체스판 범위를 벗어나면 건너뜀
        if (nr < 0 || nc < 0 || nr > L - 1 || nc > L - 1) continue;

        // 이미 방문한 칸이면 건너뜀
        if (MAP[nr][nc] != 0) continue;

        queue[wp].r = nr;
        queue[wp++].c = nc;
        MAP[nr][nc] = MAP[out.r][out.c] + 1;
    }
}
```

### ★ 이 파일은 0-indexed다
```c
if (nr < 0 || nc < 0 || nr > L - 1 || nc > L - 1) continue;
```
좌표가 `0 ~ L-1` 이다. 문제 입력이 0부터 시작하기 때문.

> **레포의 다른 파일은 거의 전부 1-indexed + 테두리 sentinel** 인데 이 파일만 0-indexed에 명시적 범위 체크다.
> 나이트는 **두 칸씩 건너뛰므로** sentinel을 쓰려면 테두리를 **2겹** 둘러야 한다. 그럴 바에는 명시적 체크가 낫다.
> → **"한 칸씩 움직이지 않는 문제에서는 sentinel이 불리하다"** 는 판단 기준을 여기서 얻는다.

### 도착 시 조기 반환
```c
if (out.r == er && out.c == ec)
    return MAP[out.r][out.c] - 1;
```
**큐에서 꺼낼 때** 검사한다. BFS는 처음 도달이 곧 최단이므로 여기서 바로 끝내도 된다.

`시작 == 목표` 인 경우도 자동 처리된다. 시작 칸을 큐에 넣고 첫 `dequeue` 에서 바로 걸려 `1 - 1 = 0` 을 반환한다.

### T-loop 초기화
```c
void input()
{
    scanf("%d", &L);

    // 이전 케이스의 거리 정보를 지운다
    for (int r = 0; r < L; r++)
        for (int c = 0; c < L; c++)
            MAP[r][c] = 0;

    scanf("%d %d", &sr, &sc);
    scanf("%d %d", &er, &ec);
}
```
`MAP` 이 거리 배열을 겸하므로 케이스마다 0으로 되돌려야 한다. [35번](35_BOJ_4963_섬의개수.md)과 같은 함정.

## 5. 예제 손 추적 — BOJ 7562 예제

### 케이스 1: `L=8`, `(0,0)` → `(7,0)` — 정답 **5**
8×8 판의 왼쪽 위에서 왼쪽 아래 끝까지. 직선거리로는 7칸이지만 나이트는 L자로만 가므로 5수가 필요하다.

**층별 확산** (거리 = `MAP - 1`)
| 거리 | 도달 |
|---|---|
| 0 | `(0,0)` |
| 1 | `(1,2)`, `(2,1)` |
| 2 | `(0,4)`, `(2,3)`, `(3,0)`, `(3,2)`, `(4,1)` … |
| 3 | … |
| 4 | … |
| **5** | **`(7,0)`** ← 도착 |

나이트는 한 수에 **거리 3만큼(맨해튼)** 움직이므로, 맨해튼 거리 7을 커버하려면 최소 3수(=9)면 될 듯하지만 **패리티** 때문에 안 된다. 나이트는 매 수마다 칸 색이 바뀌고 좌표합의 홀짝이 뒤집힌다. 이런 제약 때문에 5수가 답이다.

> **이것이 BFS를 쓰는 이유다.** 수식으로 구하려면 경우 분석이 복잡하지만, BFS는 그냥 세어준다.

**시작과 목표가 같다.** 첫 `dequeue` 에서 즉시 `1 - 1 = 0`.

## 6. 함정 / 예상 함정
- **★★ 나이트 방향 배열을 잘못 씀.** `|dr| + |dc| == 3` 검산을 반드시 한다. 대각선(`1,1`)이나 직선(`0,2`)이 섞이면 완전히 다른 문제가 된다.
- **★★ T-loop 에서 `MAP` 초기화 누락.** `MAP` 이 거리 배열이라 앞 케이스 값이 남으면 "이미 방문"으로 오판한다. **첫 케이스만 맞는** 전형적 증상.
- **★ 루프 상한을 `i < 4` 로 둠.** 배열은 8개인데 4개만 본다.
- **★ 0-indexed / 1-indexed 혼동.** 이 파일은 0-indexed에 `0 ~ L-1`. 다른 파일 습관대로 `1 ~ L` 로 쓰면 어긋난다.
- **sentinel 을 쓰려다 실패.** 나이트는 2칸씩 뛰므로 테두리 1겹으로는 부족하다. **명시적 범위 체크**를 쓴다.
- **시작 = 목표 케이스.** 시작 칸을 `MAP = 1` 로 두고 `dequeue` 시점에 검사하면 자동으로 0이 나온다. 넣을 때 검사하는 구조라면 별도 처리가 필요하다.
- **시작값 1 / 반환 시 `-1`** 오프셋을 잊음. 이 문제는 **이동 횟수**를 묻지 칸 수가 아니다 — [36번](36_BOJ_2178_미로탐색.md)과 의미가 다르지만 `-1` 처리로 똑같이 맞아떨어진다.
- **큐 크기.** `L ≤ 300` 이면 `300 × 300 = 9만`. `MAX * MAX` 로 충분.

## 7. 백지 재현 체크리스트
- [ ] 나이트 8방향을 **`|dr| + |dc| == 3`** 으로 검산할 수 있는가
- [ ] 루프 상한을 8로 고쳤는가
- [ ] **T-loop 마다 `MAP` 을 초기화**했는가
- [ ] 0-indexed 범위 체크(`0 ~ L-1`)를 정확히 썼는가
- [ ] 나이트 문제에서 **sentinel 이 왜 불리한지** 설명할 수 있는가
- [ ] 시작 = 목표 케이스가 자동 처리되는지 확인했는가
- [ ] "이동 규칙이 바뀌면 방향 배열만 갈아끼운다"는 감각이 있는가
