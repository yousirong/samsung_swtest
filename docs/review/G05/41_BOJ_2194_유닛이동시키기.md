# 41 — 유닛 이동시키기 (BOJ 2194)

| 항목 | 내용 |
|---|---|
| 유형 | G05 그리드 탐색 심화 — **② 거리 누적 + 상태 압축** |

## 1. 문제 요약
`N × M` 격자에 `A × B` 크기의 **직사각형 유닛**이 있다.
유닛을 상하좌우로 한 칸씩 움직여 시작 위치에서 도착 위치까지 가는 **최소 이동 횟수**를 구한다.
격자에는 장애물 K개가 있고, **유닛이 덮는 영역에 장애물이 하나라도 있으면 그 위치에 놓을 수 없다.**
도달 불가면 `-1`.

좌표는 모두 **유닛의 왼쪽 위 기준**으로 주어진다.

**입력 형식**: `N M A B K` → K줄의 장애물 좌표 → `sr sc er ec`

## 2. 필요한 이론
→ [G05 — ② 거리 누적](../../theory/G05_그리드탐색심화.md)

**1부의 마무리에 어울리는 문제다.** 여기서 배우는 것은 새 알고리즘이 아니라 **모델링**이다.

> ### ★ "무엇을 BFS의 노드로 삼을 것인가"
>
> 순진한 생각: 유닛이 `A × B` 칸을 차지하니까 상태가 복잡할 것 같다.
> **실제**: 유닛은 **모양이 고정**이고 회전도 없다. 따라서 **왼쪽 위 좌표 하나면 상태가 완전히 결정된다.**
>
> ```
> 상태 = (유닛의 왼쪽 위 r, c)     ← 딱 2차원
> ```
>
> 유닛 전체를 상태에 넣으려 하면 차원이 폭발한다. **대표점 하나로 압축**하는 것이 핵심.

[37번](37_BOJ_2206_14442_벽부수고이동하기.md)이 "상태를 **늘리는**" 문제였다면, 이 문제는 "상태를 **줄이는**" 문제다. 두 방향을 다 겪어보는 것이 의미가 있다.

대신 대가가 있다. **한 칸이 유효한지 판정하는 비용이 `O(A × B)` 로 늘어난다.**

## 3. 코드 흐름
```
main()
 └ input()                  N M A B K, 장애물, 시작·도착 좌표
   printf(BFS(sr, sc))

BFS(r, c):
   visit[r][c] = 1
   큐에 (r, c) 삽입
   while (rp < wp):
      out = dequeue
      if (도착) return visit[out] - 1
      4방향:
         ① 유닛 전체가 맵 안인가?  (nr+A-1 ≤ N, nc+B-1 ≤ M)
         ② isEmpty(nr, nc)         A×B 영역에 장애물 없는가?
         ③ visit[nr][nc] == 0      미방문인가?
         → 큐 삽입 + visit[nr][nc] = visit[out] + 1
   return -1
```

## 4. 핵심 코드

### ★ 배치 가능 판정 — `A × B` 영역을 전부 훑는다
```c
// 현재 유닛의 왼쪽 위 좌표가 (sr, sc)일 때
// A x B 직사각형 내부에 장애물이 없는지 검사
bool isEmpty(int sr, int sc)
{
    for (int r = sr; r <= sr + A - 1; r++)
    {
        for (int c = sc; c <= sc + B - 1; c++)
        {
            if (MAP[r][c] == 1) return false;   // 하나라도 장애물이면 실패
        }
    }
    return true;
}
```

**루프 범위 `sr ~ sr + A - 1`** 에 주목. 왼쪽 위가 `sr` 이고 세로 길이가 `A` 이므로 끝은 `sr + A - 1` 이다.
**`+ A` 로 쓰면 한 칸 더 본다** — 오프바이원의 단골 자리.

### ★ 범위 체크 — 유닛의 오른쪽 아래까지
```c
// 유닛의 왼쪽 위가 (nr, nc)이면 오른쪽 아래 끝 좌표는 (nr + A - 1, nc + B - 1)
// 이 범위가 맵을 벗어나면 이동 불가
if (nr < 1 || nc < 1 || (nr + A - 1) > N || (nc + B - 1) > M)
    continue;
```

**보통의 범위 체크(`nr > N`)와 다르다.** 대표점이 안에 있어도 **유닛 몸통이 삐져나갈 수 있다.**
`nr + A - 1 > N` 이 그것을 잡는다.

> 대표점으로 압축한 대가가 여기서도 나타난다 — **대표점 기준으로 생각하되 몸통을 잊지 않아야** 한다.

### BFS — 조건 세 개
```c
int BFS(int r, int c)
{
    int rp, wp;
    rp = wp = 0;

    // 시작점을 1로 두고, 이후 한 칸 이동할 때마다 +1 해서 거리 저장
    visit[r][c] = 1;

    queue[wp].r = r;
    queue[wp++].c = c;

    while (rp < wp)
    {
        RC out = queue[rp++];

        // 시작점을 1로 뒀으므로 실제 이동 횟수는 -1
        if (out.r == er && out.c == ec)
            return visit[out.r][out.c] - 1;

        for (int i = 0; i < 4; i++)
        {
            int nr = out.r + dr[i];
            int nc = out.c + dc[i];

            // ① 유닛 전체가 맵 안에 들어가야 함
            if (nr < 1 || nc < 1 || (nr + A - 1) > N || (nc + B - 1) > M)
                continue;

            // ② 장애물 없음  ③ 미방문
            if (isEmpty(nr, nc) == false || visit[nr][nc] != 0)
                continue;

            queue[wp].r = nr;
            queue[wp++].c = nc;
            visit[nr][nc] = visit[out.r][out.c] + 1;
        }
    }

    return -1;      // 끝까지 못 감
}
```

**세 조건의 순서가 중요하다.**
1. **범위 먼저** — `isEmpty` 가 배열 밖을 읽지 않도록
2. `isEmpty` (비싸다, `O(A×B)`)
3. `visit` (싸다)

> 사실 **`visit` 검사를 `isEmpty` 보다 앞에 두면 더 빠르다.** 이미 방문한 칸이면 비싼 검사를 건너뛸 수 있다.
> ```c
> if (visit[nr][nc] != 0 || isEmpty(nr, nc) == false) continue;   // 더 빠름
> ```
> 답은 같다. **싼 검사를 먼저**가 일반 원칙.

### 시작값 1 / 반환 시 `-1`
[36번](36_BOJ_2178_미로탐색.md)·[39번](39_BOJ_7562_나이트의이동.md)과 같은 관용구.
`visit == 0` 을 미방문 판정에 쓰므로 시작을 1로 두고, **이동 횟수**를 물으므로 마지막에 `-1`.

`시작 == 도착` 이면 첫 `dequeue` 에서 `1 - 1 = 0` 이 자동으로 나온다.

### 복잡도
```
칸 수 × 4방향 × isEmpty 비용 = (N×M) × 4 × (A×B)
```
`N, M ≤ 500`, `A, B ≤ 500` 이면 최악에 커 보이지만, **유닛이 크면 놓을 수 있는 위치가 적어져** 실제로는 균형이 맞는다. (`(N-A+1) × (M-B+1) × A × B` 는 `N×M×?` 수준으로 억제된다.)

> 더 빠르게 하려면 **2차원 누적합**으로 `isEmpty` 를 `O(1)` 로 만들 수 있다. A형 범위에서는 불필요하다.

## 5. 예제 손 추적

### (가) 유닛 1×1, 장애물 없음 — 맨해튼 거리
```
입력  5 5 1 1 0
      1 1
      5 5
```
`A = B = 1` 이므로 평범한 격자 BFS와 같다. 장애물도 없다.
```
(1,1) → (5,5) 맨해튼 = (5-1) + (5-1) = 8
```
```
출력  8
```

### (나) 유닛 2×2 — 이동 가능 범위가 줄어든다
```
입력  5 5 2 2 0
      1 1
      4 4
```
`A = B = 2` 이므로 왼쪽 위 좌표는 **`1..4` 범위**만 가능하다 (`nr + 2 - 1 ≤ 5` → `nr ≤ 4`).
```
(1,1) → (4,4) 맨해튼 = 3 + 3 = 6
```
```
출력  6
```

**유닛이 커지면 도착 좌표도 작아진다.** `(5,5)` 는 애초에 놓을 수 없는 위치 — 문제가 유효한 도착점을 준다.

### (다) 시작 = 도착
```
입력  5 5 1 1 0
      2 2
      2 2
```
```
출력  0
```
첫 `dequeue` 에서 즉시 반환.

> 세 케이스 모두 실행으로 검증했다.
> ```bash
> printf '5 5 1 1 0\n1 1\n5 5\n' | ./a.out    # 8
> printf '5 5 2 2 0\n1 1\n4 4\n' | ./a.out    # 6
> printf '5 5 1 1 0\n2 2\n2 2\n' | ./a.out    # 0
> ```
> **입력 첫 줄이 `N M A B K` 다섯 개**라는 점에 주의 — K를 빠뜨리면 이후 값이 전부 밀려 엉뚱한 답(`-1`)이 나온다.

## 6. 함정 / 예상 함정
- **★★ 유닛 전체가 아니라 대표점만 범위 체크.** `nr > N` 만 보면 유닛 몸통이 격자 밖으로 삐져나간다. **`nr + A - 1 > N`** 이어야 한다.
- **★★ `isEmpty` 루프 범위 오프바이원.** `sr ~ sr + A - 1` 이지 `sr ~ sr + A` 가 아니다.
- **★ 상태를 유닛 전체로 잡으려 함.** 유닛은 모양이 고정이라 **왼쪽 위 좌표 하나**면 충분하다. 모델링 실패가 가장 큰 손해.
- **★ 입력 첫 줄이 다섯 개(`N M A B K`).** K를 빼먹으면 이후 `scanf` 가 전부 밀린다. **증상이 `-1` 이라 원인을 찾기 어렵다.**
- **★ 장애물 좌표와 유닛 좌표의 기준 혼동.** 장애물은 그냥 칸이고, 유닛 좌표는 **왼쪽 위 기준**이다.
- **시작 위치 자체가 유효한지 검사 안 함.** 문제가 보장하지만, 방어적으로 `isEmpty(sr, sc)` 를 확인할 수 있다.
- **비싼 검사를 먼저 함.** `visit` 을 `isEmpty` 앞에 두면 더 빠르다.
- **시작값 1 / 반환 `-1`** 오프셋.
- **도달 불가 시 `-1` 반환** 을 빠뜨림. `while` 을 빠져나온 뒤 `return -1`.

## 7. 백지 재현 체크리스트

- [ ] 범위 체크에 **`nr + A - 1 > N`** 을 넣었는가
- [ ] `isEmpty` 루프가 `sr ~ sr + A - 1` 인가
- [ ] 입력 첫 줄이 **다섯 개**임을 확인했는가
- [ ] 싼 검사(`visit`)를 비싼 검사(`isEmpty`) 앞에 둘 수 있는가
- [ ] 시작값 1 / 반환 `-1` 오프셋을 넣었는가
- [ ] 도달 불가 시 `-1` 을 반환하는가
