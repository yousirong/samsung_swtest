# 37 — 벽 부수고 이동하기 (BOJ 2206 · 14442) ★★

> **이 그룹, 어쩌면 1부 전체에서 가장 중요한 문제다.**
> 여기서 배우는 "상태 확장"이 기출 BFS의 절반을 떠받친다.

## 1. 문제 요약
N×M 지도에서 `0` 은 이동 가능, `1` 은 벽.
`(1,1)` 에서 `(N,M)` 까지 최단 경로의 칸 수를 구한다. **단, 벽을 최대 한 번 부수고 지나갈 수 있다.**
도달 불가면 `-1`.

- **2206**: 벽을 최대 **1번**
- **14442**: 벽을 최대 **K번** (K ≤ 10)

## 2. 필요한 이론
→ [G05 — ④ 상태 확장](../../theory/G05_그리드탐색심화.md)

### 왜 평범한 BFS로는 안 되는가

`visit[r][c]` 하나만 쓰면 이런 일이 벌어진다.

```
어떤 칸 X에 두 경로로 도달할 수 있다고 하자.
  경로 A: 거리 5, 벽을 이미 부숨   (crash = 1)
  경로 B: 거리 7, 벽을 안 부숨     (crash = 0)

BFS는 A가 먼저 도착하므로 X를 방문 처리한다.
→ B는 X에 못 들어간다.
→ 하지만 X 이후에 벽이 하나 더 있다면?
   A는 이미 부술 기회를 썼으므로 막힌다.
   B였다면 뚫었을 텐데, 진입 자체를 못 했다.
```

**거리가 짧다고 항상 유리한 게 아니다.** "부술 기회를 남겨둔 상태"가 더 가치 있을 수 있다.

> ### ★★ 해법: 같은 좌표라도 상태가 다르면 다른 노드
> ```
> (r, c)  →  (r, c, crash)
> ```
> 방문 배열에 **상태 축을 하나 추가**한다.
> ```c
> int visit[2][MAX][MAX];   // visit[벽 부순 횟수][r][c]
> ```
> 이제 `X` 를 `crash=0` 으로도, `crash=1` 로도 각각 한 번씩 방문할 수 있다.

## 3. 코드 흐름
```
main()
 └ input()               N, M, 지도 (%1d)
   printf(BFS(1, 1))

BFS(r, c):
   visit[0][r][c] = 1                    ← crash=0 상태로 시작
   큐에 (r, c, crash=0) 삽입
   while (큐):
      out = dequeue
      if (도착) return visit[out.crash][out.r][out.c]
      4방향:
         범위 밖이면 skip
         if (out.crash == 0):
            빈칸이고 visit[0] 미방문  → crash=0 으로 이동
            벽이고   visit[1] 미방문  → crash=1 로 이동 (부수기)
         else:
            빈칸이고 visit[1] 미방문  → crash=1 로 이동
   return -1
```

## 4. 핵심 코드

### ★ 자료구조 — 상태를 큐에도 싣는다
```c
int visit[2][MAX][MAX];         // visit[벽 부순 횟수][r][c] = 해당 상태로 도착한 거리

struct RC
{
    int r;
    int c;
    int crash;   // 지금까지 벽을 부순 횟수 (0 또는 1)
};

RC queue[MAX * MAX * 2];        // ★ 상태 수가 2배이므로 큐도 2배 크기
```

**세 가지가 세트로 움직인다.**
1. `visit` 에 상태 축 추가 → `visit[2][...]`
2. 큐 원소에 상태 필드 추가 → `int crash`
3. **큐 배열 크기에 상태 수 곱하기** → `* 2`

3번을 잊으면 큰 입력에서 오버런한다. [G02](../../theory/G02_스택큐덱.md)의 "큐는 전진만 한다"가 여기서 배로 작용한다.

### 상태 전이 — 두 갈래
```c
// ---------------------------
// 아직 벽을 한 번도 안 부순 상태
// ---------------------------
if (out.crash == 0)
{
    // 다음 칸이 빈칸이고, 아직 "벽을 안 부순 상태"로 방문하지 않았다면 이동 가능
    if (MAP[nr][nc] == 0 && visit[0][nr][nc] == 0)
    {
        queue[wp].r = nr;
        queue[wp].c = nc;
        queue[wp++].crash = 0;                              // ★ 상태 유지
        visit[0][nr][nc] = visit[0][out.r][out.c] + 1;
    }
    else
    {
        // 다음 칸이 벽이라면, 이번에 벽을 부수고 이동 가능
        // 단, 아직 "벽 1번 부순 상태"로 방문한 적이 없어야 함
        if (MAP[nr][nc] == 1 && visit[1][nr][nc] == 0)
        {
            queue[wp].r = nr;
            queue[wp].c = nc;
            queue[wp++].crash = 1;                          // ★ 상태 전이!
            visit[1][nr][nc] = visit[0][out.r][out.c] + 1;  // ★ 부모는 visit[0]
        }
    }
}
```

**`visit[1][nr][nc] = visit[0][out.r][out.c] + 1`** 이 이 문제의 심장이다.
- 쓰는 곳은 `visit[1]` (자식 상태)
- 읽는 곳은 `visit[0]` (**부모 상태**)

상태가 바뀌는 전이에서는 **읽기와 쓰기의 상태 축이 다르다.** 여기서 둘 다 `visit[1]` 로 쓰면 초기값 0을 읽어 거리가 1로 리셋된다.

`out.crash == 1` 인 경우는 더 부술 수 없으므로 빈칸으로만 이동하며 `visit[1]` 안에서만 논다.

### 구조체 큐 삽입 — 필드가 3개
```c
queue[wp].r = nr;
queue[wp].c = nc;
queue[wp++].crash = 0;      // ★ 마지막 대입에서만 wp++
```
필드가 늘어나도 규칙은 같다. **마지막에서만 증가.**

### 범위 체크 — sentinel을 못 쓴다
```c
if (nr < 1 || nc < 1 || nr > N || nc > M) continue;
```
[34번](34_BOJ_2667_단지번호붙이기.md)처럼 테두리를 벽(`0`)으로 두는 트릭을 **여기서는 쓸 수 없다.**
이 문제는 **벽도 이동 대상**이기 때문 — 테두리 벽을 "부수고" 지도 밖으로 나가버린다.
그래서 명시적 범위 체크가 필수다.

### 14442 (K번) 로의 확장
```c
int visit[K + 1][MAX][MAX];     // 상태 축이 0..K
RC queue[MAX * MAX * (K + 1)];  // 큐도 (K+1)배

// 전이
if (out.crash < K && MAP[nr][nc] == 1 && visit[out.crash + 1][nr][nc] == 0)
{
    ... crash = out.crash + 1
    visit[out.crash + 1][nr][nc] = visit[out.crash][out.r][out.c] + 1;
}
```
**상태 축의 크기만 2 → K+1 로 늘리면 된다.** 구조는 그대로 — 이것이 상태 확장 기법의 확장성이다.

## 5. 예제 손 추적

### (가) BOJ 2206 예제 1 — 정답 **15**
```
입력  6 4
      0100          . # . .
      1110          # # # .
      1000          # . . .
      0000          . . . .
      0111          . # # #
      0000          . . . .
```
(`#` = 1 = 벽, `.` = 0 = 길)

`(1,1)` 에서 `(6,4)` 로 가야 한다.

**벽을 안 부수고 갈 수 있는가?**
`(1,1)` 은 길이지만 오른쪽 `(1,2)` 는 벽, 아래 `(2,1)` 도 벽. → **시작하자마자 막힌다.**
따라서 **반드시 한 번은 부숴야 한다.** 문제는 *어디서* 부수느냐다.

**부수는 위치가 이후를 결정한다.**

| 어디서 부수나 | 그 다음 |
|---|---|
| `(2,1)` 벽을 부숨 | 왼쪽 줄로 내려가지만, 이후 `(5,4)` 가 벽(5행 = `0111`)이라 **오른쪽 아래로 못 붙는다.** 기회를 이미 썼으므로 막힘 |
| 벽을 아껴두고 우회 | 더 멀리 돌아가지만 **결정적인 순간에 한 번 쓸 수 있다** |

**"거리가 짧은 쪽"과 "기회를 남긴 쪽"이 서로 다른 칸에서 유리해진다.** 그래서 두 경로를 **둘 다 살려둬야** 하고, 그것이 `visit[0]` / `visit[1]` 두 장의 지도다.

`visit[0]` (기회 보존)과 `visit[1]` (기회 소진)이 **동시에 확산**하며 각자의 최단을 기록하고, 도착 칸에 먼저 닿은 쪽이 답 **15**가 된다.

> 한 장짜리 `visit` 으로 풀면 이 예제에서 **다른 값이 나온다.** 직접 지워보고 비교하는 것이 이 문제를 가장 확실히 이해하는 방법이다.

```
출력  15
```

### (나) BOJ 2206 예제 2 — 정답 **-1**
```
입력  4 4
      0111          . # # #
      1111          # # # #
      1111          # # # #
      1110          # # # .
```
`(1,1)` 에서 `(4,4)` 까지 가려면 벽을 **여러 개** 부숴야 한다. 기회는 1번뿐 → 불가능.

```
출력  -1
```

> 두 예제 모두 실행으로 검증했다.
> ```bash
> printf '6 4\n0100\n1110\n1000\n0000\n0111\n0000\n' | python3 docs/split.py 37_BOJ_2206_14442_벽부수고이동하기.cpp 2206   # 15
> printf '4 4\n0111\n1111\n1111\n1110\n' | python3 docs/split.py 37_BOJ_2206_14442_벽부수고이동하기.cpp 2206              # -1
> ```

### `visit` 두 장을 나란히 보기
소스에 디버그 함수가 있다.
```c
printf("visit[0]\n");  printMap(visit[0]);
printf("visit[1]\n");  printMap(visit[1]);
```
**두 지도를 함께 출력해 보는 것**이 이 문제를 이해하는 가장 빠른 길이다.
`visit[0]` 은 "벽을 아낀 채 갈 수 있는 곳", `visit[1]` 은 "한 번 쓰고 갈 수 있는 곳" — 서로 다른 영역을 덮는다.

## 6. 함정 / 예상 함정
- **★★ `visit[r][c]` 하나로 품.** 이 문제의 존재 이유를 놓친 것. 예제 1에서 틀린 답이 나온다.
- **★★ 상태 전이에서 부모의 상태 축을 잘못 읽음.**
  ```c
  visit[1][nr][nc] = visit[0][out.r][out.c] + 1;   // ✓ 부모는 visit[0]
  visit[1][nr][nc] = visit[1][out.r][out.c] + 1;   // ✗ 초기값 0을 읽어 거리 리셋
  ```
- **★★ 큐 크기에 상태 수를 안 곱함.** `MAX * MAX` 로 두면 최악의 경우 오버런. `* 2` (또는 `* (K+1)`).
- **★ 테두리 sentinel 을 씀.** 벽도 이동 대상이라 테두리를 부수고 나간다. **명시적 범위 체크 필수.**
- **★ 구조체 큐에서 `wp++` 를 마지막이 아닌 곳에.** 필드가 3개라 더 어긋나기 쉽다.
- **`else` 구조 주의.** 위 코드는 `if (빈칸 && 미방문) { } else { if (벽 && 미방문) { } }` 형태다. `else` 가 붙어 있어 "빈칸인데 이미 방문한 경우"에도 벽 분기로 들어가지만, `MAP[nr][nc] == 1` 조건이 다시 걸러준다. 헷갈리면 `else` 를 떼고 독립 `if` 두 개로 쓰는 편이 안전하다.
- **도착 판정 위치.** 큐에서 **꺼낼 때** 검사한다. 넣을 때 검사해도 되지만 시작점이 곧 도착인 경우를 놓칠 수 있다.
- **`crash` 상태를 큐에 안 싣고 전역으로 관리.** 각 경로마다 다른 값이라 전역으로는 불가능하다.
- 한 파일에 프로그램 2개 — 그대로 컴파일 불가.

## 7. 백지 재현 체크리스트
- [ ] **왜 `visit[r][c]` 하나로는 안 되는지** 반례를 들어 설명할 수 있는가
- [ ] `visit[상태][r][c]` 로 축을 추가했는가
- [ ] 큐 원소에 **상태 필드를 함께 실었는가**
- [ ] **큐 배열 크기에 상태 수를 곱했는가**
- [ ] 상태 전이 시 **부모의 상태 축**을 올바로 읽는가
- [ ] 벽도 이동 대상이라 **sentinel 을 못 쓴다**는 것을 아는가
- [ ] 2206(1번)을 14442(K번)로 확장할 수 있는가
- [ ] 다른 문제에서 "상태 축으로 잡을 것"을 찾아낼 수 있는가

## 8. 한 줄 요약
"**같은 좌표라도 상태가 다르면 다른 노드.** `visit[상태][r][c]` + 큐에 상태 싣기 + **큐 크기 곱하기**."
