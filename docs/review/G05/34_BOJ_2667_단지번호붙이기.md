# 34 — 단지번호붙이기 (BOJ 2667)

| 항목 | 내용 |
|---|---|
| 유형 | G05 그리드 탐색 심화 — **플러드필 ①** |

## 1. 문제 요약
N×N 지도에서 집은 `1`, 빈터는 `0`. **상하좌우로 붙어 있는 집들의 모임**을 단지라 한다.
- 총 단지 수
- 각 단지의 집 수를 **오름차순**으로

## 2. 필요한 이론
→ [G05 — ① 플러드필](../../theory/G05_그리드탐색심화.md)

[G03 24번 바이러스](../G03/24_BOJ_2606_바이러스DFS.md)의 "연결 요소 세기"를 격자로 옮긴 것이다. 정점 번호가 `(r, c)` 가 됐을 뿐 알고리즘은 동일하다.

> **★ 플러드필의 골격 = 이중 루프 + BFS**
> 바깥 이중 루프가 **시작점 후보를 훑고**, BFS가 **덩어리 하나를 통째로 먹는다.**
> BFS가 크기를 반환하게 하면 답이 바로 나온다.

## 3. 코드 흐름
```
main()
 └ input()                          N, 지도 (%1d 로 한 자리씩)
   for r in 1..N, c in 1..N:
      if (집이고 미방문) answers[ansCount++] = BFS(r, c)   ← 단지 하나
   printf(ansCount)                 총 단지 수
   선택 정렬 (오름차순)
   각 단지 크기 출력
```

## 4. 핵심 코드

### 입력 — `%1d` 관용구
```c
scanf("%1d", &MAP[r][c]);
```
입력이 `0110100` 처럼 **공백 없이 붙어** 있다. `%d` 로 읽으면 `110100` 이 통째로 들어간다.
`%1d` 는 "한 자리만 읽어라"는 뜻 — 지도 문제에서 반복 등장하는 관용구다.

### 플러드필 — 시작점 훑기
```c
int ansCount = 0;

// 모든 칸을 순회하면서
// 아직 방문하지 않은 집(1)을 만나면 BFS 시작
for (int r = 1; r <= N; r++)
{
    for (int c = 1; c <= N; c++)
    {
        if (MAP[r][c] == 1 && visit[r][c] == false)
        {
            answers[ansCount++] = BFS(r, c);
        }
    }
}
```

**두 조건이 모두 필요하다.**
- `MAP == 1` — 집이어야 시작
- `visit == false` — **이미 다른 단지에 흡수된 칸이면 건너뛴다**

두 번째를 빼면 같은 단지를 집 개수만큼 반복해서 센다.

### BFS — 크기를 반환한다
```c
int BFS(int r, int c)
{
    int rp, wp;
    rp = wp = 0;

    queue[wp].r = r;
    queue[wp++].c = c;      // ★ 마지막 대입에서만 wp++
    visit[r][c] = true;     // ★ 넣는 순간 찍는다

    while (rp < wp)
    {
        RC out = queue[rp++];

        for (int i = 0; i < 4; i++)
        {
            int nr = out.r + dr[i];
            int nc = out.c + dc[i];

            if (MAP[nr][nc] == 0 || visit[nr][nc] == true) continue;

            queue[wp].r = nr;
            queue[wp++].c = nc;
            visit[nr][nc] = true;
        }
    }

    return wp;      // ★ 큐에 들어간 칸 수 = 단지 크기
}
```

**`return wp` 가 우아하다.** 별도 카운터가 필요 없다 — `wp` 는 이 BFS에서 큐에 넣은 총 개수이고, `visit` 을 넣을 때 찍었으므로 각 칸이 정확히 한 번씩만 들어갔기 때문이다.

> `visit` 을 꺼낼 때 찍었다면 중복 삽입으로 `wp` 가 부풀어 **이 트릭이 깨진다.** [G03](../../theory/G03_DFS_BFS기초.md)의 규칙이 여기서 결과에 직접 반영된다.

### 범위 체크가 없는 이유
```c
if (MAP[nr][nc] == 0 || visit[nr][nc] == true) continue;
```
`nr`, `nc` 가 범위를 벗어나도 `if` 가 없다. **테두리 sentinel** 덕분이다.
`MAP` 은 전역이라 0으로 초기화되어 있고, `1..N` 밖은 전부 0(빈터)이므로 자동으로 걸러진다.
`#define MAX (25 + 5)` 의 `+5` 가 그 여유.

### 정렬 — 선택 정렬
```c
for (int i = 0; i < ansCount - 1; i++)
    for (int k = i + 1; k < ansCount; k++)
        if (answers[i] > answers[k])
        { int tmp = answers[i]; answers[i] = answers[k]; answers[k] = tmp; }
```
STL `sort` 가 없으므로 직접 쓴다. [G04](../../theory/G04_경우의수.md)의 입력 정렬과 같은 관용구.

## 5. 예제 손 추적 — BOJ 2667 예제

```
입력  7
      0110100          . # # . # . .
      0110101          . # # . # . #
      1110101          # # # . # . #
      0000111    →     . . . . # # #
      0100000          . # . . . . .
      0111110          . # # # # # .
      0111000          . # # # . . .
```

이중 루프가 `(1,1)` 부터 훑는다.

| 시작점 발견 | BFS가 먹는 칸 | 크기 |
|---|---|---|
| `(1,2)` | `(1,2)(1,3)(2,2)(2,3)(3,1)(3,2)(3,3)` | **7** |
| `(1,5)` | `(1,5)(2,5)(2,7)(3,5)(3,7)(4,5)(4,6)(4,7)` | **8** |
| `(5,2)` | `(5,2)(6,2)(6,3)(6,4)(6,5)(6,6)(7,2)(7,3)(7,4)` | **9** |

> `(2,2)` 에 도달했을 때는 이미 `visit` 이 찍혀 있어 새 BFS가 시작되지 않는다. 이게 `visit[r][c] == false` 조건의 역할.

`answers = {7, 8, 9}` → 이미 오름차순이라 정렬해도 그대로.

```
출력  3
      7
      8
      9
```

> 실행으로 검증했다.
> ```bash
> printf '7\n0110100\n0110101\n1110101\n0000111\n0100000\n0111110\n0111000\n' | ./a.out
> ```

## 6. 함정 / 예상 함정
- **★★ `%1d` 를 안 씀.** `0110100` 이 한 정수로 읽혀 지도가 완전히 깨진다. 입력 형식을 먼저 본다.
- **★ 시작점 조건에서 `visit` 검사 누락.** 같은 단지를 여러 번 세어 단지 수가 폭증한다.
- **★ 구조체 큐 삽입에서 `wp++` 위치.**
  ```c
  queue[wp].r = r;
  queue[wp++].c = c;      // ✓ 마지막에서만
  ```
  첫 줄에 `wp++` 를 쓰면 `.c` 가 다음 칸에 들어가 좌표가 어긋난다.
- **`return wp` 가 크기가 되려면** `visit` 을 넣을 때 찍어야 한다. 꺼낼 때 찍으면 중복 삽입으로 크기가 부푼다.
- **대각선을 포함시킴.** 이 문제는 **상하좌우 4방향**이다. 8방향은 [35번 섬의 개수](35_BOJ_4963_섬의개수.md).
- **테두리 sentinel 을 믿었는데 `MAX` 가 부족.** `N` 이 최대일 때 `N+1` 인덱스를 쓰므로 `+여유` 가 필요하다.
- **정렬 없이 출력.** 문제가 오름차순을 요구한다.
- `answers` 크기는 최악의 경우(체크무늬로 집이 흩어짐) `N*N/2` 정도. `MAX * MAX` 로 넉넉히.

## 7. 백지 재현 체크리스트
- [ ] `%1d` 로 붙은 숫자를 한 자리씩 읽었는가
- [ ] 시작점 조건이 **`집 && 미방문`** 두 개인가
- [ ] BFS가 `return wp` 로 크기를 돌려주는 구조인가, 그게 왜 성립하는지 아는가
- [ ] 구조체 큐 삽입에서 `wp++` 를 **마지막 대입에만** 붙였는가
- [ ] `visit` 을 큐에 **넣는 순간** 찍는가
- [ ] 4방향인가 8방향인가를 문제에서 확인했는가
- [ ] 테두리 sentinel 로 범위 체크를 생략했는가
- [ ] 선택 정렬을 STL 없이 쓸 수 있는가

## 8. 한 줄 요약
"**이중 루프가 시작점을 훑고, BFS가 덩어리를 먹는다.** `return wp` 가 곧 크기."
