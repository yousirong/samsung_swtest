## 1. 문제 요약
컴퓨터 V대가 네트워크로 연결되어 있다. 1번 컴퓨터가 웜 바이러스에 걸렸을 때,
**1번을 통해 감염되는 컴퓨터 수**를 출력한다. (1번 자신은 제외)

= 1번이 속한 연결 요소(connected component)의 크기 - 1

## 2. 필요한 이론
→ [G03 DFS/BFS 기초 — DFS](../../theory/G03_DFS_BFS기초.md)

**DFS의 원형 문제다.** 세는 것은 "1번에서 도달 가능한 정점 수"이고, 도달 가능성만 물으므로 DFS/BFS 어느 쪽이든 된다. [25번](25_BOJ_2606_바이러스BFS.md)이 같은 문제의 BFS 판이니 **나란히 읽는 것**이 이 그룹의 핵심 학습이다.

## 3. 코드 흐름
```
main()
 └ input()          V, E, 간선 → 인접 행렬 (양방향)
   DFS(1)           1번부터 재귀 탐색, 갈 때마다 count++
   printf(count)
```

`count` 가 전역이라 별도 반환값 없이 누적된다. 1번 자신은 `count` 에 안 더해지므로 자연스럽게 "1번 제외"가 된다.

## 4. 핵심 코드

### 인접 행렬 — 양방향 등록
```c
scanf("%d %d", &n1, &n2);

// 무방향 그래프이므로 양쪽 모두 연결 표시
MAP[n1][n2] = 1;
MAP[n2][n1] = 1;
```
**한 줄이라도 빠뜨리면 답이 작게 나온다.** 무방향 그래프의 기본기.

### DFS — 전부 이게 다다
```c
void DFS(int node)
{
    // 현재 노드 방문 처리
    visit[node] = true;

    // 현재 노드와 연결된 모든 노드 확인
    for (int c = 1; c <= V; c++)
    {
        // 연결이 없거나 이미 방문한 경우 건너뜀
        if (MAP[node][c] == 0 || visit[c] == true)
            continue;

        // 새롭게 감염된 컴퓨터
        count++;

        // 해당 노드로 깊이 우선 탐색 진행 (재귀 호출)
        DFS(c);
    }
}
```

세 가지만 보면 된다.
1. **진입 즉시 `visit[node] = true`** — 재귀가 되돌아오는 것을 막는다
2. **`연결 없음 || 이미 방문` → `continue`** — 이 한 줄이 DFS 관용구
3. **`count++` 를 재귀 호출 직전에** — 새로 감염된 순간에만 센다

### `count` 를 세는 위치가 왜 저기인가
```c
count++;      // ← 여기 (자식으로 내려가기 직전)
DFS(c);
```
`DFS` 함수 안에서 `count++` 를 하면 **시작 노드 1번까지 세어** 답이 1 커진다.
"자식으로 내려갈 때만 센다"는 배치가 곧 "1번 제외" 규칙의 구현이다.

> 대안: `DFS` 안에서 세고 마지막에 `count - 1` 을 출력해도 된다. 어느 쪽이든 **한 번 정하고 일관되게** 쓰는 게 중요하다.

## 5. 예제 손 추적 — BOJ 2606 예제

```
입력    7        (컴퓨터 7대)
        6        (연결 6개)
        1 2
        2 3
        1 5
        5 2
        5 6
        4 7
```

인접 관계:
```
      1 ── 2 ── 3
      │   ╱
      │  ╱
      5 ─┘
      │
      6              4 ── 7    ← 별개 덩어리
```

`DFS(1)` 재귀 전개:

| 깊이 | 호출 | `c` 스캔 | 동작 | `count` |
|---|---|---|---|---|
| 0 | `DFS(1)` | `visit[1]=T` | | 0 |
| 0 | | c=2: 연결 O, 미방문 | `count++`, `DFS(2)` | **1** |
| 1 | `DFS(2)` | `visit[2]=T` | | 1 |
| 1 | | c=1: 이미 방문 → skip | | |
| 1 | | c=3: 연결 O, 미방문 | `count++`, `DFS(3)` | **2** |
| 2 | `DFS(3)` | `visit[3]=T`, 갈 곳 없음 | 복귀 | 2 |
| 1 | | c=5: 연결 O, 미방문 | `count++`, `DFS(5)` | **3** |
| 2 | `DFS(5)` | `visit[5]=T` | | 3 |
| 2 | | c=1, c=2: 이미 방문 | | |
| 2 | | c=6: 연결 O, 미방문 | `count++`, `DFS(6)` | **4** |
| 3 | `DFS(6)` | `visit[6]=T`, 갈 곳 없음 | 복귀 | 4 |
| 1 | | 스캔 종료 → 복귀 | | |
| 0 | | c=5: 이미 방문, c=6,7: 연결 X | 종료 | 4 |

```
출력    4
```

**4, 7은 한 번도 방문되지 않는다.** 1번과 연결된 덩어리에 속하지 않기 때문 — 이게 "연결 요소"의 의미다.

> 실행으로 검증했다.
> ```bash
> printf '7\n6\n1 2\n2 3\n1 5\n5 2\n5 6\n4 7\n' | ./a.out    # 4
> ```

**방문 순서는 `1 → 2 → 3 → 5 → 6`.** 2에서 3으로 **끝까지 내려갔다가** 되돌아와 5로 가는 것이 "깊이 우선"이다. [25번 BFS](25_BOJ_2606_바이러스BFS.md)에서는 순서가 달라진다(답은 같다).

## 6. 함정 / 예상 함정
- **★ 간선을 한 방향만 등록.** `MAP[n1][n2] = 1` 만 쓰면 무방향이 아니게 되어 답이 작아진다. 예제에서 `4 7` 은 어차피 안 닿아 티가 안 나므로 **다른 케이스에서야 발견**되는 유형.
- **★ `count` 를 세는 위치.** `DFS` 진입부에서 세면 1번까지 포함되어 5가 나온다. 재귀 호출 직전에 세거나, 마지막에 1을 빼거나 — 둘 중 하나만.
- **`visit` 을 재귀 호출 후에 찍음.** 진입 직후여야 한다. 늦게 찍으면 무한 재귀에 빠진다.
- **`visit` 을 되돌림(`visit[node] = false`).** 이건 백트래킹([G04](../../theory/G04_경우의수.md))의 습관이다. **연결 요소 탐색에서는 절대 되돌리지 않는다.** 되돌리면 모든 경로를 다 세어 지수 시간이 된다 — 이 둘의 구분이 나중에 큰 차이를 만든다.
- **`count` 초기화.** 전역이라 자동으로 0이지만, T-loop 문제라면 케이스마다 리셋이 필요하다.
- **재귀 깊이.** V ≤ 100 이라 문제없다. 격자 문제에서 100만 칸짜리 DFS는 스택 오버플로 위험이 있어 BFS로 바꾸는 판단이 필요하다.

## 7. 백지 재현 체크리스트
- [ ] 인접 행렬을 **양방향**으로 등록했는가
- [ ] `visit[node] = true` 를 함수 **진입 직후**에 찍었는가
- [ ] `연결 없음 || 이미 방문 → continue` 관용구를 쓸 수 있는가
- [ ] `count` 를 세는 위치가 "1번 제외"를 만족하는가
- [ ] 연결 요소 탐색에서는 `visit` 을 **되돌리지 않는** 이유를 아는가
- [ ] 같은 문제를 BFS로도 바꿔 쓸 수 있는가 → [25번](25_BOJ_2606_바이러스BFS.md)

## 8. 한 줄 요약
"`visit` 진입 즉시 찍고, `연결X || 방문O → continue`, 내려갈 때만 센다. **되돌리지 않는다.**"
