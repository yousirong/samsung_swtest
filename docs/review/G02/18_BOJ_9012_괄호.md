# 18 — 괄호 (BOJ 9012)

| 항목 | 내용 |
|---|---|
| 유형 | G02 스택·큐·덱 (**스택을 카운터로 축약**) |
| 소스 | [swtest/18_BOJ_9012_괄호.cpp](../../../swtest/18_BOJ_9012_괄호.cpp) |
| 링크 | https://www.acmicpc.net/problem/9012 |
| 구조 | T-loop |

## 1. 문제 요약
주어진 문자열이 **올바른 괄호 문자열(VPS)** 인지 판별한다. `YES` / `NO` 출력.

올바른 조건 두 가지:
1. `(` 와 `)` 의 개수가 같다
2. 왼쪽부터 읽어가며 **어느 순간에도** `)` 가 `(` 보다 많아지지 않는다

## 2. 필요한 이론
→ [G02 스택·큐·덱](../../theory/G02_스택큐덱.md)

**이 문제의 교훈은 "스택을 안 써도 된다"** 는 것이다.

괄호가 한 종류뿐이면 스택에 **무엇이 들었는지는 중요하지 않고 몇 개인지만 중요**하다.
그래서 `stack[]` 전체가 정수 하나(`sp`)로 축약된다.

| | 스택 버전 | 카운터 버전 |
|---|---|---|
| `(` | `stack[sp++] = '('` | `sp++` |
| `)` | `--sp` (짝 확인) | `sp--` |
| 검사 | `sp < 0` | `sp < 0` |

> **괄호가 여러 종류(`()`, `{}`, `[]`)면 축약이 불가능하다.** 무엇이 열렸는지 기억해야 하므로 진짜 스택이 필요하다. 이 구분이 이 문제에서 챙길 감각이다.

## 3. 코드 흐름
```
main()
 └ scanf(T)
   for T번:
      scanf(str)
      sp = 0; flag = false
      length 계산 (직접)
      for i in 0..length-1:
         '(' 면 sp++, 아니면 sp--
         if (sp < 0) { flag = true; break; }      ← 조건 ②
      (flag || sp != 0) ? "NO" : "YES"            ← sp != 0 이 조건 ①
```

## 4. 핵심 코드

### 문자열 길이 — 직접 센다
```c
// '\0' (문자열 끝)까지 세면서 길이 구함
for (length = 0; str[length]; length++);
```
`strlen` 대신 쓰는 관용구. 세미콜론이 바로 오는 빈 루프다.

> 사실 이 문제에서는 길이를 미리 안 구하고 `for (int i = 0; str[i]; i++)` 로 바로 돌아도 된다. 길이를 구해두는 습관이 다른 문제에서 유용해서 남긴 형태.

### 판별 루프
```c
sp = 0;             // 현재 열린 괄호 개수
flag = false;       // 오류 발생 여부

for (int i = 0; i < length; i++)
{
    int ch = str[i];

    if (ch == '(') sp++;
    else           sp--;

    // 닫는 괄호가 더 많아지는 순간 (sp < 0) 이미 잘못된 문자열
    if (sp < 0)
    {
        flag = true;
        break;         // 더 볼 필요 없음
    }
}
```

### 최종 판별 — 두 조건을 한 줄로
```c
// 1) 중간에 실패(flag == true)
// 2) 끝났는데도 열린 괄호가 남아 있음 (sp != 0)
if (flag == true || sp != 0)  printf("NO\n");
else                          printf("YES\n");
```

**두 조건이 서로 다른 실패**라는 점이 중요하다.
- `flag` → `())` 처럼 **중간에** 깨진 경우
- `sp != 0` → `(()` 처럼 **끝까지 안 닫힌** 경우

하나만 검사하면 반대쪽 케이스를 놓친다.

## 5. 예제 손 추적

### `(())())` → **NO** (중간 실패)
| i | 문자 | `sp` | 비고 |
|---|---|---|---|
| 0 | `(` | 1 | |
| 1 | `(` | 2 | |
| 2 | `)` | 1 | |
| 3 | `)` | 0 | 여기까지 `(())` 는 정상 |
| 4 | `(` | 1 | |
| 5 | `)` | 0 | |
| 6 | `)` | **-1** | ★ `flag = true`, break |

→ `flag == true` 이므로 `NO`.

### `(((()())()` → **NO** (끝까지 안 닫힘)
`sp` 가 한 번도 음수가 되지 않아 `flag == false` 로 루프를 완주한다.
`(` 6개, `)` 4개 → 최종 `sp = 2`.

→ **`sp != 0` 조건이 아니면 놓치는 케이스.** 이걸 잡으려고 두 번째 조건이 있다.

### `(()())((()))` → **YES**
`sp` 추이: `1 2 1 2 1 0 1 2 3 2 1 0`
음수인 적 없고 최종 0 → `YES`.

> 실행으로 검증했다.
> ```bash
> printf '3\n(())())\n(((()())()\n(()())((()))\n' | ./a.out
> # NO / NO / YES
> ```

## 6. 함정 / 예상 함정
- **★ 두 실패 조건 중 하나만 검사.** `sp < 0` 만 보면 `(((` 를 YES로, `sp != 0` 만 보면 `)(` 를 YES로 낸다. **둘 다 필요하다.**
  - `)(` 는 개수는 같지만(최종 `sp = 0`) 중간에 `-1` 이 된다 → `flag` 가 잡는다
- **★ `break` 후 `sp` 값에 의존하면 안 된다.** break 시점의 `sp` 는 `-1` 이라 `sp != 0` 로도 걸리긴 하지만, 이건 우연이다. 실패 표시는 `flag` 로 명시하는 게 안전.
- **T-loop 초기화.** `sp` 와 `flag` 를 케이스마다 리셋해야 한다. 이 코드는 루프 **안에서 선언**해서 구조적으로 방지했다 — 좋은 습관.
- **`else sp--` 로 뭉뚱그림.** 입력에 `(` 와 `)` 만 온다는 보장이 있어서 가능하다. 다른 문자가 섞이는 문제면 `else if (ch == ')')` 로 명시해야 한다.
- 빈 문자열이면 `sp = 0` 으로 `YES`. 문제 조건상 길이 ≥ 2 라 무관하지만 규약은 알아둘 것.

## 7. 백지 재현 체크리스트
- [ ] 괄호가 **한 종류**라서 카운터로 축약 가능함을 설명할 수 있는가
- [ ] 여러 종류면 왜 진짜 스택이 필요한지 아는가
- [ ] 실패 조건이 **두 개**임을 아는가 (`중간 음수` + `최종 비영`)
- [ ] `)(` 가 왜 NO인지, 어느 조건에 걸리는지 아는가
- [ ] T-loop 에서 `sp`, `flag` 를 케이스마다 초기화했는가

## 8. 한 줄 요약
"괄호가 한 종류면 스택은 **정수 하나**로 줄어든다. 실패는 **중간 음수**와 **최종 비영** 두 갈래."
