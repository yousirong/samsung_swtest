# 21 — 덱 (BOJ 10866)

| 항목 | 내용 |
|---|---|
| 유형 | G02 스택·큐·덱 |
| 소스 | [swtest/21_BOJ_10866_덱.cpp](../../../swtest/21_BOJ_10866_덱.cpp) |
| 링크 | https://www.acmicpc.net/problem/10866 |
| 구조 | 명령 N개 처리 |

## 1. 문제 요약
덱(deque, double-ended queue)을 직접 구현하고 N개의 명령을 처리한다.
덱은 **앞과 뒤 양쪽에서** 삽입·삭제가 가능하다.

| 명령 | 동작 |
|---|---|
| `push_front X` / `push_back X` | 앞 / 뒤에 삽입 |
| `pop_front` / `pop_back` | 앞 / 뒤에서 제거 + 출력. 비었으면 `-1` |
| `size` | 원소 개수 |
| `empty` | 비었으면 `1` |
| `front` / `back` | 앞 / 뒤 원소 출력(제거 X). 비었으면 `-1` |

## 2. 필요한 이론
→ [G02 스택·큐·덱 — 덱](../../theory/G02_스택큐덱.md)

[19번 큐](19_BOJ_10845_18258_큐_큐2.md)에서 딱 하나가 달라진다: **`front` 가 감소할 수 있다.**

큐에서는 `rp` 가 전진만 했다. 덱에서는 `push_front` 가 `front` 를 **뒤로 밀어야** 한다.
그래서 인덱스 0에서 시작하면 즉시 음수가 된다.

> **★ 해결책: 배열 중앙에서 시작한다.**
> ```c
> #define OFFSET (MAX / 2)
> front = back = OFFSET;
> ```
> 양쪽으로 자유롭게 확장할 여유가 생긴다. 이 한 줄이 덱 구현의 전부라고 해도 된다.

## 3. 코드 흐름
```
main()
 └ front = back = OFFSET               ← 중앙에서 시작
   scanf(N)
   for N번:
      scanf(command) → strcmp 로 분기
         push_front → deque[--front] = value
         push_back  → deque[back++]  = value
         pop_front  → 비었나? -1 : printf(deque[front++])
         pop_back   → 비었나? -1 : printf(deque[--back])
         size       → printf(back - front)
         empty      → printf((back == front) ? 1 : 0)
         front      → printf(deque[front])
         back       → printf(deque[back - 1])
```

## 4. 핵심 코드

### 자료구조 — 중앙 시작이 핵심
```c
#define MAX (10000 + 500)
#define OFFSET (MAX / 2)   // 중앙 위치

int deque[MAX * 2];    // 배열로 구현한 덱
int front, back;       // front: 첫 원소 위치, back: 다음 삽입 위치

// 덱을 배열 중앙에서 시작
// 이렇게 하면 양쪽으로 자유롭게 확장 가능
front = back = OFFSET;
```

데이터 범위는 큐와 같다: `deque[front] ~ deque[back - 1]`, 개수는 `back - front`.

### 네 가지 삽입·삭제 — 증감 방향 표
```c
deque[--front] = value;              // push_front : 먼저 감소 후 쓰기
deque[back++]  = value;              // push_back  : 쓰고 나서 증가

printf("%d\n", deque[front++]);      // pop_front  : 읽고 나서 증가
printf("%d\n", deque[--back]);       // pop_back   : 먼저 감소 후 읽기
```

| | 전위(`--`) | 후위(`++`) |
|---|---|---|
| **front 쪽** | `push_front` | `pop_front` |
| **back 쪽** | `pop_back` | `push_back` |

규칙 하나로 외운다: **`front` 는 "현재 원소", `back` 은 "다음 자리".**
- `front` 쪽으로 넣으려면 → 빈 자리를 먼저 만들어야 함 → `--front`
- `back` 쪽에서 빼려면 → 마지막 원소로 먼저 내려가야 함 → `--back`

### 조회 — 비대칭 그대로
```c
printf("%d\n", deque[front]);        // front : 그대로
printf("%d\n", deque[back - 1]);     // back  : 한 칸 앞
```

### ⚠️ 자체 `strcmp` — 이름 충돌 주의
```c
int strcmp(const char* a, const char* b)   // ← 표준 함수와 같은 이름
{
    while (*a && *a == *b) { ++a; ++b; }
    return *a - *b;
}
```
[17번](17_BOJ_10828_스택.md)·[19번](19_BOJ_10845_18258_큐_큐2.md)은 `strCompare` 로 이름을 피했는데, 이 파일만 `strcmp` 를 그대로 썼다.
`<string.h>` 를 include 하지 않아 지금은 동작하지만, **누군가 헤더를 추가하는 순간 재정의 충돌**이 난다. 습관적으로 `strCompare` 를 쓰는 게 안전하다.

## 5. 예제 손 추적

`OFFSET` 을 편의상 `10` 이라 두고 따라간다 (실제는 `MAX/2 = 5250`).

명령: `push_back 1` `push_front 2` `front` `back` `size` `empty` `pop_front` `pop_back` `pop_front` `size` `empty`

| 명령 | 동작 | `front` | `back` | 배열 (인덱스 8~12) | 논리 상태 | 출력 |
|---|---|---|---|---|---|---|
| 시작 | | 10 | 10 | `_ _ _ _ _` | `[]` | |
| `push_back 1` | `deque[10]=1, back=11` | 10 | 11 | `_ _ 1 _ _` | `[1]` | |
| `push_front 2` | `front=9, deque[9]=2` | **9** | 11 | `_ 2 1 _ _` | `[2,1]` | |
| `front` | `deque[9]` | 9 | 11 | | | `2` |
| `back` | `deque[back-1]=deque[10]` | 9 | 11 | | | `1` |
| `size` | `11 - 9` | 9 | 11 | | | `2` |
| `empty` | `back != front` | 9 | 11 | | | `0` |
| `pop_front` | `deque[9]`, `front=10` | **10** | 11 | | `[1]` | `2` |
| `pop_back` | `back=10`, `deque[10]` | 10 | **10** | | `[]` | `1` |
| `pop_front` | `back == front` | 10 | 10 | | `[]` | `-1` |
| `size` | `10 - 10` | 10 | 10 | | | `0` |
| `empty` | | 10 | 10 | | | `1` |

> **`push_front 2` 에서 `front` 가 10 → 9 로 내려간 것**이 핵심이다.
> `front = back = 0` 으로 시작했다면 여기서 `deque[-1]` 을 쓴다. 이게 `OFFSET` 이 존재하는 이유.

## 6. 함정 / 예상 함정
- **★★ `OFFSET` 없이 0에서 시작.** `push_front` 첫 호출에 `deque[-1]` 을 쓴다. 전역 배열이라 크래시 없이 **인접 전역 변수를 덮어쓰는** 최악의 버그가 된다.
- **★ 배열 크기.** `deque[MAX * 2]` 에 `OFFSET = MAX / 2` 로 시작한다. 왼쪽으로 `MAX/2` 칸, 오른쪽으로 `MAX*3/2` 칸 여유. 모든 명령이 `push_front` 여도 안전하다.
  - 큐와 마찬가지로 자리는 **재활용되지 않는다**. 총 삽입 횟수 기준으로 잡는다
- **★ 증감의 전위/후위 4종을 섞음.** 위 표를 손으로 다시 유도할 수 있어야 한다. 특히 `pop_back` 은 `deque[back--]` 가 아니라 `deque[--back]`.
- **`back` 조회가 `deque[back]`.** `back` 은 아직 안 쓴 자리다. `deque[back - 1]` 이어야 한다.
- **빈 검사 누락.** `pop_front`, `pop_back`, `front`, `back` 네 곳 모두 `back == front` 검사가 필요하다.
- **`strcmp` 이름 충돌** (위 참조).
- **명령어 접두사 충돌.** `push_front` 와 `push_back` 은 앞 5글자가 같다. `strCompare` 는 전체를 비교하므로 문제없지만, "앞 4글자만 비교" 같은 최적화를 하면 깨진다.

## 7. 백지 재현 체크리스트
- [ ] `front = back = OFFSET` 으로 **중앙에서 시작**했는가, 그 이유를 설명할 수 있는가
- [ ] 네 연산의 전위/후위를 표로 유도할 수 있는가
- [ ] `front` 는 "현재 원소", `back` 은 "다음 자리" 규약을 기억하는가
- [ ] `size` 가 `back - front`, `back` 조회가 `deque[back - 1]` 인가
- [ ] 빈 검사(`back == front`)를 네 연산 모두에 넣었는가
- [ ] 배열 크기를 총 삽입 횟수 기준으로 잡았는가
- [ ] 자체 구현 함수 이름을 표준과 겹치지 않게 지었는가

## 8. 한 줄 요약
"덱 = 큐 + **감소하는 front**. 그래서 **배열 중앙에서 시작**한다."
