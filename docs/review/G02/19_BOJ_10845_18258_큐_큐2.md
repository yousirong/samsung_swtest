# 19 — 큐 · 큐 2 (BOJ 10845 · 18258)

| 항목 | 내용 |
|---|---|
| 유형 | G02 스택·큐·덱 ★ **이후 모든 BFS의 원형** |
| 소스 | [swtest/19_BOJ_10845_18258_큐_큐2.cpp](../../../swtest/19_BOJ_10845_18258_큐_큐2.cpp) |
| 링크 | https://www.acmicpc.net/problem/10845 · https://www.acmicpc.net/problem/18258 |
| 구조 | 명령 N개 처리 |

## 1. 문제 요약
큐를 직접 구현하고 N개의 명령을 처리한다.

| 명령 | 동작 |
|---|---|
| `push X` | 뒤에 X를 넣는다 |
| `pop` | 앞의 원소를 빼고 출력. 비었으면 `-1` |
| `size` | 원소 개수 |
| `empty` | 비었으면 `1`, 아니면 `0` |
| `front` | 앞 원소 출력(제거 X). 비었으면 `-1` |
| `back` | 뒤 원소 출력(제거 X). 비었으면 `-1` |

10845와 18258은 명령 개수 상한만 다르다(2만 / 200만). 같은 코드로 푼다.

## 2. 필요한 이론
→ [G02 스택·큐·덱 — 큐](../../theory/G02_스택큐덱.md)

**이 그룹에서 가장 중요한 문제다.** 여기서 만든 큐가 [G03 DFS/BFS](../../theory/G03_DFS_BFS기초.md)부터 기출 38개 전부에서 그대로 쓰인다. 기출에서는 `int` 대신 `RC` 구조체가 들어갈 뿐 골격이 동일하다.

포인터 두 개를 쓴다.
```
rp (read pointer)  → 현재 맨 앞 원소 위치
wp (write pointer) → 다음 원소가 들어갈 위치

실제 데이터 = queue[rp] ~ queue[wp - 1]
```

## 3. 코드 흐름
```
main()
 └ rp = wp = 0
   scanf(N)
   for N번:
      scanf(command)
      strCompare 로 분기:
         push  → scanf(value); queue[wp++] = value
         pop   → (wp == rp) ? -1 : printf(queue[rp++])
         size  → printf(wp - rp)
         empty → printf((wp == rp) ? 1 : 0)
         front → (wp == rp) ? -1 : printf(queue[rp])
         back  → (wp == rp) ? -1 : printf(queue[wp - 1])
```

## 4. 핵심 코드

### 자료구조 — 배열 하나 + 포인터 둘
```c
int queue[MAX];   // 배열로 구현한 큐
int rp, wp;       // rp: 읽기 위치, wp: 쓰기 위치
```

### 여섯 연산
```c
queue[wp++] = value;                     // push  : 뒤에 넣고 wp 증가

printf("%d\n", queue[rp++]);             // pop   : 앞에서 읽고 rp 증가

printf("%d\n", wp - rp);                 // size  ★ wp 가 아니다

printf("%d\n", (wp == rp) ? 1 : 0);      // empty

printf("%d\n", queue[rp]);               // front : rp 그대로

printf("%d\n", queue[wp - 1]);           // back  : wp 바로 앞
```

**스택과의 대비**: 스택은 `pop` 이 전위 감소(`--sp`)였는데, 큐는 `pop` 이 **후위 증가**(`rp++`)다.
- 스택 `sp` 는 다음 자리 → 빼려면 먼저 내려가야 함
- 큐 `rp` 는 **현재 앞 원소** → 바로 읽고 나서 전진

`wp` 만 "다음 자리"고 `rp` 는 "현재 자리"라는 비대칭을 기억한다.

### 빈 검사는 `wp == rp`
```c
if (wp == rp) printf("-1\n");
else          printf("%d\n", queue[rp++]);
```
개수가 `wp - rp` 이므로 0이라는 뜻. 네 연산(`pop`, `front`, `back`, `empty`)이 전부 이 조건을 쓴다.

### 디버그 함수
```c
void printQueue()
{
    for (int i = rp; i < wp; i++)   // 앞에서 뒤로
        printf("%d ", queue[i]);
    putchar('\n');
}
```
루프 범위 `rp ..< wp` 자체가 "데이터 범위" 규약의 표현이다.

## 5. 예제 손 추적

명령: `push 1` `push 2` `front` `back` `size` `empty` `pop` `pop` `pop` `size` `empty` `pop` `push 3` `empty` `front`

| 명령 | `rp` | `wp` | 배열 (인덱스별) | 유효 구간 | 출력 |
|---|---|---|---|---|---|
| 시작 | 0 | 0 | `[_ _ _]` | 없음 | |
| `push 1` | 0 | 1 | `[1 _ _]` | `[0,1)` | |
| `push 2` | 0 | 2 | `[1 2 _]` | `[0,2)` | |
| `front` | 0 | 2 | | | `1` |
| `back` | 0 | 2 | `queue[wp-1]=queue[1]` | | `2` |
| `size` | 0 | 2 | `wp - rp` | | `2` |
| `empty` | 0 | 2 | | | `0` |
| `pop` | **1** | 2 | `[1 2 _]` | `[1,2)` | `1` |
| `pop` | **2** | 2 | `[1 2 _]` | 없음 | `2` |
| `pop` | 2 | 2 | `wp == rp` | | `-1` |
| `size` | 2 | 2 | `2 - 2` | | `0` |
| `empty` | 2 | 2 | | | `1` |
| `pop` | 2 | 2 | | | `-1` |
| `push 3` | 2 | **3** | `[1 2 3]` | `[2,3)` | |
| `empty` | 2 | 3 | | | `0` |
| `front` | 2 | 3 | `queue[2]` | | `3` |

> **★ 마지막 `push 3` 을 보라.** 큐가 논리적으로 비었는데도 `queue[0]`, `queue[1]` 을 재활용하지 않고 `queue[2]` 에 썼다.
> `rp` 도 `wp` 도 **전진만 하기 때문**이다. 이것이 다음 함정의 정체다.

## 6. 함정 / 예상 함정
- **★★ 큐 배열 크기 산정.** 위 추적에서 봤듯 자리가 재활용되지 않는다. 배열 크기는 "동시에 든 최대 개수"가 아니라 **총 push 횟수**로 잡아야 한다.
  - 이 문제는 명령이 N개이므로 push도 최대 N개 → `MAX` 로 충분
  - 하지만 [20번 카드1](20_BOJ_2161_카드1.md) 처럼 **루프 안에서 push 가 추가로 일어나면** 크기가 모자란다. 거기서는 `queue[MAX * 2]` 를 쓴다
  - BFS에서도 마찬가지: 상태를 확장하면 큐도 배수로 잡는다 → [37번](../G05/37_BOJ_2206_14442_벽부수고이동하기.md)
- **★ `size` 를 `wp` 로 출력.** 정답은 `wp - rp`. pop을 한 번이라도 하면 즉시 틀린다.
- **★ `pop` 의 증감 방향.** `queue[rp++]` 이다. 스택 습관으로 `queue[--rp]` 를 쓰면 뒤로 간다.
- **`back` 이 `queue[wp]`.** `wp` 는 아직 안 쓴 자리라 쓰레기값이다. `queue[wp - 1]` 이어야 한다.
- **빈 검사 누락.** `front`/`back`/`pop` 셋 다 필요하다. 특히 `back` 에서 빈 상태면 `queue[-1]` 을 읽는다.
- **18258은 출력이 많다.** 200만 줄이라 `printf` 로 아슬아슬할 수 있다. 시간 초과가 나면 출력 버퍼링을 검토한다(A형 실전에선 거의 무관).

## 7. 백지 재현 체크리스트
- [ ] `rp` 는 **현재 앞 원소**, `wp` 는 **다음 자리** — 비대칭을 설명할 수 있는가
- [ ] `push`=`queue[wp++]`, `pop`=`queue[rp++]` 를 바로 쓸 수 있는가
- [ ] `size` 가 `wp - rp` 인가
- [ ] `back` 이 `queue[wp - 1]` 인가
- [ ] 빈 검사가 `wp == rp` 인가, 네 연산 모두에 넣었는가
- [ ] **큐 배열 크기를 총 push 횟수로 잡아야 하는 이유**를 설명할 수 있는가
- [ ] 이 큐를 `RC` 구조체 버전으로 바꿔 쓸 수 있는가 (BFS 대비)

## 8. 한 줄 요약
"`rp`는 현재, `wp`는 다음. 데이터는 `[rp, wp)`. **둘 다 전진만 하므로 배열은 총 push 횟수로.**"
