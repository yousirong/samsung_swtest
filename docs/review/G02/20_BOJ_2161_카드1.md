| 항목 | 내용 |
|---|---|
| 유형 | G02 스택·큐·덱 (**큐 시뮬레이션 + 배열 크기 함정**) |
| 소스 | [swtest/20_BOJ_2161_카드1.cpp](../../../swtest/20_BOJ_2161_카드1.cpp) |

## 1. 문제 요약
카드 `1 ~ N` 이 위에서부터 순서대로 놓여 있다. 다음을 반복한다.
1. 맨 위 카드를 **버린다**
2. 그 다음 카드를 **맨 아래로** 옮긴다

카드가 하나 남을 때까지 반복하며, **버려지는 순서**와 **마지막 남는 카드**를 출력한다.

## 2. 필요한 이론
→ [G02 스택·큐·덱 — 큐](../../theory/G02_스택큐덱.md)

이론은 [19번](19_BOJ_10845_18258_큐_큐2.md) 에서 끝났다. 이 문제의 존재 이유는 하나다:

> **★ 큐 배열 크기 함정을 실제로 밟아보는 것.**

지문의 두 동작이 큐 연산으로 그대로 번역된다.
| 지문 | 큐 연산 |
|---|---|
| 맨 위 카드를 버린다 | `pop` |
| 다음 카드를 맨 아래로 | `pop` 해서 `push` |

## 3. 코드 흐름
```
main()
 └ scanf(N); rp = wp = 0
   초기화: for i in 1..N → queue[wp++] = i
   for i in 0..N-2:                  ← N-1 번 반복
      printf(queue[rp++])            ① 버림
      queue[wp++] = queue[rp++]      ② 뒤로 보냄
   printf(queue[wp - 1])             마지막 한 장
```

## 4. 핵심 코드

### 전부 이게 다다
```c
int queue[MAX * 2];      // ★ MAX 가 아니라 MAX * 2
int rp, wp;

int main()
{
    scanf("%d", &N);
    rp = wp = 0;

    // 초기 카드 상태: 1, 2, 3, ..., N
    for (int i = 1; i <= N; i++)
        queue[wp++] = i;

    // 마지막 카드 하나가 남을 때까지 반복
    for (int i = 0; i < N - 1; i++)
    {
        // 1) 맨 앞 카드를 버림
        printf("%d ", queue[rp++]);

        // 2) 다음 카드를 맨 뒤로 보냄
        queue[wp++] = queue[rp++];
    }

    // 마지막으로 남은 카드 출력
    printf("%d\n", queue[wp - 1]);

    return 0;
}
```

### ★ `MAX * 2` 인 이유 — 총 push 횟수를 세어 본다
```
초기 삽입           : N 번
루프 안 재삽입       : N - 1 번
────────────────────────────
총 push            : 2N - 1 번
```
`rp` 도 `wp` 도 전진만 하므로 배열은 **`2N - 1` 칸**이 필요하다.
`N` 칸만 잡으면 절반쯤 진행했을 때 `wp` 가 배열 밖으로 나간다.

> 이게 [19번 §6](19_BOJ_10845_18258_큐_큐2.md#6-함정--예상-함정) 에서 말한 함정의 실제 사례다.
> "동시에 큐에 든 카드는 최대 N장"이라고 생각하면 `MAX` 로 잡게 되고, 그러면 틀린다.

### 종료 조건 `N - 1` 번
루프 한 번에 카드가 **2장 소비되고 1장 재삽입** → 순감소 1장.
N장에서 1장 남기려면 `N - 1` 번. 마지막 남은 카드는 `queue[wp - 1]` — 가장 마지막에 뒤로 보낸 그 카드다.

## 5. 예제 손 추적 — N = 6

`queue` 인덱스와 값을 따라간다. 초기 삽입 후: `rp=0, wp=6`, `queue = [1 2 3 4 5 6]`

| 회차 | ① 버림 `queue[rp++]` | ② 뒤로 `queue[wp++] = queue[rp++]` | `rp` | `wp` | 남은 카드 (앞→뒤) |
|---|---|---|---|---|---|
| 시작 | | | 0 | 6 | `1 2 3 4 5 6` |
| 1 | **1** | `2` → idx6 | 2 | 7 | `3 4 5 6 2` |
| 2 | **3** | `4` → idx7 | 4 | 8 | `5 6 2 4` |
| 3 | **5** | `6` → idx8 | 6 | 9 | `2 4 6` |
| 4 | **2** | `4` → idx9 | 8 | 10 | `6 4` |
| 5 | **6** | `4` → idx10 | 10 | 11 | `4` |

루프 종료(5 = N-1 회). 마지막: `queue[wp - 1] = queue[10] = 4`

```
출력   1 3 5 2 6 4
```

> 실행으로 검증했다.
> ```bash
> printf '6\n' | ./a.out     # 1 3 5 2 6 4
> ```

**배열 사용량 확인**: `wp` 가 최종 `11` 까지 갔다. `2N - 1 = 11` 과 정확히 일치한다.
N=1000 이면 `wp` 가 1999까지 간다 — `MAX = 1100` 짜리 배열이었다면 **오버런**이다.

## 6. 함정 / 예상 함정
- **★★ 배열 크기를 `N` 으로 잡음.** 이 문제의 전부다. `2N - 1` 이 필요하다. 작은 N으로 테스트하면 전역 배열 뒤쪽 여유 공간 덕에 **조용히 통과**하고 큰 N에서만 터지는 유형의 버그.
  - 근본 해결은 **원형 큐**(`% MAX`)지만, A형에서는 넉넉히 잡는 쪽이 실수가 적다
- **★ 루프 횟수 `N` 으로 씀.** `N` 번 돌면 마지막에 빈 큐에서 pop 한다. `N - 1` 번이다.
- **N = 1 케이스.** 루프가 0번 돌고 `queue[wp - 1] = queue[0] = 1` 이 출력된다. 정상 동작 — `wp` 를 초기 삽입 후 값(1)으로 두었기에 성립한다.
- **마지막 카드를 `queue[rp]` 로 출력.** 이 시점에 `rp == wp - 1` 이라 우연히 같은 값이지만, 의미상 "마지막으로 뒤에 보낸 카드"이므로 `queue[wp - 1]` 이 맞다.
- **출력 형식.** 버리는 카드는 공백 구분, 마지막은 개행. `printf("%d ", ...)` 와 `printf("%d\n", ...)` 를 구분한다.
- **①과 ②의 순서를 바꾸면** 완전히 다른 답이 나온다. "버리고 → 옮긴다" 순서를 지문 그대로 지킨다.

## 7. 백지 재현 체크리스트
- [ ] **총 push 횟수가 `2N - 1`** 임을 계산해서 배열 크기를 잡았는가
- [ ] 루프 횟수가 `N - 1` 인 이유(한 회차에 순감소 1장)를 설명할 수 있는가
- [ ] 한 회차가 `pop 출력` + `pop 해서 push` 두 줄인가
- [ ] 마지막 답이 `queue[wp - 1]` 인가
- [ ] N=1 에서 동작하는가
- [ ] 왜 자리가 재활용되지 않는지 설명할 수 있는가

## 8. 한 줄 요약
"버리고, 옮기고. 큐 두 줄이면 끝 — 단 **배열은 `2N-1` 칸**이어야 한다."
