## 1. 문제 요약
N×N 격자에 먼지가 있다. 토네이도가 **격자 가운데에서 시작해 나선(달팽이) 경로**로 이동한다.

**토네이도가 한 칸 이동할 때마다**
1. 그 칸의 먼지가 **정해진 비율표대로** 주변 칸으로 흩어진다
2. 비율은 **이동 방향에 따라 다르다** (좌/하/우/상 4가지 표)
3. 각 칸으로 가는 양은 `현재 먼지 × 비율 / 100` (**정수 나눗셈, 버림**)
4. 흩어지고 **남은 양(`α`)** 은 **이동 방향 바로 앞 칸**으로 간다
5. 격자 밖으로 나간 먼지는 **사라진다**

격자 밖으로 나간 **먼지의 총량**을 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 조각 두 개가 결합돼 있다.

| 조각 | 어디서 |
|---|---|
| 나선(달팽이) 경로 생성 | [G01 16번 달팽이](../G01/16_BOJ_1913_달팽이.md) — **거의 그대로** |
| 방향별 비율표 | 이 문제 고유 — **표로 미리 적어둔다** |

> ### ★★ 이 문제의 핵심: "표로 적어두면 로직이 사라진다"
> 비율 확산을 조건문으로 짜려면 방향 4가지 × 위치 10여 개 = **분기 지옥**이다.
> **`5×5` 배열 4장으로 미리 적어두면** 이중 루프 하나로 끝난다.
>
> [G07 테트리스](../G07/2017상오전1_테트리스블럭안의합최대화하기.md)의 "19가지 모양을 배열에 적어둔다"와 **완전히 같은 전략**이다.

## 3. 코드 흐름
```
main()
 └ input()            N, MAP
   makeSnail()        ★ 나선 경로를 track[] 에 미리 생성 + 각 칸의 진행 방향 계산
   printf(simulate())

simulate():
   outDust = 0
   for i in 0..tcnt-2:
      다음 칸 (track[i+1]) 으로 토네이도 이동
      방향은 track[i].dir
      outDust += clean(다음칸, 방향)
   return outDust
```

## 4. 핵심 코드

### ★★ 비율표 — 방향마다 `5×5` 한 장
```c
// ←, ↓, →, ↑
int dr[] = { 0, 1, 0, -1 };
int dc[] = { -1, 0, 1, 0 };

// ratio[방향][5][5] — 퍼센트 값
int ratio[4][5][5] =
{
    {   // 0: 왼쪽으로 이동할 때
        {0,  0, 2, 0, 0},
        {0, 10, 7, 1, 0},
        {5,  0, 0, 0, 0},      // ★ 가운데 행: 왼쪽 끝이 5%
        {0, 10, 7, 1, 0},
        {0,  0, 2, 0, 0},
    },
    {   // 1: 아래로 이동할 때
        {0,  0, 0,  0, 0},
        {0,  1, 0,  1, 0},
        {2,  7, 0,  7, 2},
        {0, 10, 0, 10, 0},
        {0,  0, 5,  0, 0},     // ★ 아래 끝이 5%
    },
    ... 오른쪽, 위쪽 ...
};
```

**`[2][2]` 가 토네이도 자신의 위치**다 (5×5의 중심).
각 방향 표는 **왼쪽 표를 회전시킨 것**이다 — 손으로 적을 때 회전 관계를 이용하면 실수가 줄어든다.

> **★ 표에 `α`(남은 양) 자리는 0으로 비워둔다.** 코드에서 따로 채운다 (아래 참조).
> `0: 왼쪽` 표에서 `[2][1]` 이 0인데, 여기가 바로 이동 방향 앞 칸(`α` 자리)이다.

### 나선 경로 생성 — [달팽이](../G01/16_BOJ_1913_달팽이.md) 그대로
```c
void makeSnail()
{
    int sr, sc, direction, index, size;

    sr = sc = (N + 1) / 2;        // ★ 가운데에서 시작
    direction = 0;                 // 왼쪽부터
    index = 1;
    size = 0;

    snail[sr][sc] = index++;
    track[tcnt].r = sr;  track[tcnt++].c = sc;

    for (int i = 0; i < 2 * N - 1; i++)      // ★ 방향 전환 2N-1번
    {
        if (i % 2 == 0) size++;               // ★ 두 번마다 길이 +1

        for (int s = 0; s < size; s++)
        {
            int nr = sr + dr[direction];
            int nc = sc + dc[direction];

            snail[nr][nc] = index++;
            sr = nr;  sc = nc;

            track[tcnt].r = nr;  track[tcnt++].c = nc;   // ★ 경로를 배열에 저장
        }

        direction++;
        if (direction == 4) direction = 0;
    }
    ...
}
```

**[G01 16번 달팽이](../G01/16_BOJ_1913_달팽이.md)와 두 가지만 다르다.**
1. 방향 순서가 **`←, ↓, →, ↑`** (달팽이는 `상우하좌`)
2. 좌표를 **`track[]` 배열에 저장**한다 — 나중에 순회해야 하므로

`2N-1` 번 전환, `1,1,2,2,3,3…` 길이 증가는 **완전히 같다.**

### 각 칸의 진행 방향 계산
```c
tcnt = N * N;

for (int i = 0; i < tcnt - 1; i++)
{
    int r = track[i].r,     c = track[i].c;
    int nr = track[i+1].r,  nc = track[i+1].c;

    if      (nc - c == -1) track[i].dir = 0;   // 왼쪽
    else if (nc - c ==  1) track[i].dir = 2;   // 오른쪽
    else if (nr - r == -1) track[i].dir = 3;   // 위쪽
    else if (nr - r ==  1) track[i].dir = 1;   // 아래쪽
}
track[tcnt - 1].dir = 0;
```

**경로를 만든 뒤 "각 칸에서 다음 칸으로 가는 방향"을 역산**한다.
생성 중에 방향을 저장할 수도 있지만, **좌표 차이로 역산하는 편이 검산하기 쉽다.**

> **`tcnt = N * N`** 로 강제 설정하는 것에 주의. 나선 생성 루프가 격자 밖까지 갔을 수 있어 **유효 개수로 자른다.**

### ★★ 확산 — 표를 그대로 적용
```c
int clean(int sr, int sc, int dir)
{
    int center = MAP[sr][sc];        // ★ 원본 먼지량 (기준)
    int tmpMAP[5][5] = { 0 };

    // 1) 비율표대로 각 칸에 갈 양을 계산하고, 그만큼 중심에서 뺀다
    for (int r = 0; r < 5; r++)
    {
        for (int c = 0; c < 5; c++)
        {
            int dust = center * ratio[dir][r][c] / 100;    // ★ center 기준!
            tmpMAP[r][c] = dust;
            MAP[sr][sc] -= dust;
        }
    }

    // 2) 남은 양(α)은 이동 방향 바로 앞 칸으로
    tmpMAP[2 + dr[dir]][2 + dc[dir]] = MAP[sr][sc];
    MAP[sr][sc] = 0;

    // 3) tmpMAP 을 실제 격자에 반영, 밖으로 나간 것은 누적
    int ret = 0;
    for (int r = 0; r < 5; r++)
    {
        for (int c = 0; c < 5; c++)
        {
            int tr = sr + r - 2;      // ★ 5×5 로컬 → 전역 좌표
            int tc = sc + c - 2;

            if (tr < 1 || tc < 1 || tr > N || tc > N) ret += tmpMAP[r][c];
            else                                      MAP[tr][tc] += tmpMAP[r][c];
        }
    }

    return ret;
}
```

**세 단계가 명확히 분리돼 있다.**

**① 비율 계산은 항상 `center`(원본) 기준.**
`MAP[sr][sc]` 가 계속 줄어드는데, 비율은 **처음 값**으로 계산해야 한다.
`MAP[sr][sc] * ratio / 100` 로 쓰면 **계산할수록 양이 줄어** 완전히 틀린다.

**② `α` = 다 빼고 남은 것.**
```c
tmpMAP[2 + dr[dir]][2 + dc[dir]] = MAP[sr][sc];
```
`[2][2]` 가 중심이므로 `[2 + dr][2 + dc]` 가 **이동 방향 앞 칸**이다.
정수 나눗셈 버림 때문에 생긴 나머지가 전부 여기로 간다.

**③ 좌표 변환 `sr + r - 2`.**
로컬 `5×5` 의 `[2][2]` 가 전역 `(sr, sc)` 이므로 오프셋이 `-2`.

**격자 밖은 `MAP` 에 더하지 않고 `ret` 에 누적**한다 — 이게 답이다.

> **★ `tmpMAP` 으로 분리하는 이유**: 확산 중에 `MAP` 을 직접 건드리면
> 5×5 범위가 **자기 자신과 겹쳐** 방금 더한 값을 다시 읽을 수 있다. [G10의 "동시성"](../../theory/G10_순수시뮬레이션.md) 원칙.

### 시뮬레이션 — 경로를 따라 순회
```c
int simulate()
{
    int outDust = 0;

    for (int i = 0; i < tcnt - 1; i++)
    {
        int r = track[i + 1].r;      // ★ 다음 칸으로 이동
        int c = track[i + 1].c;
        int dir = track[i].dir;      // ★ 방향은 현재 칸의 것

        outDust += clean(r, c, dir);
    }

    return outDust;
}
```

**★ 인덱스가 어긋나 있다.** 토네이도는 `track[i+1]` 로 **이동한 뒤** 그 칸에서 확산하고,
방향은 `track[i]` 에서 `track[i+1]` 로 간 방향이다.

> 시작 칸 `track[0]`(가운데)에서는 확산이 일어나지 않는다 — 아직 이동을 안 했으므로.

## 5. 예제 손 추적

### 비율 적용 — 왼쪽 이동, 먼지 100
```
center = 100, dir = 0 (왼쪽)

ratio[0] 의 0 아닌 칸들:
  [0][2] = 2   → 100 * 2 / 100 = 2
  [1][1] = 10  → 10
  [1][2] = 7   → 7
  [1][3] = 1   → 1
  [2][0] = 5   → 5
  [3][1] = 10  → 10
  [3][2] = 7   → 7
  [3][3] = 1   → 1
  [4][2] = 2   → 2

합계 = 2+10+7+1+5+10+7+1+2 = 45
MAP[sr][sc] = 100 - 45 = 55        ★ α = 55

α 자리: [2 + dr[0]][2 + dc[0]] = [2 + 0][2 + (-1)] = [2][1]
tmpMAP[2][1] = 55
```
**총합 보존**: `45 + 55 = 100` ✓

### 정수 나눗셈의 효과 — 먼지 7
```
center = 7, dir = 0

  [0][2] = 2%  → 7 * 2 / 100 = 0    ★ 버림
  [1][1] = 10% → 7 * 10 / 100 = 0
  [1][2] = 7%  → 0
  [2][0] = 5%  → 0
  ... 전부 0

합계 = 0
α = 7 - 0 = 7        ★ 전부 앞 칸으로
```
**작은 먼지는 거의 전부 `α` 로 간다.** 이게 정수 나눗셈의 의도된 결과.

### `center` 기준의 중요성
```
잘못된 코드: dust = MAP[sr][sc] * ratio / 100

첫 칸: 100 * 2 / 100 = 2,  MAP = 98
둘째:  98 * 10 / 100 = 9,  MAP = 89     ★ 100 기준이면 10이어야 함
셋째:  89 * 7 / 100 = 6,   MAP = 83     ★ 7이어야 함
...
```
**계산할수록 값이 줄어 전부 틀린다.**

### 좌표 변환
```
토네이도가 (5, 5) 에 있고 로컬 [0][0] 을 처리

tr = 5 + 0 - 2 = 3
tc = 5 + 0 - 2 = 3
→ 전역 (3, 3)        ★ 중심에서 좌상단으로 2칸
```

### 격자 밖
```
토네이도가 (1, 1) 에 있고 로컬 [0][0] 처리

tr = 1 + 0 - 2 = -1  → 범위 밖
→ ret += tmpMAP[0][0]        ★ 답에 누적
```

## 6. 함정 / 예상 함정
- **★★ 비율을 `MAP[sr][sc]` 기준으로 계산.** **원본 `center` 기준**이어야 한다. 이 문제 최다 실수.
- **★★ `α` 계산 위치.** 비율을 **전부 뺀 뒤** 남은 값이다. 미리 계산하면 안 된다.
- **★★ `α` 가 가는 칸.** **이동 방향 바로 앞** = `[2 + dr[dir]][2 + dc[dir]]`.
- **★ `tmpMAP` 없이 직접 반영.** 5×5 범위가 자기 자신과 겹쳐 값이 오염된다.
- **★ 나선 방향 순서.** 이 문제는 **`←, ↓, →, ↑`**. [달팽이](../G01/16_BOJ_1913_달팽이.md)의 `상우하좌` 와 다르다.
- **★ 비율표 방향 인덱스와 `dr/dc` 순서 불일치.** 표 4장의 순서가 방향 배열과 맞아야 한다.
- **★ 좌표 변환 오프셋.** `sr + r - 2`. `-2` 를 빼먹으면 5×5가 엉뚱한 곳에 찍힌다.
- **★ 격자 밖 먼지를 `MAP` 에 더함.** `ret` 에만 누적하고 버려야 한다.
- **`simulate()` 의 인덱스 어긋남.** 위치는 `track[i+1]`, 방향은 `track[i]`.
- **`tcnt = N * N` 강제 설정** 누락 — 나선 생성이 격자를 넘칠 수 있다.
- **정수 나눗셈.** `/100` 은 버림. 실수로 하면 총합이 안 맞는다.
- **T-loop 마다 `MAP`, `track`, `tcnt` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] 비율 확산을 **`5×5` 표 4장**으로 미리 적어둘 수 있는가
- [ ] 비율 계산을 **원본 `center` 기준**으로 하는가
- [ ] **`α` = 다 빼고 남은 값**이고 **이동 방향 앞 칸**으로 감을 아는가
- [ ] `tmpMAP` 으로 **동시 반영**하는가
- [ ] 나선을 **`←↓→↑` 순서**로 만들고 `track[]` 에 저장하는가
- [ ] 각 칸의 방향을 **좌표 차이로 역산**할 수 있는가
- [ ] 좌표 변환 `sr + r - 2` 를 정확히 쓰는가
- [ ] 격자 밖 먼지를 **`ret` 에만** 누적하는가
- [ ] `simulate()` 에서 **위치는 `[i+1]`, 방향은 `[i]`** 인가
