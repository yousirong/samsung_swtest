## 1. 문제 요약
N×N 격자 위에 M명의 플레이어가 있다. 각 플레이어는 **현재 위치, 방향, 방향 우선순위**를 갖는다.

모든 플레이어는 자신이 지나간 칸에 **독점 계약**을 남기며, 그 계약은 **K초 동안 유지**된다.

**매 초 진행 규칙**
1. 살아 있는 플레이어가 **현재 칸에 자기 독점 계약**을 남긴다 (유효기간 K)
2. 각 플레이어가 **자기 방향의 우선순위**대로 이동
   - 먼저 **독점 계약이 없는 빈 칸**을 찾는다
   - 없으면 **자기 독점 계약이 남아 있는 칸**으로 간다
3. 이동 후 같은 칸에 여러 명이 모이면 **번호가 작은 플레이어만 생존**
4. 계약 유효기간을 1씩 감소
5. 한 명만 남으면 그 시각을 출력

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 이 그룹의 하위 패턴 세 개가 결합돼 있다.

| 패턴 | 내용 |
|---|---|
| **우선순위 이동** | 방향마다 다른 우선순위 배열이 주어진다 |
| **동시 이동 + 충돌** | `tmpMAP` 으로 처리 |
| **시한부 상태** | 계약이 K초 후 만료 — `time[][]` 카운트다운 |

> ### ★ 시한부 상태 관리
> 계약을 `bool` 로 두면 만료를 표현할 수 없다. **남은 시간을 `int` 로** 둔다.
> ```c
> int MAP[MAX][MAX];    // 그 칸을 독점한 플레이어 번호
> int time[MAX][MAX];   // 그 계약의 남은 유효 시간
> ```
> **두 배열이 한 쌍**으로 움직인다. `time == 0` 이면 `MAP` 값은 의미가 없다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()            N, M, K, MAP, player[] (위치/방향/우선순위)
      printf(simulate())

simulate():
   playerCount = M
   for t in 1..1000:
      ① 살아있는 플레이어가 현재 칸에 계약 (MAP=번호, time=K)
      ② tmpMAP = {0}
         각 플레이어: getDirection() → 이동 → 충돌 처리
      ③ tmpMAP 결과를 MAP에 반영
      ④ time 전체 -1 (0이면 계약 해제)
      if (playerCount == 1) return t
   return -1
```

## 4. 핵심 코드

### 방향 우선순위 — 2차원 배열
```c
struct PLAYER
{
    int r, c;
    int dir;                    // 현재 방향 (1~4)
    int priority[5][5];         // ★ priority[현재방향][순위] = 시도할 방향
    bool dead;
};
```

**`priority[dir][i]`** — "현재 방향이 `dir` 일 때 `i` 번째로 시도할 방향".
방향마다 우선순위가 **다르게** 주어지므로 2차원이어야 한다.

**1-based** (`1~4`)라 배열이 `[5][5]`, `[0]` 은 더미.
```c
int dr[] = { 0, -1, 1, 0, 0 };   // [0]더미, 1=위 2=아래 3=왼쪽 4=오른쪽
int dc[] = { 0,  0, 0,-1, 1 };
```

### ★★ 이동 방향 결정 — 2단계 탐색
```c
int getDirection(int number)
{
    PLAYER p = player[number];
    int dir = p.dir;

    // 1. 독점 계약이 없는 빈 공간 찾기
    for (int i = 1; i <= 4; i++)
    {
        int nextDir = p.priority[dir][i];
        int nr = p.r + dr[nextDir];
        int nc = p.c + dc[nextDir];

        if (MAP[nr][nc] == WALL) continue;       // 벽 제외

        if (time[nr][nc] == 0)                   // ★ 계약이 전혀 없는 칸
            return nextDir;
    }

    // 2. 자신의 독점 구역 찾기
    for (int i = 1; i <= 4; i++)
    {
        int nextDir = p.priority[dir][i];
        int nr = p.r + dr[nextDir];
        int nc = p.c + dc[nextDir];

        if (MAP[nr][nc] == number)               // ★ 자기 계약이 있는 칸
            return nextDir;
    }

    return -1;
}
```

**★ 두 루프를 순서대로 도는 것이 핵심이다.**
- **1차**: 빈 칸(계약 없음)을 **우선순위대로** 찾는다
- **2차**: 1차에서 못 찾았으면 **자기 계약 칸**을 우선순위대로 찾는다

**한 루프에서 `if/else` 로 처리하면 안 된다.** 우선순위 3번의 빈 칸이 우선순위 1번의 자기 칸보다 **먼저**여야 하기 때문.

> **판정 기준이 다르다는 것도 주의.**
> - 빈 칸: **`time == 0`** (계약 만료 여부)
> - 자기 칸: **`MAP == number`** (누구 계약인지)
>
> `time` 과 `MAP` 을 각각 봐야 한다.

> ⚠️ **2차 루프에 벽 검사가 없다.** 벽 칸은 `MAP == WALL(-1)` 이라 `== number`(양수) 조건에 안 걸리므로 안전하다. 우연이 아니라 값 설계 덕분.

### 계약 남기기
```c
for (int p = 1; p <= M; p++)
{
    if (player[p].dead == true) continue;

    MAP[player[p].r][player[p].c] = p;      // 누구 계약인지
    time[player[p].r][player[p].c] = K;     // ★ 유효기간 리셋
}
```
**이미 자기 계약이 있어도 `time` 을 K로 되돌린다.** 다시 밟았으므로 갱신.

### ★★ 동시 이동 + 충돌
```c
int tmpMAP[MAX][MAX] = { 0 };      // 이번 초 이동 후 그 칸에 남는 플레이어

for (int p = 1; p <= M; p++)
{
    if (player[p].dead == true) continue;

    int dir = getDirection(p);
    int nr = player[p].r + dr[dir];
    int nc = player[p].c + dc[dir];

    if (tmpMAP[nr][nc] == 0)                    // 아직 아무도 없음
    {
        player[p].r = nr;  player[p].c = nc;  player[p].dir = dir;
        tmpMAP[nr][nc] = p;
    }
    else                                         // 충돌
    {
        int anotherPlayer = tmpMAP[nr][nc];
        playerCount--;                           // ★ 한 명 탈락

        if (anotherPlayer < p)
            player[p].dead = true;               // 기존이 더 작으면 내가 죽음
        else
        {
            player[anotherPlayer].dead = true;   // 내가 더 작으면 기존이 죽음
            player[p].r = nr;  player[p].c = nc;  player[p].dir = dir;
            tmpMAP[nr][nc] = p;
        }
    }
}
```

**★ `tmpMAP` 이 "이번 초에 그 칸을 차지한 사람"** 을 기록한다.
- 비어 있으면 그냥 차지
- 이미 있으면 **번호가 작은 쪽만 생존**

> **번호 순서로 순회하므로 `anotherPlayer < p` 는 항상 참**일 것 같지만,
> `getDirection` 결과에 따라 **나중 번호가 먼저 그 칸에 도달**할 수는 없다 — 순회가 번호순이므로.
> 그래도 **양쪽 분기를 다 쓰는 것이 방어적으로 안전**하다.

**`playerCount--` 를 충돌마다** 한다. 여러 명이 겹치면 그 수만큼 줄어든다.

### 계약 만료
```c
for (int r = 1; r <= N; r++)
    for (int c = 1; c <= N; c++)
        if (time[r][c] > 0) time[r][c]--;
```
**매 초 전체를 훑어 카운트다운.** `time == 0` 이 되면 그 칸은 다시 "빈 칸"이 된다.

> `MAP` 값은 굳이 지우지 않아도 된다 — `getDirection` 의 1차 루프가 `time == 0` 으로 판정하므로.
> 다만 2차 루프(`MAP == number`)에서는 **만료된 계약도 자기 것으로 인식**할 수 있어 주의가 필요하다.
> **실제로는 1차에서 이미 잡히므로 문제없다** (만료 = 빈 칸 = 1차 대상).

## 5. 예제 손 추적

### 우선순위 이동
```
플레이어 1: 현재 방향 = 2(아래)
priority[2] = [_, 3, 1, 2, 4]      1순위=왼쪽, 2순위=위, 3순위=아래, 4순위=오른쪽

이웃 칸 상태:
  왼쪽(3): time=5  (누군가의 계약)
  위(1):   벽
  아래(2): time=0  (빈 칸)  ★
  오른쪽(4): time=0

1차 루프:
  i=1: 왼쪽 → time=5 ≠ 0 → 통과
  i=2: 위 → WALL → continue
  i=3: 아래 → time=0 ✓ → return 2
```
**우선순위 3번이 선택됐다.** 1·2번이 조건을 못 채웠기 때문.

### 2단계 탐색이 필요한 경우
```
이웃 칸이 전부 계약 있음:
  왼쪽:  MAP=2 (다른 사람)
  위:    MAP=1 (자기)
  아래:  MAP=3 (다른 사람)
  오른쪽: 벽

1차 루프: 빈 칸 없음 → 전부 통과
2차 루프:
  i=1: 왼쪽 → MAP(2) != 1 → 통과
  i=2: 위 → MAP(1) == 1 ✓ → return
```
**자기 계약 칸으로 간다.**

### 충돌
```
플레이어 2와 5가 같은 칸 (3,3) 으로 이동

p=2 처리: tmpMAP[3][3] = 0 → 차지, tmpMAP[3][3] = 2
p=5 처리: tmpMAP[3][3] = 2 → 충돌!
          anotherPlayer = 2, p = 5
          2 < 5 → player[5].dead = true
          playerCount--
```
**번호가 작은 2번이 살아남는다.**

### 계약 만료 타이밍
```
t=1: 플레이어가 (2,2) 에 계약 → time[2][2] = K = 3
     ... 이동 ...
     time[2][2] = 2

t=2: time[2][2] = 1
t=3: time[2][2] = 0     ★ 이제 빈 칸

t=4: 다른 플레이어가 (2,2) 를 "빈 칸"으로 인식
```

## 6. 함정 / 예상 함정
- **★★ 2단계 탐색을 한 루프로 합침.** 빈 칸이 **모든 우선순위에서** 자기 칸보다 먼저다. **루프를 두 번** 돌아야 한다.
- **★★ 동시 이동을 즉시 반영.** `tmpMAP` 없이 하면 먼저 움직인 사람이 나중 사람의 판단을 바꾼다.
- **★★ 충돌에서 번호 비교 방향.** **작은 번호가 생존.**
- **★ 판정 기준 혼동.** 빈 칸은 **`time == 0`**, 자기 칸은 **`MAP == number`**.
- **★ 계약 갱신 누락.** 이미 자기 칸이어도 다시 밟으면 `time = K` 로 **리셋**.
- **★ `playerCount` 감소 위치.** 충돌마다 1명씩. 여러 명이 겹치면 여러 번.
- **★ 우선순위 배열이 1-based.** `priority[5][5]`, `dr/dc` 도 `[0]` 더미.
- **방향을 갱신 안 함.** 이동하면 `player[p].dir = dir` 도 바꿔야 다음 턴 우선순위가 맞다.
- **`time` 카운트다운을 이동 전에.** 계약을 남기고 → 이동 → **그 다음** 감소. 순서가 바뀌면 1초씩 어긋난다.
- **종료 판정.** `playerCount == 1` 이 되는 **그 초**를 반환.
- **T-loop 마다 `MAP`, `time`, `player` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **`MAP`(누구 계약) + `time`(남은 시간)** 두 배열 쌍으로 관리하는가
- [ ] `getDirection` 이 **2단계 루프**(빈 칸 → 자기 칸)인가
- [ ] 판정 기준이 **`time == 0`** 과 **`MAP == number`** 로 다름을 아는가
- [ ] `tmpMAP` 으로 **동시 이동**을 보장하는가
- [ ] 충돌에서 **작은 번호가 생존**하는가
- [ ] 계약을 밟을 때마다 **`time = K` 리셋**하는가
- [ ] 이동 후 **`dir` 도 갱신**하는가
- [ ] `time` 감소를 **이동 뒤에** 하는가
- [ ] 우선순위/방향 배열이 1-based(더미 `[0]`)인가

## 8. 한 줄 요약
"**`MAP` + `time` 두 배열**로 시한부 계약을 관리하고, 이동은 **빈 칸 → 자기 칸 2단계 루프.** 충돌은 **작은 번호 생존.**"
