## 1. 문제 요약 (BOJ 17140 기준)

`3×3` 배열 `A` 가 주어지고, `A[r][c] == k` 가 되는 **최소 시간**을 구한다.
100초가 지나도 안 되면 `-1`.

**1초마다 다음 연산 중 하나가 일어난다**

| 조건 | 연산 |
|---|---|
| **행 개수 ≥ 열 개수** | **R 연산** — 모든 **행**에 정렬 수행 |
| 행 개수 < 열 개수 | **C 연산** — 모든 **열**에 정렬 수행 |

**R 연산 (한 행에 대해)**
1. 그 행에 등장하는 **수와 등장 횟수**를 센다
2. **등장 횟수가 작은 것부터**, 횟수가 같으면 **수가 작은 것부터** 정렬
3. `수, 등장횟수, 수, 등장횟수, …` 순서로 그 행을 다시 채운다
4. 행의 길이가 서로 다르면 **짧은 행은 0으로 채운다**
5. **길이가 100을 넘으면 앞의 100개만** 남긴다

C 연산은 같은 것을 **열 단위**로 한다.

## 3. 설계 — 어떻게 짤 것인가

```
main()
 └ input()               A[3][3], r, c, k  (좌표는 1-based)
   R = C = 3             현재 행 개수, 열 개수
   for time in 0..100:
      if (A[r][c] == k) → time 출력, 종료
      if (R >= C) 모든 행에 sortLine()      ★ R 연산
      else        모든 열에 sortLine()      ★ C 연산
      R, C 갱신
   -1 출력
```

### 한 줄(행 또는 열)을 정렬하는 함수
```c
// arr: 한 줄의 값 배열, len: 유효 길이
// 반환: 정렬 후 새 길이
int sortLine(int arr[], int len)
{
    // 1. 값별 등장 횟수 세기
    //    값 범위가 1~100 이므로 count[101] 배열로 충분
    int count[101] = { 0 };
    for (i in 0..len-1)
        if (arr[i] != 0) count[arr[i]]++;      // ★ 0은 세지 않는다

    // 2. (값, 횟수) 쌍을 모은다
    PAIR pairs[101]; int pcnt = 0;
    for (v in 1..100)
        if (count[v] > 0) pairs[pcnt++] = {v, count[v]};

    // 3. 정렬: 횟수 오름차순 → 같으면 값 오름차순
    선택정렬 (pcnt 가 작으므로 O(pcnt²) 충분)

    // 4. 다시 채우기: 값, 횟수, 값, 횟수, ...
    int idx = 0;
    for (i in 0..pcnt-1)
    {
        if (idx >= 100) break;                  // ★ 100 제한
        arr[idx++] = pairs[i].value;
        if (idx >= 100) break;
        arr[idx++] = pairs[i].count;
    }

    // 5. 나머지는 0으로
    for (; idx < 100; idx++) arr[idx] = 0;

    return 새 길이;      // 이 줄이 필요로 하는 길이
}
```

### 전체 길이 갱신
```c
// 모든 줄을 정렬한 뒤, 가장 긴 줄의 길이가 새 열 개수(R 연산 시)가 된다
int maxLen = 0;
for (각 줄) maxLen = max(maxLen, 그 줄의 길이);

C = min(maxLen, 100);      // R 연산이었다면 열 개수가 바뀐다
```

**★ 짧은 줄은 0으로 패딩**되어 자동으로 길이가 맞는다.

## 4. 예상 함정 — 짜기 전에 알아둘 것

- **★★ `0` 을 개수에 포함.** 패딩용 `0` 은 **세지 않는다.** 포함하면 `0` 이 값으로 취급되어 전부 어긋난다.
- **★★ 정렬 기준 두 축.** **횟수 먼저(오름차순), 값이 나중(오름차순).** 순서를 바꾸면 틀린다.
- **★★ 100 제한.** 길이가 100을 넘으면 **앞 100개만** 남긴다. 값과 횟수가 쌍이므로 **홀수 위치에서 잘릴 수 있다** — `idx >= 100` 검사를 **값 쓰기 전과 횟수 쓰기 전 각각** 넣어야 한다.
- **★★ R/C 판정이 매 초 바뀐다.** `R >= C` 를 **연산 전에** 확인하고, 연산 후 `R`, `C` 를 갱신한다. 판정을 갱신 후에 하면 한 박자 밀린다.
- **★ 0초 검사.** 연산을 하기 **전에** `A[r][c] == k` 를 먼저 확인해야 `0` 이 답인 경우를 잡는다.
- **★ 배열 크기.** 최대 `100 × 100`. `#define MAX (100 + 10)`.
- **★ `A[r][c]` 접근 시 범위.** `r`, `c` 가 현재 `R`, `C` 를 넘으면 그 칸은 존재하지 않는다 (= `0`). 배열이 0으로 초기화돼 있으면 자동 처리되지만, **`k != 0` 이면 매칭이 안 되는 게 맞다.**
- **★ C 연산을 별도로 짜지 말 것.** [보도블럭](2017하오전2_보도블럭.md)처럼 **전치해서 R 연산 재사용**이 정석.
- **100초 초과 → `-1`.** 루프 상한을 정확히.

## 5. 백지 재현 체크리스트
- [ ] `R >= C` 판정을 **연산 전에** 하는가
- [ ] **0초(연산 전) 검사**를 먼저 하는가
- [ ] 값별 개수를 셀 때 **`0` 을 제외**하는가
- [ ] 정렬이 **횟수 → 값** 순서 두 축인가 (둘 다 오름차순)
- [ ] 채우기가 **값, 횟수** 쌍이고 **100 제한을 두 곳에서** 검사하는가
- [ ] 짧은 줄을 **0으로 패딩**하는가
- [ ] C 연산을 **전치로 재사용**하는가
- [ ] 연산 후 `R`, `C` 를 갱신하는가
- [ ] 100초 초과 시 `-1` 인가
