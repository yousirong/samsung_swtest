## 1. 문제 요약
N×M 격자에 여러 마리의 곰팡이가 있다. 각 곰팡이는 **이동 거리(`distance`), 이동 방향(`dir`), 크기(`size`)** 를 갖는다.

**진행 순서** (1열부터 M열까지 반복)
1. 인턴이 현재 열로 이동
2. 그 열에서 **가장 위에 있는 곰팡이 1마리를 채취** (크기를 점수에 누적)
3. 남아 있는 **모든 곰팡이가 동시에 이동**
   - 격자 끝에 닿으면 **방향을 반전**하고 계속 간다 (반사)
   - 이동 후 같은 칸에 여러 마리가 모이면 **가장 큰 것만 살아남는다**

총 채취한 크기의 합을 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**세 가지 함정이 한 문제에 다 들어 있다.**

| 함정 | 대응 |
|---|---|
| **동시 이동** | `tmpMold` 에 결과를 쌓고 마지막에 반영 |
| **반사(벽에서 튕김)** | 방향 반전 배열 + 한 칸씩 이동 |
| **시간 초과** | 이동 거리를 **주기로 나눈 나머지**로 줄이기 |

> **★ 세 번째가 이 문제의 진짜 난이도다.** `distance` 가 1000까지 오는데 곰팡이가 많고 열도 많으면
> `열 × 곰팡이 × distance` 가 폭발한다. **주기성을 이용해 줄여야 한다.**

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()              N, M, K, mold[][]
      printf(simulate())

simulate():
   answer = 0
   for sc in 1..M:              인턴이 1열 → M열
      answer += catchMold(sc)   ★ 가장 위 곰팡이 채취
      moveMold()                ★ 전부 동시 이동
   return answer
```

## 4. 핵심 코드

### 구조체로 곰팡이 상태를 묶는다
```c
struct MOLD
{
    int distance;   // 이동 거리
    int dir;        // 이동 방향 (1=위, 2=아래, 3=오른쪽, 4=왼쪽)
    int size;       // 크기
};

MOLD mold[MAX][MAX];      // 현재 상태
MOLD tmpMold[MAX][MAX];   // 이동 결과 (동시성 보장용)
```

**`size == 0` 이 "빈 칸"의 의미**다. 별도 플래그가 필요 없다.

> **격자에 구조체를 직접 두는 방식**이다. 곰팡이 목록을 따로 관리하는 방법도 있지만,
> "같은 칸에 모이면 큰 것만"이라는 규칙 때문에 **격자 기반이 자연스럽다.**

### 채취 — 가장 위쪽
```c
int catchMold(int sc)
{
    // 위쪽 행부터 확인
    for (int r = 1; r <= N; r++)
    {
        if (mold[r][sc].size != 0)
        {
            int ret = mold[r][sc].size;

            // 채취 후 해당 칸은 빈칸 처리
            mold[r][sc].size = 0;
            mold[r][sc].dir = 0;
            mold[r][sc].distance = 0;

            return ret;         // ★ 한 마리만
        }
    }
    return 0;                   // 그 열에 곰팡이가 없음
}
```

**`r = 1` 부터 훑어 처음 만난 것**이 가장 위쪽이다. `return` 으로 즉시 나가 **한 마리만** 채취한다.
세 필드를 **모두 0으로** 비워야 한다 — `size` 만 지우면 `dir`/`distance` 가 남아 나중에 오작동할 수 있다.

### ★★ 동시 이동 — `tmpMold` 분리
```c
void moveMold()
{
    // tmpMold를 빈 상태로 초기화
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            tmpMold[r][c].distance = tmpMold[r][c].dir = tmpMold[r][c].size = 0;

    // 방향 반전용 배열
    // 1(위) <-> 2(아래),  3(오른쪽) <-> 4(왼쪽)
    int changeDir[5] = { 0, 2, 1, 4, 3 };

    for (int r = 1; r <= N; r++)
    {
        for (int c = 1; c <= M; c++)
        {
            if (mold[r][c].size == 0) continue;
            ...  // 이동 계산 → tmpMold 에 기록
        }
    }

    // tmpMold를 실제 상태에 반영
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            mold[r][c] = tmpMold[r][c];
}
```

**읽기는 `mold`, 쓰기는 `tmpMold`.** [G01의 제1원칙](../../theory/G01_배열회전.md)이 구조체 격자로 확장된 형태.

> **이걸 안 하면**: 먼저 이동한 곰팡이가 아직 이동 안 한 곰팡이의 자리를 덮어쓴다.
> 그 곰팡이는 **사라지거나 두 번 이동**한다.

### 방향 반전 배열 — 0번 인덱스를 비워둔다
```c
int changeDir[5] = { 0, 2, 1, 4, 3 };
//                   ↑  ↑  ↑  ↑  ↑
//                   -  1→2 2→1 3→4 4→3
```
방향이 **1~4** 이므로 배열 크기는 5, `[0]` 은 더미.
[2017 자율주행자동차](2017상오후1_자율주행자동차.md)의 `changeDir` 과 같은 관용구지만, **여기는 반전(180도)** 이다.

### ★★ 주기로 이동 거리 줄이기
```c
if (dir == 위 || dir == 아래) move = md.distance % ((N - 1) * 2);
else                          move = md.distance % ((M - 1) * 2);
```

**세로 이동의 주기는 `(N-1) × 2`** 다.
```
N = 4 일 때 위/아래로 튕기며 이동:
  1 → 2 → 3 → 4 → 3 → 2 → 1 → 2 → ...
  └────────────────────┘
        주기 = 6 = (4-1) × 2
```
한 번 왕복하면 **원래 자리와 방향으로 정확히 돌아온다.** 그래서 나머지만 이동하면 된다.

> **★ 이 최적화가 없으면 시간 초과**가 난다. `distance ≤ 1000`, 곰팡이 최대 `N×M`, 열 `M` 번 반복이면
> `M × N×M × 1000` 이 되어 터진다. 나머지를 취하면 `distance` 가 최대 `(N-1)×2` 로 줄어든다.
>
> ⚠️ **`N == 1` 이면 `(N-1)*2 == 0` 이라 `% 0` 은 0으로 나누기다.** 문제 조건이 `N ≥ 2` 를 보장하는지 확인할 것.

### 반사 — 한 칸씩 가며 벽에서 뒤집기
```c
for (int m = 0; m < move; m++)
{
    int nr = sr + dr[dir];
    int nc = sc + dc[dir];

    // 다음 칸이 범위 밖이면 방향 반전
    if (nr < 1 || nc < 1 || nr > N || nc > M)
    {
        dir = changeDir[dir];       // ★ 방향을 실제로 바꾼다
        nr = sr + dr[dir];
        nc = sc + dc[dir];
    }

    sr = nr;
    sc = nc;
}
```

**★ 한 칸씩 가면서 매번 범위를 확인**한다. 한 번에 `move` 칸을 점프하면 반사를 처리할 수 없다.

**★ `dir` 를 실제로 바꾼다.** 이동이 끝난 뒤의 `dir` 가 **곰팡이의 새 방향**이 된다.
임시로만 뒤집으면 다음 턴에 잘못된 방향으로 간다.

> 수식으로 반사 위치를 바로 계산할 수도 있지만, **한 칸씩 도는 편이 훨씬 안전**하다.
> 주기 나머지로 `move` 가 이미 작아졌으므로 성능도 문제없다.

### 충돌 — 큰 것만 살아남는다
```c
// 같은 칸 (sr, sc)에 여러 마리가 모이면 크기가 가장 큰 곰팡이만 살아남는다.
if (tmpMold[sr][sc].size < mold[r][c].size)
{
    tmpMold[sr][sc] = mold[r][c];
    tmpMold[sr][sc].dir = dir;      // ★ 이동 후 최종 방향 반영
}
```

**`tmpMold` 가 0으로 초기화**되어 있으므로, 첫 도착자는 `0 < size` 로 무조건 들어간다.
이후 도착자는 **더 클 때만** 덮어쓴다.

**`.dir = dir`** 한 줄이 중요하다. `mold[r][c]` 를 통째로 복사하면 **이동 전 방향**이 들어간다.
반사로 뒤집힌 방향을 반영해야 한다.

## 5. 예제 손 추적

### 주기 확인 — `N = 4`, 세로 이동
```
주기 = (4-1) × 2 = 6

distance = 6  →  6 % 6 = 0   → 제자리, 방향도 그대로
distance = 7  →  7 % 6 = 1   → 1칸만 이동
distance = 13 →  13 % 6 = 1  → 역시 1칸
```

**실제로 6칸 이동해 보면** (`r=1`, 아래 방향으로 시작)
```
m=0: (1) → (2)
m=1: (2) → (3)
m=2: (3) → (4)
m=3: (4) → 다음은 (5) 범위 밖 → 반전(위) → (3)
m=4: (3) → (2)
m=5: (2) → (1)     ★ 원위치
```
**방향은?** 마지막에 `dir` 가 "위"다. 처음이 "아래"였는데?

> ⚠️ **6칸 후 위치는 같지만 방향이 반대**다. 완전한 주기는 `(N-1) × 2` 가 맞지만,
> **위치만 같고 방향이 다르면** 다음 턴이 달라진다.
>
> 다시 세어 보자. `m=5` 에서 `(2) → (1)` 로 갈 때 `dir` 는 "위"다. 그리고 `(1)` 에 도착.
> 다음에 한 칸 더 가려면 `(0)` 이 범위 밖이라 반전되어 "아래"가 된다.
> **즉 `(1)` 에 도착한 시점에서는 아직 "위"** 이고, 원래 상태("아래")와 다르다.
>
> **정확히는 위치와 방향이 모두 복원되려면 `(N-1) × 2` 칸을 가고 나서 벽에 닿아 한 번 더 반전되어야** 한다.
> 이 구현은 **다음 이동 시작 시 범위 검사에서 자동으로 반전**되므로 결과적으로 맞다.
> **경계 케이스이므로 작은 값으로 직접 돌려 확인하는 것이 안전하다.**

### 충돌 처리
```
이동 후 (2,3) 칸에 세 마리가 도착

곰팡이 A: size = 5   (먼저 처리됨)
곰팡이 B: size = 9
곰팡이 C: size = 3

tmpMold[2][3].size = 0  →  A: 0 < 5 ✓  → A 저장 (size=5)
                           B: 5 < 9 ✓  → B로 교체 (size=9)
                           C: 9 < 3 ✗  → 무시

결과: B만 살아남음
```

### 채취 순서
```
격자 (3행 × 2열), 인턴이 1열 → 2열

열 1:  r=1 비어있음
       r=2 곰팡이(size=4) ← 채취!  answer += 4
       r=3 곰팡이(size=7)   남음

→ moveMold()

열 2:  ...
```
**가장 위쪽 한 마리만.** 아래 것은 그대로 두고 이동 단계로 넘어간다.

### 동시성 확인 — `tmpMold` 없이 하면
```
초기:  (1,1) 곰팡이A [아래로 1칸]
       (2,1) 곰팡이B [아래로 1칸]

올바른 결과 (동시):
  A → (2,1),  B → (3,1)     둘 다 살아남음

즉시 반영했다면:
  A를 (2,1)로 옮김 → B가 덮어씌워져 사라짐
  B를 처리하려 해도 이미 없음
  → 곰팡이 하나가 증발
```

## 6. 함정 / 예상 함정
- **★★ 동시 이동을 즉시 반영.** `tmpMold` 필수. 곰팡이가 증발하거나 두 번 이동한다.
- **★★ 이동 거리를 주기로 안 줄임.** 시간 초과. 세로 `(N-1)*2`, 가로 `(M-1)*2`.
- **★★ 반사 후 `dir` 를 안 갱신.** 다음 턴에 반대로 간다. `tmpMold[..].dir = dir` 한 줄 필수.
- **★ 한 번에 `move` 칸 점프.** 반사를 처리할 수 없다. **한 칸씩.**
- **★ 채취 시 `size` 만 지움.** `dir`, `distance` 도 0으로.
- **★ 충돌에서 `<=` 사용.** `<` 여야 먼저 온 같은 크기가 유지된다 (같은 크기가 없다면 무관하지만 습관).
- **★ 방향 인덱스 0-based/1-based 혼동.** 방향이 1~4이므로 `dr/dc` 배열도 `[0]` 을 더미로 둔다.
- **`N == 1` 또는 `M == 1` 이면 `% 0`.** 문제 조건 확인 필요.
- **`tmpMold` 초기화 누락.** 매 이동마다 리셋.
- **T-loop 마다 `mold` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] `tmpMold` 로 **동시 이동**을 보장하는가
- [ ] 이동 거리를 **주기(`(N-1)*2`, `(M-1)*2`)로 나눈 나머지**로 줄이는가
- [ ] 반사를 **한 칸씩 이동하며 범위 검사**로 처리하는가
- [ ] 반사 시 **`dir` 를 실제로 갱신**하고 최종 방향을 저장하는가
- [ ] 채취가 **가장 위쪽 한 마리**이고 세 필드를 모두 비우는가
- [ ] 충돌에서 **큰 것만** 남기는가
- [ ] 방향 배열이 1-based(더미 `[0]`)인가
- [ ] `tmpMold` 를 매 이동마다 초기화하는가

## 8. 한 줄 요약
"**`tmpMold` 로 동시 이동**, 이동 거리는 **주기 나머지**로 줄이고, 반사는 **한 칸씩 + `dir` 실제 갱신.**"
