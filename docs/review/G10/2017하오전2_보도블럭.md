## 1. 문제 요약
N×N 높이 지도가 주어지고, **길이 `L` 의 경사로**를 이용해 **지나갈 수 있는 길의 개수**를 구한다.

**길의 정의**: 모든 **가로줄** N개 + 모든 **세로줄** N개 = 총 `2N` 개

**지나갈 수 있는 조건**
- 모든 칸의 높이가 같으면 통과
- 높이 차가 **1** 이면 경사로를 놓아 통과 가능
- 높이 차가 **2 이상**이면 불가능
- 경사로는 **길이 `L` 만큼 연속으로 같은 높이인 칸**에만 놓을 수 있다
- 한 칸에 **경사로를 두 번 놓을 수 없다**

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**격자 문제처럼 보이지만 실제로는 1차원 문제 `2N` 개**다.

> ### ★★ 두 가지 핵심 아이디어
>
> **① 행과 열은 완전히 독립이다.**
> 한 줄씩 떼어내 **1차원 배열 하나를 판정하는 함수**(`checkRow`)를 만들고, `2N` 번 호출하면 끝.
>
> **② 세로줄은 전치(transpose)해서 가로줄처럼 처리한다.**
> ```c
> TMAP[c][r] = MAP[r][c];     // 전치 행렬
> ```
> 세로줄 전용 코드를 또 짜지 않는다. **`checkRow` 하나를 재사용.**
>
> 이 두 발상으로 코드가 **절반**이 된다.

> ### ★ 세 번째 아이디어: 내리막만 처리하고 뒤집어서 한 번 더
> 내리막과 오르막을 각각 처리하려면 조건이 복잡해진다.
> **배열을 뒤집으면 오르막이 내리막이 된다.** 같은 로직을 두 번 돌리면 끝.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()           N, L, MAP → 동시에 TMAP(전치) 생성
      printf(checkAllRow())

checkAllRow():
   answer = 0
   for r in 1..N: answer += checkRow(MAP[r])     가로줄 N개
   for c in 1..N: answer += checkRow(TMAP[c])    세로줄 N개 (전치본)
   return answer

checkRow(arr):
   1단계: 왼쪽→오른쪽으로 훑으며 "내리막" 처리
   2단계: 배열을 뒤집어 다시 훑으며 원래의 "오르막" 처리
   둘 다 통과하면 1
```

## 4. 핵심 코드

### 전치 행렬 — 입력할 때 같이 만든다
```c
int MAP[MAX][MAX];     // 원본 지도
int TMAP[MAX][MAX];    // 전치 행렬 (세로줄을 가로줄처럼 검사하기 위한 배열)

// input() 안에서
scanf("%d", &MAP[r][c]);
TMAP[c][r] = MAP[r][c];        // ★ 인덱스를 바꿔 저장
```

**한 줄 추가로 세로줄 처리가 공짜가 된다.** `TMAP[c]` 가 원래의 `c` 번째 세로줄이다.

### 평탄 구간 검사
```c
bool isFlat(int arr[MAX], int start, int end)
{
    int value = arr[start];

    for (int i = start + 1; i <= end; i++)
        if (value != arr[i]) return false;

    return true;
}
```
`[start, end]` 구간이 **전부 같은 높이**인지. 경사로를 놓을 수 있는지 판정하는 데 쓴다.

### ★★ 내리막 처리
```c
int checkRow(int arr[MAX])
{
    bool visit[MAX] = { 0 };          // 원래 배열 기준 경사로 설치 여부
    int inverse[MAX] = { 0 };         // 뒤집은 배열
    bool visit_inverse[MAX] = { 0 };

    // 1단계: 원래 방향(왼쪽 -> 오른쪽) 검사 — "높이가 낮아지는 경우" 처리
    for (int c = 1; c <= N - 1; c++)
    {
        if (arr[c] == arr[c + 1]) continue;              // 같으면 문제 없음

        // 조건 1) 높이 차이가 1보다 크면 불가능
        if (abs(arr[c] - arr[c + 1]) > 1) return 0;

        // 현재 칸이 다음 칸보다 높으면 "내리막"
        if (arr[c] > arr[c + 1])
        {
            // 경사로 길이 L만큼 앞으로 갈 수 있어야 함
            if (c + L > N) return 0;                     // ★ 범위 초과

            // 그 구간이 전부 같은 높이여야 함
            if (isFlat(arr, c + 1, c + L) == false) return 0;

            // 이미 경사로가 놓인 칸이 있으면 불가
            for (int i = c + 1; i <= c + L; i++)
                if (visit[i] == true) return 0;

            // 경사로 설치
            for (int i = c + 1; i <= c + L; i++)
                visit[i] = true;
        }
    }
    ...
}
```

**내리막에서 경사로를 놓는 세 가지 검사**
1. **범위**: `c + L > N` 이면 경사로가 배열 밖으로 나간다
2. **평탄**: `[c+1, c+L]` 이 전부 같은 높이여야 한다
3. **중복**: 그 구간에 이미 경사로가 있으면 안 된다

세 검사를 **전부** 해야 한다. 하나라도 빠지면 틀린다.

> **★ 검사 → 설치 순서.** 세 검사를 다 통과한 뒤에 설치한다.
> 검사하면서 설치하면, 중간에 실패했을 때 이미 놓은 경사로가 남는다.
> (여기서는 `return 0` 으로 함수를 나가므로 `visit` 이 지역 배열이라 무해하지만, **습관으로 중요**하다.)

### ★ 오르막 처리 — 뒤집어서 같은 로직
```c
// 2단계: 배열을 뒤집은 뒤 다시 왼쪽 -> 오른쪽으로 검사
for (int c = 1; c <= N; c++)
    inverse[c] = arr[N - c + 1];        // ★ 뒤집기

for (int c = 1; c <= N - 1; c++)
{
    // 1단계와 완전히 같은 로직, visit_inverse 사용
    ...
}

return 1;
```

**원래 배열의 오르막 = 뒤집은 배열의 내리막.**
로직을 복사해 `arr` → `inverse`, `visit` → `visit_inverse` 로만 바꾼다.

> **`visit` 을 두 벌 쓰는 이유**: 원래 방향과 뒤집은 방향에서 **경사로 위치가 다르다.**
> 하나로 공유하면 잘못된 중복 판정이 난다.
>
> ⚠️ 엄밀히는 **같은 물리적 경사로**이므로 공유해야 맞다는 논리도 가능하다.
> 하지만 내리막용과 오르막용 경사로는 **놓이는 칸이 다르다** — 내리막은 `[c+1, c+L]`, 오르막은 뒤집힌 좌표계의 `[c+1, c+L]`.
> 두 벌로 관리하는 것이 이 구현의 선택이고, 통과했다.

### 합산
```c
int checkAllRow()
{
    int answer = 0;

    for (int r = 1; r <= N; r++) answer += checkRow(MAP[r]);    // 가로줄
    for (int c = 1; c <= N; c++) answer += checkRow(TMAP[c]);   // 세로줄

    return answer;
}
```
`checkRow` 가 `1` 또는 `0` 을 반환하므로 **그냥 더하면 개수**가 된다.

## 5. 예제 손 추적 — `L = 2`

### 케이스 ①: `[3, 3, 3, 3, 3]` — 전부 평탄
```
c=1: arr[1]==arr[2] → continue
c=2,3,4: 전부 continue
→ 1단계 통과

뒤집어도 동일 → 2단계 통과

결과: 1 (통과 가능)
```

### 케이스 ②: `[2, 2, 1, 1, 2]`
```
1단계 (내리막 처리)
c=1: 2==2 → continue
c=2: arr[2]=2 > arr[3]=1 → 내리막!
     범위: c+L = 2+2 = 4 <= 5 ✓
     평탄: arr[3..4] = [1, 1] 같음 ✓
     중복: visit[3], visit[4] 모두 false ✓
     → 설치: visit[3] = visit[4] = true
c=3: 1==1 → continue
c=4: arr[4]=1 < arr[5]=2 → 오르막 → 1단계에서는 처리 안 함
→ 1단계 통과

2단계 (뒤집기)
inverse = [2, 1, 1, 2, 2]
c=1: inverse[1]=2 > inverse[2]=1 → 내리막!
     범위: 1+2 = 3 <= 5 ✓
     평탄: inverse[2..3] = [1, 1] ✓
     중복: 없음 ✓
     → 설치
c=2: 1==1 → continue
c=3: inverse[3]=1 < inverse[4]=2 → 오르막 → 처리 안 함
→ 2단계 통과

결과: 1 ✓
```

### 케이스 ③: `[2, 2, 1, 2, 2]` — 중복 충돌
```
1단계
c=2: 2 > 1 → 내리막
     평탄: arr[3..4] = [1, 2] → 다름! ✗ → return 0
```
**경사로를 놓을 자리가 평탄하지 않아 실패.**

### 케이스 ④: `[3, 2, 1]`, `L = 2` — 범위 초과
```
1단계
c=1: 3 > 2 → 내리막
     범위: 1+2 = 3 <= 3 ✓
     평탄: arr[2..3] = [2, 1] → 다름! ✗ → return 0
```

### 케이스 ⑤: `[1, 2, 2, 1]`, `L = 2`
```
1단계 (내리막만)
c=1: 1 < 2 → 오르막, 스킵
c=2: 2==2 → continue
c=3: 2 > 1 → 내리막
     범위: 3+2 = 5 > 4 ✗ → return 0
```
**경사로가 배열 밖으로 나가 실패.**

### 높이 차 2 이상
```
[1, 3, ...]  →  abs(1-3) = 2 > 1  →  즉시 return 0
```

## 6. 함정 / 예상 함정
- **★★ 세로줄 처리를 따로 짬.** **전치 행렬**로 `checkRow` 를 재사용한다. 코드가 절반이 된다.
- **★★ 오르막을 별도 로직으로.** **뒤집어서 내리막 로직 재사용**이 정석.
- **★★ 세 검사 중 하나 누락.** 범위 / 평탄 / 중복 **전부** 필요하다.
- **★ `visit` 을 한 벌만 씀.** 원래 방향과 뒤집은 방향은 좌표계가 다르다. **두 벌.**
- **★ 높이 차 2 이상 검사 누락.** `abs(...) > 1` 이면 즉시 실패.
- **★ 경사로 설치를 검사 도중에.** 세 검사를 다 통과한 뒤 설치.
- **★ `visit` 을 전역으로 두고 초기화 안 함.** `2N` 번 호출되므로 **지역 배열 `{0}`** 이 안전.
- **루프 범위 `c <= N - 1`.** `arr[c+1]` 을 보므로 마지막 칸 전까지.
- **`checkRow` 가 `bool` 이 아니라 `int` 를 반환**하는 이유 — 그대로 더해서 개수를 세기 위함.
- **T-loop 마다 `MAP`, `TMAP` 초기화** (크기가 바뀌면 잔여값 주의).

## 7. 백지 재현 체크리스트
- [ ] **행과 열이 독립**임을 알고 1차원 함수 하나로 분해하는가
- [ ] **전치 행렬**로 세로줄을 재사용하는가
- [ ] **뒤집기로 오르막을 내리막 로직에 흡수**하는가
- [ ] 경사로 설치 전 **범위 / 평탄 / 중복** 세 검사를 다 하는가
- [ ] `visit` 을 **두 벌**(원래 / 뒤집은) 쓰는가
- [ ] 높이 차 `> 1` 이면 즉시 실패하는가
- [ ] `visit` 을 지역 배열로 두어 호출마다 초기화되는가
- [ ] `checkRow` 반환값을 그대로 더해 개수를 세는가
