> 그쪽은 BFS 반복(G09), 이쪽은 순수 시뮬레이션(G10).

## 1. 문제 요약
자동차가 현재 위치와 방향을 갖고 정해진 규칙에 따라 도로를 탐색하며 이동한다.

| 칸 값 | 의미 |
|---|---|
| `0` (`ROAD`) | 도로 (아직 방문 안 함) |
| `1` (`STREET`) | 인도/벽 (이동 불가) |
| `2` (`MARK`) | 이미 방문한 도로 |

**방향**: `0 = 북, 1 = 동, 2 = 남, 3 = 서`

**진행 규칙**
1. 현재 칸을 방문 처리
2. **왼쪽 칸**이 아직 방문 안 한 도로면 → **왼쪽으로 회전하고 전진**
3. 아니면 → **왼쪽으로 회전만** 하고 다시 확인 (최대 4방향)
4. 4방향 모두 갈 수 없으면 → **방향은 그대로 두고 후진**
5. 후진할 곳이 인도/벽이면 **종료**

최종적으로 **방문한 칸(`MARK`)의 개수**를 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 지문의 규칙 5개를 그대로 옮기면 된다.
BFS도, 완전탐색도, 자료구조도 필요 없다 — **`while` 루프 하나와 방향 배열이 전부.**

> ### ★ 이 유형에서 이기는 법
> 1. **지문의 규칙에 번호를 매기고** 코드의 분기와 1:1 대응시킨다
> 2. **방향 회전을 배열/산술로** 미리 정의한다
> 3. **종료 조건을 명확히** 한다 (`while(1)` 은 반드시 `break` 가 있어야 한다)

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()          N, M, R, C, D, MAP
      simulate()
      printf(getAnswer())

simulate():
   changeDir[] = {3, 0, 1, 2}       ★ 왼쪽 회전 표
   while (1):
      MAP[R][C] = MARK              규칙 1
      nDir = changeDir[D]
      if (왼쪽이 ROAD):             규칙 2
         D = nDir; 이동
      else:                          규칙 3
         for i in 0..3:
            D = nDir
            if (앞이 ROAD) { 이동; break; }
            nDir = changeDir[D]
         if (i == 4):                규칙 4
            후진
            if (뒤가 STREET) break   규칙 5
```

## 4. 핵심 코드

### ★ 왼쪽 회전을 배열로
```c
// 현재 방향 D에서 "왼쪽 방향"으로 바꾸는 규칙
//
// D=0(북) -> 3(서)
// D=1(동) -> 0(북)
// D=2(남) -> 1(동)
// D=3(서) -> 2(남)
int changeDir[] = { 3, 0, 1, 2 };
```

**`changeDir[D]` 한 번으로 왼쪽 회전이 끝난다.**

산술로도 가능하다.
```c
int nDir = (D + 3) % 4;      // 왼쪽(반시계) 90도
```
방향 배열이 `북-동-남-서`(시계 순)이므로 `+3 = -1 mod 4` 가 반시계 90도.

> **표와 산술 중 어느 쪽이든 좋다.** 다만 **방향 배열 순서와 반드시 일치**해야 한다.
> [G07 이상한 체스](../G07/2018상오전1_이상한체스.md)의 방향 산술과 같은 원리.

### 규칙 2 — 왼쪽이 도로면 회전 + 전진
```c
MAP[R][C] = MARK;                   // 1. 현재 위치 방문 처리

int nDir = changeDir[D];
int nr = R + dr[nDir];
int nc = C + dc[nDir];

// 경우 1) 왼쪽 칸이 아직 방문하지 않은 도로이면
//         왼쪽으로 회전하고 그 칸으로 이동
if (MAP[nr][nc] == ROAD)
{
    D = nDir;   // 방향을 왼쪽으로 바꿈
    R = nr;
    C = nc;
}
```

**`== ROAD`(0) 로 검사**하는 것이 포인트. `!= STREET` 로 쓰면 **이미 방문한 도로(`MARK`)** 도 통과해 무한 루프에 빠진다.

### ★★ 규칙 3 — 4방향 회전 탐색
```c
else
{
    int i;
    for (i = 0; i < 4; i++)
    {
        D = nDir;                   // ★ 실제로 방향을 왼쪽으로 회전

        int nr = R + dr[D];
        int nc = C + dc[D];

        if (MAP[nr][nc] == ROAD)    // 아직 방문 안 한 도로 발견
        {
            R = nr;
            C = nc;
            break;                  // ★ i < 4 로 빠져나감
        }

        nDir = changeDir[D];        // 그 방향도 안 되면 또 왼쪽으로
    }
    ...
}
```

**`for` 를 빠져나온 방식이 `break` 인지 완주인지를 `i` 값으로 판별**한다.
- `break` → `i < 4`
- 완주 → `i == 4`

> **★ `i` 를 `for` 밖에서 선언**한 이유가 이것이다. C89 스타일이지만 여기서는 **의도적**이다.
>
> 요즘 스타일이라면 `bool moved = false;` 플래그를 쓰는 게 읽기 좋다.
> ```c
> bool moved = false;
> for (int i = 0; i < 4; i++) { ... moved = true; break; ... }
> if (!moved) { 후진 }
> ```

**★ 회전은 실제로 `D` 를 바꾼다.** 임시 변수로만 돌려보는 게 아니다.
4방향을 다 돌면 `D` 가 원래 값으로 돌아오지만, **중간에 `break` 하면 그 방향이 최종 방향**이 된다.

### 규칙 4·5 — 후진과 종료
```c
// 4방향 모두 갈 수 없는 경우 뒤로 한 칸 후진
if (i == 4)
{
    // 현재 방향 D의 반대 방향으로 한 칸 이동
    nr = R - dr[D];             // ★ 빼기 (반대 방향)
    nc = C - dc[D];

    R = nr;
    C = nc;

    // 뒤가 인도/벽이면 종료
    if (MAP[R][C] == STREET) break;
}
```

**후진은 `dr[D]` 를 빼면 된다.** 반대 방향 인덱스(`(D+2)%4`)를 계산할 필요 없다.

> **★ 후진해도 방향 `D` 는 안 바뀐다.** 지문이 "방향은 유지한 채 후진"이라고 했다.
> `D` 를 바꾸면 다음 턴의 왼쪽 방향이 달라져 전부 어긋난다.

> ⚠️ **종료 검사 순서가 미묘하다.** 이 코드는 **먼저 이동한 뒤** 그 칸이 `STREET` 인지 본다.
> 즉 벽 위로 한 칸 들어간 상태에서 `break` 한다. `MAP[R][C] = MARK` 는 다음 루프 시작에서 하는데 그 전에 `break` 하므로 **벽이 `MARK` 로 오염되지 않는다.** 순서 덕분에 우연히 안전한 구조.
>
> 더 안전하게 쓰려면 **이동 전에 검사**한다.
> ```c
> int br = R - dr[D], bc = C - dc[D];
> if (MAP[br][bc] == STREET) break;
> R = br; C = bc;
> ```

### 답 세기
```c
int getAnswer()
{
    int sum = 0;
    for (int r = 0; r < N; r++)
        for (int c = 0; c < M; c++)
            if (MAP[r][c] == MARK) sum++;
    return sum;
}
```
> ⚠️ **루프 범위가 `0 ~ N-1`** 이다. 이 파일은 **0-indexed** — 레포의 다른 파일(1-indexed + sentinel)과 다르다.
> 입력도 `MAP[0][0]` 부터 읽는다. **범위 체크가 지문 조건(테두리는 항상 인도)으로 보장**된다.

## 5. 예제 손 추적

```
격자 (0-indexed)          방향: 0=북 1=동 2=남 3=서

     c=0 c=1 c=2 c=3
r=0   1   1   1   1
r=1   1   0   0   1        시작: (1,1), D=0(북)
r=2   1   0   0   1
r=3   1   1   1   1
```

### 1턴
```
MAP[1][1] = MARK

D=0(북) → nDir = changeDir[0] = 3(서)
왼쪽 칸 (1,0) = 1(STREET) → 규칙 2 실패 → else 진입

for i=0: D=3(서), 앞 (1,0)=1 → 아님
         nDir = changeDir[3] = 2(남)
    i=1: D=2(남), 앞 (2,1)=0(ROAD) ✓ → 이동!
         R=2, C=1, break (i=1)
```
**상태: `(2,1)`, `D=2`(남)**

### 2턴
```
MAP[2][1] = MARK

D=2(남) → nDir = changeDir[2] = 1(동)
왼쪽 칸 (2,2) = 0(ROAD) ✓ → 규칙 2 성공
D=1(동), R=2, C=2
```
**상태: `(2,2)`, `D=1`(동)**

### 3턴
```
MAP[2][2] = MARK

D=1(동) → nDir = changeDir[1] = 0(북)
왼쪽 칸 (1,2) = 0(ROAD) ✓
D=0(북), R=1, C=2
```
**상태: `(1,2)`, `D=0`(북)**

### 4턴
```
MAP[1][2] = MARK          ★ 네 칸을 모두 방문

D=0(북) → nDir = 3(서)
왼쪽 (1,1) = 2(MARK) → 규칙 2 실패 → else

for i=0: D=3(서), 앞 (1,1)=MARK → 아님
         nDir = 2(남)
    i=1: D=2(남), 앞 (2,2)=MARK → 아님
         nDir = 1(동)
    i=2: D=1(동), 앞 (1,3)=STREET → 아님
         nDir = 0(북)
    i=3: D=0(북), 앞 (0,2)=STREET → 아님
         nDir = 3(서)
→ 완주, i == 4

후진: D=0(북)이므로 반대는 남
  R = 1 - (-1) = 2,  C = 2 - 0 = 2
  MAP[2][2] = MARK  → STREET 아님 → 계속
```
**상태: `(2,2)`, `D=0`(북)** — 후진했지만 **방향은 북 그대로**

### 이후
남은 도로가 없으므로 계속 후진하다가 벽을 만나 종료.
```
출력  4       (방문한 도로 4칸)
```

### 만약 `!= STREET` 로 검사했다면
4턴에서 `MAP[1][1] = MARK` 인데 `!= STREET` 는 참이므로 **왼쪽으로 이동**한다.
그러면 `(1,1) → (2,1) → (2,2) → (1,2) → (1,1) → …` **무한 루프.**

## 6. 함정 / 예상 함정
- **★★ 도로 검사를 `!= STREET` 로.** **`== ROAD`(0)** 여야 한다. 방문한 도로(`MARK`)를 다시 밟으면 무한 루프.
- **★★ 회전 탐색에서 `D` 를 실제로 안 바꿈.** 임시 변수로만 돌려보면 `break` 시 방향이 안 남는다.
- **★★ 후진 시 방향을 바꿈.** **방향은 유지**한다. 바꾸면 이후가 전부 어긋난다.
- **★ `changeDir` 표가 방향 배열 순서와 불일치.** `dr/dc` 가 `북-동-남-서` 여야 `{3,0,1,2}` 가 왼쪽 회전이 된다.
- **★ `for` 완주 판별.** `i` 를 루프 밖에서 선언하거나 `bool` 플래그를 쓴다. C99 스타일 `for (int i...)` 로 쓰면 밖에서 `i` 를 못 읽는다.
- **★ 종료 조건 누락 → 무한 루프.** `while(1)` 은 반드시 `break` 경로가 있어야 한다.
- **0-indexed vs 1-indexed 혼동.** 이 파일은 **0-indexed**다. 레포의 다른 파일 습관대로 쓰면 어긋난다.
- **후진 시 범위 체크.** 테두리가 항상 인도라는 문제 조건에 의존한다. 아니면 명시적 체크 필요.
- **T-loop 마다 `MAP`, `R`, `C`, `D` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] 지문의 규칙 5개를 **코드 분기와 1:1 대응**시킬 수 있는가
- [ ] 왼쪽 회전을 **표 또는 `(D+3)%4`** 로 쓸 수 있는가, 방향 배열 순서와 맞췄는가
- [ ] 도로 검사가 **`== ROAD`** 인가 (`!= STREET` 아님)
- [ ] 회전 탐색에서 **`D` 를 실제로 갱신**하는가
- [ ] `for` 완주 여부를 **`i == 4`** 또는 플래그로 판별하는가
- [ ] 후진이 **`R - dr[D]`** 이고 **방향은 유지**하는가
- [ ] 종료 조건(뒤가 `STREET`)이 있는가
- [ ] 0-indexed 임을 확인했는가

## 8. 한 줄 요약
