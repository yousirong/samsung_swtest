## 1. 문제 요약
N×N 체스판 위에 K개의 말이 있다. 각 말은 **위치 `(r, c)`** 와 **방향 `dir`** 를 갖는다.

**칸 색깔**
| 값 | 색 | 규칙 |
|---|---|---|
| `0` | 흰색 | 그냥 이동 (쌓인 순서 유지) |
| `1` | 빨간색 | 이동하되 **쌓인 순서를 뒤집는다** |
| `2` | 파란색 | **방향을 반대로** 바꾸고 한 번 더 시도. 그래도 파란색이면 **제자리** |

**진행 규칙**
1. **1번 말부터 K번 말까지 순서대로** 이동
2. 어떤 말이 이동할 때 **그 말 위에 쌓여 있는 말들도 함께** 이동
3. 이동 후 한 칸에 **말이 4개 이상 쌓이면 종료**, 그때의 턴 번호를 출력
4. 1000턴 안에 안 되면 `-1`

**격자 밖도 파란색**으로 취급한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션 — 쌓임(스택) 관리](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 이 문제의 난이도는 전부 **자료구조 설계**에 있다.

> ### ★★ 핵심: "칸마다 스택" + "말마다 자기 위치 인덱스"
> ```c
> int board[MAX][MAX][10 + 3];   // board[r][c][i] = (r,c) 에 쌓인 i번째 말 번호
> int index[MAX][MAX];           // index[r][c] = 그 칸에 쌓인 말 수 (스택 top)
>
> struct HORSE {
>     int r, c, dir;
>     int pos;                    // ★ 자기 칸 스택에서 자신의 인덱스
> };
> ```
> **양방향 참조**가 필요하다.
> - `board` : 칸 → 말 번호들 (아래에서 위로)
> - `horse[n].pos` : 말 → 자기가 스택 몇 번째인지
>
> **왜 `pos` 가 필요한가**: "그 말 **위에** 쌓인 것들도 함께 이동"하려면
> **그 말이 스택의 어디에 있는지**를 알아야 한다. 매번 스택을 훑어 찾을 수도 있지만, `pos` 로 `O(1)` 이다.

[G02 스택](../G02/17_BOJ_10828_스택.md)의 `top` 인덱스 관리가 **칸마다** 있는 셈이다.

## 3. 코드 흐름
```
main()
 └ input()             N, K, MAP(색), horse[] — 격자 밖은 BLUE로 초기화
   printf(simulation())

simulation():
   changeDir[5] = {0, 2, 1, 4, 3}          방향 반전표
   for turn in 1..999:
      for h in 1..K:                        ★ 말 번호 순서대로
         다음 칸 색 확인
         WHITE → moveWhite(h)
         RED   → moveRed(h)
         BLUE  → 방향 반전 후 재시도 (또 BLUE면 정지)
         if (index[nr][nc] >= 4) return turn
   return -1
```

## 4. 핵심 코드

### 방향 규약 — 1-based, 0번은 더미
```c
// 1:오른쪽, 2:왼쪽, 3:위, 4:아래
int dr[] = { 0,  0, 0, -1, 1 };
int dc[] = { 0,  1,-1,  0, 0 };

// 방향 반전 테이블: 1↔2 (좌우), 3↔4 (상하)
int changeDir[5] = { 0, 2, 1, 4, 3 };
```
[랩 인턴](2019상오전2_생명과학부랩인턴.md)과 **같은 반전 테이블**이다. `[0]` 은 더미.

### ★★ 흰색 이동 — 순서 유지
```c
// number번 말부터 그 위에 쌓인 말들을 모두 이동
void moveWhite(int number)
{
    HORSE h = horse[number];
    int sr = h.r, sc = h.c, dir = h.dir;
    int nr = sr + dr[dir], nc = sc + dc[dir];

    int front = h.pos;                 // ★ 이동 시작 인덱스
    int& back     = index[sr][sc];     // 출발 칸 스택 크기
    int& nextBack = index[nr][nc];     // 도착 칸 스택 크기

    // front부터 back-1까지 (아래→위 순서) 그대로 다음 칸에 추가
    for (int k = front; k < back; k++)
    {
        int selectedNumber = board[sr][sc][k];

        horse[selectedNumber].r = nr;
        horse[selectedNumber].c = nc;
        horse[selectedNumber].pos = nextBack;      // ★ pos 갱신 필수

        board[nr][nc][nextBack++] = selectedNumber;
    }

    back = front;      // ★ 출발 칸은 front 이전까지만 남김
}
```

**세 가지가 세트로 움직인다.**
1. `board[도착]` 에 말 번호 추가
2. `horse[말].r/c/pos` 갱신 — **`pos` 를 빼먹으면 다음 이동이 엉뚱한 위치를 옮긴다**
3. `index[출발] = front` 로 잘라내기

**`front` 부터 `back-1` 까지**가 "그 말과 그 위에 쌓인 것들"이다. `front` 아래는 그대로 남는다.

### 빨간색 이동 — 역순
```c
// back-1부터 front까지 (위→아래 역순) 다음 칸에 추가
for (int k = back - 1; k >= front; k--)
{
    ... 흰색과 동일한 3단계 ...
}
back = front;
```

**루프 방향만 뒤집었다.** 나머지는 완전히 같다.
"뒤집어서 쌓는다"가 **위에 있던 말이 아래로** 간다는 뜻이다.

> **두 함수를 하나로 합칠 수도 있다** (방향 플래그 인자). 하지만 **따로 두는 편이 읽기 쉽다** — 인덱스를 헷갈릴 여지가 줄어든다.

### ★ 파란색 — 반전 후 재시도
```c
else if (MAP[nr][nc] == BLUE)
{
    // 파란색(또는 경계): 방향 반전 후 재시도
    dir = changeDir[dir];
    horse[h].dir = dir;                // ★ 방향을 실제로 바꾼다

    nr = sr + dr[dir];
    nc = sc + dc[dir];

    if (MAP[nr][nc] == WHITE)      moveWhite(h);
    else if (MAP[nr][nc] == RED)   moveRed(h);
    // 반전 후에도 BLUE면 이동하지 않음
}
```

**세 가지 포인트**
1. **방향은 반전된 채로 유지**된다. 이동을 못 해도 `horse[h].dir` 는 바뀐 상태로 남는다
2. 반전 후 또 파란색이면 **아무 일도 안 한다** (제자리, 방향만 바뀜)
3. **격자 밖도 파란색**이라 별도 범위 체크가 필요 없다 — [G05 sentinel](../../theory/G05_그리드탐색심화.md)

### 종료 판정
```c
// 이동 후 해당 칸에 4개 이상 쌓이면 현재 턴 반환
if (index[nr][nc] >= 4) return i;
```

**말 하나를 옮길 때마다 즉시 확인**한다. 턴이 끝난 뒤에 확인하면 안 된다 — 규칙이 "말이 4개 이상 쌓이는 순간"이므로.

> ⚠️ **`nr`, `nc` 가 파란색 분기에서 갱신된 값**임에 주의. 이동이 실제로 일어난 칸을 봐야 한다.
> 반전 후에도 BLUE라 이동을 안 했다면 `index[nr][nc]` 는 그 칸의 기존 값이라 4 이상일 리 없다 (그 칸은 벽/파란칸).

### 턴 상한
```c
for (int i = 1; i < 1000; i++) { ... }
return -1;
```
문제가 "1000턴 안에"라고 명시한다. **무한 루프 방지 장치**이기도 하다.

## 5. 예제 손 추적

### 쌓임과 `pos`
```
칸 (2,2) 스택:  board[2][2] = [3, 1, 5]     index[2][2] = 3
                                ↑  ↑  ↑
                            아래  중간  위

horse[3].pos = 0
horse[1].pos = 1
horse[5].pos = 2
```

### 1번 말이 흰색 칸으로 이동
```
horse[1].pos = 1  →  front = 1
back = 3

k=1: board[2][2][1] = 1  →  1번 말 이동, pos = 0 (도착 칸이 비었다면)
k=2: board[2][2][2] = 5  →  5번 말 이동, pos = 1

출발 칸: index[2][2] = front = 1  →  [3] 만 남음
도착 칸: [1, 5]                    ★ 순서 유지
```

**3번 말은 안 움직인다.** 1번 말 **아래**에 있기 때문.

### 같은 상황에서 빨간색 칸이면
```
k=2: board[2][2][2] = 5  →  5번 말 먼저 이동, pos = 0
k=1: board[2][2][1] = 1  →  1번 말 이동, pos = 1

도착 칸: [5, 1]                    ★ 순서 뒤집힘
```

### 파란색 — 방향 반전
```
horse[2].dir = 1 (오른쪽)
오른쪽 칸이 BLUE

→ dir = changeDir[1] = 2 (왼쪽)
  horse[2].dir = 2                 ★ 영구 변경
  왼쪽 칸이 WHITE → moveWhite(2)

다음 턴에도 2번 말은 왼쪽으로 간다
```

**양쪽 다 BLUE면**
```
→ dir = 2 로 바뀌지만 이동은 없음
  다음 턴에는 왼쪽으로 시도 (또 막히면 다시 오른쪽으로 반전)
```

### 종료
```
어떤 칸의 index 가 4가 되는 순간 → 그 턴 번호 반환

턴 3에서 2번 말을 옮겼더니 index[1][3] = 4
→ return 3      ★ 나머지 말은 안 옮기고 즉시 종료
```

## 6. 함정 / 예상 함정
- **★★ `pos` 갱신 누락.** 말을 옮기면서 `horse[n].pos` 를 안 바꾸면, 다음에 그 말을 옮길 때 **엉뚱한 인덱스부터** 들어올린다. 이 문제 최다 실수.
- **★★ 출발 칸 스택을 안 잘라냄.** `back = front` 로 크기를 줄여야 한다. 안 하면 말이 복제된다.
- **★★ "위에 쌓인 것도 함께"를 빠뜨림.** `front` 부터 `back-1` 까지 **전부** 옮긴다. 한 마리만 옮기면 틀린다.
- **★ 빨간색에서 루프 방향.** `back-1` → `front` 역순.
- **★ 파란색 반전 후 방향을 되돌림.** **반전된 채로 유지**된다.
- **★ 종료 판정을 턴 끝에.** 말 하나 옮길 때마다 **즉시** 확인.
- **★ 격자 밖을 파란색으로 초기화 안 함.** 범위 체크가 필요해지거나 밖으로 나간다.
- **방향 인덱스 1-based.** `dr/dc` 와 `changeDir` 모두 `[0]` 이 더미.
- **`board` 3차원 크기.** 한 칸에 최대 K개(=10)까지 쌓이므로 `[10+3]` 이면 충분.
- **`index` 라는 변수명이 `<string.h>` 의 `index()` 함수와 충돌 가능.** 이 파일은 include 안 해서 무사하지만 위험하다 — [G02 21번 덱](../G02/21_BOJ_10866_덱.md)의 `strcmp` 와 같은 문제.
- **T-loop 마다 `board`, `index`, `horse` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **칸마다 스택 + 말마다 `pos`** 양방향 구조를 설계할 수 있는가
- [ ] `pos` 가 왜 필요한지 설명할 수 있는가
- [ ] 이동 시 **`board` 추가 / `horse` 갱신(`pos` 포함) / 출발 칸 자르기** 3단계를 다 하는가
- [ ] `front` 부터 `back-1` 까지 **함께 이동**하는가
- [ ] 빨간색이 **역순 루프**인가
- [ ] 파란색에서 **방향이 영구 반전**되는가, 두 번 막히면 정지하는가
- [ ] 격자 밖을 **파란색**으로 초기화했는가
- [ ] 종료 판정을 **말 하나마다 즉시** 하는가
- [ ] 방향 배열이 1-based(더미 `[0]`)인가

## 8. 한 줄 요약
"**칸마다 스택 + 말마다 `pos`.** 이동은 `front`부터 통째로, 빨강은 역순, 파랑은 **방향만 영구 반전.**"
