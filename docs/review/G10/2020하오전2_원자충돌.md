## 1. 문제 요약
N×N 격자에 M개의 원자가 있다. 각 원자는 **위치 `(r,c)`, 질량 `m`, 속력 `s`, 방향 `d`** 를 갖는다.
격자는 **위아래·좌우가 연결된 원형 격자**다.

**매 턴**
1. 모든 원자가 자기 방향으로 **속력 `s` 만큼 이동**
2. 이동 후 **같은 칸에 2개 이상** 모이면 충돌
3. 충돌한 원자들은 하나로 합쳐진 뒤 **다시 4개로 분리**
   - 새 질량 = `합친 질량 / 5` — **0이면 소멸**
   - 새 속력 = `합친 속력 / 합친 개수`
   - 새 방향: 원래 방향이 **전부 짝수이거나 전부 홀수**면 `0,2,4,6`, 아니면 `1,3,5,7`

K턴 후 **남은 원자들의 질량 합**을 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 대신 이 그룹의 하위 패턴이 세 개나 들어 있다.

| 패턴 | 내용 |
|---|---|
| **원형 격자** | `(r + N) % N` 계열 좌표 보정 |
| **한 칸에 여러 개** | 격자에 값 하나가 아니라 **합산 정보 구조체** |
| **합산 후 재생성** | 원자 배열을 매 턴 **통째로 다시 만든다** |

> ### ★★ 핵심 설계: "격자에 원자를 두지 않는다"
> 원자를 격자에 직접 배치하면 "한 칸에 여러 개"를 표현할 수 없다.
> **원자는 배열(`atom[]`)로 관리하고, 격자(`MAP`)는 이번 턴의 합산 정보만 임시로** 담는다.
>
> ```
> atom[] (원자 목록)  ──이동──▶  MAP[][] (칸별 합산)  ──분리──▶  새 atom[]
> ```
> **매 턴 `atom[]` 을 통째로 다시 만든다.** 이게 "동시 이동"과 "충돌 처리"를 한 번에 해결한다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()            N, M, K, atom[], acnt
      simulate()
      printf(getAnswer())

simulate():
   for k in 0..K-1:
      INFO MAP[MAX][MAX] = {0}        ★ 매 턴 새 합산판
      ① 모든 원자 이동 → MAP에 합산
      ② MAP을 훑어 새 atom[] 생성 (acnt = 0 부터)
```

## 4. 핵심 코드

### 자료구조 — 원자 배열 + 합산 정보 구조체
```c
struct ATOM { int r, c, m, s, d; };
ATOM atom[100000 + 5000];      // 현재 살아 있는 원자
int acnt;                       // 개수

// 한 칸에 모인 원자들의 합산 정보
struct INFO
{
    int m;       // 질량 합
    int s;       // 속력 합
    int d;       // 방향 (원자가 1개인 경우 복원용)
    int even;    // 짝수 방향 원자 개수
    int odd;     // 홀수 방향 원자 개수
    int count;   // 모인 원자 개수
};
```

**`INFO` 가 이 문제의 발명품이다.** 충돌 계산에 필요한 것만 **합계로 압축**해서 담는다.
개별 원자를 칸마다 리스트로 들고 있을 필요가 없다 — **합, 개수, 짝/홀 카운트면 충분**하기 때문.

**`d` 필드**는 `count == 1` 일 때만 의미가 있다. 충돌이 없으면 원래 방향을 그대로 써야 하므로 마지막 값이 남아 있으면 된다.

### 8방향 — 대각선 포함
```c
// ↑, ↗, →, ↘, ↓, ↙, ←, ↖
int dr[] = { -1, -1, 0, 1, 1, 1, 0, -1 };
int dc[] = {  0,  1, 1, 1, 0,-1,-1, -1 };
```
**시계 방향 한 바퀴**다. `0,2,4,6` 이 **상하좌우**(직교), `1,3,5,7` 이 **대각선**.

> **★ 이 배치가 "짝수/홀수 방향" 규칙의 의미다.**
> 짝수 = 직교, 홀수 = 대각선. 규칙이 "전부 짝수거나 전부 홀수면 `0,2,4,6`" 인 것은
> **"방향이 한 종류로 통일돼 있으면 직교로, 섞여 있으면 대각선으로"** 라는 뜻.

### ★★ 이동 — 속력을 `% N` 으로 줄이고 원형 보정
```c
// 속력이 N보다 클 수 있으므로 s % N만큼만 이동해도 결과가 같다.
nr = atom[i].r + dr[d] * (s % N);
nc = atom[i].c + dc[d] * (s % N);

// 격자는 원형으로 연결되어 있으므로 범위를 벗어나면 반대편으로 이동
if (nr > N) nr -= N;
if (nc > N) nc -= N;
if (nr < 1) nr += N;
if (nc < 1) nc += N;
```

**두 가지가 맞물린다.**

**① `s % N`** — 원형 격자에서 N칸 이동하면 제자리다. 속력이 1000이어도 `s % N` 이면 충분.
**이게 없으면 좌표가 크게 벗어나** 아래 보정 한 번으로 못 돌아온다.

**② 보정이 `if` 한 번씩**인 이유 — `s % N < N` 이므로 좌표가 최대 `N-1` 만큼만 벗어난다.
`1 ~ N` 범위에서 최대 `2N-1`, 최소 `2-N` 이라 **한 번의 `±N` 로 복귀**한다.

> **`%` 로 한 번에 쓰려면** 0-based로 바꿔야 깔끔하다.
> ```c
> nr = ((atom[i].r - 1 + dr[d] * (s % N)) % N + N) % N + 1;
> ```
> 1-based에서 `%` 를 쓰면 `+N` 보정이 지저분해진다. **`if` 두 줄이 오히려 명확하다.**

### 합산
```c
MAP[nr][nc].m += m;
MAP[nr][nc].s += s;
MAP[nr][nc].d  = d;              // count == 1 일 때만 유효

if (d % 2 == 0) MAP[nr][nc].even++;
else            MAP[nr][nc].odd++;

MAP[nr][nc].count++;
```
**`INFO MAP[MAX][MAX] = { 0 };` 이 턴마다 지역 선언**되어 자동 초기화된다.
전역으로 빼면 명시적 리셋이 필요하다 — [G07 원본 보존](../../theory/G07_완전탐색시뮬.md)의 변형.

### ★ 재생성 — 충돌 없음 / 있음
```c
acnt = 0;                        // ★ 배열을 처음부터 다시 채운다

for (int r = 1; r <= N; r++)
{
    for (int c = 1; c <= N; c++)
    {
        if (MAP[r][c].count == 0) continue;

        // 3-1. 원자가 1개 → 그대로 유지
        if (MAP[r][c].count == 1)
        {
            atom[acnt].r = r;  atom[acnt].c = c;
            atom[acnt].m = MAP[r][c].m;
            atom[acnt].s = MAP[r][c].s;
            atom[acnt].d = MAP[r][c].d;      // ★ 원래 방향 복원
            acnt++;
            continue;
        }

        // 3-2. 2개 이상 → 충돌
        // 새 질량이 0이면 분리되지 않고 소멸
        if ((MAP[r][c].m / 5) == 0) continue;      // ★ 소멸

        int dir[4];
        if (MAP[r][c].even == MAP[r][c].count      // 전부 짝수
            || MAP[r][c].odd == MAP[r][c].count)   // 또는 전부 홀수
        { dir[0]=0; dir[1]=2; dir[2]=4; dir[3]=6; }
        else
        { dir[0]=1; dir[1]=3; dir[2]=5; dir[3]=7; }

        for (int i = 0; i < 4; i++)
        {
            atom[acnt].r = r;  atom[acnt].c = c;
            atom[acnt].m = MAP[r][c].m / 5;                 // 합친 질량 / 5
            atom[acnt].s = MAP[r][c].s / MAP[r][c].count;   // 합친 속력 / 개수
            atom[acnt].d = dir[i];
            acnt++;
        }
    }
}
```

**세 갈래를 정확히 구분한다.**
| `count` | 처리 |
|---|---|
| `0` | 아무것도 없음 → skip |
| `1` | **그대로 유지** (방향도 원래대로) |
| `≥ 2` | 충돌 → 질량 `/5` 가 0이면 **소멸**, 아니면 **4개로 분리** |

**★ `count == 1` 을 충돌로 처리하면 안 된다.** 혼자 있는 원자는 합쳐질 게 없다.

**★ 소멸 판정이 `분리 전`** 이다. `m / 5 == 0` 이면 4개를 만들지 않고 그냥 버린다.

### 답
```c
int getAnswer()
{
    int sum = 0;
    for (int i = 0; i < acnt; i++) sum += atom[i].m;
    return sum;
}
```
**격자가 아니라 `atom[]` 배열을 훑는다.** 원자가 어디 있든 상관없이 질량만 더한다.

## 5. 예제 손 추적

### 원형 이동
```
N = 5, 원자가 (1,1) 에 있고 방향 = 0(↑), 속력 = 3

s % N = 3 % 5 = 3
nr = 1 + (-1) * 3 = -2
nc = 1 + 0 * 3 = 1

보정: nr < 1 → nr += 5 → nr = 3
결과: (3, 1)
```
**위로 3칸 = 아래에서 3번째 줄.** 원형 격자가 맞다.

### 속력이 N보다 큰 경우
```
s = 13, N = 5
s % N = 3           →  위 예와 동일한 결과

if (s % N) 없이 13칸 이동하면:
  nr = 1 - 13 = -12
  보정 한 번(+5) → -7    ★ 여전히 범위 밖!
```
**`% N` 이 없으면 보정 `if` 한 번으로 안 돌아온다.**

### 충돌 — 방향이 전부 짝수
```
칸 (2,2) 에 세 원자 도착
  A: m=10, s=2, d=0 (↑, 짝수)
  B: m=20, s=4, d=2 (→, 짝수)
  C: m=30, s=6, d=4 (↓, 짝수)

MAP[2][2]: m=60, s=12, count=3, even=3, odd=0

even(3) == count(3) → 전부 짝수 → dir = {0, 2, 4, 6}

새 원자 4개:
  m = 60 / 5 = 12
  s = 12 / 3 = 4
  d = 0, 2, 4, 6
```
**질량 합**: `12 × 4 = 48`. 원래 60이었으니 **12가 사라졌다** (`/5` 의 손실).

### 충돌 — 방향이 섞임
```
  A: d=0 (짝수),  B: d=1 (홀수)

even=1, odd=1, count=2
even != count 이고 odd != count  →  섞임  →  dir = {1, 3, 5, 7}
```

### 소멸
```
칸에 두 원자, m 합 = 4
4 / 5 = 0  →  분리 안 하고 소멸
→ 이 칸에서는 새 원자가 하나도 안 생김
```
**질량 4가 통째로 사라진다.**

### `count == 1` 유지
```
칸에 원자 하나, m=10, s=3, d=5
count == 1  →  그대로 유지
  m=10, s=3, d=5        ★ d 필드가 여기서 쓰인다
```
`INFO.d` 를 안 저장했다면 방향을 복원할 수 없다.

## 6. 함정 / 예상 함정
- **★★ `s % N` 누락.** 속력이 N보다 크면 보정으로 못 돌아온다. **원형 격자의 필수 최적화.**
- **★★ 원형 보정에서 `+N` 을 빼먹음.** `if (nr < 1) nr += N;` 네 줄 모두 필요.
- **★★ `count == 1` 을 충돌로 처리.** 혼자면 **그대로 유지**하고 **원래 방향**을 복원한다.
- **★★ 소멸 판정 누락.** `m / 5 == 0` 이면 4개를 만들지 않는다.
- **★ 짝/홀 판정.** `even == count || odd == count` — **전부** 같아야 직교(`0,2,4,6`). 하나라도 다르면 대각선.
- **★ 속력을 `/ count` 로 나눔.** 질량은 `/5`, 속력은 `/count`. **분모가 다르다.**
- **★ `MAP` 을 전역으로 두고 초기화 안 함.** 턴마다 `{0}` 리셋 필요. 지역 선언이 안전.
- **★ `acnt = 0` 리셋 누락.** 매 턴 배열을 처음부터 다시 채운다.
- **`atom[]` 크기.** 충돌마다 원자가 늘 수 있다 (`count` 개 → 4개). `100000+` 로 넉넉히.
- **8방향 배열 순서.** `0,2,4,6` 이 직교여야 짝/홀 규칙이 성립한다. 순서를 바꾸면 전부 틀린다.
- **T-loop 마다 `atom`, `acnt` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **원자는 배열, 격자는 합산판**이라는 구조를 설계할 수 있는가
- [ ] `INFO` 에 **합계·개수·짝홀 카운트**만 담으면 충분함을 아는가
- [ ] 이동에 **`s % N`** 을 넣었는가, 왜 필요한지 아는가
- [ ] 원형 보정 **네 줄**을 다 넣었는가
- [ ] `count` 를 **0 / 1 / ≥2** 세 갈래로 나누는가
- [ ] `count == 1` 일 때 **원래 방향을 복원**하는가
- [ ] `m / 5 == 0` 이면 **소멸**시키는가
- [ ] 짝/홀 판정이 **`even == count || odd == count`** 인가
- [ ] 질량은 `/5`, 속력은 `/count` 로 **분모를 구분**하는가
- [ ] 8방향 배열에서 **짝수 인덱스가 직교**인가
- [ ] 매 턴 `MAP` 초기화 + `acnt = 0` 하는가

## 8. 한 줄 요약
"원자는 **배열**, 격자는 **합산판**. 매 턴 `atom[]` 을 **통째로 재생성**하면 동시 이동과 충돌이 한 번에 풀린다."
