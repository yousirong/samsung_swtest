## 1. 문제 요약
블록 K개가 차례대로 주어진다. 각 블록은 **타입**과 **기준 좌표 `(r, c)`** 를 갖는다.

| 타입 | 모양 |
|---|---|
| `1` | `1×1` |
| `2` | `1×2` 가로 |
| `3` | `2×1` 세로 |

블록 하나가 주어질 때마다 **같은 블록을 두 보드에 각각** 넣는다.
- **빨간 보드**: 블록이 **오른쪽으로** 떨어진다
- **노란 보드**: 블록이 **아래로** 떨어진다

**한 블록 처리 후**
1. 각 보드에서 **꽉 찬 줄을 삭제**하고 **1점**씩 획득
2. **연한 칸**(경계 영역)에 블록이 걸치면, 그만큼 **줄을 밀어낸다** (점수 없음)

최종 **총점**과 **남아 있는 블록 칸 수**를 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 이 문제의 난이도는 **"같은 로직을 두 방향으로 두 벌 써야 한다"** 는 데 있다.

> ### ★★ 핵심 설계: 하나의 큰 배열에 두 보드를 겹쳐 둔다
> ```c
> #define START (4)
> #define END   (9)
>
> int MAP[MAX][MAX];      // 전체 보드 배열 (두 보드가 한 배열에)
> ```
> - **빨간 보드**: `MAP[0..3][START..END]` — 가로로 긴 영역
> - **노란 보드**: `MAP[START..END][0..3]` — 세로로 긴 영역
>
> **좌상단 `4×4` 영역이 두 보드의 공통 진입부**다.
> 배열 하나로 관리하면 좌표 변환이 필요 없어진다.

**전치([보도블럭](2017하오전2_보도블럭.md))로 코드를 재사용할 수도 있었지만**, 이 문제는 두 보드의 규칙이 미묘하게 달라 **각각 쓰는 편이 안전**하다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()            K, TYPE[], R[], C[]
      simulate()

simulate():
   score = 0
   for k in 0..K-1:
      moveRed(TYPE[k], R[k], C[k])       ① 빨간 보드 배치
      moveYellow(TYPE[k], R[k], C[k])    ② 노란 보드 배치

      score += getScoreRed();     score += getScoreRed();      ③ 최대 2줄
      score += getScoreYellow();  score += getScoreYellow();

      if (checkRed()) deleteRed(END);     ④ 연한 칸 밀어내기 (최대 2회)
      if (checkRed()) deleteRed(END);
      ... 노란 보드도 동일 ...
   printf(score, 남은 칸 수)
```

## 4. 핵심 코드

### ★ 낙하 — 타입마다 다른 충돌 검사
```c
void moveRed(int type, int sr, int sc)
{
    int c = sc;

    if (type == 1)          // 1x1 블록: 오른쪽 끝까지 이동
    {
        while (1)
        {
            if (MAP[sr][c + 1] != 0) break;
            c++;
        }
        MAP[sr][c] = 1;
    }
    else if (type == 2)     // 1x2 가로 블록
    {
        // 오른쪽 한 칸 더 나아간 위치까지 두 칸이 모두 비어 있어야 이동 가능
        while (1)
        {
            if (MAP[sr][c + 2] != 0) break;      // ★ c+2 를 본다
            c++;
        }
        MAP[sr][c] = MAP[sr][c + 1] = 1;
    }
    else if (type == 3)     // 2x1 세로 블록
    {
        // 위아래 두 칸이 함께 오른쪽으로 이동해야 하므로 두 행 모두 검사
        while (1)
        {
            if (MAP[sr][c + 1] != 0) break;
            if (MAP[sr + 1][c + 1] != 0) break;  // ★ 두 행 모두
            c++;
        }
        MAP[sr][c] = MAP[sr + 1][c] = 1;
    }
}
```

**타입마다 "다음 칸"의 정의가 다르다.**
| 타입 | 빨간 보드에서 검사할 칸 |
|---|---|
| `1` (1×1) | `[sr][c+1]` |
| `2` (1×2 가로) | **`[sr][c+2]`** — 블록이 두 칸을 차지하므로 앞쪽 끝 |
| `3` (2×1 세로) | `[sr][c+1]` **와** `[sr+1][c+1]` — 두 행 모두 |

> **★ 타입 2에서 `c+2` 를 보는 이유**: 블록이 `[c]`, `[c+1]` 을 차지하니 오른쪽으로 가려면 `[c+2]` 가 비어야 한다.
> `c+1` 을 보면 **자기 자신을 벽으로 착각**한다.

**노란 보드(`moveYellow`)는 `r` 과 `c` 를 맞바꾼 같은 로직**이다. 아래로 떨어지므로 행이 증가한다.

**테두리를 벽(`WALL = -1`)으로 초기화**해 `while(1)` 이 자동으로 멈춘다 — [G05 sentinel](../../theory/G05_그리드탐색심화.md).

### 줄 삭제 — 밀어내기
```c
void deleteRed(int col)
{
    for (int c = col; c > START; c--)
        for (int r = 0; r < 4; r++)
            MAP[r][c] = MAP[r][c - 1];       // ★ 뒤에서부터 당겨온다

    MAP[0][START] = MAP[1][START] = MAP[2][START] = MAP[3][START] = 0;
}
```

**`col` 부터 `START` 방향으로 당겨온다.** [G10 시공의 돌풍](2019상오전1_시공의돌풍.md)의 순환 밀어내기와 같은 원리 — **흐름의 반대 방향부터** 처리해야 덮어쓰지 않는다.

마지막에 **진입부(`START`)를 비운다.**

### 점수 판정
```c
int getScoreRed()
{
    // 진한 영역(START+2 ~ END)의 각 열을 검사
    for (int c = START + 2; c <= END; c++)
    {
        int cnt = 0;
        for (int r = 0; r < 4; r++) cnt += MAP[r][c];

        if (cnt == 4)               // 4칸 모두 차 있으면
        {
            deleteRed(c);
            return 1;               // ★ 한 번에 한 줄만
        }
    }
    return 0;
}
```

**한 번 호출에 한 줄만 지운다.** 그래서 `simulate()` 에서 **두 번 호출**한다.
```c
score += getScoreRed();
score += getScoreRed();     // ★ 한 블록으로 최대 2줄까지 찰 수 있으므로
```

> **왜 2번인가**: 블록이 최대 2칸을 차지하므로 **한 번에 최대 2줄**이 완성될 수 있다.
> `while` 로 "더 이상 없을 때까지" 돌리는 편이 더 안전하다.
> ```c
> int s;
> while ((s = getScoreRed()) > 0) score += s;
> ```

### 연한 칸 처리
```c
bool checkRed()
{
    // 연한 칸(START+1 열)에 블록이 있는지
    for (int r = 0; r < 4; r++)
        if (MAP[r][START + 1] == 1) return true;
    return false;
}

// simulate() 에서
if (checkRed() == true) deleteRed(END);
if (checkRed() == true) deleteRed(END);
```

**연한 칸에 걸치면 점수 없이 줄이 밀려난다.**
`deleteRed(END)` 로 **가장 끝 줄을 버리고** 전체를 한 칸 밀어낸다.

**최대 2칸까지 밀릴 수 있어 두 번 검사**한다 — 같은 이유로 `while` 이 더 안전하다.

> ⚠️ **`START + 1` 이 "연한 칸"이고 `START + 2` 부터가 "진한 영역"(점수 대상)** 이다.
> 이 경계를 헷갈리면 점수와 밀어내기가 뒤섞인다.

## 5. 예제 손 추적

### 타입 2(1×2 가로) 낙하
```
빨간 보드 한 행 (START=4, END=9)
인덱스:  4   5   6   7   8   9  10(벽)
값:      0   0   0   0   1   1   -1

블록이 c=4 에서 시작
while: MAP[sr][4+2] = MAP[sr][6] = 0 → c=5
       MAP[sr][5+2] = MAP[sr][7] = 0 → c=6
       MAP[sr][6+2] = MAP[sr][8] = 1 → break

배치: MAP[sr][6] = MAP[sr][7] = 1
```
```
결과:    0   0   1   1   1   1   -1
```
**`c+2` 를 봤기 때문에 `[6][7]` 에 정확히 붙었다.** `c+1` 을 봤다면 `[7][8]` 로 겹쳤을 것.

### 타입 3(2×1 세로) 낙하 — 두 행 검사
```
행 sr:    0   0   0   1
행 sr+1:  0   0   1   1

c=4 부터:
  c+1=5: MAP[sr][5]=0, MAP[sr+1][5]=0  → c=5
  c+1=6: MAP[sr][6]=0, MAP[sr+1][6]=1  → break   ★ 아래 행이 막힘

배치: MAP[sr][5] = MAP[sr+1][5] = 1
```
**한 행만 검사했다면** `c=6` 까지 가서 아래 행이 겹쳤을 것.

### 줄 삭제
```
삭제 전 (열 4~9):
  r=0:  0  1  1  1  1  1
  r=1:  0  0  1  1  1  1
  r=2:  0  0  0  1  1  1
  r=3:  0  0  0  0  1  1

열 8 이 꽉 참? r=0..3 합 = 1+1+1+1 = 4 ✓
→ deleteRed(8)

c=8: MAP[r][8] = MAP[r][7]
c=7: MAP[r][7] = MAP[r][6]
c=6: MAP[r][6] = MAP[r][5]
c=5: MAP[r][5] = MAP[r][4]
MAP[r][4] = 0

삭제 후:
  r=0:  0  0  1  1  1  1
  r=1:  0  0  0  1  1  1
  r=2:  0  0  0  0  1  1
  r=3:  0  0  0  0  0  1
```
**뒤에서부터 당겨왔기 때문에** 값이 안 겹쳤다.

### 연한 칸
```
열 인덱스:  4(START)  5(연한)  6  7  8  9(END)
                       ↑
              여기에 블록이 있으면 밀어냄

MAP[r][5] == 1 인 r 이 하나라도 있으면 → deleteRed(END)
→ 가장 끝(9번 열)이 버려지고 전체가 한 칸 밀림
```

## 6. 함정 / 예상 함정
- **★★ 타입별 충돌 검사 칸을 잘못 잡음.** 1×2 가로는 **`c+2`**, 2×1 세로는 **두 행 모두**. 이 문제 최다 실수.
- **★★ 줄 삭제를 앞에서부터 밀기.** **뒤에서부터 당겨와야** 덮어쓰지 않는다.
- **★★ 점수 판정을 한 번만.** 한 블록으로 최대 2줄이 찬다. **두 번 또는 `while`.**
- **★ 연한 칸과 진한 영역 경계 혼동.** `START+1` = 연한(밀어내기), `START+2 ~ END` = 진한(점수).
- **★ 두 보드를 하나로 합쳐 처리하려 함.** 규칙이 미묘하게 달라 **각각 쓰는 편이 안전.**
- **★ 노란 보드에서 `r`/`c` 를 안 바꿈.** `moveYellow` 는 행이 증가한다.
- **★ 테두리 벽 초기화 누락.** `while(1)` 이 무한 루프에 빠진다.
- **점수 함수가 삭제까지 한다.** `getScoreRed()` 가 `deleteRed()` 를 호출하므로 **점수와 삭제가 붙어 있다.** 분리하려면 구조를 바꿔야 한다.
- **남은 칸 수 계산 범위.** 두 보드 각각의 유효 영역만 센다.
- **T-loop 마다 `MAP` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] **두 보드를 한 배열에 겹쳐** 두는 좌표 설계를 할 수 있는가
- [ ] 타입별 충돌 검사 칸(**1×2는 `c+2`, 2×1은 두 행**)을 정확히 잡는가
- [ ] 줄 삭제를 **뒤에서부터 당겨오기**로 하는가
- [ ] 점수 판정을 **두 번(또는 `while`)** 하는가
- [ ] **연한 칸(`START+1`)과 진한 영역(`START+2~END`)** 을 구분하는가
- [ ] 연한 칸 처리도 **두 번(또는 `while`)** 하는가
- [ ] 테두리를 벽으로 초기화했는가
- [ ] 노란 보드에서 `r`/`c` 를 맞바꿨는가

## 8. 한 줄 요약
"**두 보드를 한 배열에 겹쳐** 두고, 타입별 **충돌 검사 칸**만 정확히. 삭제는 **뒤에서부터**, 판정은 **두 번.**"
