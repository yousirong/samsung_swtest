## 1. 문제 요약
N×M 격자에 먼지가 있고, **공기청정기가 2칸**을 차지한다 (`-1` 로 표시, 세로로 붙어 있음).

**매 초마다 두 단계가 순서대로**
1. **먼지 확산**
   - 각 먼지 칸은 상하좌우로 **`현재 먼지 / 5`** 만큼 퍼뜨린다 (정수 나눗셈)
   - 공기청정기 칸(`-1`)과 격자 밖으로는 안 퍼진다
   - 원래 칸은 **퍼진 방향 수 × 확산량**만큼 줄어든다
2. **공기청정기 작동**
   - **위쪽** 청정기: **반시계** 방향으로 바람 순환
   - **아래쪽** 청정기: **시계** 방향으로 바람 순환
   - 바람이 지나가는 칸의 먼지는 **한 칸씩 밀리고**, 청정기로 들어간 먼지는 **사라진다**

`T` 초 후 **남은 먼지의 총합**을 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 하지만 이 그룹에서 **가장 함정이 많은 문제** 중 하나다.

> ### ★★ 두 개의 큰 함정
> **① 확산은 "동시에" 일어난다.**
> 먼저 처리한 칸이 줄어들면 뒤 칸이 잘못된 값을 본다. **판정/반영 분리 필수.**
>
> **② 공기청정기 순환은 "밀어내기"다.**
> 각 칸의 먼지가 **다음 칸으로 밀린다.** 순서를 잘못 잡으면 값이 덮인다.

[회전하는 빙하](../G06/2020하오후2_회전하는빙하.md)의 "판정/반영 분리"가 여기서 다시 나온다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()             N, M, time, MAP — 공기청정기 위치 수집
      for t in 1..time:
         diffusion()      ★ 확산 (동시)
         cleaning()       ★ 순환 (밀어내기)
      printf(getAnswer())
```

## 4. 핵심 코드

### ★★ 확산 — `tmpMAP` 에 누적 후 한 번에 반영
```c
void diffusion()
{
    // 이번 초에 퍼진 먼지 양을 저장할 tmpMAP 초기화
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            tmpMAP[r][c] = 0;

    for (int r = 1; r <= N; r++)
    {
        for (int c = 1; c <= M; c++)
        {
            // 먼지가 없거나 공기청정기 칸이면 확산할 필요 없음
            if (MAP[r][c] <= 0) continue;        // ★ <= 0 : 0과 -1을 한 번에

            int dust, count;
            dust = count = 0;

            for (int i = 0; i < 4; i++)
            {
                int nr = r + dr[i];
                int nc = c + dc[i];

                if (nr < 1 || nc < 1 || nr > N || nc > M) continue;
                if (MAP[nr][nc] == TORNADO_POSITION) continue;   // 청정기로는 안 퍼짐

                dust = MAP[r][c] / 5;            // ★ 원본 값 기준
                tmpMAP[nr][nc] += dust;          // ★ 누적만
                count++;
            }

            // 현재 칸에서는 count번만큼 퍼져나갔으므로 그만큼 감소
            MAP[r][c] -= (dust * count);
        }
    }

    // 확산 결과를 원본 MAP에 반영
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            MAP[r][c] += tmpMAP[r][c];
}
```

**★ `tmpMAP` 은 "퍼져 들어온 양"만 담는다.** 전체 상태의 복사본이 아니다.
- 나가는 양(`-= dust * count`)은 **`MAP` 에서 즉시** 뺀다
- 들어오는 양은 **`tmpMAP` 에 모았다가 마지막에** 더한다

이 비대칭이 **동시성을 보장**한다.

> **왜 나가는 건 즉시 빼도 되나?**
> `dust = MAP[r][c] / 5` 를 **계산한 뒤** 빼기 때문에, 그 칸의 확산량은 이미 확정됐다.
> 그리고 다른 칸이 이 칸을 **읽지 않는다** — 읽는 건 `MAP[nr][nc] == TORNADO_POSITION` 검사뿐이고, 그건 먼지 양과 무관하다.
>
> ⚠️ 단 **한 가지 주의**: `MAP[r][c] <= 0` 검사가 **줄어든 값**을 볼 수 있다.
> 확산으로 줄어든 칸이 0 이하가 되면 이후 칸 처리에는 영향이 없으므로 안전하다.

**`dust` 를 루프 밖에서 선언**한 것도 의도적이다. 루프가 끝난 뒤 `dust * count` 를 쓰기 위함.
> ⚠️ **`count == 0` 이면 `dust` 도 0이라 `dust * count = 0`** — 문제없다.
> 하지만 `dust` 를 루프 안에서 선언했다면 밖에서 못 쓴다. **초기화 `dust = count = 0` 도 필수.**

**`MAP[r][c] <= 0` 한 줄**로 빈 칸(`0`)과 청정기(`-1`)를 동시에 거른다.

### 공기청정기 순환 — 밀어내기
```c
void cleaning()
{
    // 위쪽 청정기: 반시계 순환
    //   위로 → 오른쪽으로 → 아래로 → 왼쪽으로(청정기로 흡입)
    //
    // 아래쪽 청정기: 시계 순환
    //   아래로 → 오른쪽으로 → 위로 → 왼쪽으로(청정기로 흡입)
    ...
}
```

**★ 밀어내기의 방향이 중요하다.**
바람이 `A → B → C` 로 흐르면, **먼지도 `A → B → C` 로 밀린다.**
값을 옮길 때는 **흐름의 반대 방향부터** 처리하거나, **한 칸씩 당겨오는** 방식으로 써야 덮어쓰기가 안 난다.

```
흐름:  [a] → [b] → [c] → [청정기]

당겨오기 방식 (안전):
  c ← b
  b ← a
  a ← 0        (청정기에서 나온 깨끗한 공기)
```
**뒤에서부터 당겨오면** 아직 안 옮긴 값이 살아 있다.

> **밀어내기 방식으로 앞에서부터 쓰면** `b` 에 `a` 를 넣는 순간 원래 `b` 값이 사라져 `c` 로 못 보낸다.
> [G01의 제1원칙](../../theory/G01_배열회전.md)("읽는 곳과 쓰는 곳 분리")이 여기서도 적용된다.

**청정기 바로 앞 칸의 먼지는 사라진다** (흡입). 그리고 청정기에서 나오는 칸은 `0` 이 된다.

### 공기청정기 위치
```c
#define TORNADO_POSITION (-1)

// input() 안에서 -1인 칸의 좌표를 수집
// 두 칸이 세로로 붙어 있으므로 위쪽/아래쪽을 구분해 저장
```
**위쪽이 반시계, 아래쪽이 시계**이므로 둘을 구분해야 한다.

### 답
```c
int getAnswer()
{
    int sum = 0;
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            if (MAP[r][c] > 0) sum += MAP[r][c];    // ★ 청정기(-1) 제외
    return sum;
}
```
**`> 0` 조건**으로 청정기 칸(`-1`)을 제외한다. 안 하면 `-2` 가 더해져 답이 2 작아진다.

## 5. 예제 손 추적 — 확산 규칙

### 한 칸의 확산
```
       0
  0  [100]  0          가운데 칸에 먼지 100, 사방이 모두 빈 칸
       0
```
```
dust = 100 / 5 = 20
4방향 모두 확산 가능 → count = 4

각 이웃: tmpMAP += 20
원래 칸: MAP -= 20 * 4 = 80  →  100 - 80 = 20
```
```
결과      20
     20  [20]  20
          20
```
**총합 보존**: `20 × 4 + 20 = 100` ✓ 확산은 먼지를 만들거나 없애지 않는다.

### 청정기가 옆에 있으면
```
      -1              위가 청정기
  0  [100]  0
       0
```
```
dust = 20
위쪽은 청정기 → 확산 불가
→ count = 3 (오른쪽, 아래, 왼쪽)

원래 칸: 100 - 20*3 = 40
```
```
결과      -1
     20  [40]  20
          20
```
**총합**: `20 × 3 + 40 = 100` ✓ **막힌 방향의 몫은 원래 칸에 남는다.**

### 정수 나눗셈
```
MAP = 7   →   dust = 7 / 5 = 1
4방향 확산 → 각 1씩, 원래 칸 7 - 4 = 3
```
`7 = 1×4 + 3` ✓ 버림 때문에 원래 칸에 나머지가 남는다.

### ★ 동시성 확인 — `tmpMAP` 없이 하면
```
초기      [10]  [10]      두 칸이 나란히
```
**올바른 결과** (동시)
```
왼쪽: dust = 2, 오른쪽으로 2 확산 (다른 방향은 벽이라 가정, count=1)
      → MAP[왼] = 10 - 2 = 8
오른쪽: dust = 2, 왼쪽으로 2 확산
      → MAP[오] = 10 - 2 = 8

반영: MAP[왼] = 8 + 2 = 10,  MAP[오] = 8 + 2 = 10
```

**즉시 반영했다면**
```
왼쪽 처리: MAP[왼] = 8,  MAP[오] = 10 + 2 = 12
오른쪽 처리: dust = 12 / 5 = 2  ← ★ 이미 늘어난 값으로 계산!
      → MAP[오] = 12 - 2 = 10,  MAP[왼] = 8 + 2 = 10
```
**우연히 같아 보이지만** 값이 커지면 `dust` 계산이 달라져 결과가 갈린다.
`12/5 = 2` 지만 `13/5 = 2`, `15/5 = 3` — **경계에서 틀린다.**

## 6. 함정 / 예상 함정
- **★★ 확산을 즉시 반영.** `tmpMAP` 에 모았다가 한 번에 더해야 한다. **동시성 위반.**
- **★★ 청정기 순환에서 덮어쓰기.** **흐름의 반대 방향부터 당겨오기.**
- **★★ 위/아래 청정기 회전 방향 혼동.** 위는 **반시계**, 아래는 **시계**.
- **★ 확산량을 `count` 로 안 곱함.** 막힌 방향이 있으면 `count < 4` 다. `dust * count` 만큼만 뺀다.
- **★ 정수 나눗셈.** `/5` 는 버림. 실수로 하면 총합이 안 맞는다.
- **★ 청정기 칸을 답에 포함.** `MAP > 0` 조건으로 `-1` 제외.
- **★ `dust` 를 루프 안에서 선언.** 루프 후 `dust * count` 를 쓰려면 밖에서 선언 + 초기화.
- **`MAP[r][c] <= 0` 조건.** `== 0` 만 쓰면 청정기(`-1`)가 확산 시도를 한다.
- **`tmpMAP` 초기화 누락.** 매 초 `0` 으로 리셋해야 한다.
- **T-loop 마다 `MAP`, 청정기 좌표 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] 확산을 **`tmpMAP` 누적 → 일괄 반영**으로 분리했는가
- [ ] `tmpMAP` 이 "들어온 양"만 담고 **나가는 양은 즉시 뺀다**는 구조를 이해하는가
- [ ] `dust * count` 로 **막힌 방향을 반영**하는가
- [ ] `dust` 를 루프 밖에서 선언하고 초기화했는가
- [ ] `MAP <= 0` 으로 빈 칸과 청정기를 한 번에 거르는가
- [ ] 청정기 순환을 **반대 방향부터 당겨오기**로 구현하는가
- [ ] 위=**반시계**, 아래=**시계** 를 구분하는가
- [ ] 답에서 청정기 칸(`-1`)을 제외하는가
- [ ] 매 초 `tmpMAP` 을 초기화하는가

## 8. 한 줄 요약
