## 1. 문제 요약
길이가 **`2N`** 인 무빙워크가 **원형으로 연결**되어 있다.
사람은 **1번 칸**에 올라가고, **N번 칸**에 도착하면 **즉시 내린다.**

각 칸에는 **안정성**이 있고, 사람이 **올라가거나 이동해서 도착하면 안정성이 1 감소**한다.

**매 단계 진행 순서** (순서가 곧 정답이다)
1. 무빙워크가 **한 칸 회전** — 사람도 함께 실려 간다
2. 무빙워크 위 사람들이 **앞 칸으로 이동 가능하면 이동**
3. **1번 칸에 사람이 없고 안정성이 0이 아니면** 새 사람 탑승
4. **안정성이 0인 칸이 K개 이상이면 종료**

종료된 **단계 번호**를 출력한다.

## 2. 필요한 이론
→ [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)

**새 알고리즘이 없다.** 이 문제는 **"순서를 정확히 지키는가"** 만 본다.

> ### ★★ 이 문제의 정체: 4단계 순서 문제
> 단계 하나만 어긋나도 답이 완전히 달라진다.
> - 회전을 **사람 이동보다 나중에** 하면? → 틀림
> - 새 사람을 **이동보다 먼저** 태우면? → 틀림
> - 종료 검사를 **단계 끝이 아니라 중간에** 하면? → 틀림
>
> **[G10 이론](../../theory/G10_순수시뮬레이션.md)의 "규칙 번호와 함수를 1:1 대응"** 이 그대로 적용된다.

**두 번째 포인트: N번 칸 도착 = 즉시 하차.** 이 판정이 **두 곳**(회전 후, 이동 후)에 필요하다.

## 3. 코드 흐름
```
main()
 └ input()             N, K, 안정성 2N개
   printf(simulate())

simulate():
   step = 0, crush = 0, pIndex = 1
   while (1):
      step++
      ① rotate()                      벨트 한 칸 회전
      ①-2 모든 사람 position += 1     회전에 실려 감
          → position == N 이면 즉시 하차
      ② 사람 이동 (앞 칸이 비어있고 안정성 > 0)
          → 도착 칸 안정성--, N이면 하차
      ③ 1번 칸에 새 사람 탑승 (조건 만족 시)
          → 안정성--
      ④ if (crush >= K) return step
```

## 4. 핵심 코드

### 자료구조 — 벨트 배열 + 사람 위치 배열
```c
struct MOVING
{
    int index;          // 원래 칸 번호 (디버그용)
    int peopleNumber;   // 현재 이 칸 위에 있는 사람 번호, 없으면 0
    int stability;      // 현재 안정성
};

MOVING moving[MAX * 2];              // moving[i] = i번째 "위치"의 칸 정보 (1 ~ 2N)
int position[200000 + 5000];         // position[i] = i번 사람의 현재 위치 (내렸으면 -1)
int livePeople[MAX];                 // 현재 벨트 위에 있는 사람 번호 목록
int lcnt;                            // 그 수
```

**★ `moving[i]` 는 "i번째 위치"이지 "i번 칸"이 아니다.**
회전하면 **칸이 통째로 이동**하므로, 배열 인덱스는 **자리(position)** 를 뜻한다.
`index` 필드가 "원래 몇 번 칸이었는지"를 기억한다 (디버그용).

**`livePeople[]` 목록**을 따로 두는 이유: 매 단계 **벨트 전체를 훑지 않고** 사람만 순회하기 위함.

### ★ 회전 — 배열을 통째로 민다
```c
void rotate()
{
    MOVING tmp = moving[2 * N];              // 마지막 칸을 빼두고
    for (int i = 2 * N - 1; i >= 1; i--)
        moving[i + 1] = moving[i];           // 뒤에서부터 한 칸씩 밀고
    moving[1] = tmp;                          // 빼둔 것을 앞에
}
```

**뒤에서부터 미는 것**이 핵심이다. 앞에서부터 밀면 덮어쓴다 — [G01의 제1원칙](../../theory/G01_배열회전.md).
[G06 팔각의자](../G06/2017하오후1_돌아가는팔각의자.md)의 원형 시프트와 같은 관용구.

> **더 빠른 방법**: 실제로 밀지 않고 **offset 변수**만 증가시키는 것. `2N ≤ 200` 이라 굳이 필요 없다.

### ★★ 회전에 실려 가는 사람 — 위치도 +1
```c
rotate();

// 회전에 따라 사람 위치도 한 칸 증가
for (int i = 0; i < lcnt; i++)
{
    int peopleNumber = livePeople[i];
    position[peopleNumber] = position[peopleNumber] + 1;
}
```

**칸이 움직이면 그 위의 사람도 같이 움직인다.** 이게 규칙 1의 절반이다.

> **`moving[].peopleNumber` 는 칸에 붙어 있어서 회전과 함께 자동으로 따라간다.**
> 하지만 `position[]` 은 사람 기준이라 **따로 갱신**해야 한다. **두 배열의 동기화**가 이 문제의 미묘한 지점.

### 회전 직후 하차 판정
```c
int nextlcnt = 0;
for (int i = 0; i < lcnt; i++)
{
    int peopleNumber = livePeople[i];
    int curPos = position[peopleNumber];

    // 회전만으로 N번 위치에 도착한 경우 즉시 내림
    if (curPos == N)
    {
        position[peopleNumber] = -1;
        moving[curPos].peopleNumber = 0;
        continue;                          // ★ livePeople 에 안 넣는다
    }
    ... 이동 처리 ...
}
```

**회전만으로도 N번에 도달할 수 있다.** 이 판정을 빼면 사람이 N을 지나쳐 계속 돈다.

### 사람 이동
```c
    int nextPos = curPos + 1;

    // 앞 칸이 비어 있고 안정성이 남아 있어야 이동 가능
    if (moving[nextPos].peopleNumber == 0 && moving[nextPos].stability > 0)
    {
        moving[curPos].peopleNumber = 0;
        moving[nextPos].peopleNumber = peopleNumber;

        moving[nextPos].stability--;                        // ★ 도착 칸 안정성 감소
        if (moving[nextPos].stability == 0) crush++;        // ★ 처음 0이 될 때만

        position[peopleNumber] = nextPos;

        if (nextPos == N)                                   // ★ 이동 후 하차 판정
        {
            position[peopleNumber] = -1;
            moving[nextPos].peopleNumber = 0;
        }
        else livePeople[nextlcnt++] = peopleNumber;
    }
    else livePeople[nextlcnt++] = peopleNumber;             // 못 움직이면 그대로 남음
```

**세 가지 조건이 맞물린다.**
1. 앞 칸이 **비어 있어야** 한다 (`peopleNumber == 0`)
2. 앞 칸 **안정성이 0보다 커야** 한다
3. 이동 후 **N이면 즉시 하차**

**`crush++` 를 `== 0` 일 때만** 하는 것이 중요하다. 안정성은 음수로 안 내려가지만, 이미 0인 칸을 또 세면 안 된다.
> 실제로 안정성이 0인 칸에는 **이동해 들어갈 수 없으므로**(조건 2) 0 아래로 내려가지 않는다.

### 새 사람 탑승
```c
// 1번 칸에 사람이 없고 안정성이 0이 아니면 새 사람 탑승
if (moving[1].peopleNumber == 0 && moving[1].stability != 0)
{
    position[pIndex] = 1;
    livePeople[nextlcnt++] = pIndex;
    moving[1].peopleNumber = pIndex++;

    moving[1].stability--;
    if (moving[1].stability == 0) crush++;
}

lcnt = nextlcnt;      // ★ 남은 사람 수 갱신
```

**탑승은 이동 다음**이다. 순서를 바꾸면 갓 탄 사람이 같은 단계에 또 움직인다.

### 종료
```c
if (crush >= K) return step;
```
**단계의 맨 마지막**에 확인한다. 중간에 확인하면 그 단계의 나머지 처리가 누락된다.

## 5. 예제 손 추적

### 회전과 위치 동기화
```
N = 3 (벨트 길이 6), 사람 A가 position 2 에 있음

회전 전:  [1][2][3][4][5][6]      A는 2번 위치
                ↑ A

rotate():  마지막 칸(6)이 앞으로
          [6][1][2][3][4][5]
                   ↑ A 가 실려 3번 위치로

position[A] = 2 + 1 = 3
```
**`position` 을 +1 안 하면** A가 여전히 2번이라고 믿어 벨트와 어긋난다.

### 회전만으로 하차
```
N = 3, 사람 B가 position 2

회전 → position[B] = 3 == N  →  즉시 하차 ✓
```
**이동 단계를 거치지 않고 내린다.**

### 이동 조건
```
사람 C가 position 1, 앞 칸(2번)의 상태:

경우 ①: peopleNumber = 0, stability = 3  →  이동 ✓
        stability 3 → 2

경우 ②: peopleNumber = 5 (사람 있음)     →  못 움직임
경우 ③: peopleNumber = 0, stability = 0  →  못 움직임 (안정성 소진)
```

### `crush` 카운트
```
칸의 안정성 2 → 사람 도착 → 1     (crush 변화 없음)
칸의 안정성 1 → 사람 도착 → 0     (crush++ ✓)
칸의 안정성 0 → 사람이 못 들어옴  (crush 변화 없음)
```
**`== 0` 이 되는 순간에만 센다.**

### 단계 순서가 왜 중요한가
```
잘못된 순서: 탑승 → 회전 → 이동

1번 칸에 사람을 태우고 회전하면
그 사람이 2번으로 실려 가고, 1번이 다시 비어
같은 단계에 또 태울 수 있게 된다
→ 사람이 2배로 들어간다
```

## 6. 함정 / 예상 함정
- **★★ 단계 순서 위반.** **회전 → 이동 → 탑승 → 종료검사.** 하나만 바꿔도 답이 달라진다.
- **★★ 회전 시 `position[]` 갱신 누락.** `moving[].peopleNumber` 는 자동으로 따라가지만 `position[]` 은 아니다. **두 배열 동기화.**
- **★★ 하차 판정이 두 곳 필요.** 회전 직후 + 이동 직후. 하나만 넣으면 사람이 N을 지나친다.
- **★ 회전을 앞에서부터 밀기.** **뒤에서부터** 밀어야 덮어쓰지 않는다.
- **★ `crush` 를 매번 셈.** 안정성이 **처음 0이 될 때만** 증가.
- **★ 이동 조건에서 안정성 검사 누락.** 앞 칸이 비어 있어도 **안정성이 0이면 못 간다.**
- **★ 탑승 조건에서 안정성 검사 누락.** 1번 칸 안정성이 0이면 못 탄다.
- **★ 종료 검사 위치.** 단계 **끝**에서.
- **벨트 길이가 `2N`** 인데 `N` 으로 잡음. 배열 크기 주의.
- **`position` 배열 크기.** 사람 번호가 계속 증가하므로 단계 수만큼 커질 수 있다. `200000+` 로 넉넉히.
- **`livePeople` 재구성.** `nextlcnt` 로 새로 담고 마지막에 `lcnt = nextlcnt`. 내린 사람을 목록에서 빼야 한다.

## 7. 백지 재현 체크리스트
- [ ] **회전 → 이동 → 탑승 → 종료검사** 순서를 지키는가
- [ ] 회전 시 `moving[]` 과 **`position[]` 을 모두** 갱신하는가
- [ ] 하차 판정을 **회전 직후와 이동 직후 두 곳**에 넣었는가
- [ ] 회전을 **뒤에서부터** 미는가
- [ ] 이동 조건이 **빈 칸 && 안정성 > 0** 두 개인가
- [ ] `crush++` 를 **처음 0이 될 때만** 하는가
- [ ] 탑승 조건에 **안정성 검사**가 있는가
- [ ] `livePeople` 을 매 단계 **재구성**하는가
- [ ] 벨트 길이가 **`2N`** 임을 반영했는가

## 8. 한 줄 요약
"**회전 → 이동 → 탑승 → 검사**, 순서가 곧 정답. 회전 시 **`position[]` 도 같이** 밀고, 하차 판정은 **두 곳**."
