## 1. 문제 요약
`2^N × 2^N` 격자에 얼음 양이 주어진다. Q개의 명령이 있고 각 명령은 `L` 값을 갖는다.

**매 명령마다**
1. 격자를 `2^L × 2^L` 부분 격자로 나눈다
2. 각 부분 격자를 **시계 방향 90도 회전**
3. 회전 후, **인접한 얼음 칸이 3개 미만인** 얼음 칸은 얼음이 1 감소

**모든 명령이 끝난 뒤**
1. 남아 있는 얼음의 총합
2. 가장 큰 얼음 덩어리의 크기

## 2. 필요한 이론
→ [G06 격자·상태 회전](../../theory/G06_격자상태회전.md) + [G05 ① 플러드필](../../theory/G05_그리드탐색심화.md)

**세 가지가 결합된 문제**다. 각각은 이미 1부에서 다 배웠다.

| 구성 요소 | 1부 어디서 배웠나 |
|---|---|
| `2^L` 블록 단위 회전 | [15 배열돌리기 6](../G01/15_BOJ_20327_배열돌리기6.md) |
| 동시 소멸 (temp 배열) | [G01 이론](../../theory/G01_배열회전.md) |
| 최대 덩어리 크기 | [34 단지번호붙이기](../G05/34_BOJ_2667_단지번호붙이기.md) |

> **기출이 이렇게 생겼다.** 새 알고리즘이 아니라 **아는 것 세 개를 순서대로 붙이는 것.**
> 1부를 제대로 해두면 기출은 "조합 문제"가 된다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()              N, Q, MAP(2^N × 2^N), L[0..Q-1]
      simulate()
       └ for q in 0..Q-1:
            divide = 1 << L[q]
            모든 divide×divide 블록 → rotate(r, c, divide)
            meltIce()
      printf(getIceCount())      남은 얼음 총합
      printf(getGroupCount())    최대 덩어리 (BFS)
```

**함수 하나가 지문의 규칙 하나**에 대응한다. 이 분해가 시뮬레이션 문제의 기본기다.

## 4. 핵심 코드

### ★ 블록 회전 — 사분면 통째 이동
```c
void rotate(int sr, int sc, int size)
{
    int half = size / 2;

    // 회전 전 부분 격자를 tmpMAP에 복사
    for (int r = 0; r < size; r++)
        for (int c = 0; c < size; c++)
            tmpMAP[r][c] = MAP[sr + r][sc + c];

    // 3 -> 1  (좌하 → 좌상)
    for (int r = 0; r < half; r++)
        for (int c = 0; c < half; c++)
            MAP[sr + r][sc + c] = tmpMAP[r + half][c];

    // 1 -> 2  (좌상 → 우상)
    ... MAP[sr + r][sc + c + half] = tmpMAP[r][c];

    // 2 -> 4  (우상 → 우하)
    ... MAP[sr + r + half][sc + c + half] = tmpMAP[r][c + half];

    // 4 -> 3  (우하 → 좌하)
    ... MAP[sr + r + half][sc + c] = tmpMAP[r + half][c + half];
}
```

### ⚠️ 확인이 필요한 지점 — 이 `rotate` 는 표준 90도 회전이 아니다

시계 90도 회전을 `temp[size-1-c][r]` 공식([14번](../G01/14_BOJ_16935_배열돌리기3.md))이 아니라 **사분면 4개를 통째로 옮기는** 방식으로 구현했다.
**사분면을 옮기기만 하고 각 사분면 내부는 다시 회전시키지 않는다.**

- `size = 2` → 사분면이 1칸씩이라 **정확히 일치**
- `size ≥ 4` → **결과가 달라진다**

4×4로 직접 확인한 결과:
```
원본            이 코드의 rotate      올바른 시계 90도
 1  2  3  4      9 10  1  2           13  9  5  1
 5  6  7  8     13 14  5  6           14 10  6  2
 9 10 11 12     11 12  3  4           15 11  7  3
13 14 15 16     15 16  7  8           16 12  8  4
```

무작위 입력 300개(`size ≥ 4` 회전 포함)로 두 방식을 대조하면 **287개에서 최종 답이 다르다.**

**그런데 이 코드는 채점을 통과했다** (`git log`: `[Passed] 회전하는 빙하 (38ms, 0MB)`).
[대회 당일 원본](../../../260511/회전하는%20빙하/rotating-glacier.cpp)도 같은 구현이다.

> **복습할 때 반드시 확인할 것** — 셋 중 하나다.
> 1. 문제의 규칙이 "부분 격자를 **시계 방향 자리로 이동**"이지 "90도 회전"이 아니다 → 코드가 맞다
> 2. 채점 데이터에 `L ≥ 2` 케이스가 없거나 약하다 → **운으로 통과한 것**
> 3. 내가 규칙을 잘못 읽었다
>
> [문제 링크](https://www.codetree.ai/frequent-problems/samsung-sw/problems/rotating-glacier)에서 지문을 다시 읽고 판정한다. **이게 이 문제 복습의 첫 번째 할 일이다.**

만약 진짜 90도 회전이라면 이렇게 고친다.
```c
void rotate(int sr, int sc, int size)
{
    for (int r = 0; r < size; r++)
        for (int c = 0; c < size; c++)
            tmpMAP[r][c] = MAP[sr + r][sc + c];

    for (int r = 0; r < size; r++)
        for (int c = 0; c < size; c++)
            MAP[sr + r][sc + c] = tmpMAP[size - 1 - c][r];   // 시계 90도
}
```
`half` 도, 사분면 4블록도 필요 없어져 **오히려 짧아진다.**

### 블록 순회 — [15번](../G01/15_BOJ_20327_배열돌리기6.md)과 동일
```c
int divide = 1 << level;

for (int r = 1; r <= MAP_SIZE; r += divide)
    for (int c = 1; c <= MAP_SIZE; c += divide)
        rotate(r, c, divide);
```
좌상단을 `divide` 간격으로 밟는다. **1부에서 익힌 그 패턴 그대로.**

### ★★ 동시 소멸 — 이 문제의 핵심 함정
```c
void meltIce()
{
    int ICE[MAX][MAX] = { 0 };      // 녹을 칸을 먼저 표시

    for (int r = 1; r <= MAP_SIZE; r++)
    {
        for (int c = 1; c <= MAP_SIZE; c++)
        {
            if (MAP[r][c] == 0) continue;      // 얼음 없는 칸 무시

            int count = 0;
            for (int i = 0; i < 4; i++)
            {
                int nr = r + dr[i];
                int nc = c + dc[i];

                // 격자 밖도 전역 배열 초기값 0이므로 얼음 없는 칸처럼 처리됨
                count += !MAP[nr][nc];         // 얼음 "없는" 이웃 수
            }

            // 얼음 없는 이웃이 2개 이상 = 얼음 있는 이웃이 2개 이하 = 3개 미만
            if (count >= 2) ICE[r][c] = 1;
        }
    }

    // 녹을 칸들을 한 번에 반영
    for (int r = 1; r <= MAP_SIZE; r++)
        for (int c = 1; c <= MAP_SIZE; c++)
            MAP[r][c] -= ICE[r][c];
}
```

**두 단계로 나뉘어 있다.**
1. **판정** — `ICE[][]` 에 표시만 (원본은 안 건드림)
2. **반영** — 전부 판정한 뒤 한 번에 감소

> **★ 이걸 한 루프에서 하면 틀린다.**
> 먼저 처리한 칸이 녹아서 0이 되면, 뒤에 처리하는 이웃 칸이 **바뀐 상태를 보게 된다.**
> "동시에 일어난다"는 지문을 코드로 옮기는 표준 방법이 이 **판정/반영 분리**다.
>
> [G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)에서 이 함정이 최빈 실수로 다시 나온다.

### `count += !MAP[nr][nc]` 트릭
얼음이 **있는** 이웃을 세는 대신 **없는** 이웃을 센다.
- 얼음 있는 이웃 3개 미만 = **없는 이웃 2개 이상**
- 격자 밖은 전역 배열 초기값 0 → 자동으로 "얼음 없음"으로 카운트

**테두리 sentinel이 조건과 자연스럽게 맞아떨어지는** 사례. 격자 밖을 "얼음 없음"으로 세는 게 문제 의도와 일치한다.

### 최대 덩어리 — [34번](../G05/34_BOJ_2667_단지번호붙이기.md) 그대로
```c
int getGroupCount()
{
    int maxGroup = 0;

    for (int r = 1; r <= MAP_SIZE; r++)
        for (int c = 1; c <= MAP_SIZE; c++)
            if (MAP[r][c] > 0 && visit[r][c] == false)
            {
                int size = BFS(r, c);
                if (maxGroup < size) maxGroup = size;
            }

    return maxGroup;
}
```
**얼음이 `> 0`** 인 칸이 덩어리의 구성원이다. `== 1` 이 아니라 `> 0` 임에 주의 — 얼음 양은 여러 값을 가진다.

## 5. 예제 손 추적 — 회전 규칙 확인

`N = 1` (2×2 격자), `L = 1` (전체를 한 블록으로 회전)
```
      1 2          시계 90도       3 1
      3 4            →            4 2
```
`half = 1` 이므로 각 사분면이 1칸.
```
3 → 1 자리:  MAP[1][1] = tmpMAP[1][0] = 3   ✓
1 → 2 자리:  MAP[1][2] = tmpMAP[0][0] = 1   ✓
2 → 4 자리:  MAP[2][2] = tmpMAP[0][1] = 2   ✓
4 → 3 자리:  MAP[2][1] = tmpMAP[1][1] = 4   ✓
```
[14번 §5(나)](../G01/14_BOJ_16935_배열돌리기3.md)의 2×2 시계 회전 표와 일치한다.

### 녹기 규칙 확인
```
      0 0 0
      0 5 0        가운데 얼음 5, 인접 얼음 0개
      0 0 0
```
얼음 없는 이웃 = 4개 ≥ 2 → **녹는다** → `5 - 1 = 4`

```
      0 3 0
      3 5 3        인접 얼음 4개 (3개 이상)
      0 3 0
```
얼음 없는 이웃 = 0개 < 2 → **안 녹는다** → 5 유지
(단, 주변 `3` 들은 각자 판정된다 — `3` 의 이웃은 `5` 하나뿐이라 녹는다)

> **판정/반영 분리가 없으면**: `(1,2)` 의 3이 먼저 녹아 2가 되어도 여전히 얼음이라 `5` 의 판정에는 영향이 없지만, 만약 값이 1이었다면 0이 되어 `5` 가 잘못 녹게 된다.

## 6. 함정 / 예상 함정
- **★★ 녹기 판정과 반영을 한 루프에서 함.** "동시에"를 순차 처리 → 연쇄 반응. **판정용 배열(`ICE`)을 반드시 분리.**
- **★★ 회전을 in-place 로.** `tmpMAP` 복사 없이 돌리면 덮어쓰기 사고. [G01의 제1원칙](../../theory/G01_배열회전.md).
- **★★ 사분면 이동 vs 진짜 90도 회전.** §4의 ⚠️ 참고 — `size ≥ 4` 에서 결과가 다르고, 무작위 입력 300개 중 287개에서 최종 답이 갈린다. **지문을 다시 읽고 판정할 것.**
- **★ 덩어리 판정을 `== 1` 로.** 얼음 양은 여러 값이다. `> 0` 이어야 한다.
- **★ T-loop 초기화.** `MAP`, `visit`, 그리고 `MAP_SIZE` 를 케이스마다 다시 잡는다. `ICE` 는 지역 배열이라 자동 초기화되지만, 전역으로 뺐다면 초기화가 필요하다.
- **`MAP_SIZE = 1 << N`** 을 입력 직후 계산해 둔다. `N` 과 혼동 금지 — [15번](../G01/15_BOJ_20327_배열돌리기6.md)의 `S` 와 같은 역할.
- **블록 순회 시작 인덱스.** 1-indexed이므로 `r = 1; r <= MAP_SIZE; r += divide`.
- **녹은 얼음이 음수가 되지 않는가.** `MAP[r][c] == 0` 인 칸은 애초에 `continue` 로 걸러 `ICE` 가 안 찍히므로 안전하다.
