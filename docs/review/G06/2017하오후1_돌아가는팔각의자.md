## 1. 문제 요약
**4개의 팔각의자**가 일렬로 놓여 있고, 각 의자는 8개의 톱니 상태(`0` 또는 `1`)를 갖는다.

**회전 규칙**
- 어떤 의자를 회전시키면
- **양옆 의자와 맞닿은 톱니를 비교**해서
- **서로 다르면** 옆 의자도 **반대 방향**으로 회전
- **같으면** 그 방향으로는 **더 이상 전파되지 않는다**

K개의 회전 명령을 처리한 뒤 최종 상태로 점수를 계산한다.

## 2. 필요한 이론
→ [G06 — 회전의 세 가지 층위 ②③](../../theory/G06_격자상태회전.md)

두 가지가 결합되어 있다.

> **① 원형 배열 회전** — 톱니 8개가 원형이다. 시계/반시계로 한 칸씩 민다.
> **② ★ 전파 판정** — 이 문제의 진짜 주제.

### ★★ 전파의 핵심: "판정 먼저, 회전 나중"

**가장 흔한 오답**: 의자를 하나 돌리고, 그 다음 옆 의자를 판정한다.
→ **이미 돌아버린 톱니로 비교**하게 되어 전파가 틀린다.

**올바른 순서**
```
1. 아무것도 돌리지 않은 채, 원래 상태로 전파 방향을 전부 결정한다  (check[] 배열)
2. 결정이 끝난 뒤, 한꺼번에 회전시킨다
```

[회전하는 빙하](2020하오후2_회전하는빙하.md)의 **판정/반영 분리**와 정확히 같은 원리다.
[G10 순수 시뮬레이션](../../theory/G10_순수시뮬레이션.md)의 "동시에" 함정이 여기서도 나온다.

## 3. 코드 흐름
```
main()
 └ input()               chair[1..4][1..8], K개 명령
   simulate()
    └ for k in 0..K-1:
         check[1..4] = {0}                  이번에 각 의자가 돌 방향
         check[target] = direction          시작 의자
         오른쪽 전파 검사 (target → 3)       ★ 원본 톱니로 판정
         왼쪽  전파 검사 (target → 2)
         check 대로 rotate() 일괄 수행       ★ 판정 끝난 뒤 회전
   점수 계산
```

## 4. 핵심 코드

### 톱니 인덱스 규약
```c
// chair[number][1] : 12시 방향 톱니
// chair[number][3] : 오른쪽(3시) 톱니   ← 오른쪽 의자와 맞닿음
// chair[number][7] : 왼쪽(9시)  톱니   ← 왼쪽 의자와 맞닿음
```
**`3` 과 `7` 만 전파 판정에 쓰인다.** 시계 방향으로 1~8을 붙였을 때 3시·9시 자리.

### 원형 회전 — 인덱스 시프트
```c
void rotate(int number, int direction)
{
    int tmp;

    // 반시계 방향 회전
    if (direction == COUNTER_CLOCKWISE)
    {
        tmp = chair[number][1];

        for (int index = 1; index <= 7; index++)
            chair[number][index] = chair[number][index + 1];

        chair[number][8] = tmp;      // 첫 값을 마지막으로
    }
    // 시계 방향 회전
    else
    {
        tmp = chair[number][8];

        for (int index = 8; index >= 2; index--)
            chair[number][index] = chair[number][index - 1];

        chair[number][1] = tmp;      // 마지막 값을 처음으로
    }
}
```

**끝값을 `tmp` 에 빼두고 나머지를 밀어낸 뒤 반대쪽에 넣는다.**
[13번 배열 돌리기](../G01/13_BOJ_16926_16927_배열돌리기1_2.md)의 링 시프트와 같은 발상이지만, 여기는 회전이 **한 칸씩**이라 `% index` 가 필요 없다.

> 배열을 실제로 밀지 않고 **offset 변수**만 관리하는 방법도 있다([G06 이론](../../theory/G06_격자상태회전.md)). 톱니가 8개뿐이라 그냥 미는 편이 간단하다.

### ★★ 전파 판정 — 원본 톱니로, 회전 전에
```c
// check[i] = i번 의자가 이번 명령에서 회전할 방향
//  0이면 회전 안 함 / 1이면 시계 / -1이면 반시계
int check[5 + 1] = { 0 };

int target    = chairNumber[k];   // 이번에 직접 회전시키는 의자
int direction = directions[k];

check[target] = direction;        // 시작 의자는 무조건 회전

// 오른쪽으로 회전 전파 검사
// 현재 의자의 오른쪽 톱니(3번)와 오른쪽 의자의 왼쪽 톱니(7번)를 비교
for (int right = target; right <= 3; right++)
{
    if (chair[right][3] != chair[right + 1][7])
        check[right + 1] = check[right] * (-1);     // ★ 반대 방향
    else
        break;                                       // ★ 같으면 전파 중단
}

// 왼쪽으로 회전 전파 검사
for (int left = target; left >= 2; left--)
{
    if (chair[left][7] != chair[left - 1][3])
        check[left - 1] = check[left] * (-1);
    else
        break;
}

// 판정이 끝난 뒤 한꺼번에 회전
for (int i = 1; i <= 4; i++)
    if (check[i] != 0) rotate(i, check[i]);
```

**세 가지가 핵심이다.**
1. **`chair[][]` 를 읽기만** 하고 아직 안 돌린다 → 원본 기준 판정
2. **`* (-1)`** — 전파될수록 방향이 번갈아 뒤집힌다
3. **`break`** — 톱니가 같으면 **그 방향으로는 끝**. `continue` 가 아니다

### 루프 범위 `right <= 3`, `left >= 2`
의자가 4개(1~4)이므로
- 오른쪽 전파: `right` 가 3까지 (그때 `right+1 = 4`)
- 왼쪽 전파: `left` 가 2까지 (그때 `left-1 = 1`)

**경계를 넘어서면 `chair[0]` / `chair[5]` 를 읽는다.** 범위를 정확히 잡아야 한다.

## 5. 예제 손 추적 — 전파 규칙 확인

의자 4개, 각 의자의 3시(`[3]`)·9시(`[7]`) 톱니만 표시.
```
        의자1        의자2        의자3        의자4
 [7]:    -            0            1            0
 [3]:    1            1            0            -
```

### 의자 2를 **시계 방향**(`+1`)으로 회전시키는 명령

**오른쪽 전파 검사** (`target = 2` 부터)
```
right = 2:  chair[2][3] = 1  vs  chair[3][7] = 1   →  같다  →  break
```
→ 의자 3, 4로는 **전파 안 됨**

**왼쪽 전파 검사** (`target = 2` 부터)
```
left = 2:   chair[2][7] = 0  vs  chair[1][3] = 1   →  다르다
            check[1] = check[2] * (-1) = -1        →  의자 1은 반시계
```
→ 의자 1까지 전파. (더 왼쪽이 없어 루프 종료)

**최종 `check`**
```
check[1] = -1   (반시계)
check[2] = +1   (시계)
check[3] =  0
check[4] =  0
```
→ 의자 1은 반시계, 의자 2는 시계로 **동시에** 회전.

### 판정/회전을 섞으면 어떻게 틀리는가
의자 2를 먼저 돌리면 `chair[2][3]` 과 `chair[2][7]` 이 **다른 톱니로 바뀐다.**
그 상태로 의자 1·3을 판정하면 **전혀 다른 전파 결과**가 나온다.

> **이 문제의 존재 이유가 이 함정이다.** 회전 자체는 [13번](../G01/13_BOJ_16926_16927_배열돌리기1_2.md)에서 이미 배웠다.

### 전파 방향의 교대
```
의자:      1  ←  2  →  3  →  4
방향:     -1     +1    -1    +1     (전파될 때마다 뒤집힘)
```
연쇄 전파가 일어나면 **방향이 번갈아** 나타난다. `* (-1)` 이 그것을 만든다.

## 6. 함정 / 예상 함정
- **★★ 판정과 회전을 섞음.** 하나 돌리고 다음을 판정하면 **바뀐 톱니로 비교**하게 된다. `check[]` 로 전부 결정한 뒤 일괄 회전.
- **★★ 전파 중단을 `break` 가 아닌 `continue` 로.** 톱니가 같으면 **그 방향은 거기서 끝**이다. 건너뛰고 더 보면 안 된다.
- **★ 방향을 뒤집지 않음.** 전파될 때마다 `* (-1)`. 같은 방향으로 전파하면 전부 틀린다.
- **★ 맞닿는 톱니 번호를 혼동.** 왼쪽 의자의 **3시**와 오른쪽 의자의 **9시**가 맞닿는다. 같은 번호끼리 비교하는 게 아니다.
- **★ 루프 경계.** `right <= 3`, `left >= 2`. 넘어가면 `chair[0]`/`chair[5]` 를 읽는다.
- **원형 회전 방향 착각.** 시계/반시계에서 어느 쪽 끝값을 `tmp` 에 빼는지. 8칸 예제로 검산한다.
- **`check` 를 명령마다 초기화 안 함.** 지역 배열 `= {0}` 으로 매번 새로 만드는 게 안전하다.

## 7. 백지 재현 체크리스트
- [ ] **`check[]` 로 전파를 먼저 전부 판정**하고 나중에 일괄 회전하는가
- [ ] 전파 중단이 **`break`** 인가
- [ ] 전파될 때마다 **`* (-1)`** 로 방향을 뒤집는가
- [ ] 맞닿는 톱니가 **`[3]` vs `[7]`** 임을 아는가
- [ ] 루프 경계(`right <= 3`, `left >= 2`)를 정확히 잡았는가
- [ ] 원형 회전을 시계/반시계 각각 쓸 수 있는가
- [ ] "판정 먼저, 반영 나중"이 [회전하는 빙하](2020하오후2_회전하는빙하.md)와 같은 원리임을 아는가
