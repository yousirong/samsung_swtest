## 1. 문제 요약
지도 위에 정육면체(주사위)를 놓고 **동/서/북/남** 명령에 따라 굴린다.

**이동 규칙**
1. 명령 방향으로 한 칸 이동할 수 있으면 굴린다 (지도 밖이면 **명령 무시**)
2. 이동한 칸의 값이 `0` 이면 → **주사위 바닥면 숫자를 칸에 복사**
3. `0` 이 아니면 → **칸의 숫자를 주사위 바닥면에 복사**하고 칸은 `0` 으로
4. 이동이 성공할 때마다 **주사위 윗면 숫자를 출력**

## 2. 필요한 이론
→ [G06 — 회전의 세 가지 층위 ②](../../theory/G06_격자상태회전.md)

**[G01](../../theory/G01_배열회전.md)의 회전과 종류가 다르다.**

| | G01 (배열 회전) | 이 문제 (상태 회전) |
|---|---|---|
| 무엇이 도나 | **격자 값의 자리** | **주사위 면의 값** |
| 도구 | 인덱스 공식 | **변수 swap 표** |
| 좌표 | 바뀐다 | 주사위 좌표는 그냥 `+dr/+dc` |

> **★ 핵심: 주사위는 격자가 아니라 "6개 변수의 묶음"이다.**
> 굴리기 = 그 6개 변수를 **방향별로 정해진 순서로 돌려 담기**. 인덱스 공식이 아니라 **표를 만들어 외운다.**

## 3. 코드 흐름
```
main()
 └ input()               N, M, 시작 (r, c), K, 명령들, 지도
   for 각 명령:
      다음 칸 계산 → 지도 밖이면 continue (★ 무시, 실패가 아님)
      moveEast/West/North/South()      ← 주사위 면 회전
      칸 값이 0 이면  MAP = cube.bottom
      아니면          cube.bottom = MAP, MAP = 0
      printf(cube.up)                  ← 윗면 출력
```

## 4. 핵심 코드

### ★ 주사위를 구조체 6면으로
```c
// 주사위 6면 정보
struct CUBE
{
    int up;      // 북쪽 면
    int left;    // 왼쪽 면
    int top;     // 윗면      ← 하늘
    int right;   // 오른쪽 면
    int down;    // 남쪽 면
    int bottom;  // 아랫면    ← 바닥
};
typedef struct CUBE CUBE;

CUBE cube;
```

> **⚠️ 이름에 주의.** `up/down` 이 하늘/바닥이 **아니라 북/남**이다. 하늘·바닥은 `top/bottom` 이다.
> ```
> top    = 윗면(하늘)      bottom = 아랫면(바닥)
> up     = 북쪽            down   = 남쪽
> left   = 서쪽            right  = 동쪽
> ```
> 관례와 다르지만 **코드 전체가 이 규약을 일관되게 지킨다.** 출력도 `printf("%d\n", cube.top)` (윗면), 지도 교환도 `cube.bottom` (바닥면)으로 정확하다.
>
> 그래도 **백지에서 다시 쓸 때는 `top/bottom/north/south/east/west` 로 짓는 것을 권한다.** 이 명명이 이 파일을 읽기 어렵게 만드는 유일한 요인이다.

### ★ 방향별 swap — tmp 배열로 한 번에
```c
// 각 move 함수는 현재 면 값을 tmp에 저장한 뒤
// 필요한 면만 새 값으로 덮어쓴다
void moveEast()
{
    int tmp[6] = {
        cube.up, cube.left, cube.top,
        cube.right, cube.down, cube.bottom
    };

    cube.top    = tmp[1];   // left   -> top
    cube.right  = tmp[2];   // top    -> right
    cube.bottom = tmp[3];   // right  -> bottom
    cube.left   = tmp[5];   // bottom -> left
    // up, down 은 그대로
}

void moveWest()
{
    int tmp[6] = { ... 동일 ... };

    cube.top    = tmp[3];   // right  -> top
    cube.right  = tmp[5];   // bottom -> right
    cube.bottom = tmp[1];   // left   -> bottom
    cube.left   = tmp[2];   // top    -> left
}
```

**동/서는 서로 역방향**이다. 화살표를 반대로 돌린 같은 코드.
**남/북도 마찬가지**로 짝을 이룬다.

> **★ 여기서도 [G01의 제1원칙](../../theory/G01_배열회전.md)이 그대로다.**
> `tmp[]` 에 현재 상태를 **먼저 통째로 담고** 나서 덮어쓴다.
> `cube.top = cube.left; cube.left = cube.bottom; ...` 처럼 순차 대입하면 **먼저 덮인 값이 사라진다.**
> 배열이든 구조체든 **읽는 곳과 쓰는 곳을 분리**한다.

### 굴릴 때 도는 면 / 안 도는 면
| 방향 | 도는 면 4개 | 고정 |
|---|---|---|
| 동/서 | `up, right, down, left` | **북, 남** |
| 남/북 | `up, north, down, south` | **동, 서** |

**굴리는 축에 수직인 두 면은 안 움직인다.** 이 규칙 하나로 표를 검산할 수 있다.

### 지도 밖이면 명령 "무시"
```c
if (nr < 1 || nc < 1 || nr > N || nc > M)
    continue;      // ★ 종료가 아니라 무시
```
**출력도 하지 않는다.** 이동이 성공한 경우에만 윗면을 출력한다는 게 규칙 4다.

### 값 교환 — 두 방향
```c
if (MAP[nr][nc] == 0)
    MAP[nr][nc] = cube.down;      // 주사위 → 지도
else
{
    cube.down = MAP[nr][nc];      // 지도 → 주사위
    MAP[nr][nc] = 0;
}
```
**바닥면(`down`)만 관여**한다. 굴린 **뒤**에 이 처리를 해야 한다 — 굴리기 전 바닥면은 다른 면이다.

## 5. 예제 손 추적 — 주사위 굴리기

면에 번호를 붙여 따라가 본다. (표준 주사위 배치)
```
        top=1        ← 하늘
 left=3  ·  right=4
       bottom=6      ← 바닥
   (up=2 북, down=5 남)
```

### `moveEast()` — 동쪽으로 굴리기
```c
tmp = { cube.up, cube.left, cube.top, cube.right, cube.down, cube.bottom }
      =   2,        3,        1,        4,         5,          6
       tmp[0]    tmp[1]    tmp[2]    tmp[3]     tmp[4]      tmp[5]

cube.top    = tmp[1] = 3     (left   → top)
cube.right  = tmp[2] = 1     (top    → right)
cube.bottom = tmp[3] = 4     (right  → bottom)
cube.left   = tmp[5] = 6     (bottom → left)
```
결과:
```
        top=3
 left=6  ·  right=1
       bottom=4
   (up=2, down=5)   ← 북/남은 그대로 ✓
```
**동쪽으로 굴리면 서→위, 위→동, 동→아래, 아래→서.** 굴리는 축(남북축)에 수직인 북·남 두 면은 **고정**된다 ✓

### `moveNorth()` — 북쪽으로 굴리기
```c
cube.up     = tmp[2];   // top    -> up      (위 → 북)
cube.top    = tmp[4];   // down   -> top     (남 → 위)
cube.down   = tmp[5];   // bottom -> down    (아래 → 남)
cube.bottom = tmp[0];   // up     -> bottom  (북 → 아래)
```
이번에는 **동·서(`left`, `right`)가 고정**된다 ✓

> **검산법**: 굴리는 방향의 축에 **수직인 두 면이 안 바뀌면** 표가 맞다.
> - 동/서로 굴림 → **북·남 고정**
> - 남/북으로 굴림 → **동·서 고정**

### 값 교환 확인
```c
if (MAP[R][C] == 0)  MAP[R][C] = cube.bottom;                  // 지도 ← 주사위 바닥
else               { cube.bottom = MAP[R][C]; MAP[R][C] = 0; } // 주사위 바닥 ← 지도

printf("%d\n", cube.top);                                       // 윗면 출력
```
**한쪽만 바뀐다**는 것이 포인트. 서로 교환(swap)이 아니다.
그리고 관여하는 것은 **`bottom`(바닥)** 이고 출력은 **`top`(윗면)** — 이름 규약만 잡으면 그 외는 직관대로다.

## 6. 함정 / 예상 함정
- **★★ 순차 대입으로 면을 돌림.** `tmp[]` 없이 `a = b; b = c; ...` 하면 값이 사라진다. [G01 제1원칙](../../theory/G01_배열회전.md).
- **★★ 이름 규약 오해.** `up/down` 은 북/남이고 하늘/바닥은 `top/bottom` 이다. 코드는 일관되지만 **읽는 사람이 헷갈린다.** 재작성 시 명명부터 고친다.
- **★ 지도 밖일 때 출력까지 함.** 명령은 무시하고 **출력도 건너뛴다.**
- **★ 값 교환을 굴리기 전에 함.** 굴린 **뒤**의 바닥면이 관여한다.
- **★ 값 교환을 swap 으로.** `0` 인 칸은 주사위 값을 **복사**받고 주사위는 안 바뀐다. 양방향 교환이 아니다.
- **동/서, 남/북 표를 뒤바꿈.** 굴리는 축에 수직인 두 면이 고정되는지로 검산한다.
- **명령 번호 매핑.** 문제가 `1=동, 2=서, 3=북, 4=남` 식으로 준다. `dr/dc` 배열 인덱스와 대응시킬 때 **0-based/1-based** 를 맞춘다.

## 7. 백지 재현 체크리스트
- [ ] 주사위를 **6개 변수 묶음**으로 모델링할 수 있는가
- [ ] `tmp[]` 로 **읽기/쓰기를 분리**했는가
- [ ] 네 방향 swap 표를 쓸 수 있는가, **수직 두 면이 고정**되는지로 검산하는가
- [ ] 필드 이름을 **역할과 일치**하게 지었는가
- [ ] 지도 밖이면 **명령 무시 + 출력 없음** 인가
- [ ] 값 교환이 **굴린 뒤**, **바닥면만**, **복사(swap 아님)** 인가
- [ ] 윗면을 출력하는가
