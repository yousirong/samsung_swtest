## 1. 문제 요약
N개의 원판이 있고, 각 원판에는 M개의 숫자가 **원형으로** 적혀 있다.
Q번의 회전을 수행하며, 각 회전은 `X D K` 정보를 갖는다.
- `X` : **X의 배수** 번호를 가진 원판들을 회전
- `D` : 방향 (`0` = 시계, `1` = 반시계)
- `K` : K칸 회전

**회전 후 처리**
1. **인접하면서 같은 수**를 찾는다 (같은 원판의 양옆 + 위아래 원판의 같은 위치)
   - 원판은 원형이므로 **1번 칸과 M번 칸도 인접**
2. 있으면 **모두 지운다**
3. 없으면 **전체 평균**을 구해, 평균보다 큰 수는 `-1`, 작은 수는 `+1`

모든 회전 후 **남은 수의 합**을 출력한다.

## 2. 필요한 이론
→ [G06 — 원형 배열 회전](../../theory/G06_격자상태회전.md) + [G05 ① 플러드필](../../theory/G05_그리드탐색심화.md)

**세 가지가 결합**되어 있다.

| 구성 요소 | 어디서 배웠나 |
|---|---|
| 원형 배열 회전 (인덱스 시프트) | [13 배열돌리기 1·2](../G01/13_BOJ_16926_16927_배열돌리기1_2.md) |
| 같은 값 덩어리 찾아 지우기 | [34 단지번호붙이기](../G05/34_BOJ_2667_단지번호붙이기.md) |
| 원형 인접 (1번 ↔ M번) | **이 문제의 고유 난점** |

> **★ 이 문제의 특징: 격자가 원통(cylinder)이다.**
> - **세로(원판 번호)** 는 원형이 **아니다** — 1번 위, N번 아래는 없음
> - **가로(칸 번호)** 는 원형이다 — 1번과 M번이 붙어 있음
>
> **한쪽만 원형**이라는 비대칭이 실수의 근원이다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()            N, M, Q, circle[1..N][1..M], X[], D[], K[]
      simulate()
       └ for q in 0..Q-1:
            rotate(X[q], D[q], K[q])       ★ 원형 인덱스 시프트
            startGame()
             └ 모든 칸에서 BFS → 지워진 게 있으면 true
                없으면 makeAverage()        평균 기준 ±1
      printf(getAnswer())                   남은 수의 합
```

## 4. 핵심 코드

### ★ 원형 회전 — 방향을 부호로 흡수
```c
void rotate(int x, int d, int k)
{
    int arr[MAX] = { 0 };

    // 반시계 방향이면 시계 방향 기준으로 -k 처리
    if (d == COUNTER_CLOCKWISE) k = -k;

    // x의 배수 원판들만 회전
    for (int r = x; r <= N; r += x)      // ★ x, 2x, 3x, ...
    {
        int index = 0;

        // 현재 원판의 값을 arr에 복사
        for (int c = 1; c <= M; c++)
            arr[index++] = circle[r][c];

        // 회전 후 다시 circle에 반영
        for (int i = 0; i < index; i++)
        {
            int newIndex = (i - k) % index;

            // 음수 보정
            newIndex = (newIndex < 0) ? newIndex + index : newIndex;

            circle[r][i + 1] = arr[newIndex];
        }
    }
}
```

**세 가지 관용구가 한 함수에 다 있다.**

1. **방향을 부호로**: `if (반시계) k = -k;` — 함수 두 개를 쓰지 않는다
2. **배수 순회**: `for (r = x; r <= N; r += x)` — X의 배수만
3. **음수 나머지 보정**: `newIndex < 0 ? + index` — [13번](../G01/13_BOJ_16926_16927_배열돌리기1_2.md)에서 본 그 함정

> **`arr` 로 복사한 뒤 되쓰는 것**도 [G01의 제1원칙](../../theory/G01_배열회전.md) 그대로다.
> `K` 가 `M` 보다 클 수 있으므로 `% index` 가 필수다.

### ★★ 원형 인접 BFS — 좌우만 특별 처리
```c
bool BFS(int r, int c)
{
    ...
    while (rp < wp)
    {
        RC out = queue[rp++];

        // 상하좌우 탐색
        for (int i = 0; i < 4; i++)
        {
            int nr = out.r + dr[i];
            int nc = out.c + dc[i];

            if (circle[nr][nc] == 0) continue;              // 이미 삭제된 칸
            if (circle[nr][nc] != circle[r][c] ||
                visit[nr][nc] == true) continue;

            queue[wp].r = nr;
            queue[wp++].c = nc;
            visit[nr][nc] = true;
        }

        // ★ 원형 구조 처리
        // c == 1이면 왼쪽 이웃은 M
        if (out.c == 1) { /* (out.r, M) 을 같은 방식으로 검사 */ }
        // c == M이면 오른쪽 이웃은 1
        if (out.c == M) { /* (out.r, 1) 을 같은 방식으로 검사 */ }
    }
}
```

**일반 4방향 루프 + 원형 경계 두 개**를 따로 처리한다.

> **더 깔끔한 대안**: 열 인덱스를 0-based로 두고 `nc = (out.c + dc[i] + M) % M` 로 통일하면 특별 처리가 사라진다.
> ```c
> // 0-based 열 인덱스일 때
> int nc = (out.c + dc[i] + M) % M;     // 좌우만 이렇게, 상하는 그대로
> ```
> **단, 세로는 원형이 아니므로** `nr` 에는 `%` 를 쓰면 안 된다. 이 비대칭 때문에 코드가 지저분해지는 것.

### 삭제 판정 — "2개 이상이면 지운다"
`BFS` 가 같은 값 덩어리를 찾고, **크기가 2 이상이면** 그 덩어리를 전부 0으로 만든다.
크기 1이면 지우지 않는다 — 즉 **혼자 있는 수는 살아남는다.**

반환값이 `bool` 인 이유: **이번 회전에서 삭제가 한 번이라도 있었는지**를 `startGame()` 이 알아야 하기 때문. 삭제가 없어야 평균 처리로 넘어간다.

### 평균 처리
```c
void makeAverage()
{
    // 0이 아닌 칸들의 평균을 구하고
    // 평균보다 크면 -1, 작으면 +1, 같으면 그대로
}
```
**평균은 실수**다. 정수 나눗셈으로 비교하면 틀린다.
합과 개수를 들고 `value * count > sum` 형태로 **분모를 없애 비교**하는 것이 안전하다.
```c
if (circle[r][c] * count > sum)      circle[r][c]--;
else if (circle[r][c] * count < sum) circle[r][c]++;
```

## 5. 예제 손 추적 — 회전 인덱스 확인

원판 하나에 `M = 4`, 값이 `[1, 2, 3, 4]` (칸 1~4).

### 시계 방향 `K = 1` (`d = 0`, `k = 1`)
```
arr = [1, 2, 3, 4]        (0-based)

i=0: newIndex = (0-1) % 4 = -1 → 보정 → 3 → circle[r][1] = arr[3] = 4
i=1: newIndex = (1-1) % 4 =  0        → circle[r][2] = arr[0] = 1
i=2: newIndex = (2-1) % 4 =  1        → circle[r][3] = arr[1] = 2
i=3: newIndex = (3-1) % 4 =  2        → circle[r][4] = arr[2] = 3

결과: [4, 1, 2, 3]      ← 오른쪽으로 한 칸 밀림 (시계)
```

### 반시계 `K = 1` (`d = 1` → `k = -1`)
```
i=0: newIndex = (0+1) % 4 = 1  → circle[r][1] = arr[1] = 2
i=1: newIndex = 2              → circle[r][2] = arr[2] = 3
i=2: newIndex = 3              → circle[r][3] = arr[3] = 4
i=3: newIndex = (3+1) % 4 = 0  → circle[r][4] = arr[0] = 1

결과: [2, 3, 4, 1]      ← 왼쪽으로 한 칸 밀림 (반시계)
```

**`i=0` 에서 음수가 나오는 것**이 시계 방향의 첫 스텝이다 — 보정이 없으면 `arr[-1]`.

### 배수 순회 확인
`N = 6`, `X = 2` 이면
```
r = 2, 4, 6      ← 2의 배수만 회전
```
`X = 1` 이면 전부, `X = 6` 이면 6번만.

### 원형 인접 확인
`M = 4` 인 원판에서 `[5, 1, 1, 5]` 라면
```
칸1=5  칸2=1  칸3=1  칸4=5
```
- 칸2·칸3 은 `1` 로 인접 → 지워진다
- **칸1·칸4 도 `5` 로 인접** (원형!) → 지워진다

**원형 처리를 빼먹으면 칸1·칸4가 살아남아 답이 커진다.**

## 6. 함정 / 예상 함정
- **★★ 좌우 원형 인접 누락.** 1번 칸과 M번 칸이 붙어 있다. 이 문제의 1번 함정.
- **★★ 세로도 원형으로 처리.** **원판 번호는 원형이 아니다.** 1번 위, N번 아래는 없다. `%` 를 세로에 쓰면 안 된다.
- **★ 음수 나머지 보정 누락.** `(i - k) % index` 가 음수가 될 수 있다.
- **★ `K % M` 을 안 함.** K가 M보다 크면 인덱스가 튄다. 이 코드는 `% index` 를 인덱스 계산에 녹여 자동 처리.
- **★ 삭제와 평균을 둘 다 함.** 삭제가 **하나라도 있었으면 평균 처리는 안 한다.** `bool` 반환값으로 판정.
- **★ 평균 비교를 정수 나눗셈으로.** `sum / count` 로 자르면 틀린다. **양변에 `count` 를 곱해** 비교한다.
- **★ 삭제된 칸(`0`)을 이후 계산에 포함.** 평균 계산에서도, 인접 판정에서도 `0` 은 제외.
- **크기 1인 덩어리를 지움.** **2개 이상**일 때만 지운다.
- **`visit` 을 회전마다 초기화 안 함.** 매 회전의 삭제 판정마다 새로 시작해야 한다.
- **T-loop 초기화** — `circle`, `visit` 전부.

## 7. 백지 재현 체크리스트
- [ ] 방향을 **부호(`k = -k`)로 흡수**할 수 있는가
- [ ] 배수 순회 `for (r = x; r <= N; r += x)` 를 쓸 수 있는가
- [ ] **음수 나머지 보정**을 넣었는가
- [ ] **좌우만 원형, 세로는 원형 아님**을 구분하는가
- [ ] 삭제가 있었는지를 `bool` 로 올려보내 평균 처리와 배타적으로 만들었는가
- [ ] 평균 비교에서 **분모를 없애** 정수로 비교하는가
- [ ] 크기 **2 이상**일 때만 지우는가
- [ ] 삭제된 칸(`0`)을 모든 계산에서 제외하는가

## 8. 한 줄 요약
"**좌우만 원형인 원통 격자.** 회전은 부호로 방향 흡수 + 음수 보정, 삭제와 평균은 **배타적**이다."
