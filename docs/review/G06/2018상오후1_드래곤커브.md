## 1. 문제 요약
드래곤 커브를 N개 그린 뒤, **꼭짓점 4개가 모두 드래곤 커브 위에 있는 1×1 정사각형의 개수**를 구한다.

각 커브는 `시작점 (r, c)`, `시작 방향 d`, `세대 g` 로 주어진다.

**드래곤 커브 규칙**
- **0세대**: 시작 방향으로 1칸 이동하는 선분
- **다음 세대**: 이전 세대의 방향열을 **뒤에서부터** 보면서, 각 방향에 **+1 (mod 4)** 한 값을 뒤에 붙인다

## 2. 필요한 이론
→ [G06 — 회전의 세 가지 층위 ③](../../theory/G06_격자상태회전.md)

**격자가 도는 게 아니라 "방향의 수열"이 돈다.**

| | 무엇이 회전하나 |
|---|---|
| [회전하는 빙하](2020하오후2_회전하는빙하.md) | 격자 값의 **자리** |
| [정육면체 굴리기](2016하2_정육면체굴리기.md) | 주사위 **면의 값** |
| **드래곤 커브** (이 문제) | **진행 방향의 수열** |

> **★ 핵심: 커브를 그리지 말고 "방향열"을 먼저 완성한다.**
> 좌표를 직접 다루면 복잡하지만, **방향 배열 하나를 세대마다 2배로 늘린 뒤** 마지막에 한 번만 따라가며 찍으면 된다.
> **문제를 "수열 생성 + 한 번의 순회"로 분해**하는 것이 이 문제의 교훈.

## 3. 코드 흐름
```
makeDragonCurve()
 └ for 커브 N개:
      scanf(r, c, d, g)
      dragonPosition[0] = d,  length = 1
      for step in 1..g:                  ← 세대 확장
         뒤에서부터 읽어 +1 mod 4 해서 뒤에 붙임
         length *= 2
      MAP[r][c] = 1                      시작점 표시
      for k in 0..2^g-1:                 방향열 따라 이동하며 표시
         r += dr[dragonPosition[k]]
         c += dc[dragonPosition[k]]
         MAP[r][c] = 1
countSquares()
 └ 모든 (r,c)에서 네 꼭짓점이 다 1인지
```

## 4. 핵심 코드

### ★ 세대 확장 — 뒤에서부터 읽어 +1
```c
dragonPosition[0] = d;   // 0세대의 방향열은 시작 방향 하나뿐
int length = 1;

for (int step = 1; step <= g; step++)
{
    // 규칙: 기존 방향열을 뒤에서부터 보며
    //       각 방향에 +1(mod 4) 한 값을 뒤에 붙인다.
    //
    // 예: 기존 [0, 1]
    //     뒤에서부터: [1, 0]
    //     +1 mod 4:   [2, 1]
    //     결과: [0, 1, 2, 1]
    for (int i = length + 1; i <= length * 2; i++)
    {
        dragonPosition[i - 1] = (dragonPosition[length * 2 - i] + 1) % 4;
    }

    length *= 2;      // 방향열 길이 2배
}
```

**인덱스 대응을 뜯어보면**
```
i = length + 1  →  쓰는 곳: length      읽는 곳: length*2 - (length+1) = length - 1   (맨 뒤)
i = length + 2  →  쓰는 곳: length + 1  읽는 곳: length - 2
...
i = length * 2  →  쓰는 곳: length*2-1  읽는 곳: 0                                     (맨 앞)
```
**쓰는 곳은 앞→뒤로, 읽는 곳은 뒤→앞으로** 진행한다. 그것이 "뒤에서부터 읽는다"의 구현.

> **오프바이원의 소굴이다.** `i` 를 `length+1` 부터 `length*2` 까지 돌리고 `i-1` 에 쓰는 이유를 손으로 한 번 유도해 두면 좋다.
> **0-based로 다시 쓰면 더 명확하다.**
> ```c
> for (int i = 0; i < length; i++)
>     dragonPosition[length + i] = (dragonPosition[length - 1 - i] + 1) % 4;
> ```
> 이 형태가 "뒤에서부터 읽어 뒤에 붙인다"를 그대로 보여준다. **백지 재현 시 이쪽을 권한다.**

### 방향열을 따라 좌표 찍기
```c
MAP[r][c] = 1;              // 시작점도 커브 위의 점

int moveCount = 1 << g;     // g세대의 총 이동 횟수는 2^g

for (int k = 0; k < moveCount; k++)
{
    r = r + dr[dragonPosition[k]];
    c = c + dc[dragonPosition[k]];
    MAP[r][c] = 1;
}
```

**길이가 정확히 `2^g`** 다. 0세대가 1칸이고 세대마다 2배가 되므로.
`length` 변수와 `1 << g` 가 같은 값이어야 한다 — 검산 포인트.

### 네 꼭짓점 검사
```c
for (int r = 0; r < 100; r++)
    for (int c = 0; c < 100; c++)
        if (MAP[r][c] + MAP[r + 1][c] + MAP[r][c + 1] + MAP[r + 1][c + 1] == 4)
            count++;
```
**네 점의 합이 4면 전부 1**이라는 뜻. `&&` 네 개보다 짧다.
`(r, c)` 를 좌상단으로 하는 1×1 정사각형이다.

> 좌표 범위가 0~100 이라 **0-indexed 로 전체를 훑는다.** 이 문제는 좌표가 `0 ≤ x, y ≤ 100` 으로 주어지므로 sentinel 없이 그냥 크게 잡았다.

## 5. 예제 손 추적 — 방향열 생성

시작 방향 `d = 0`, 세대 `g = 2` 로 따라가 본다.

### 0세대
```
dragonPosition = [0]                length = 1
```

### 1세대 — 뒤에서부터 읽어 +1
```
기존:        [0]
뒤에서부터:  [0]
+1 mod 4:    [1]
붙이면:      [0, 1]               length = 2
```

### 2세대
```
기존:        [0, 1]
뒤에서부터:  [1, 0]
+1 mod 4:    [2, 1]
붙이면:      [0, 1, 2, 1]         length = 4
```

**주석의 예시와 정확히 일치한다** (소스 68~73행).

### 3세대까지 가면
```
기존:        [0, 1, 2, 1]
뒤에서부터:  [1, 2, 1, 0]
+1 mod 4:    [2, 3, 2, 1]
붙이면:      [0, 1, 2, 1, 2, 3, 2, 1]      length = 8
```
`2^3 = 8` ✓

### 좌표로 그려보기 (`d=0` 이 우측이라 가정, `dr/dc` 규약에 따름)
```
방향열 [0, 1, 2, 1] 을 따라가면
시작 → 0방향 → 1방향 → 2방향 → 1방향
```
꺾이는 모양이 **드래곤 커브**의 특징적인 형태를 만든다. 세대가 올라갈수록 자기 자신을 90도 꺾어 이어붙인 모양이 된다.

### 길이 검산
| 세대 g | 방향열 길이 | `1 << g` |
|---|---|---|
| 0 | 1 | 1 |
| 1 | 2 | 2 |
| 2 | 4 | 4 |
| 3 | 8 | 8 |
| 10 | 1024 | 1024 |

`g ≤ 10` 이므로 방향열 배열은 **1024 + 여유**면 충분하다.

## 6. 함정 / 예상 함정
- **★★ 세대 확장 인덱스 오프바이원.** 이 문제의 전부다. **0-based 형태(`dragonPosition[length + i] = (dragonPosition[length - 1 - i] + 1) % 4`)로 쓰는 것을 권한다.**
- **★★ 앞에서부터 읽어 붙임.** "뒤에서부터"가 규칙이다. 앞에서부터 읽으면 완전히 다른 곡선이 된다.
- **★ `+1` 을 `mod 4` 안 함.** 방향이 3에서 4가 되어 배열 밖.
- **★ 시작점을 안 찍음.** `MAP[r][c] = 1` 을 이동 전에 해야 한다. 시작점도 커브 위의 점이다.
- **★ 이동 횟수를 `length` 가 아닌 다른 값으로.** `2^g` 이고 `length` 와 같아야 한다.
- **★ 방향 배열 `dr/dc` 의 규약.** 문제가 `0=우, 1=상, 2=좌, 3=하` 로 준다. **+1이 반시계 90도**가 되도록 배열을 맞춰야 한다. 이게 어긋나면 곡선이 엉뚱하게 그려진다.
- **좌표 범위.** `0 ≤ x, y ≤ 100` 인데 커브가 밖으로 나갈 수 있다. `MAP` 을 넉넉히 잡고, 정사각형 검사는 `0..99` 만.
- **`r`, `c` 를 커브마다 다시 읽음.** 이동하면서 `r`, `c` 가 바뀌므로 다음 커브에서 새로 `scanf` 해야 한다 (코드는 루프 안에서 선언하므로 안전).
- **정사각형 개수 검사에서 `+1` 인덱스가 배열 밖.** `MAP` 크기를 `102` 이상으로.

## 7. 백지 재현 체크리스트
- [ ] **"방향열을 먼저 완성하고 마지막에 한 번 순회"** 로 분해할 수 있는가
- [ ] 세대 확장을 **0-based 형태**로 정확히 쓸 수 있는가
- [ ] **뒤에서부터** 읽는다는 것을 인덱스로 표현할 수 있는가
- [ ] `+1 mod 4` 를 넣었는가
- [ ] 방향열 길이가 `2^g` 임을 검산했는가
- [ ] 시작점을 찍었는가
- [ ] `dr/dc` 배열이 문제의 방향 규약(`+1 = 반시계 90도`)과 맞는가
- [ ] 네 꼭짓점 검사를 **합 == 4** 로 쓸 수 있는가
