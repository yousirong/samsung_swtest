> **술래가 1~3칸 중 어디로 갈지가 분기**이고, 그 모든 경우의 최댓값을 구한다 → **G07이 맞다.**
>
> **판별법**: "최댓값/최솟값을 구하라"이고 **선택지가 있으면** 완전탐색이다.
> 순수 시뮬레이션은 **선택 없이 규칙만 따르면 답이 하나로 정해진다.**

## 1. 문제 요약
`4×4` 격자에 **1~16번 도둑말**이 하나씩 놓여 있다. 각 말은 **방향**을 갖는다.
술래는 `(0,0)` 에서 시작해 **그 칸의 도둑말을 먼저 잡아먹는다.**

**한 턴**
1. 술래가 현재 칸의 도둑말을 잡아먹고 **그 말의 방향을 물려받는다**. 번호만큼 점수 획득
2. 살아 있는 도둑말들이 **번호가 작은 순서대로** 이동
   - 현재 방향으로 가려다 **격자 밖이거나 술래 칸이면 반시계 45도씩 회전**하며 가능한 칸을 찾는다
   - 8방향을 다 돌아도 못 가면 **그대로 머문다**
   - 이동할 칸에 말이 있으면 **서로 자리를 바꾼다**
3. 술래가 **자기 방향으로 1~3칸 이동** — 이동한 칸에 **도둑말이 있어야** 한다

술래가 더 못 움직일 때까지 반복하며, **얻을 수 있는 점수 합의 최댓값**을 구한다.

## 2. 필요한 이론
→ [G07 표준 골격](../../theory/G07_완전탐색시뮬.md)

```
후보 : 매 턴 술래가 1~3칸 중 하나 선택  →  최대 3갈래씩 분기
평가 : 더 못 갈 때까지 간 뒤의 누적 점수
```

**[2048](2016하2_2048게임.md)과 골격은 같지만 결정적 차이가 있다.**

| | 2048 | 술래잡기 체스 |
|---|---|---|
| 탐색 깊이 | **고정** (5턴) | **가변** (못 갈 때까지) |
| 상태 복원 | `copyMap(ansMAP, oMAP)` **한 번** | **재귀 호출마다 깊은 복사** |
| 답 갱신 | 종료 조건에서 | **막다른 길에서** |

> ### ★★ 이 문제의 핵심: "상태를 인자로 넘긴다"
> 깊이가 가변이라 **매 재귀 단계의 상태가 다르다.** 전역 배열 하나로는 복원이 안 된다.
> ```c
> void DFS(CHESS prevTagger, int prevMap[MAX][MAX], CHESS prevChess[MAX_H], int score)
> {
>     int tmpMAP[MAX][MAX] = { 0 };      // ★ 지역 배열에 깊은 복사
>     CHESS tmpChess[MAX_H] = { 0 };
>     ... 복사 ...
> }
> ```
> **함수가 자기 사본 위에서만 논다.** 되돌릴 필요가 없다 — 재귀에서 나오면 사본이 사라진다.
>
> **백트래킹의 두 방식**
> | 방식 | 언제 |
> |---|---|
> | **되돌리기** (`visit[i]--`) | 상태 변화가 **작을 때** — [G04 순열](../G04/30_BOJ_15649_15654_15663_순열.md), [G07 사다리](2018상오전2_디버깅.md) |
> | **깊은 복사** (이 문제) | 상태 변화가 **클 때** (격자 전체가 바뀜) |
>
> `4×4` 라 복사 비용이 싸서 후자를 택할 수 있다. 격자가 컸다면 되돌리기가 필요했을 것.

## 3. 코드 흐름
```
main()
 └ input()            MAP, chess[1..16], 초기 술래 위치 (0,0)
   maxAnswer = 0
   DFS(초기술래, MAP, chess, 0)
   printf(maxAnswer)

DFS(prevTagger, prevMap, prevChess, score):
   상태 깊은 복사 → tmpMAP, tmpChess, pt
   ① 술래가 현재 칸 말을 먹음 → 방향 물려받기, score += 번호
   ② 도둑말 이동 (1~16 순서, 반시계 45도 탐색, 자리 교환)
   ③ 술래가 1~3칸 이동 → 각각 DFS 재귀
   막다른 길이면 maxAnswer 갱신
```

## 4. 핵심 코드

### 8방향 — 반시계, 1-based
```c
// 1 ~ 8, [0]은 더미
int dr[] = { 0,-1,-1, 0, 1, 1, 1, 0,-1 };
int dc[] = { 0, 0,-1,-1,-1, 0, 1, 1, 1 };
```
**인덱스 순서가 반시계**여야 "반시계 45도 회전"이 `dir + 1` 로 처리된다.
[G07 이상한 체스](2018상오전1_이상한체스.md)의 방향 산술과 같은 원리 — **배열 순서가 규칙을 결정**한다.

### ★★ 깊은 복사 — 재귀 진입마다
```c
void DFS(CHESS prevTagger, int prevMap[MAX][MAX], CHESS prevChess[MAX_H], int score)
{
    int tmpMAP[MAX][MAX] = { 0 };
    CHESS tmpChess[MAX_H] = { 0 };
    CHESS pt = prevTagger;

    // 현재 상태 깊은 복사
    for (int r = 0; r < 4; r++)
        for (int c = 0; c < 4; c++)
            tmpMAP[r][c] = prevMap[r][c];

    for (int i = 1; i <= 16; i++)
        tmpChess[i] = prevChess[i];
    ...
}
```

**`tmpMAP`, `tmpChess` 가 지역 배열**이라 재귀가 끝나면 자동 소멸한다.
형제 분기끼리 서로 영향을 주지 않는다 — **되돌리기 코드가 아예 필요 없다.**

> ⚠️ **`prevMap` 이 배열 인자**라 C에서는 **포인터로 전달**된다. 그래서 `tmpMAP` 으로 복사하는 것이 필수다.
> 복사 없이 `prevMap` 을 직접 수정하면 **호출자의 배열이 오염**되어 형제 분기가 깨진다.

### ① 잡아먹기 — 방향 물려받기
```c
int deadIndex = tmpMAP[pt.r][pt.c];       // 현재 칸의 도둑말 번호

if (tmpChess[deadIndex].dead == true) return;   // 안전장치

pt.dir = tmpChess[deadIndex].dir;          // ★ 방향 물려받기
tmpChess[deadIndex].dead = true;
score += deadIndex;                        // ★ 번호가 곧 점수
```

**"방향을 물려받는다"** 가 이 문제의 특징적 규칙이다. 술래의 다음 이동 방향이 여기서 정해진다.

### ② 도둑말 이동 — 번호 순서 + 반시계 탐색
```c
for (int i = 1; i <= 16; i++)              // ★ 번호가 작은 순서대로
{
    if (tmpChess[i].dead == true) continue;

    for (int k = 0; k < 8; k++)            // 8방향 시도
    {
        int nd = tmpChess[i].dir + k;
        if (nd > 8) nd -= 8;               // ★ 반시계 45도씩

        int nr = tmpChess[i].r + dr[nd];
        int nc = tmpChess[i].c + dc[nd];

        if (범위 밖) continue;
        if (nr == pt.r && nc == pt.c) continue;   // ★ 술래 칸은 못 감

        // 자리 교환
        ...
        tmpChess[i].dir = nd;              // ★ 방향도 갱신
        break;
    }
}
```

**세 가지 포인트**
1. **번호 순서**로 이동 — 순서가 결과에 영향을 준다
2. **술래 칸으로는 못 간다** — 격자 밖과 함께 걸러야 한다
3. **자리 교환** — 빈 칸으로 가는 게 아니라 **서로 맞바꾼다**

> **`nd > 8` 이면 `-8`** — 방향이 1-based라 `% 8` 이 아니다. 0-based였다면 `% 8` 로 깔끔했을 것.

### ③ 술래 이동 — 1~3칸, 분기
```c
int sr = pt.r, sc = pt.c;
bool canMove = false;

for (int i = 1; i <= 3; i++)
{
    int nr = sr + dr[pt.dir] * i;
    int nc = sc + dc[pt.dir] * i;

    // 범위를 벗어나면 더 멀리도 당연히 못 가므로 종료
    if (nr < 0 || nc < 0 || nr > 3 || nc > 3) break;      // ★ break (continue 아님)

    // 잡아먹을 말이 있는 칸일 때만 진행
    if (tmpChess[tmpMAP[nr][nc]].dead == true) continue;

    canMove = true;

    CHESS nextTagger = pt;
    nextTagger.r = nr;
    nextTagger.c = nc;

    DFS(nextTagger, tmpMAP, tmpChess, score);            // ★ 분기
}

// 더 이상 술래가 이동할 수 없으면 현재 점수로 정답 갱신
if (canMove == false)
{
    if (maxAnswer < score) maxAnswer = score;
}
```

**★ `break` 와 `continue` 의 구분이 핵심이다.**
- **범위 밖** → `break`. 2칸이 밖이면 3칸은 더 밖이다
- **죽은 말 칸** → `continue`. 2칸이 비어도 **3칸에는 말이 있을 수 있다**

이 구분을 틀리면 유효한 경로를 놓치거나 범위를 벗어난다.

**`canMove` 플래그**로 막다른 길을 판정해 답을 갱신한다.
[G07 사다리](2018상오전2_디버깅.md)의 `i == 4` 완주 판별과 같은 관용구.

## 5. 예제 손 추적

### 방향 물려받기 연쇄
```
술래가 (0,0) 의 5번 말(방향 3)을 먹음
  → 술래 방향 = 3, score = 5

술래가 방향 3으로 2칸 이동 → 그 칸의 12번 말(방향 7)을 먹음
  → 술래 방향 = 7, score = 5 + 12 = 17
```
**술래의 경로가 잡아먹은 말들의 방향에 좌우된다.** 그래서 "어느 칸의 말을 먹느냐"가 중요한 선택이 된다.

### 도둑말의 반시계 탐색
```
7번 말, 방향 2, 가려는 칸이 격자 밖

k=0: nd = 2      → 격자 밖 → 다음
k=1: nd = 3      → 술래 칸 → 다음
k=2: nd = 4      → 이동 가능! ✓
     tmpChess[7].dir = 4 로 갱신
```
**방향도 함께 갱신**된다. 다음 턴에 그 방향으로 간다.

### `break` vs `continue`
```
술래 방향으로 1칸: 죽은 말 칸  → continue (2칸 시도)
술래 방향으로 2칸: 살아있는 말 → DFS 분기 ✓
술래 방향으로 3칸: 격자 밖     → break
```
```
술래 방향으로 1칸: 격자 밖     → break  ★ 2,3칸은 볼 필요 없음
```

### 분기 트리
```
DFS(술래 위치 A, score=5)
 ├─ 1칸 이동 → DFS(B, score=5+7=12)
 │              ├─ ...
 │              └─ 막다른 길 → maxAnswer = max(..., 30)
 ├─ 2칸 이동 → DFS(C, score=5+3=8)
 │              └─ ...
 └─ 3칸 이동 → 격자 밖 (break)
```
**각 분기가 독립된 상태 사본** 위에서 진행된다. 형제끼리 간섭 없음.

### 깊은 복사를 안 하면
```
분기 ①에서 tmpMAP 을 수정 (말들이 이동)
분기 ②가 시작될 때 이미 오염된 격자를 받음
→ 완전히 다른 게임이 되어 답이 틀린다
```

## 6. 함정 / 예상 함정
- **★★ 상태 깊은 복사 누락.** 배열 인자는 포인터라 원본이 오염된다. **재귀 진입마다 사본.**
- **★★ 이 문제를 순수 시뮬레이션으로 착각.** **선택지가 있으면 완전탐색.** 한 경로만 굴리면 최댓값을 못 찾는다.
- **★★ `break` / `continue` 혼동.** 범위 밖은 `break`, 죽은 말은 `continue`.
- **★ 방향 물려받기 누락.** 술래가 잡아먹은 말의 방향을 이어받는다.
- **★ 도둑말이 술래 칸으로 감.** 격자 밖과 함께 걸러야 한다.
- **★ 도둑말 이동을 "빈 칸 찾기"로.** **자리 교환**이다.
- **★ 도둑말 이동 순서.** **번호가 작은 것부터.** 순서가 결과를 바꾼다.
- **★ 도둑말 방향 갱신 누락.** 회전해서 이동했으면 그 방향이 새 방향이다.
- **★ 답 갱신 위치.** **막다른 길(`canMove == false`)** 에서만. 매 재귀마다 갱신하면 중간 점수가 섞인다.
- **8방향 배열이 반시계 순서**여야 `dir + 1` 이 45도 회전이 된다.
- **0-based 격자** (`0~3`). 이 파일은 0-indexed다.
- **`maxAnswer` 를 T-loop 마다 초기화.**

## 7. 백지 재현 체크리스트
- [ ] 이 문제가 **완전탐색**임을 판별할 수 있는가 (선택지 + 최댓값)

- [ ] 술래가 **방향을 물려받는가**
- [ ] 도둑말이 **번호 순서**로, **반시계 45도씩** 탐색하는가
- [ ] 도둑말이 **술래 칸을 피하고**, **자리 교환**하는가
- [ ] 도둑말 **방향을 갱신**하는가
- [ ] 술래 이동에서 **범위 밖은 `break`, 죽은 말은 `continue`** 인가
- [ ] 답을 **막다른 길에서만** 갱신하는가
- [ ] 8방향 배열이 **반시계 순서**인가
