## 1. 문제 요약
세로선 C개, 가로 위치 R개인 **사다리 게임**이 주어진다. 현재 놓인 가로선 M개가 있다.

가로선을 **최대 3개까지 추가**해서 **각 세로선 번호가 그대로 자기 자신으로 도착**하도록 만들 수 있는지 확인한다.
추가해야 하는 가로선의 **최소 개수**를 출력. 불가능하면 `-1`.

**제약**: 가로선은 서로 **붙어 있을 수 없다** (인접한 두 세로선 사이에 겹쳐 놓기 금지).

## 2. 필요한 이론
→ [G07 — 가지치기](../../theory/G07_완전탐색시뮬.md)

**이 그룹에서 유일하게 가지치기가 필수인 문제다.**

```
후보 위치 최대 = R × (C-1) ≈ 30 × 9 = 270
3개 조합 = C(270, 3) ≈ 325만
각각 사다리 타기 O(R × C) = 270
→ 8억 연산. 그대로는 위험하다.
```

> ### ★★ 핵심 전략: "개수를 작은 것부터 늘려가며, 성공하면 즉시 중단"
> ```
> 0개로 되는가?  → 되면 0
> 1개로 되는가?  → 되면 1
> 2개로 되는가?  → 되면 2
> 3개로 되는가?  → 되면 3
> 안 되면 -1
> ```
> **최소 개수를 묻는 문제의 정석**이다. 처음 성공한 개수가 곧 답이므로 더 볼 필요가 없다.
> 실제로 답이 작으면 `C(270, 1)` 이나 `C(270, 2)` 에서 끝나 훨씬 빠르다.

## 3. 코드 흐름
```
main()
 └ input()                     C, M, R, MAP (가로선)
   getEmptyLadder()            ★ 설치 가능한 후보 위치 미리 수집 → ladder[], lcnt
   PASS = false
   printf(simulate())

simulate():
   if (check()) return 0                 ★ 이미 되면 0
   for setup in 1..3:
      DFS(0, 0, setup)
      if (PASS) return setup             ★ 성공 즉시 반환
   return -1

DFS(depth, start, setup):
   if (depth == setup):
      if (check()) PASS = true
      return
   for i in start..lcnt-1:
      인접 검사 → 불가면 continue
      MAP[r][c] = 1                      ★ 직접 설치
      DFS(depth + 1, i + 1, setup)
      MAP[r][c] = 0                      ★ 백트래킹
```

## 4. 핵심 코드

### ★ 후보 위치 미리 수집
```c
struct LADDER { int r; int c; };
LADDER ladder[MAX_H * MAX_N];
int lcnt;

void getEmptyLadder()
{
    // 조건: 현재 위치에 가로선이 없고, 양옆에도 없어야 함
    ...
    ladder[lcnt].r = r;
    ladder[lcnt++].c = c;
}
```

**매번 격자를 훑지 않고 후보 목록을 만든다.** DFS가 `ladder[i]` 를 인덱스로 고르므로 **조합 재귀([G04 31번](../G04/31_BOJ_15650_15655_15664_조합.md))가 그대로 적용**된다.

### ★★ 조합 + 직접 설치/복구 백트래킹
```c
void DFS(int depth, int start, int setup)
{
    // 필요한 개수만큼 다 추가했으면 현재 상태 검사
    if (depth == setup)
    {
        if (check() == true) PASS = true;
        return;
    }

    for (int i = start; i < lcnt; i++)
    {
        int r = ladder[i].r;
        int c = ladder[i].c;

        // 현재 위치 양옆에 이미 가로선이 있으면 설치 불가
        // (가로선은 서로 붙어 있을 수 없음)
        if (MAP[r][c - 1] == 1 || MAP[r][c + 1] == 1) continue;

        MAP[r][c] = 1;                      // ★ 가로선 설치

        DFS(depth + 1, i + 1, setup);       // ★ 조합 (i+1)

        MAP[r][c] = 0;                      // ★ 백트래킹: 복구
    }
}
```

**세 가지가 동시에 작동한다.**

**① 조합** — `DFS(depth+1, i+1)`. 같은 위치를 두 번 고르지 않는다.

**② `MAP` 에 직접 설치하고 복구.**
`copyMap` 으로 사본을 뜨는 방식([2048](2016하2_2048게임.md))도 되지만, 여기서는 **한 칸만 바뀌므로 직접 켰다 끄는 게 훨씬 싸다.**
```c
MAP[r][c] = 1;   →   DFS   →   MAP[r][c] = 0;
```
[G04 순열의 `visit` 되돌림](../G04/30_BOJ_15649_15654_15663_순열.md)과 같은 패턴.

**③ 인접 검사를 실시간으로.**
`getEmptyLadder()` 에서 미리 걸렀어도, **DFS 도중에 방금 설치한 가로선 때문에** 새로 불가능해지는 위치가 생긴다.
그래서 루프 안에서 `MAP[r][c-1]`, `MAP[r][c+1]` 를 **매번 다시 확인**해야 한다.

> ⚠️ 이게 이 문제에서 가장 놓치기 쉬운 지점이다. 후보 목록만 믿으면 **붙어 있는 가로선을 놓게 된다.**

### 사다리 타기 검사
```c
bool check()
{
    int start[MAX_N] = { 0 };

    // 시작 번호 초기화
    for (int c = 1; c <= C; c++)
        start[c] = c;

    // 위에서 아래로 내려가며 가로선이 있으면 swap
    for (int r = 1; r <= R; r++)
    {
        for (int c = 1; c <= C; c++)
        {
            if (MAP[r][c] == 0) continue;

            int tmp = start[c];
            start[c] = start[c + 1];
            start[c + 1] = tmp;
        }
    }

    // 마지막에 자기 번호로 돌아왔는지 확인
    for (int c = 1; c <= C; c++)
        if (start[c] != c) return false;

    return true;
}
```

**★ 사다리 타기를 "세로선마다 따로 내려가는 것"이 아니라 "한 번의 순회로 전부"** 처리한다.

`start[c]` 를 "현재 c번 세로선 자리에 있는 번호"로 두면,
가로선을 만날 때마다 **인접한 두 값을 swap** 하면 된다. `R × C` 한 번으로 모든 세로선의 결과가 나온다.

> 세로선마다 따로 내려가면 `C × R` 이 되어 같지만, **코드가 훨씬 길고 인덱스를 틀리기 쉽다.**
> "전체를 한 번에 굴린다"는 발상이 [G05 다중 시작점 BFS](../G05/38_BOJ_7576_토마토.md)와 같은 계열.

### 개수를 늘려가는 루프
```c
int simulate()
{
    // 이미 만족하면 0
    if (check() == true) return 0;

    // 1개, 2개, 3개 추가 시도
    for (int setup = 1; setup <= 3; setup++)
    {
        DFS(0, 0, setup);

        if (PASS == true) return setup;    // ★ 성공 즉시 반환
    }

    return -1;
}
```

**`setup` 을 1부터 올려가며 처음 성공한 값이 답.** 이게 "최소 개수" 요구를 만족시키는 방법이다.

## 5. 예제 손 추적 — 사다리 타기

`C = 4` (세로선 4개), 가로선이 아래처럼 있다고 하자.
```
        1   2   3   4
r=1     |---|   |   |        MAP[1][1] = 1
r=2     |   |---|   |        MAP[2][2] = 1
r=3     |   |   |---|        MAP[3][3] = 1
```

### `check()` 진행
```
초기:  start = [_, 1, 2, 3, 4]      (인덱스 1~4)

r=1, c=1: MAP[1][1]=1 → swap(start[1], start[2])
          start = [_, 2, 1, 3, 4]

r=2, c=2: MAP[2][2]=1 → swap(start[2], start[3])
          start = [_, 2, 3, 1, 4]

r=3, c=3: MAP[3][3]=1 → swap(start[3], start[4])
          start = [_, 2, 3, 4, 1]

검사: start[1]=2 ≠ 1  →  return false
```

**1번 세로선에서 출발하면 4번에 도착**하는 상태. 조작이 필요하다.

### 인접 검사 확인
`MAP[1][1] = 1` 인 상태에서 `MAP[1][2]` 에 놓으려 하면
```
MAP[1][2-1] = MAP[1][1] = 1  →  continue     ★ 설치 불가
```
가로선이 붙으면 세로선 2번이 좌우 어느 쪽으로 갈지 모호해지므로 문제가 금지한다.

### 가지치기 효과
답이 `1` 인 케이스라면
```
setup=1: C(후보수, 1) ≈ 270 번 검사 → 성공 → 즉시 반환
```
`setup=2`, `setup=3` 은 **아예 안 돈다.** `C(270,2) ≈ 3.6만`, `C(270,3) ≈ 325만` 을 통째로 아낀다.

## 6. 함정 / 예상 함정
- **★★ 가지치기 없이 3개 조합을 전부 탐색.** 코드트리 버전은 **테스트케이스가 강해서** 시간 초과가 난다. `setup` 을 1부터 올리는 구조가 필수.
- **★★ DFS 도중 인접 검사를 안 함.** 후보 목록은 **설치 전** 기준이다. 방금 놓은 가로선 때문에 인접 불가가 새로 생긴다. 루프 안에서 매번 확인.
- **★ `MAP[r][c] = 0` 복구 누락.** 백트래킹이 안 되어 가로선이 계속 쌓인다.
- **★ 조합이 아니라 순열로 탐색.** `DFS(depth+1, i+1)` 이어야 한다. `i` 로 쓰면 같은 위치를 또 고르고, `0` 으로 쓰면 순서만 다른 같은 조합을 중복 탐색한다.
- **★ `check()` 에서 `start` 초기화 누락.** 매 호출마다 `start[c] = c` 로 리셋. 지역 배열이라 `{0}` 으로 자동 0이 되지만, **`c` 로 채우는 초기화는 명시적으로** 해야 한다.
- **`PASS` 를 `setup` 루프마다 리셋 안 함.** 이 코드는 `main` 에서 한 번만 `false` 로 두는데, 한 번 `true` 가 되면 즉시 `return` 하므로 문제없다. **하지만 T-loop 이면 케이스마다 리셋 필요.**
- **swap 대상 인덱스.** `MAP[r][c] == 1` 이면 **`c` 와 `c+1`** 을 바꾼다. `c-1` 과 `c` 가 아니다.
- **0개 케이스를 안 봄.** 처음부터 만족할 수 있다. `simulate()` 첫 줄의 `if (check()) return 0`.

## 7. 백지 재현 체크리스트
- [ ] **`setup` 을 1부터 3까지 늘려가며 성공 시 즉시 반환**하는 구조인가
- [ ] **0개 케이스**를 먼저 확인하는가
- [ ] 후보 위치를 미리 수집하고 **조합 재귀**(`i+1`)로 고르는가
- [ ] **DFS 도중에도 인접 검사**를 다시 하는가
- [ ] `MAP[r][c] = 1` / `DFS` / `MAP[r][c] = 0` **세 줄 세트**인가
- [ ] `check()` 가 **한 번의 순회로 모든 세로선**을 처리하는가 (`start[]` swap)
- [ ] swap 대상이 `c` 와 `c+1` 인가
- [ ] 왜 가지치기가 필수인지 (탐색 공간 계산) 설명할 수 있는가

## 8. 한 줄 요약
"**개수를 1부터 늘려가며 성공 즉시 중단.** 사다리 타기는 `start[]` **swap 한 번**으로, 인접 검사는 **DFS 도중에도.**"
