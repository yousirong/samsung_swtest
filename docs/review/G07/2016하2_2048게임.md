## 1. 문제 요약
N×N 보드에서 2048 게임을 **최대 5번** 이동시킬 수 있을 때, 만들 수 있는 **가장 큰 블록 값**을 구한다.

**이동 규칙** — 한 방향으로 기울이면
1. 모든 블록이 그 방향 끝으로 **밀린다** (빈칸 압축)
2. 같은 값이 맞닿으면 **합쳐져 2배**가 된다
3. 한 번의 이동에서 **이미 합쳐진 블록은 다시 합쳐지지 않는다**

## 2. 필요한 이론
→ [G07 표준 골격](../../theory/G07_완전탐색시뮬.md)

**이 그룹을 대표하는 문제다.** 골격이 가장 깨끗하게 드러난다.

```
후보 만들기      : 방향 4가지 × 5번 = 4^5 = 1024 가지 (중복순열)
각 후보마다      : 원본 복사 → 5번 이동 시뮬레이션 → 최댓값 갱신
```

> **탐색 공간이 1024개밖에 안 된다.** 완전탐색이 명백히 가능하다는 신호.
> 문제가 "최대 5번"이라고 못 박은 것 자체가 **"전부 해보라"는 뜻**이다.

[G04 28번 중복순열](../G04/28_BOJ_15651_15656_중복순열.md)의 재귀 + [G01 배열 조작](../../theory/G01_배열회전.md)이 결합된 형태.

## 4. 핵심 코드

### ★ DFS — 방향 수열 만들기
```c
void DFS(int depth)
{
    // 5번 이동 방향이 모두 정해졌으면 시뮬레이션
    if (depth == 5)
    {
        simulate();

        int tmp = findMax();
        if (maxAnswer < tmp)
            maxAnswer = tmp;

        return;
    }

    for (int i = 0; i < 4; i++)
    {
        num_of_cases[depth] = i;
        DFS(depth + 1);
    }
}
```
`visit` 도 `start` 도 없는 **순수 중복순열**이다. 같은 방향을 연속으로 눌러도 되고, 순서도 의미가 있으므로.

### ★★ 원본 보존 — 이 문제의 생명줄
```c
int oMAP[MAX][MAX];     // original Map: 원본 보드
int ansMAP[MAX][MAX];   // 시뮬레이션 중 실제로 변형할 보드

void simulate()
{
    // 시뮬레이션 시작 전 원본 보드 복사
    copyMap(ansMAP, oMAP);      // ★ 없으면 1024개 후보가 전부 오염된다

    for (int i = 0; i < 5; i++)
    {
        int direction = num_of_cases[i];

        if      (direction == UP)    moveUp();
        else if (direction == RIGHT) moveRight();
        else if (direction == DOWN)  moveDown();
        else if (direction == LEFT)  moveLeft();
    }
}
```

**변수 이름부터 `oMAP`(원본) / `ansMAP`(작업용)으로 분리**한 것이 좋은 방어다.
`moveXXX()` 는 전부 `ansMAP` 만 건드리고 `oMAP` 은 절대 안 건드린다.

> 복사를 빼먹으면 첫 후보(`↑↑↑↑↑`)만 정상이고, 이후 1023개는 **이미 뭉개진 보드** 위에서 계산된다.
> 증상: 답이 터무니없이 크게 나온다.

### ★ 이동 — 2단계로 나눈다
```c
void moveUp()
{
    int tmpMAP[MAX][MAX] = { 0 };

    // 각 열을 독립적으로 처리
    for (int c = 1; c <= N; c++)
    {
        int index = 1;  // 위에서부터 채울 위치

        // 1단계: 0이 아닌 블록을 위로 압축
        for (int r = 1; r <= N; r++)
        {
            if (ansMAP[r][c] == 0) continue;
            tmpMAP[index++][c] = ansMAP[r][c];
        }

        // 2단계: 위에서 아래로 보며 같은 값 합치기
        for (int r = 1; r <= N - 1; r++)
        {
            if (tmpMAP[r][c] != tmpMAP[r + 1][c]) continue;   // 값이 다르면 못 합침
            if (tmpMAP[r][c] == 0) break;                     // 0이면 더 볼 필요 없음

            tmpMAP[r][c] *= 2;                                // 2배로

            // 합쳐진 뒤 뒤쪽 블록들을 한 칸씩 앞으로 당김
            for (int tr = r + 1; tr <= N - 1; tr++)
                tmpMAP[tr][c] = tmpMAP[tr + 1][c];

            tmpMAP[N][c] = 0;                                 // 마지막 칸은 0
        }
    }

    copyMap(ansMAP, tmpMAP);
}
```

**핵심 설계 세 가지**

**① 압축과 합치기를 분리한다.**
한꺼번에 하려 들면 "빈칸 건너뛰고 같은 값 찾기"가 복잡해진다.
**먼저 빈칸을 다 없앤 뒤** 이웃끼리만 비교하면 로직이 단순해진다.

**② 열(또는 행)마다 독립 처리.**
위/아래 이동은 **각 열이 서로 영향을 주지 않는다.** `for (c)` 안에서 그 열만 처리.
좌/우 이동은 각 **행**이 독립.

**③ "이미 합쳐진 블록은 다시 안 합쳐진다"가 자동 해결.**
합친 뒤 뒤쪽을 **한 칸씩 당기고** `r` 은 그대로 다음 반복으로 넘어간다.
`r+1` 자리에 새 값이 오지만, `r` 자리는 이미 2배가 된 값이라 **다음 비교는 `r+1` 부터** 시작한다.

> ⚠️ **정확히는 `r` 이 `for` 에 의해 증가하므로 다음 비교는 `(r+1, r+2)`** 가 된다.
> 방금 합친 `r` 자리는 다시 안 본다 → 규칙 3 만족.

### 네 방향은 대칭
```c
void moveRight()   // 한 행씩 처리, 오른쪽 끝부터 압축, 오른쪽→왼쪽으로 합침
```
`moveUp` 의 `r`↔`c` 를 바꾸고 루프 방향을 뒤집으면 나머지 셋이 나온다.
**네 함수를 각각 쓰는 편이 안전**하다 — 하나로 합치려다 인덱스를 틀리는 것보다.

## 5. 예제 손 추적 — 이동 규칙 확인

한 열이 위에서 아래로 `[2, 2, 4, 4]` 일 때 **위로 이동**.

### 1단계: 압축
```
원본:    2 2 4 4        (빈칸 없음)
압축 후: 2 2 4 4        (그대로)
```

### 2단계: 합치기
```
r=1: tmp[1]=2, tmp[2]=2  →  같다!
     tmp[1] = 4
     뒤쪽 당김: tmp[2]=4, tmp[3]=4, tmp[4]=0
     상태: 4 4 4 0

r=2: tmp[2]=4, tmp[3]=4  →  같다!
     tmp[2] = 8
     뒤쪽 당김: tmp[3]=0, tmp[4]=0
     상태: 4 8 0 0

r=3: tmp[3]=0  →  break
```
```
결과: 4 8 0 0
```

**규칙 3이 지켜지는가**: `r=1` 에서 만든 `4`(=2+2)는 `r=2` 이후로는 **왼쪽에 있어 다시 안 본다.**
`r=2` 에서 합쳐진 `8` 은 원래 `4, 4` 였던 것이지 방금 만든 `4` 가 아니다. ✓

### 빈칸이 섞인 경우 `[2, 0, 0, 2]`
```
압축:    2 2 0 0
합치기:  r=1 → 4 0 0 0
결과:    4 0 0 0
```
**빈칸을 사이에 두고도 합쳐진다** — 압축을 먼저 하기 때문. 이게 ①의 이유.

### `[4, 2, 2, 4]`
```
압축:    4 2 2 4
r=1: 4≠2 → skip
r=2: 2=2 → tmp[2]=4, 당김 → 4 4 4 0
r=3: tmp[3]=4, tmp[4]=0 → 다름 → skip
결과:    4 4 4 0
```
⚠️ `r=1` 을 이미 지나쳤으므로 새로 생긴 `4 4` (인덱스 1,2)는 **합쳐지지 않는다.** 규칙 3에 맞다.

## 6. 함정 / 예상 함정
- **★★ `copyMap(ansMAP, oMAP)` 누락.** 후보 1024개가 전부 오염. **이 그룹 최다 실수.**
- **★★ "이미 합쳐진 블록 재합체" 허용.** `[2,2,4]` 를 `[4,4]` 로 만든 뒤 또 합쳐 `[8]` 로 만들면 틀리다. 정답은 `[4,4]`.
- **★ 압축과 합치기를 한 루프에서.** 빈칸을 건너뛰며 비교하려다 로직이 꼬인다. **분리하면 단순해진다.**
- **★ `maxAnswer` 를 T-loop 마다 초기화 안 함.** 앞 케이스의 값이 남는다.
- **★ 네 방향 함수를 복붙하고 인덱스를 안 고침.** `moveUp` 을 복사해 `moveDown` 을 만들 때 루프 방향(`r = N; r >= 1; r--`)과 채우는 위치(`index = N; index--`)를 둘 다 뒤집어야 한다.
- **`tmpMAP` 을 지역 배열로 `= {0}` 초기화.** 매 호출마다 새로 0이 되어야 한다. 전역으로 빼면 **명시적 초기화 필요.**
- **"최대 5번"인데 5번 미만도 봐야 하는가?** 이 문제는 볼 필요 없다 — 같은 방향을 반복해서 누르면 더 이상 변화가 없으므로 5번 미만의 경우가 5번 수열에 포함된다.
- **보드에 블록이 하나도 없거나 하나뿐인 경우** — 이동해도 변화 없음. 자연히 처리된다.

## 7. 백지 재현 체크리스트
- [ ] `DFS(depth)` + `depth == 5` 종료 + 4방향 루프를 쓸 수 있는가
- [ ] `simulate()` 첫 줄에 **원본 복사**를 넣었는가
- [ ] 이동을 **압축 → 합치기 2단계**로 분리했는가
- [ ] "이미 합쳐진 블록 재합체 금지"가 어떻게 보장되는지 설명할 수 있는가
- [ ] 위/아래는 **열 독립**, 좌/우는 **행 독립**임을 아는가
- [ ] `4^5 = 1024` 를 계산해 완전탐색 가능을 확인했는가
- [ ] T-loop 마다 `maxAnswer` 를 초기화했는가
