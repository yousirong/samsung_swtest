## 1. 문제 요약
N×N 격자를 **5개의 구역**으로 나눈다.
기준점 `(sr, sc)` 와 두 길이 `d1`, `d2` 를 정하면 문제 조건에 따라 5개 구역이 결정된다.

각 구역의 인구 합을 구하고, **(가장 큰 구역 인구 − 가장 작은 구역 인구)의 최솟값**을 찾는다.

## 2. 필요한 이론
→ [G07 — 좌표·파라미터 다중 루프](../../theory/G07_완전탐색시뮬.md)

**재귀가 없다.** 후보가 `(sr, sc, d1, d2)` 네 개의 정수이므로 **4중 루프**로 전부 시도한다.

```
후보 수 ≈ N² × d1_max × d2_max  →  N=20 이면 대략 수만 가지
각 후보마다 구역 분할 O(N²)     →  충분히 통과
```

> **★ 이 문제의 난점은 탐색이 아니라 "5구역을 정확히 그리는 것"** 이다.
> 1번 구역(가운데 마름모)의 경계를 한 칸이라도 틀리면 전부 어긋난다.
> **알고리즘 문제라기보다 도형 구현 문제**에 가깝다.

## 3. 코드 흐름
```
main()
 └ input()                    N, MAP
   minAnswer = INF
   simulate()
    └ for sr, sc:             기준점 전체
         d1 = 1; while (유효):
            d2 = 1; while (유효):
               calculate(sr, sc, d1, d2)     ★ 5구역 나누고 차이 갱신
               d2++
            d1++
   printf(minAnswer)
```

## 4. 핵심 코드

### ★ 유효성 검사를 `while` 조건으로
```c
void simulate()
{
    for (int r = 1; r <= N - 2; r++)
    {
        for (int c = 2; c <= N - 1; c++)
        {
            int d1 = 1;
            while (1)
            {
                // 왼쪽 아래 방향 경계가 격자 밖이면 d1 종료
                if (MAP[r + d1][c - d1] == -1) break;

                int d2 = 1;
                while (1)
                {
                    // 오른쪽 아래 방향 경계 또는
                    // 가장 아래 꼭짓점이 격자 밖이면 d2 종료
                    if (MAP[r + d2][c + d2] == -1 ||
                        MAP[r + d1 + d2][c + d2 - d1] == -1)
                        break;

                    calculate(r, c, d1, d2);
                    d2++;
                }
                d1++;
            }
        }
    }
}
```

**세 가지 설계 포인트**

**① 테두리를 `-1` 로 채워 범위 검사를 값 비교로 바꿨다.**
`if (r + d1 > N || c - d1 < 1)` 같은 복잡한 조건 대신 `MAP[...] == -1` 한 번.
[G05 테두리 sentinel](../../theory/G05_그리드탐색심화.md)의 응용.

**② 마름모의 세 꼭짓점만 검사하면 충분하다.**
- 왼쪽 꼭짓점 `(sr+d1, sc-d1)`
- 오른쪽 꼭짓점 `(sr+d2, sc+d2)`
- 아래 꼭짓점 `(sr+d1+d2, sc+d2-d1)`

이 셋이 격자 안이면 마름모 전체가 안에 들어간다.

**③ 루프 범위가 `r <= N-2`, `c` 는 `2 ~ N-1`.**
`d1 ≥ 1`, `d2 ≥ 1` 이므로 기준점이 가장자리에 붙으면 마름모를 못 그린다.
범위를 미리 좁혀 무의미한 시도를 줄인다.

### ★★ 1번 구역 — 마름모 채우기
```c
int area[MAX][MAX] = { 0 };   // 각 칸이 어느 구역인지

start = end = sc;
left = -1;      // 왼쪽 경계는 왼쪽으로
right = 1;      // 오른쪽 경계는 오른쪽으로

for (int r = sr; r <= sr + d1 + d2; r++)
{
    // 현재 행의 [start ~ end]를 전부 1번 구역으로
    for (int c = start; c <= end; c++)
        area[r][c] = 1;

    // 다음 행을 위해 경계 이동
    start += left;
    end += right;

    // 왼쪽 경계가 가장 왼쪽 꼭짓점에 닿으면 다시 오른쪽으로
    if (start == sc - d1) left = 1;

    // 오른쪽 경계가 가장 오른쪽 꼭짓점에 닿으면 다시 왼쪽으로
    if (end == sc + d2) right = -1;
}
```

**마름모를 "행마다 구간 `[start, end]`"로 표현**한 것이 이 구현의 핵심 아이디어다.

- 처음 `(sr, sc)` 한 칸에서 시작 (`start == end == sc`)
- 아래로 내려가며 **양쪽으로 벌어진다** (`left = -1`, `right = +1`)
- 꼭짓점에 닿으면 **방향을 뒤집어 좁아진다**

좌우가 **독립적으로 벌어졌다 좁아진다**는 게 포인트. `d1 ≠ d2` 면 마름모가 비대칭이라 각각 따로 꺾인다.

```
d1 = 2, d2 = 3 일 때 (sr,sc) = (1,4) 기준

행    구간            상태
1     [4, 4]          시작
2     [3, 5]          양쪽 벌어짐
3     [2, 6]          왼쪽이 sc-d1=2 도달 → left = +1
4     [3, 7]          오른쪽이 sc+d2=7 도달 → right = -1
5     [4, 6]          양쪽 좁아짐
6     [5, 5]          끝 (sr+d1+d2 = 6)
```

### 2~5번 구역 — 조건식 + `break`
```c
// 2번 구역: 1 <= r <= sr+d1-1,  1 <= c <= sc
for (int r = 1; r <= N; r++)
{
    for (int c = 1; c <= N; c++)
    {
        if (area[r][c] == 1) break;      // ★ 1번 구역 만나면 그 행은 끝

        if ((1 <= r && r <= sr + d1 - 1) && (1 <= c && c <= sc))
            area[r][c] = 2;
    }
}
```

**`break` 의 의미**: 1번 구역(마름모)은 각 행에서 **연속 구간**이므로, 왼쪽에서 오다가 마름모를 만나면 **그 행의 나머지는 2번이 될 수 없다.**

> 문제 조건이 "1번 구역이 아닌 칸 중 조건을 만족하는 것"이므로, 이 `break` 가 마름모 경계를 자연스럽게 처리한다.

3~5번도 같은 방식으로 각자의 부등식 범위 + 마름모 회피로 채운다.

### 최대-최소 차이
```c
min = INF; max = 0;
for (int i = 1; i <= 5; i++)
{
    if (min > sum[i]) min = sum[i];
    if (max < sum[i]) max = sum[i];
}

if (minAnswer > max - min) minAnswer = max - min;
```

## 5. 예제 손 추적 — 마름모 경계

`N = 7`, 기준점 `(sr, sc) = (2, 4)`, `d1 = 2`, `d2 = 2`

**세 꼭짓점 검사**
```
왼쪽  (2+2, 4-2) = (4, 2)   격자 안 ✓
오른쪽 (2+2, 4+2) = (4, 6)   격자 안 ✓
아래  (2+2+2, 4+2-2) = (6, 4) 격자 안 ✓
```
→ 유효한 후보

**마름모 채우기** (`r` 은 `2 ~ 6`)
```
r=2:  [4, 4]        start=4, end=4
      start → 3, end → 5

r=3:  [3, 5]
      start → 2 (== sc-d1=2) → left = +1
      end   → 6 (== sc+d2=6) → right = -1

r=4:  [2, 6]        ★ 가장 넓은 행 (좌우 꼭짓점)
      start → 3, end → 5

r=5:  [3, 5]
      start → 4, end → 4

r=6:  [4, 4]        ★ 아래 꼭짓점
```

```
격자 위 1번 구역 (·  = 다른 구역)

r=1   · · · · · · ·
r=2   · · · 1 · · ·
r=3   · · 1 1 1 · ·
r=4   · 1 1 1 1 1 ·
r=5   · · 1 1 1 · ·
r=6   · · · 1 · · ·
r=7   · · · · · · ·
```
**정확한 마름모** ✓ 칸 수 = `1 + 3 + 5 + 3 + 1 = 13`

### `d1 ≠ d2` 인 경우 — 비대칭
`d1 = 1, d2 = 3`, `(sr, sc) = (1, 3)`
```
r=1:  [3, 3]     start→2, end→4
r=2:  [2, 4]     start==sc-d1=2 → left=+1;  end→5
r=3:  [3, 5]     end→6 == sc+d2=6 → right=-1
r=4:  [4, 6]     ★ 왼쪽은 이미 좁아지는 중, 오른쪽은 이제 꺾임
r=5:  [5, 5]     끝 (sr+d1+d2 = 5)
```
**좌우가 서로 다른 시점에 꺾인다** — 이게 `left`/`right` 를 따로 둔 이유.

## 6. 함정 / 예상 함정
- **★★ 마름모 경계를 한 칸 틀림.** 이 문제의 전부다. `sc - d1`, `sc + d2`, `sr + d1 + d2` 세 값을 손으로 그려 검산한다.
- **★★ 좌우 꺾이는 시점을 하나로 묶음.** `d1 ≠ d2` 면 좌우가 **다른 행에서** 꺾인다. `left`, `right` 를 따로 관리해야 한다.
- **★ 유효성 검사에서 꼭짓점을 빠뜨림.** 세 꼭짓점(`왼쪽`, `오른쪽`, `아래`)이 모두 격자 안이어야 한다. 하나만 검사하면 삐져나간 마름모가 통과한다.
- **★ 2~5번 구역에서 `break` 누락.** 마름모를 뚫고 반대편까지 칠하게 된다.
- **★ 테두리 `-1` 초기화 누락.** 값 비교로 범위를 검사하는 트릭이 깨진다. **격자 값이 인구수(양수)라 `-1` 이 안전한 sentinel.**
- **`area` 를 전역으로 두고 초기화 안 함.** 후보마다 새로 그려야 한다. **지역 배열 `{0}` 이 안전** (단 `N` 이 크면 스택 부담 — 이 문제는 `N ≤ 20` 이라 무방).
- **`d1`, `d2` 를 0부터 시작.** 둘 다 **1 이상**이다.
- **5구역 합이 전체 인구와 같은지 검산 안 함.** 디버깅할 때 `sum[1]+...+sum[5] == 전체합` 을 확인하면 구역 분할 버그를 즉시 잡는다. **매우 유용한 자가 검증.**

## 7. 백지 재현 체크리스트
- [ ] 후보가 **`(sr, sc, d1, d2)` 4개 파라미터**임을 알고 재귀 없이 루프로 도는가
- [ ] 마름모를 **행마다 구간 `[start, end]`** 로 표현할 수 있는가
- [ ] `left` / `right` 를 **따로** 관리해 비대칭을 처리하는가
- [ ] 꺾이는 조건이 `start == sc - d1`, `end == sc + d2` 인가
- [ ] 유효성 검사로 **세 꼭짓점**을 모두 확인하는가
- [ ] 2~5번 구역에서 마름모를 만나면 `break` 하는가
- [ ] 테두리 `-1` sentinel 을 넣었는가
- [ ] **5구역 합 == 전체 인구** 로 자가 검증할 수 있는가
