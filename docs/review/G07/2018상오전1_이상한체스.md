## 1. 문제 요약
격자판에 **1~5번 말**이 놓여 있다. 각 말은 **방향을 하나 정하면** 정해진 규칙대로 감시 영역을 만든다.

| 칸 값 | 의미 |
|---|---|
| `0` | 빈 칸 |
| `6` | 벽 |
| `1~5` | 말의 종류 |

**모든 말의 방향을 적절히 정해서 감시되지 않는 빈 칸(사각지대)의 개수를 최소로** 만든다.

## 2. 필요한 이론
→ [G07 표준 골격](../../theory/G07_완전탐색시뮬.md)

[2048](2016하2_2048게임.md)과 골격이 같다. 다른 점은 **"후보 수열의 길이가 입력에 따라 달라진다"** 는 것.

```
후보 = 각 말마다 4방향 중 하나  →  4^(말 개수)
말이 8개면 4^8 = 65,536 가지
```

> **★ `depth == cidx`** — 종료 조건이 상수가 아니라 **말 개수**다.
> 2048은 `depth == 5` 로 고정이었지만, 여기서는 입력을 읽어야 알 수 있다.

**말 종류별 감시 방향 규칙**을 표로 정리하는 것이 이 문제의 절반이다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()               N, M, MAP — 이때 말들을 chess[] 에 수집, cidx 계산
      minAnswer = INF
      DFS(0)
      printf(minAnswer)

DFS(depth):
   if (depth == cidx):      ★ 말 개수만큼 방향을 다 정했으면
      simulate()
      tmp = getArea()
      minAnswer = min(minAnswer, tmp)
      return
   for i in 0..3:           현재 말에 대해 4방향 시도
      num_of_cases[depth] = i
      DFS(depth + 1)

simulate():
   copyMap(tmpMAP, MAP)     ★★ 원본 복사
   각 말에 대해 종류별 감시 방향으로 checkArea()
```

## 4. 핵심 코드

### 말 수집 — 입력할 때 한 번에
```c
struct CHESS { int r; int c; int number; };
CHESS chess[MAX * MAX];
int cidx;               // 말의 개수

// input() 안에서
if (MAP[r][c] >= 1 && MAP[r][c] <= 5)
{
    chess[cidx].r = r;
    chess[cidx].c = c;
    chess[cidx++].number = MAP[r][c];
}
```

**격자를 매번 훑지 않고 말 목록을 미리 만든다.** DFS의 `depth` 가 곧 `chess[depth]` 를 가리키게 되어 코드가 단순해진다.

### ★ DFS — 길이가 가변인 중복순열
```c
void DFS(int depth)
{
    // 모든 말의 방향을 다 정했으면 시뮬레이션 수행
    if (depth == cidx)          // ★ 상수가 아니라 말 개수
    {
        simulate();

        int tmp = getArea();
        if (tmp < minAnswer) minAnswer = tmp;

        return;
    }

    // 현재 말에 대해 4방향 시도
    for (int i = 0; i < 4; i++)
    {
        num_of_cases[depth] = i;
        DFS(depth + 1);
    }
}
```
`visit` 도 `start` 도 없다 — **순수 중복순열**. 서로 다른 말이 같은 방향을 봐도 되므로.

### ★★ 원본 보존
```c
void simulate()
{
    // 원본 맵을 복사해서 시뮬레이션 시작
    copyMap(tmpMAP, MAP);       // ★ 없으면 감시 표시가 누적된다

    for (int i = 0; i < cidx; i++) { ... checkArea(...) ... }
}
```

**감시 표시(`MARK = 7`)를 `tmpMAP` 에만 찍는다.** 복사를 빼먹으면 이전 후보의 감시 영역이 그대로 남아 **사각지대가 계속 줄어들어** 답이 0에 수렴한다.

`copyMap` 범위가 `0 ~ N+1` 인 것에 주목 — **테두리 sentinel까지 복사**한다.

### 말 종류별 감시 방향 — 방향 산술
```c
int direction = num_of_cases[i];

// 1번 말: 한 방향만 감시
if (chessNumber == 1)
{
    checkArea(sr, sc, direction);
}

// 2번 말: 서로 반대 방향 두 곳 감시
else if (chessNumber == 2)
{
    int inverse = direction + 2;
    if (inverse > 3) inverse -= 4;      // ★ (direction + 2) % 4

    checkArea(sr, sc, direction);
    checkArea(sr, sc, inverse);
}

// 3번 말: 직각 방향 두 곳 감시
// 예: 상+우, 우+하, 하+좌, 좌+상
...
```

**방향 배열이 `상(0) 우(1) 하(2) 좌(3)` 순이므로 산술이 성립한다.**

| 관계 | 식 |
|---|---|
| 반대 방향 | `(d + 2) % 4` |
| 시계 90도 | `(d + 1) % 4` |
| 반시계 90도 | `(d + 3) % 4` |

| 말 | 감시 방향 |
|---|---|
| 1 | `d` |
| 2 | `d`, `d+2` (반대) |
| 3 | `d`, `d+1` (직각) |
| 4 | `d`, `d+1`, `d+2` (세 방향) |
| 5 | 네 방향 전부 |

> **5번 말은 방향이 의미 없다.** 어느 방향을 골라도 결과가 같으므로, 5번 말만 있으면 탐색이 4배씩 낭비된다.
> 최적화하려면 5번 말은 DFS에서 제외하고 미리 감시 처리하면 된다. A형 범위에서는 불필요.

### `checkArea` — 벽에 막힐 때까지 직진
```c
void checkArea(int r, int c, int direction)
{
    while (1)
    {
        r += dr[direction];
        c += dc[direction];

        if (tmpMAP[r][c] == OTHER) break;      // 벽(6)이면 중단

        if (tmpMAP[r][c] == EMPTY)             // 빈 칸이면 감시 표시
            tmpMAP[r][c] = MARK;
    }
}
```

**세 가지 포인트**
1. **벽(`6`)에서만 멈춘다** — 다른 말(`1~5`)은 통과한다
2. **빈 칸(`0`)만 `MARK(7)` 로 바꾼다** — 말이 있는 칸은 덮어쓰지 않는다
3. **테두리 sentinel이 `6`(벽)** 이라 범위 체크가 필요 없다

### 사각지대 세기
```c
int getArea()
{
    int count = 0;
    for (int r = 1; r <= N; r++)
        for (int c = 1; c <= M; c++)
            if (tmpMAP[r][c] == EMPTY) count++;    // 여전히 0인 칸
    return count;
}
```
`MARK(7)` 로 바뀌지 않고 `0` 으로 남은 칸이 사각지대다.

## 5. 예제 손 추적 — 방향 산술 확인

방향 규약: `0=상, 1=우, 2=하, 3=좌`

### 2번 말이 `direction = 1(우)` 를 골랐을 때
```
inverse = 1 + 2 = 3        (3 > 3 아니므로 그대로)
→ 감시 방향: 우(1), 좌(3)      ★ 좌우 일직선 ✓
```

### 2번 말이 `direction = 3(좌)` 를 골랐을 때
```
inverse = 3 + 2 = 5        5 > 3 이므로 5 - 4 = 1
→ 감시 방향: 좌(3), 우(1)      ★ 위와 같은 결과
```

> **2번 말은 4방향을 다 시도해도 실질적으로 2가지**다 (`좌우` 또는 `상하`). 중복 탐색이지만 답에는 영향이 없다.

### 3번 말이 `direction = 2(하)` 를 골랐을 때
```
직각 = (2 + 1) % 4 = 3
→ 감시 방향: 하(2), 좌(3)      ★ ㄴ자 모양
```

### `checkArea` 진행 — 벽에서 멈춤
```
격자:   6 6 6 6 6        (테두리 = 벽)
        6 . . 6 6
        6 P . . 6        P = 말, direction = 우(1)
        6 6 6 6 6

P 위치 (3,2) 에서 우측으로:
  (3,3) = 0 → MARK
  (3,4) = 0 → MARK
  (3,5) = 6 → break        ★ 테두리 벽에서 자동 정지
```
**범위 체크 `if` 가 한 줄도 없다** — sentinel의 효과.

## 6. 함정 / 예상 함정
- **★★ `copyMap(tmpMAP, MAP)` 누락.** 감시 표시가 후보마다 누적되어 사각지대가 0으로 수렴한다.
- **★★ 종료 조건을 상수로.** `depth == cidx` — 말 개수는 입력마다 다르다.
- **★ `checkArea` 가 다른 말에서 멈춤.** **벽(`6`)에서만** 멈춘다. 말은 통과한다.
- **★ 말이 있는 칸을 `MARK` 로 덮어씀.** `EMPTY(0)` 인 칸만 바꾼다. 덮어쓰면 그 말의 종류 정보가 사라져 이후 처리가 깨진다.
- **★ 방향 산술 `% 4` 누락.** `direction + 2` 가 4를 넘을 수 있다. `if (inverse > 3) inverse -= 4;` 또는 `% 4`.
- **★ 방향 배열 순서와 산술 불일치.** `상우하좌` 순서여야 `+2 = 반대`, `+1 = 직각` 이 성립한다. 다른 순서를 쓰면 전부 틀린다.
- **테두리를 벽(`6`)으로 초기화 안 함.** `checkArea` 가 무한 루프에 빠진다 — `while(1)` 이라 **프로그램이 멈춘다.**
- **5번 말도 4방향 탐색.** 답은 맞지만 4배 낭비. 알아두면 좋다.
- **T-loop 마다 `cidx`, `minAnswer` 초기화 누락.**

## 7. 백지 재현 체크리스트
- [ ] 말 목록을 **입력할 때 수집**해 `chess[]`, `cidx` 로 두는가
- [ ] 종료 조건이 **`depth == cidx`** 인가
- [ ] `simulate()` 첫 줄에 **원본 복사**를 넣었는가
- [ ] 방향 산술 표(`+2` 반대, `+1` 직각)를 쓸 수 있는가, `% 4` 를 넣었는가
- [ ] 말 5종의 감시 방향 표를 쓸 수 있는가
- [ ] `checkArea` 가 **벽에서만 멈추고 빈 칸만 표시**하는가
- [ ] **테두리를 벽으로 초기화**했는가 (`while(1)` 무한루프 방지)
- [ ] 사각지대를 `EMPTY` 로 남은 칸으로 세는가

## 8. 한 줄 요약
