# 2015 하반기 2번 — 2개의 사탕

| 항목 | 내용 |
|---|---|
| 유형 | G07 완전탐색 + 시뮬레이션 (**방향 수열 10 + 기울이기**) |
| 소스 | [swtest/코드트리_2015_하반기2번_2개의사탕.cpp](../../../swtest/코드트리_2015_하반기2번_2개의사탕.cpp) |
| 링크 | https://www.codetree.ai/training-field/frequent-problems/problems/two-candies |
| 별칭 | BOJ 13460 구슬 탈출 2 |

## 1. 문제 요약
빨간 사탕(`R`)과 파란 사탕(`B`)이 있는 보드를 **상/하/좌/우로 최대 10번** 기울일 수 있다.

**목표**: 빨간 사탕만 구멍(`O`)에 빠뜨리고 **파란 사탕은 빠지지 않게** 하는 **최소 기울이기 횟수**.
불가능하면 `-1`.

기울이면 두 사탕이 **더 이상 움직일 수 없을 때까지** 그 방향으로 굴러간다.

## 2. 필요한 이론
→ [G07 표준 골격](../../theory/G07_완전탐색시뮬.md)

[2048](2016하2_2048게임.md)과 **같은 골격**이지만 두 가지가 더 까다롭다.

| | 2048 | 2개의 사탕 (이 문제) |
|---|---|---|
| 탐색 공간 | `4^5 = 1024` | `4^10 = 100만` (연속 중복 제거로 더 줄임) |
| 시뮬레이션 대상 | 보드 전체 | **사탕 2개의 좌표만** |
| 실패 개념 | 없음 | **파란 사탕이 빠지면 실패** |
| 답 | 최댓값 | **최솟값** (`INF` 초기화) |

> **★ 상태를 "보드"가 아니라 "좌표 2개"로 압축**한 것이 이 구현의 핵심 선택이다.
> [G05 41번 유닛 이동시키기](../G05/41_BOJ_2194_유닛이동시키기.md)의 "상태 압축"과 같은 발상 — **보드는 안 변하고 사탕만 움직이므로** 보드를 복사할 필요가 없다.
> 그래서 `copyMap` 이 아예 없다.

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()                    N, M, MAP, RED/BLUE 초기 위치
      minAnswer = INF
      DFS(0, -1)
      printf(minAnswer == INF ? -1 : minAnswer)

DFS(depth, direction):
   if (depth == 10):
      tmp = simulate()
      minAnswer = min(minAnswer, tmp)
      return
   for i in 0..3:
      if (i == direction) continue      ★ 연속 같은 방향 제외
      num_of_cases[depth] = i
      DFS(depth + 1, i)

simulate():
   red = RED, blue = BLUE               ★ 좌표만 초기화 (보드 복사 불필요)
   for i in 0..9:
      한 방향으로 끝까지 굴리기
      빨강이 구멍에 빠졌으면 → 파랑도 빠지는지 확인 → 결과 반환
   return INF                           10번 안에 못 넣음
```

## 4. 핵심 코드

### ★ 연속 같은 방향 가지치기
```c
for (int i = 0; i < 4; i++)
{
    // 연속해서 같은 방향은 제외
    // 예: 위 다음 위
    // 보통 의미가 없거나 중복 상태를 많이 만든다
    if (i == direction) continue;

    num_of_cases[depth] = i;
    DFS(depth + 1, i);
}
```

**한 번 기울이면 끝까지 굴러가므로, 같은 방향을 또 눌러도 아무 일도 안 일어난다.**
이 가지치기로 탐색 공간이 `4^10 = 100만` → `4 × 3^9 ≈ 8만` 으로 줄어든다.

> `DFS` 가 **인자를 두 개** 받는 이유가 이것이다. 직전 방향을 알아야 거를 수 있다.
> 최초 호출은 `DFS(0, -1)` — 아직 방향이 없으므로 `-1`.

### ★★ 기울이기 — 네 가지 경우 분기
```c
while (1)
{
    int red_nr = red.r + dr[direction],  red_nc = red.c + dc[direction];
    int blue_nr = blue.r + dr[direction], blue_nc = blue.c + dc[direction];

    bool checkWallRed  = MAP[red_nr][red_nc]   == '#';
    bool checkWallBlue = MAP[blue_nr][blue_nc] == '#';

    // 서로가 서로를 막고 있는지
    bool checkCandyRed  = (red_nr == blue.r) && (red_nc == blue.c);
    bool checkCandyBlue = (blue_nr == red.r) && (blue_nc == red.c);

    // 1) 둘 다 벽이면 정지
    if (checkWallRed && checkWallBlue) break;

    // 2) 둘 다 갈 수 있으면 둘 다 이동
    if (!checkWallRed && !checkWallBlue) { red 이동; blue 이동; }

    // 3) 빨강만 막힘 → 파랑만 이동 (파랑 앞이 빨강 자리가 아닐 때)
    else if (checkWallRed && !checkCandyBlue) { blue 이동; }

    // 4) 파랑만 막힘 → 빨강만 이동
    else if (checkWallBlue && !checkCandyRed) { red 이동; }

    // 그 외: 서로 막고 있음 → 정지
    else break;

    ... 구멍 판정 ...
}
```

**두 사탕이 서로를 막는다**는 것이 이 문제를 어렵게 만든다.
- 벽 때문에 못 가는 경우
- **상대 사탕 때문에** 못 가는 경우

두 조건을 따로 계산해 조합한다.

> **★ 경우 2가 위험해 보인다.** 둘 다 벽이 아니면 무조건 둘 다 이동시키는데, 앞 사탕이 아직 안 움직였으면 겹치지 않나?
> **같은 방향으로 같은 칸씩 움직이므로 상대적 위치가 유지된다** — 겹칠 수 없다. 문제없다.

### 구멍 판정 — 빨강이 빠진 순간
```c
if (MAP[red.r][red.c] == 'O')
{
    // 같은 방향으로 파란 사탕도 계속 굴러가서 구멍에 빠질 수 있는지 끝까지 확인
    while (MAP[blue.r][blue.c] != '#')
    {
        if (MAP[blue.r][blue.c] == 'O')
            return INF;              // ★ 파란 사탕도 빠지면 실패

        blue.r += dr[direction];
        blue.c += dc[direction];
    }

    return i + 1;                    // 성공 — 이번이 몇 번째 기울이기인지
}
```

**빨강이 먼저 빠져도 끝이 아니다.** 파랑이 아직 굴러가는 중이라면, **끝까지 굴려서** 구멍에 빠지는지 확인해야 한다.

> **이것이 이 문제의 진짜 함정이다.** 빨강이 빠진 순간 성공을 선언하면, 파랑이 뒤따라 빠지는 케이스를 놓친다.

### 실패 규약 — `INF`
```c
#define INF (0x7fff0000)

int minAnswer = INF;
...
if (tmp < minAnswer) minAnswer = tmp;
...
printf("%d\n", minAnswer == INF ? -1 : minAnswer);
```

**최솟값 문제이므로 `INF` 로 초기화**하고, 실패는 `INF` 를 반환한다.
끝까지 `INF` 면 불가능 → `-1`.

`0x7fff0000` 을 쓰는 이유: `INT_MAX` 에 가깝지만 **더해도 오버플로가 안 나는** 여유를 둔 값. A형에서 흔한 관용구.

## 5. 예제 손 추적 — 서로 막는 상황

```
보드      # # # # #
          # R B . #        R=(2,2), B=(2,3)
          # . . O #        O=(3,4)
          # # # # #
```

### 오른쪽(`→`)으로 기울이면
```
1회전:
  red_next  = (2,3)  ← B가 있는 자리
  blue_next = (2,4)  ← 빈칸

  checkWallRed  = false   (2,3)은 벽 아님
  checkWallBlue = false   (2,4)는 벽 아님
  → 경우 2: 둘 다 이동

  R=(2,3), B=(2,4)      ★ 겹치지 않는다 (같은 칸씩 움직였으므로)

2회전:
  red_next  = (2,4)  ← 방금 B가 간 자리
  blue_next = (2,5)  ← 벽 '#'

  checkWallRed  = false
  checkWallBlue = true
  checkCandyRed = (red_next == blue 위치)? (2,4)==(2,4) → true

  → 경우 4 조건 `checkWallBlue && !checkCandyRed` 가 false
  → else → break     ★ 파랑이 벽에 막혔고 빨강은 파랑에 막힘
```
```
결과: R=(2,3), B=(2,4)  — 더 못 감
```

**`checkCandy` 가 없으면** 빨강이 파랑을 뚫고 `(2,4)` 로 들어가 두 사탕이 겹친다.

### 아래(`↓`)로 기울이면 — 빨강이 구멍에
```
R=(2,3) → (3,3)     B=(2,4) → (3,4) = 'O'  ★ 파랑이 구멍!
```
파랑이 빠지면 **즉시 실패**(`INF`). 빨강만 빠져야 한다.

### 실패 판정 순서가 중요하다
빨강이 빠졌는지 먼저 보고, 그 다음 파랑을 끝까지 굴려 확인한다.
**파랑이 먼저 빠지는 경우도 별도로 처리**해야 완전하다 — 위 코드는 `MAP[blue][blue] == 'O'` 를 굴리는 도중에 검사하므로 커버된다.

## 6. 함정 / 예상 함정
- **★★ 빨강이 빠진 순간 바로 성공 처리.** 파랑이 뒤따라 빠지는지 **끝까지 굴려 확인**해야 한다.
- **★★ 두 사탕이 서로를 막는 경우를 안 봄.** 벽만 검사하면 사탕이 겹친다. `checkCandyRed/Blue` 필수.
- **★ 최솟값인데 `answer` 를 0으로 초기화.** `INF` 여야 한다. 갱신이 한 번도 안 일어난다.
- **★ 연속 같은 방향 가지치기 누락.** 없어도 답은 맞지만 `4^10 = 100만 × 시뮬 비용` 이라 위험하다.
- **★ `DFS` 를 `depth == 10` 에서만 평가.** 10번 **미만**에 성공하는 경우는? `simulate()` 가 `i + 1` (성공한 회차)을 반환하므로 자동 처리된다. **수열은 10개를 다 만들되 시뮬레이션이 조기 종료**하는 구조.
- **`INF` 를 `INT_MAX` 로.** 어딘가에서 `+1` 하면 오버플로. `0x7fff0000` 처럼 여유를 둔다.
- **T-loop 마다 `minAnswer` 초기화 누락.**
- **보드를 복사하려 함.** 이 문제는 보드가 안 변한다. 사탕 좌표만 초기화하면 된다.

## 7. 백지 재현 체크리스트

- [ ] **연속 같은 방향 가지치기**를 위해 `DFS` 에 직전 방향을 넘기는가
- [ ] 기울이기의 **네 가지 경우**를 분기할 수 있는가
- [ ] **상대 사탕이 막는 경우**(`checkCandy`)를 넣었는가
- [ ] 빨강이 빠진 뒤 **파랑을 끝까지 굴려** 확인하는가
- [ ] 최솟값이므로 `INF` 로 초기화하고 실패를 `INF` 로 반환하는가
- [ ] 10번 미만 성공이 어떻게 처리되는지 설명할 수 있는가
