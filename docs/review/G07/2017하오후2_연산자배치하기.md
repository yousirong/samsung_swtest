## 1. 문제 요약
숫자 N개가 **순서대로** 주어지고, 사용할 수 있는 연산자 개수(`+`, `-`, `*`)가 주어진다.

숫자 순서는 **바꿀 수 없고**, 숫자 사이에 연산자를 배치해 만들 수 있는 결과의 **최솟값과 최댓값**을 구한다.

> **★ 연산자 우선순위를 무시하고 앞에서부터 계산한다.**
> ```
> a b c d  →  (((a op1 b) op2 c) op3 d)
> ```

## 2. 필요한 이론
→ [G07 — 개수 제한 수열](../../theory/G07_완전탐색시뮬.md)

[2048](2016하2_2048게임.md)과 골격은 같지만 **후보를 만드는 방식**이 다르다.

| | 2048 | 이 문제 |
|---|---|---|
| 후보 | 순수 중복순열 (`4^5`) | **개수가 제한된** 수열 |
| 도구 | 없음 | `visit[]` 카운터 + `possible[]` |
| 평가 | 보드 시뮬레이션 | `calculate()` 수식 계산 |

> **★ `visit` 이 bool 이 아니라 카운터다.**
> [G04 30번 15663](../G04/30_BOJ_15649_15654_15663_순열.md)에서 배운 **카운터 승격**이 여기서 실전으로 쓰인다.
> "각 연산자를 정해진 개수만큼만" = "각 값을 possible 만큼만".

## 3. 코드 흐름
```
main()
 └ T-loop:
      input()                     N, number[], possible[+,-,*]
      minAnswer = INF, maxAnswer = -INF
      DFS(0)
      printf(maxAnswer, minAnswer)

DFS(depth):
   if (depth == N - 1):           ★ 연산자는 숫자보다 1개 적다
      tmp = calculate()
      maxAnswer = max(...), minAnswer = min(...)
      return
   for i in 0..2:                 +, -, *
      if (visit[i] == possible[i]) continue    ★ 다 썼으면 skip
      num_of_cases[depth] = i
      visit[i]++
      DFS(depth + 1)
      visit[i]--                                ★ 백트래킹
```

## 4. 핵심 코드

### ★ 개수 제한 수열
```c
int visit[MAX];      // 각 연산자를 현재까지 몇 번 사용했는지
int possible[3];     // 사용할 수 있는 최대 개수: [+, -, *]

void DFS(int depth)
{
    // 연산자 N-1개를 모두 배치했으면 결과 계산
    if (depth == N - 1)
    {
        int tmp = calculate();

        if (maxAnswer < tmp) maxAnswer = tmp;
        if (minAnswer > tmp) minAnswer = tmp;

        return;
    }

    for (int i = 0; i < 3; i++)
    {
        // 이미 해당 연산자를 가능한 개수만큼 다 사용했으면 건너뜀
        if (visit[i] == possible[i]) continue;

        num_of_cases[depth] = i;
        visit[i]++;

        DFS(depth + 1);

        visit[i]--;               // ★ 백트래킹
    }
}
```

**세 줄이 세트다.**
```c
visit[i]++;
DFS(depth + 1);
visit[i]--;      // 이걸 빼면 첫 경우만 나오고 끝난다
```

> **`depth == N - 1`** 에 주의. 숫자가 N개면 **연산자는 N-1개**다.
> `depth == N` 으로 쓰면 배열 밖을 쓰고, `possible` 합계와도 안 맞는다.

### 최댓값·최솟값을 한 번에
```c
minAnswer = INF;
maxAnswer = -INF;      // ★ 방향이 반대
...
if (maxAnswer < tmp) maxAnswer = tmp;
if (minAnswer > tmp) minAnswer = tmp;
```
**한 번의 DFS로 둘 다 구한다.** 초기화 방향이 반대인 것에 주의 — 결과가 음수일 수 있으므로 `maxAnswer` 를 `0` 으로 두면 안 된다.

### `calculate()` — 앞에서부터 순차 계산
```c
int calculate()
{
    int result = number[0];

    for (int i = 0; i < N - 1; i++)
    {
        if      (num_of_cases[i] == PLUS)     result += number[i + 1];
        else if (num_of_cases[i] == MINUS)    result -= number[i + 1];
        else if (num_of_cases[i] == MULTIPLY) result *= number[i + 1];
    }

    return result;
}
```

**연산자 우선순위를 무시**한다. `2 + 3 * 4` 를 `(2+3)*4 = 20` 으로 계산한다.
문제가 그렇게 정의했기 때문 — **지문을 그대로 옮기는 것**이 시뮬레이션의 원칙.

> ⚠️ **C의 나눗셈 규칙이 나오는 변형도 있다.** BOJ 14888에는 `/` 가 있고 "음수를 양수로 바꾼 뒤 몫을 취하고 다시 음수로" 규칙이 붙는다. 이 문제는 `+ - *` 뿐이라 해당 없음.

## 5. 예제 손 추적 — `N=3`, 숫자 `[3, 4, 5]`, 연산자 `+ 1개, - 1개, * 0개`

연산자는 `N - 1 = 2` 개 배치.
`possible = [1, 1, 0]` → `+` 1개, `-` 1개, `*` 0개.

### 탐색 트리
```
depth 0:
  i=0 (+): visit[+]=1
    depth 1:
      i=0 (+): visit[+]==possible[+] (1==1) → skip
      i=1 (-): visit[-]=1
        depth 2 == N-1 → calculate()
        수식: (3 + 4) - 5 = 2
      i=2 (*): possible[*]==0 → skip
    visit[+]=0

  i=1 (-): visit[-]=1
    depth 1:
      i=0 (+): visit[+]=1
        depth 2 → (3 - 4) + 5 = 4
      i=1 (-): 1==1 → skip
      i=2 (*): skip
    visit[-]=0

  i=2 (*): possible[*]==0 → skip
```

**후보는 딱 2가지**: `+ -` 와 `- +`
```
(3 + 4) - 5 = 2
(3 - 4) + 5 = 4
```
```
최댓값 4
최솟값 2
```

**개수 제한이 탐색을 얼마나 줄이는지** 보인다. 제한이 없었다면 `3^2 = 9` 가지였을 것.

### `visit[i]--` 를 빼면
```
depth 0에서 i=0(+)를 쓰고 visit[+]=1
  → 하위 탐색 끝나고도 visit[+]가 1로 남음
depth 0에서 i=1(-)를 쓸 때 이미 +를 다 쓴 상태
  → depth 1에서 + 를 못 씀
  → (3 - 4) + 5 경우가 사라진다
```
**최댓값 4를 놓쳐서 답이 틀린다.** 백트래킹의 중요성이 여기서 드러난다.

### 우선순위 무시 확인
숫자 `[2, 3, 4]`, `+ 1개, * 1개` 라면
```
(2 + 3) * 4 = 20        ← 이 문제의 규칙
 2 + (3 * 4) = 14       ← 일반 수학 (틀림)
```

## 6. 함정 / 예상 함정
- **★★ `visit[i]--` 백트래킹 누락.** 경우가 대량으로 사라진다. **G07/G04 공통 최다 실수.**
- **★★ `depth == N` 으로 종료.** 연산자는 **`N-1`** 개다.
- **★ `maxAnswer` 를 0으로 초기화.** 결과가 음수일 수 있다. `-INF` 로.
- **★ 연산자 우선순위를 적용.** 지문이 "앞에서부터"라고 했다. `*` 를 먼저 계산하면 안 된다.
- **`visit` 을 bool 로 둠.** 같은 연산자를 여러 개 쓸 수 있다. **카운터**여야 한다.
- **T-loop 마다 `visit`, `minAnswer`, `maxAnswer` 초기화 누락.**
- **`possible` 합계 ≠ `N-1` 인 경우.** 문제가 보장하지만, 안 맞으면 `DFS` 가 종료 조건에 도달하지 못하고 조용히 아무 답도 안 낸다 (`minAnswer` 가 `INF` 그대로).
- **오버플로.** 숫자가 크고 `*` 가 많으면 `int` 를 넘길 수 있다. 이 문제 범위에서는 안전.

## 7. 백지 재현 체크리스트
- [ ] `visit` 을 **카운터**로 두고 `possible` 과 비교하는가
- [ ] `visit[i]++` / `DFS` / `visit[i]--` **세 줄 세트**를 쓰는가
- [ ] 종료 조건이 **`depth == N - 1`** 인가
- [ ] `minAnswer = INF`, `maxAnswer = -INF` 로 **방향을 반대로** 초기화했는가
- [ ] `calculate()` 가 **앞에서부터 순차** 계산인가
- [ ] 최댓값과 최솟값을 **한 번의 DFS로** 구하는가
- [ ] T-loop 초기화를 넣었는가

## 8. 한 줄 요약
"`visit` 을 **카운터로 승격**해 개수 제한을 걸고, `visit[i]--` 로 되돌린다. 연산자는 **N-1개**."
