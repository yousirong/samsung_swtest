# 16 — 달팽이 (BOJ 1913)

| 항목 | 내용 |
|---|---|
| 유형 | G01 배열 회전·변환 (변형 — 회전이 아니라 **나선 채우기**) |
| 소스 | [swtest/16_BOJ_1913_달팽이.cpp](../../../swtest/16_BOJ_1913_달팽이.cpp) |
| 링크 | https://www.acmicpc.net/problem/1913 |
| 구조 | 단일 케이스 (N은 홀수) |

## 1. 문제 요약
N×N 배열(N은 홀수)의 **가운데에서 시작**해 1부터 N²까지를 달팽이(나선) 모양으로 채운다.
채운 배열을 출력하고, 추가로 숫자 K가 놓인 좌표 `(행, 열)` 을 출력한다.

## 2. 필요한 이론
→ [G01 배열 회전·변환](../../theory/G01_배열회전.md)

엄밀히는 회전이 아니다. 하지만 **방향 배열 + 규칙적 방향 전환**이라는 골격이 회전 문제와 같고, 여기서 처음 나오는 `dr[]/dc[]` 패턴이 이후 [G05 그리드 탐색](../../theory/G05_그리드탐색심화.md) 전체와 기출 시뮬레이션의 기본기가 된다.

**이 문제에서 챙길 것은 나선 자체가 아니라 두 규칙을 찾아내는 감각이다.**

## 3. 코드 흐름
```
main()
 └ scanf(N, K)
   makesnail()
    └ 시작: r = c = (N+1)/2, direction = 0(위), index = 1, size = 0
      MAP[r][c] = 1                    중앙은 루프 밖에서 채움
      for i in 0 .. 2N-2:              방향 전환 총 2N-1번
         if (i % 2 == 0) size++;       두 번마다 이동 길이 +1
         size칸 이동하며 index 채우기
            (채우려는 index == K 이면 좌표 기록)
         direction = (direction + 1) % 4
      printMap(); printf(K 좌표)
```

## 4. 핵심 코드

### 방향 배열 — 상 → 우 → 하 → 좌
```c
int dr[] = { -1, 0, 1, 0 };   // 상, 우, 하, 좌
int dc[] = {  0, 1, 0,-1 };
```

### 나선의 두 규칙
```c
// 방향 전환을 총 2N-1번 하면 N x N 배열 전체를 모두 채울 수 있다.
for (int i = 0; i < 2 * N - 1; i++)
{
    // 두 번 방향을 바꿀 때마다 이동 길이가 1 증가
    // i = 0, 2, 4, 6 ... 일 때 size++
    if (i % 2 == 0)
        size++;

    for (int s = 0; s < size; s++)
    {
        int nr = r + dr[direction];
        int nc = c + dc[direction];

        // 지금 채우려는 숫자가 K라면 좌표 저장
        // index는 아직 MAP에 넣기 전의 숫자
        if (index == K)
        {
            ansR = nr;
            ansC = nc;
        }

        MAP[nr][nc] = index++;
        r = nr;  c = nc;
    }

    // 상(0) -> 우(1) -> 하(2) -> 좌(3) -> 다시 상(0)
    direction++;
    if (direction == 4)
        direction = 0;
}
```

**규칙 ① 이동 길이 패턴** `1, 1, 2, 2, 3, 3, 4, 4, …`
두 번 방향을 바꿀 때마다 1씩 늘어난다 → `if (i % 2 == 0) size++;`

**규칙 ② 총 방향 전환 횟수 = 2N - 1**
길이가 `1,1,2,2,…,N-1,N-1` 이면 합이 `N²-N` 이라 중앙 1칸을 더해도 `N²-N+1` 로 모자란다.
마지막에 길이 `N` 짜리 변이 하나 더 필요해서 **홀수 개**가 된다. N=5면 9번.

### K 좌표 초기화 — 이게 곧 K=1 처리
```c
r = c = ansR = ansC = (N + 1) / 2;
```
중앙은 루프 **밖에서** 채우므로 루프 안에서는 절대 잡히지 않는다. `ansR/ansC` 를 중앙으로 초기화해 두는 것이 K=1 케이스의 유일한 처리다.

## 5. 예제 손 추적 — N=5, K=13

```
출력      25 10 11 12 13
          24  9  2  3 14
          23  8  1  4 15
          22  7  6  5 16
          21 20 19 18 17

          1 5          ← K=13 의 좌표
```

중앙 `(3,3)` 에 1을 놓고 출발한다. 진행 순서:

| i | size | 방향 | 채우는 숫자 | 끝 위치 |
|---|---|---|---|---|
| 0 | 1 | 상 ↑ | 2 | (2,3) |
| 1 | 1 | 우 → | 3 | (2,4) |
| 2 | 2 | 하 ↓ | 4, 5 | (4,4) |
| 3 | 2 | 좌 ← | 6, 7 | (4,2) |
| 4 | 3 | 상 ↑ | 8, 9, 10 | (1,2) |
| 5 | 3 | 우 → | 11, 12, **13** | (1,5) |
| 6 | 4 | 하 ↓ | 14~17 | (5,5) |
| 7 | 4 | 좌 ← | 18~21 | (5,1) |
| 8 | 5 | 상 ↑ | 22~25 … | — |

`size` 가 `1,1,2,2,3,3,4,4,5` 로 커지는 것이 규칙 ①이고, i가 0~8 로 **9 = 2×5-1** 번 도는 것이 규칙 ②다.

`i=5` 단계에서 `index == 13` 인 순간의 `(nr, nc) = (1, 5)` 가 답으로 기록된다.

> 실행으로 검증했다.
> ```bash
> printf '5 13\n' | ./a.out
> ```

## 6. 함정 / 예상 함정
- **★ 방향 순서가 "상 → 우 → 하 → 좌".** 가운데에서 위로 먼저 가고 시계 방향으로 감긴다. 순서를 바꾸면 완전히 다른 배열이 나온다. N=3 예제로 즉시 검산할 것.
- **★ K 좌표 기록 시점.** `index` 는 *아직 채우기 전*의 숫자다. `MAP[nr][nc] = index++` **직전**에 비교해야 한다. `index++` 뒤에 비교하면 좌표가 한 칸씩 밀린다.
- **★ K = 1 (중앙).** 루프 안에서는 안 잡힌다. `ansR/ansC` 를 중앙으로 **초기화**하는 것이 유일한 처리다. 초기화를 빼면 K=1 에서 쓰레기값이 나온다 — 예제로는 안 걸리는 종류의 버그.
- **`2N - 1` 을 `2N` 으로 씀.** 마지막에 배열 밖으로 나가 오버런한다. `MAX` 를 넉넉히 잡아둬서 크래시 없이 **조용히 틀린 답**이 나올 수 있어 더 위험하다.
- **`size++` 조건.** `i % 2 == 0` 이라야 `1,1,2,2,3,3…` 이 된다. `i % 2 == 1` 로 쓰면 `0,1,1,2,2…` 가 되어 첫 칸부터 어긋난다.
- 마지막 변만 길이가 `N` 이라 나선이 비대칭이다. 위 추적표의 `i=8` 이 그 자리.

## 7. 백지 재현 체크리스트
- [ ] 방향 배열을 **상·우·하·좌** 순서로 정의했는가
- [ ] 시작점을 `(N+1)/2` 로 잡고 중앙에 1을 **루프 밖에서** 채웠는가
- [ ] 이동 길이 증가 조건이 `i % 2 == 0` 인가
- [ ] 총 방향 전환 횟수가 `2N - 1` 인가 (왜 홀수인지 설명 가능한가)
- [ ] K 좌표를 `index++` **전에** 비교하는가
- [ ] `ansR/ansC` 초기값을 중앙으로 두어 K=1 을 처리했는가

## 8. 한 줄 요약
"가운데에서 **상·우·하·좌**로, **1,1,2,2,3,3…** 칸씩, **2N-1번** 꺾는다."
