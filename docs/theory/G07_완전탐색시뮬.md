# G07. 완전탐색(DFS 수열) + 시뮬레이션

> 상태: ✅ 작성 완료
> **A형 기출의 가장 전형적인 골격.** [G04 경우의 수](G04_경우의수.md) 로 후보를 만들고, 각 후보마다 시뮬레이션을 돌려 최댓값/최솟값을 갱신한다.

## 언제 이 유형인가
- "최대 K번 조작할 수 있을 때 만들 수 있는 최댓값"
- "연산자를 배치하는 모든 경우"
- "말의 방향을 적절히 정해서 ~를 최소로"
- 조작 횟수가 작다 (5~10회), 선택지도 작다 (4방향, 3연산자)

---

## ★★ 표준 골격 — 이 그룹 9문제가 전부 이 모양이다

```c
void DFS(int depth)
{
    if (depth == K)                      // 후보 하나 완성
    {
        simulate();                      // ★ 원본 복사본 위에서 돌린다
        int tmp = evaluate();
        if (answer < tmp) answer = tmp;  // 최댓값 갱신
        return;
    }

    for (int i = 0; i < 선택지수; i++)
    {
        num_of_cases[depth] = i;
        DFS(depth + 1);
    }
}
```

**핵심은 두 가지뿐이다.**
1. 후보 수열을 **빠짐없이** 만든다 → [G04](G04_경우의수.md)
2. 시뮬레이션이 **원본을 오염시키지 않는다** → 매번 복사

> **[G04 33번 10819](../review/G04/33_BOJ_6603_10819_로또차이를최대로.md)의 `calculate()` 자리에 시뮬레이션이 들어간 것**이 이 그룹이다. 구조는 완전히 같다.

---

## ★ 원본 보존 — 이 그룹 최다 실수

```c
int oMAP[MAX][MAX];     // original Map: 원본 보드     ← 읽기 전용
int ansMAP[MAX][MAX];   // 시뮬레이션 중 실제로 변형할 보드

void simulate()
{
    copyMap(ansMAP, oMAP);      // ★ 매 후보마다 첫 줄
    ...실제 조작...
}
```

**변수 이름을 분리하는 것부터가 방어책이다.** `oMAP` / `ansMAP`, `MAP` / `tmpMAP` 처럼.
복사를 빼먹으면 **첫 후보만 맞고 이후는 오염된 상태에서 계산**된다 — 답이 이상하게 크거나 작게 나온다.

[G01의 제1원칙](G01_배열회전.md)("읽는 곳과 쓰는 곳을 분리")이 시뮬레이션 단위로 확대된 것.

---

## 후보를 만드는 네 가지 형태

| 형태 | 재귀 | 예 |
|---|---|---|
| **방향 수열** (중복순열) | `for i in 0..3: DFS(depth+1)` | [2048](../review/G07/2016하2_2048게임.md), [2개의 사탕](../review/G07/2015하2_2개의사탕.md) |
| **개수 제한 수열** | `visit[i] == possible[i]` 면 skip | [연산자 배치](../review/G07/2017하오후2_연산자배치하기.md) |
| **조합** (절반 분할) | `DFS(depth+1, i+1)`, `depth == N/2` | [조삼모사](../review/G07/2017하오전1_조삼모사.md) |
| **좌표·파라미터 다중 루프** | 중첩 `for` | [테트리스 합](../review/G07/2017상오전1_테트리스블럭안의합최대화하기.md), [종전](../review/G07/2019하오전1_종전.md) |

### 개수 제한 수열 — `visit` 을 카운터로
```c
int visit[3];      // 각 연산자를 지금까지 몇 번 썼는지
int possible[3];   // 쓸 수 있는 최대 개수

for (int i = 0; i < 3; i++)
{
    if (visit[i] == possible[i]) continue;   // 다 썼으면 skip

    num_of_cases[depth] = i;
    visit[i]++;
    DFS(depth + 1);
    visit[i]--;                              // ★ 백트래킹
}
```
[G04 30번 15663](../review/G04/30_BOJ_15649_15654_15663_순열.md)의 **카운터 승격**이 그대로 재등장한다.

---

## ★ 탐색 공간을 먼저 계산한다

| 문제 | 공간 | 판정 |
|---|---|---|
| 2048 (4방향 × 5회) | `4^5 = 1024` | 여유 |
| 2개의 사탕 (4방향 × 10회) | `4^10 = 100만` | 통과 |
| 연산자 배치 (3종 × 10개) | `3^10 = 6만` | 여유 |
| 이상한 체스 (4방향 × 8말) | `4^8 = 6.5만` | 여유 |
| 사다리 조작 (후보 × 3개) | `C(90, 3) ≈ 12만` | **가지치기 필요** |

**짜기 전에 이 계산을 한다.** `4^15 = 10억` 이면 완전탐색이 불가능하니 다른 접근을 찾아야 한다.

---

## 가지치기 — 필요한 순간

```c
// ① 이미 답을 넘길 수 없으면 중단
if (현재까지_비용 >= answer) return;

// ② 목표를 이미 달성했으면 중단
if (PASS == true) return;

// ③ 남은 자원으로 불가능하면 중단
if (남은_깊이 < 필요한_최소) return;
```

[사다리 조작](../review/G07/2018상오전2_디버깅.md)이 ②를 쓴다. **가로선 개수를 0개 → 1개 → 2개 → 3개 순으로 늘려가며**, 성공하는 순간 더 안 본다.

> **"최소 개수"를 묻는 문제는 개수를 작은 것부터 시도**하는 것이 정석이다. 처음 성공한 개수가 곧 답.

---

## 함정 체크리스트
- [ ] **시뮬레이션이 원본 배열을 수정**해 다음 후보가 오염됨 ★★ 최빈
- [ ] 전역 `answer` 를 테스트케이스마다 초기화하지 않음 (T-loop) ★
- [ ] `answer` 초기값 방향 실수 — 최댓값은 작게(`0`/`-INF`), 최솟값은 크게(`INF`)
- [ ] 개수 제한 수열에서 `visit` 복원(`visit[i]--`) 누락
- [ ] "최대 K번"인데 K번 **미만**의 경우를 안 세어봄
- [ ] 탐색 공간을 과소평가해 시간 초과 → 가지치기 필요 여부 판단
- [ ] 시뮬레이션이 중간에 실패했을 때의 반환 규약이 불명확
- [ ] 종료 조건 뒤 `return` 누락
