# G11. 그리디 · DP

> 상태: ✅ 작성 완료
> A형 기출에서는 드물다. 격자도 없고 시뮬도 없는 **순수 계산형** 두 문제.

## 언제 이 유형인가
- 격자가 없다. 배열 하나와 수식만 주어진다
- "최소 개수", "최대 수익" — 답이 하나의 수
- 완전탐색으로도 되지만 N이 크거나, 수식으로 바로 떨어진다

## 두 갈래
**그리디 / 수식** — 각 원소를 독립적으로 계산해 합산
- 나눗셈 올림: `(a + b - 1) / b`
- 각 항목이 다른 항목에 영향을 주지 않는지 먼저 확인

**선택 완전탐색 (또는 DP)** — 앞의 선택이 뒤에 영향을 준다

> ⚠️ **이 레포의 [외주 수익 최대화](../review/G11/2017상오전2_외주수익최대화하기.md) 소스는 DP가 아니라 `2^N` 완전탐색**이다.
> `N ≤ 15` 라 `2^15 = 32768` 로 충분하기 때문. 처음 이 카드에 "DP"라고 적었던 것을 정정한다.

- **완전탐색**: 각 날을 선택/미선택 → `2^N`, 검증 후 수익 합산
- **DP**: `dp[i] = i일부터 시작할 때의 최대 수익`
  뒤에서부터 채우면 `dp[i] = max(dp[i+1], profit[i] + dp[i + time[i]])`
- **N이 작으면 완전탐색이 더 단순하다.** 크면 DP가 필수

## 핵심 패턴
```c
// ★ 올림 나눗셈 — A형 최다 등장 관용구
//    x 를 d 로 나눈 올림 (단, x > 0 일 때만)
((x - 1) / d) + 1

// x == 0 이면 ((0-1)/d)+1 == 1 이 되어 틀린다 → 가드 필수
if (x > 0) sum += ((x - 1) / d) + 1;

// ★ 입력 크기가 크면 오버플로를 먼저 의심
typedef long long ll;
ll sum = 0;
printf("%lld\n", sum);      // %d 로 출력하면 잘린다
```

### 선택 완전탐색 골격
```c
void DFS(int depth)
{
    if (depth == N)
    {
        if (check() == true)              // ★ 검증을 평가보다 먼저
        {
            int tmp = getProfit();
            if (maxAnswer < tmp) maxAnswer = tmp;
        }
        return;
    }
    for (int i = 0; i < 2; i++)           // 선택 안 함 / 선택
    {
        num_of_cases[depth + 1] = i;
        DFS(depth + 1);
    }
}
```

## 함정 체크리스트
- [ ] 올림 나눗셈을 `a / b + 1` 로 써서 나누어떨어질 때 1 초과
- [ ] 그리디가 성립하는지 검증 없이 적용 (반례를 한 번 찾아본다)
- [ ] DP 범위를 벗어나는 인덱스 (`i + time[i] > N`) — 그 선택은 불가
- [ ] 테스트케이스마다 dp 배열 초기화 누락
