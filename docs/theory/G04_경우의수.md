# G04. 경우의 수 · 백트래킹

> 상태: ✅ 작성 완료
> **원재료**: [`swtest/27_경우의수_순열_조합_중복순열_중복조합.cpp`](../../swtest/27_경우의수_순열_조합_중복순열_중복조합.cpp) 가 4종 패턴을 **3중 for문으로** 나란히 담은 템플릿이다. 이 카드는 그것을 **재귀로 옮긴 것**이다.

## 언제 이 유형인가
- "N개 중 M개를 고른다", "순서를 정한다", "모든 경우를 시도"
- 입력 크기가 작다 (N ≤ 10~20)
- 기출에서는 **"어떤 선택을 하느냐"가 시뮬레이션의 입력이 되는** 형태로 나온다

> **이 그룹은 [G07 완전탐색+시뮬레이션](G07_완전탐색시뮬.md) 9문제의 전반부다.**
> 기출의 절반이 "여기서 후보를 만들고 → 시뮬레이션을 돌린다" 구조다.

## ★ 4종 구분표

| | 순서 O | 순서 X |
|---|---|---|
| **중복 O** | 중복순열 `nΠr` | 중복조합 `nHr` |
| **중복 X** | 순열 `nPr` | 조합 `nCr` |

**두 축만 판단하면 코드가 결정된다.**
1. `1 2` 와 `2 1` 이 다른가? → 다르면 순서 O
2. `1 1` 이 허용되는가? → 되면 중복 O

---

## ★★ 하나의 골격, 두 개의 스위치

네 가지가 **같은 재귀**다. 달라지는 건 `for` 의 시작값과 `visit` 유무뿐이다.

```c
void DFS(int depth, int start)
{
    if (depth == M) { printCases(); return; }   // 다 채웠다

    for (int i = start; i <= N; i++)
    {
        num_of_cases[depth] = i;      // 이 자리에 i를 놓고
        DFS(depth + 1, ???);          // 다음 자리로
    }
}
```

| | `for` 시작 | 다음 재귀 인자 | `visit` |
|---|---|---|---|
| **중복순열** `nΠr` | `1` | `DFS(depth+1)` | 없음 |
| **중복조합** `nHr` | `start` | `DFS(depth+1, i)` | 없음 |
| **조합** `nCr` | `start` | `DFS(depth+1, i + 1)` | 없음 |
| **순열** `nPr` | `1` | `DFS(depth+1)` | **있음 (되돌림)** |

**외우는 법**
- **순서를 없애려면** → `start` 를 넘긴다 (오름차순으로만 뽑으니 `1 2` 만 나오고 `2 1` 은 안 나옴)
- **중복을 없애려면** → 조합은 `i + 1`, 순열은 `visit[]`
- 중복조합 `i` vs 조합 `i + 1` — **딱 1 차이**다

---

## 순열의 `visit` — 반드시 되돌린다
```c
for (int i = 1; i <= N; i++)
{
    if (visit[i] == true) continue;     // 이미 쓴 숫자는 건너뜀

    num_of_cases[depth] = i;
    visit[i] = true;                    // 사용 처리

    DFS(depth + 1);

    visit[i] = false;                   // ★★ 백트래킹: 사용 해제
}
```

> **이것이 [G03 DFS](G03_DFS_BFS기초.md)와의 결정적 차이다.**
> - **연결 요소 탐색(G03)**: `visit` 을 **되돌리지 않는다.** 한 번 방문하면 끝
> - **백트래킹(G04)**: `visit` 을 **반드시 되돌린다.** 다른 경우에서 그 숫자를 다시 써야 하므로
>
> 되돌림을 빼면 첫 번째 경우만 출력되고 끝난다. 반대로 G03에서 되돌리면 지수 시간이 된다.
> **같은 `DFS` 라는 이름이지만 하는 일이 다르다.**

## 중복 입력값 처리 (N과 M 9~12번 계열)

입력에 같은 값이 여러 번 들어오는데 **같은 수열은 한 번만** 출력해야 하는 유형. 두 가지 처방이 있다.

### (가) 서로 다른 값만 추려서 쓴다 — 중복 허용 유형
```c
bool check[10000 + 100];      // 어떤 값이 이미 들어갔는지

if (check[value] == 0) { check[value] = 1; number[++N] = value; }
```
같은 값을 몇 번이든 뽑아도 되므로 **개수는 필요 없고 종류만** 알면 된다. → [32번](../review/G04/32_BOJ_15665_15666_N과M11_12.md)

### (나) 값별 개수를 세어 그 횟수만큼만 쓴다 — 중복 불가 유형
```c
int possible[MAX];    // 이 값이 입력에 몇 개 있는가
int visit[MAX];       // ★ bool 이 아니라 int — 지금까지 몇 번 썼는가

if (visit[i] == possible[number[i]]) continue;   // 다 썼으면 skip
visit[i]++;
DFS(depth + 1);
visit[i]--;
```
**`visit` 이 bool 에서 카운터로 승격**된다. `9 7 9` 에서 `9` 는 두 번까지 쓸 수 있다. → [30번 15663](../review/G04/30_BOJ_15649_15654_15663_순열.md)

> 어느 쪽이든 **먼저 정렬**해야 사전순 출력이 된다.

## 완전탐색의 전형 — 만들고 → 평가한다
```c
void DFS(int depth)
{
    if (depth == N)
    {
        int tmp = calculate();                  // 이 경우의 점수
        if (maxAnswer < tmp) maxAnswer = tmp;   // 최댓값 갱신
        return;
    }
    ...
}
```
[33번 10819](../review/G04/33_BOJ_6603_10819_로또차이를최대로.md) 가 이 형태다. **기출 G07 전체가 이 골격의 확장**이다 — `calculate()` 자리에 시뮬레이션이 들어갈 뿐.

## 탐색 공간 계산 — 짜기 전에 한다
| | 크기 |
|---|---|
| 중복순열 `nΠr` | `N^M` |
| 순열 `nPr` | `N! / (N-M)!` |
| 조합 `nCr` | `N! / (M!(N-M)!)` |
| 전체 순열 `N!` | `8! = 40320`, `10! = 362만`, `12! = 4.8억` ✗ |

`4^10 = 100만` → 통과. `4^15 = 10억` → 가지치기 필요.

## 함정 체크리스트
- [ ] **순열에서 `visit` 복원 누락** → 첫 경우만 나오고 끝 ★★
- [ ] 조합인데 `DFS(depth+1, i)` 를 써서 중복조합이 됨 (반대도) — **`i` vs `i+1`**
- [ ] 종료 조건(`depth == M`) 후 `return` 누락 → 배열 범위 초과
- [ ] `start` 를 안 넘겨서 순서 없는 조합이 순열이 됨
- [ ] 전역 결과 변수를 테스트케이스마다 초기화 안 함 (T-loop)
- [ ] 최솟값 문제인데 `answer` 를 0으로 초기화
- [ ] 사전순 출력이 필요한데 입력 정렬 누락
- [ ] 중복 입력에서 (가)/(나) 처방을 뒤바꿔 적용
- [ ] 탐색 공간을 과소평가해 시간 초과
