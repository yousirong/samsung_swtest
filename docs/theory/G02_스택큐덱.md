# G02. 스택·큐·덱 (수제 자료구조)

> 상태: ✅ 작성 완료

## 언제 이 유형인가
- **A형 환경 전반.** STL을 쓰지 않으므로 필요한 자료구조는 전부 직접 만든다
- "가장 마지막에 넣은 것부터" → 스택 / "먼저 넣은 것부터" → 큐
- 괄호 짝 맞추기, 회전하는 큐, BFS의 탐색 큐

> 이 그룹은 문제가 어려워서가 아니라 **손이 기억해야 해서** 있는 구간이다.
> 목표는 "생각 없이 3줄 안에 큐를 만들 수 있는가".

---

## ★ 전역 배열 + 인덱스 두 개

세 자료구조가 전부 같은 골격이다. **배열 하나 + 정수 포인터**.

```c
int stack[MAX];  int sp;              // 스택:  포인터 1개
int queue[MAX];  int rp, wp;          // 큐:    읽기/쓰기 2개
int deque[MAX];  int front, back;     // 덱:    앞/뒤 2개
```

공통 규약: **포인터는 "다음에 들어갈 자리"를 가리킨다.**
그래서 실제 데이터는 항상 반개구간이다.

| | 데이터 범위 | 비었는가 | 개수 |
|---|---|---|---|
| 스택 | `stack[0 .. sp-1]` | `sp == 0` | `sp` |
| 큐 | `queue[rp .. wp-1]` | `rp == wp` | `wp - rp` |
| 덱 | `deque[front .. back-1]` | `front == back` | `back - front` |

---

## 스택
```c
stack[sp++] = value;        // push
value = stack[--sp];        // pop   (먼저 감소 후 읽기)
value = stack[sp - 1];      // top   (감소 없이)
```
`push` 는 후위 증가, `pop` 은 **전위 감소**. 이 비대칭이 `sp` 가 "다음 자리"라는 규약에서 나온다.

## 큐
```c
queue[wp++] = value;        // push  (뒤에 넣고)
value = queue[rp++];        // pop   (앞에서 빼고)
value = queue[rp];          // front
value = queue[wp - 1];      // back
```

> **★ 큐 배열 크기 산정 — 이 그룹의 핵심 함정**
> `rp` 도 `wp` 도 **전진만 한다.** pop 해도 앞자리가 재활용되지 않는다.
> 그래서 배열 크기는 "동시에 들어 있는 최대 개수"가 아니라 **총 push 횟수**로 잡아야 한다.
> [20번 카드1](../review/G02/20_BOJ_2161_카드1.md) 이 정확히 이 함정 위에 있다 (`queue[MAX * 2]`).
> 원형 큐(`% MAX`)로 만들면 재활용되지만, A형에서는 **넉넉히 잡는 쪽**이 실수가 적다.

## 덱
```c
#define OFFSET (MAX / 2)
front = back = OFFSET;      // ★ 배열 중앙에서 시작

deque[--front] = value;     // push_front  (먼저 감소)
deque[back++]  = value;     // push_back
value = deque[front++];     // pop_front
value = deque[--back];      // pop_back
```
**중앙에서 시작**하는 게 요령이다. `front` 가 감소해야 하므로 왼쪽 여유가 필요하다. 0에서 시작하면 `push_front` 한 번에 음수 인덱스가 된다.

## 문자열 명령 처리
A형에는 `<string.h>` 를 안 쓰는 편이라 `strcmp` 를 직접 만든다.
```c
int strCompare(const char* a, const char* b)
{
    while (*a && *a == *b) { ++a; ++b; }
    return *a - *b;          // 같으면 0
}
```
> [21번](../review/G02/21_BOJ_10866_덱.md) 은 이 함수 이름을 그대로 `strcmp` 로 썼다. `<string.h>` 를 포함하지 않아 충돌이 없을 뿐, **이름을 피하는 게 안전**하다.

명령 분기는 `if / else if` 사슬로 푼다. `push` 처럼 인자가 따라오는 명령만 `scanf` 를 한 번 더 한다.

## 함정 체크리스트
- [ ] **큐 배열 크기를 원소 개수로 잡음** → 전진만 하는 `wp` 때문에 오버플로 ★
- [ ] 빈 상태에서 `pop`/`front` 호출 시 반환 규약(대개 `-1`)을 안 지킴
- [ ] `pop` 에서 후위 감소(`stack[sp--]`)를 써서 한 칸 어긋남 — **전위**여야 한다
- [ ] 덱을 인덱스 0에서 시작해 `push_front` 에서 음수 인덱스
- [ ] 원형 인덱스에서 `(i - 1 + MAX) % MAX` 의 `+ MAX` 누락
- [ ] `size` 를 `wp` 로 출력 (정답은 `wp - rp`)
- [ ] 자체 구현 함수 이름이 표준 라이브러리와 충돌
