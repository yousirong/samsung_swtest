# 프로그래머스 함수형 변환

`swtest/`의 표준입출력형 풀이를 **프로그래머스 함수형(`solution` 함수) 제출용**으로 옮긴 것이다.

| | 코드트리 / 백준 / SWEA | 프로그래머스 (함수형) |
|---|---|---|
| 입력 | 프로그램이 stdin에서 직접 읽음 (`scanf`) | 채점기가 인자로 넘겨줌 |
| 출력 | 프로그램이 직접 출력 (`printf`) | `return` 하면 채점기가 비교 |
| `main()` | 내가 작성 | 채점기가 갖고 있음 |

알고리즘은 이미 `swtest/`에서 검증됐다. 여기서 연습하는 것은 **입출력 껍데기를 바꾸는 작업 그 자체**다.

---

## 공통 규칙

### 1. 원본 로직은 건드리지 않는다

바뀌는 곳은 세 군데뿐이고 전부 표시를 단다.

| 마커 | 뜻 |
|---|---|
| `// [수정]` | 원래 있던 줄을 고침 (scanf → 인자 대입, printf → return, main → solution) |
| `// [추가]` | 원래 없던 줄을 새로 넣음 (include, 재호출 초기화) |
| `// [버그수정]` | 원본 버그를 고친 곳 (드묾. README에 근거를 반드시 적는다) |
| `// [이름변경]` | `using namespace std;` 와 겹쳐 전역 이름을 바꾼 곳 (윷놀이사기단 한 곳뿐) |

### 2. `using namespace std;`를 쓴다 — 단, 전역 이름 충돌만 조심

프로그래머스 C++ 템플릿에 `using namespace std;`가 기본으로 들어 있으므로 그대로 따른다.
그래서 시그니처도 `vector<int> solution(...)` 처럼 짧게 쓴다.

문제는 **전역 배열 이름이 `std` 이름과 겹칠 수 있다**는 것이다.

```
error: reference to 'move' is ambiguous
```

다만 실제로 깨지는 경우는 생각보다 적다. `<queue>` · `<stack>` · `<deque>` · `<algorithm>` 을
include 하지 않으면 `std::queue` · `std::stack` · `std::deque` · `std::count` 는 선언조차 되지 않아
전역 배열 이름과 부딪히지 않는다. 여기 파일들은 `<vector>` (와 필요할 때 `<string>`)만 쓴다.

반면 `<vector>`가 `<utility>` · `<iterator>`를 끌고 오기 때문에 **`std::move` 와 `std::next` 는 반드시 부딪힌다.**

| 원본 | 전역 선언 | 처리 |
|---|---|---|
| 2019하오후2 윷놀이사기단 | `int move[]`, `int next[][]` | `moveList`, `nextTable` 로 **이름 변경** (`// [이름변경]` 표시) |
| 21 덱, 22 회전하는큐 | `int deque[]` | `<deque>`를 include 하지 않아 그대로 둔다 |
| 24 바이러스DFS | `int count;` | `<algorithm>`을 include 하지 않아 그대로 둔다 |
| 17 스택, 19·20·25·26 | `int stack[]`, `int queue[]` | 위와 같다 |
| 2017상오전2 외주수익, 2020상오후1 승자독식모노폴리 | `int time[]` | `<ctime>`을 include 하지 않아 그대로 둔다 |

> 직접 풀 때 `#include <bits/stdc++.h>` 를 쓰면 위 이름이 전부 살아나 한꺼번에 깨진다.
> 전역 이름을 `queue` · `stack` · `count` · `time` · `next` · `move` · `y1` 로 두지 않는 편이 안전하다.
> (`y1` · `y0` · `j1` 은 `<math.h>`의 베셀 함수다. 좌표를 다루는 문제에서 특히 잘 걸린다)

### 3. `solution()`은 언제나 한 케이스

원본에 `T` 루프나 `0`-종료 루프가 있어도 `solution()`은 한 케이스만 처리한다. 루프는 하네스가 돈다.

### 4. 반환 타입

| 원본 출력 | 반환 |
|---|---|
| 정수 1개 | `int` (`%lld`면 `long long`) |
| 정수 2~3개 | `vector<int>` — **원본 출력 순서 그대로** |
| 명령마다 1줄 | `vector<int>` |
| 격자 전체 | `vector<vector<int>>` |
| 케이스마다 문자열 | `vector<string>` |

### 5. 인자 순서 = 원본 `scanf` 순서

배열 길이로 알 수 있는 값(`N`, `M`, `Q` 등)만 인자에서 뺀다.

> **축 순서를 "고쳐 주지" 않는다.** `38_BOJ_7576`은 `M N`(가로·세로), `38_BOJ_7569`는 `M N H`, `40_BOJ_2234`도 `M N` 순이다. 자연스러워 보인다고 `n, m`으로 바꾸면 하네스도 같이 바뀌어 **대조는 통과하는데 제출하면 틀린다.**

---

### 6. 내부는 swtest와 같은 C 스타일로 둔다

프로그래머스 C++ 제출은 `solution()` 시그니처를 피할 수 없다. 그래서 STL은 **경계에서만** 쓴다.

| 자리 | 쓰는 것 |
|---|---|
| `solution()` 시그니처 | `vector` / `string` (어쩔 수 없음) |
| `input()` 안 | 인자 `vector`를 전역 배열로 옮겨 담기만 한다 |
| 로직 함수 | 전역 고정 배열, 직접 만든 큐/스택. **swtest 판과 한 글자도 다르지 않다** |
| 반환 직전 | 전역 배열을 `vector`로 옮겨 담는다 |

그래서 정렬도 `sort` 대신 원본의 선택 정렬을, 큐도 `queue` 대신 `rp`/`wp` 배열 큐를 그대로 쓴다.
명령 문자열을 파싱할 때도 `substr`이 아니라 `sscanf(commands[i].c_str(), "%s %d", ...)` 로 읽는다.

## 폴더 구성

```
programmers/<문제>/
  solution.cpp    ← 제출용. swtest 판과 같은 코드이고 input()/solution()만 다르다
  local_test.cpp  ← 로컬 대조용. solution.cpp 를 include 하고 main()을 갖는다
  README.md
```

제출할 때는 `solution.cpp` 를 통째로 붙여 넣는다. `main`이 없으므로 채점기와 부딪히지 않는다.

> 반대로 `swtest/` 파일을 그대로 내면 `main`이 겹치고 `solution`이 없어서 링크가 깨진다.
> ```
> undefined reference to `solution(...)`
> ```

## 검증 방법

`local_test.cpp` 는 원본과 **똑같은 형식으로 읽고 똑같은 형식으로 출력**하므로 바이트 단위 대조가 된다.

```bash
cd programmers/<문제>
g++ -O2 -o run local_test.cpp                 # 대조용
g++ -O2 -DREPEAT_TEST -o rep local_test.cpp   # 재호출 검사용
g++ -O2 -o orig ../../swtest/<원본>.cpp        # 기준

./orig < in.txt > a.out
./run  < in.txt > b.out
cmp a.out b.out          # diff 대신 cmp — 줄 끝 공백/마지막 개행 차이를 놓치지 않는다
./rep  < in.txt          # "NOT RE-ENTRANT"가 안 나오면 통과
```

통과 기준 4가지

1. `solution.cpp` 만으로 컴파일해도 `main`이 없다 → 제출 코드가 순수함
2. `local_test.cpp` 빌드 성공
3. 랜덤 입력 전부 `cmp` 일치
4. `-DREPEAT_TEST` 전부 통과
